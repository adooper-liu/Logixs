# ADR-015 出运全生命周期业务治理收口

- 状态：accepted-business
- 日期：2026-09-24
- 决策范围：出运全生命周期业务蓝图

## 背景

原始讨论已经覆盖业务链、对象、岗位、交接、异常、费用、合规、调度、外部协作和集成标准。要将这些资料作为完整业务基线，还需要关闭Shipment拆分、主数据责任、排柜优先级、计划发布权限、伙伴可见范围和外部接入顺序六项治理问题。

## 决定

- Shipment按起运地、目的地、运输责任和货物控制范围判断拆分，Booking、提单和柜号不作为内部主身份。
- 产品部门负责产品家族和变体，研发与供应链负责物料/BOM，商业运营负责SKU/Listing，合规岗位负责法规属性，数据治理负责跨域编码和变更。
- 排柜优先级为安全与合规硬约束、法定期限与free time、已对外承诺、总成本与时效、资源利用率。
- 调度员生成候选方案，计划负责人发布计划和批准突破冻结区。
- 外部伙伴采用任务级最小可见范围；伙伴回执是证据候选，内部事实仍需按来源资格采信，法律责任由合同确定。
- 接入顺序为聚合平台、一个主要船司官方来源、一个主要港口/码头来源，再按业务价值扩展。

## 完整性边界

本决定关闭业务设计层的治理未决项。原系统字段字典、法规参数、合同、费率、凭据、真实报文、供应商SemVer和性能结果属于实施输入或验证证据。未取得输入时不得以默认值冒充事实，也不得启用相应业务范围。

## 结果

13份专题可以作为完整的出运全生命周期业务设计基线。完整表示设计范围、规则、岗位、异常、交接、权限和扩展机制齐备，不表示软件已经实现，也不表示第三方尚未提供的数据已经存在。
