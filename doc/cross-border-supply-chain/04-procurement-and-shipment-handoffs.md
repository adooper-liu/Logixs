# 采购及出运计划交接契约

## 目的与范围

本文定义补货、采购履约、可出运供给池、出运计划和备货之间的业务交接。这里的“契约”指业务双方必须提供、验证和确认的信息，不是API或数据库契约。

交接契约的目的不是要求所有信息一次填满，而是让接收岗位知道：哪些信息已经确认，哪些仍待补全，哪些风险可能影响下一步。非关键业务信息缺失时，对象可以先建立并进入待补全；无法识别供给、需求或必要关系时，才应阻断交接。

上游交接最容易出现两种问题：一是把计划当成事实，例如把供应商口头说的完工日当成已经可出运；二是为了方便合并订单或装柜，丢失原始需求和目的地。本文通过分层交接同时解决提前规划和事实可靠性。

## 交接总览

```text
补货决策
-> 采购计划/调拨计划/加急需求
-> 采购订单与供应商书面确认
-> 生产和检验事实
-> 可出运供给池
-> 出运计划预占与正式分配
-> 国家、渠道、仓库和港口方案
-> 备货单释放
```

## 补货向采购计划交接

每条采购需求至少说明：

- 补货决策及需求来源。
- SKU、物料和适用BOM版本。
- 目标国家、渠道、履约网络和仓库。
- 需求数量、目标到货日期和允许时间窗。
- 建议供应商、实际工厂及替代供应商。
- MOQ、包装倍数、有效价格和币种。
- 标准、承诺及当前预测提前期。
- 质量、合规、包装和标签要求。
- 预算、优先级、冻结状态和供应风险。

采购可以合并多个补货需求形成采购计划或订单，但必须保留来源需求、数量分摊和目标用途。采购不得将合并后的订单反向解释为新的需求来源。

例如，英国仓和德国仓分别需要同一SKU 600件和400件，采购可以合并为一张1000件订单，以满足MOQ或取得阶梯价。但订单必须保留600件和400件的需求归属。供应商只能交付800件时，系统才能根据优先级、缺货风险和业务决策重新分配，而不是让采购人员凭记忆拆分。

采购计划确认时还要回答：当前建议使用哪家工厂，是否存在备供，MOQ造成多少超采，采购是否挤占现金预算，共用物料能否合并，以及交付时间是否仍能满足目标到仓窗口。

## 采购执行与书面承诺

供应商书面确认至少应覆盖订单身份、物料或SKU、版本、数量、价格、币种、工厂、承诺交期、包装要求和已知例外。邮件、门户确认、EDI或受控文件可以作为书面确认载体，但必须能够追溯发送方、接收时间和原始内容。

口头沟通可以作为计划信号，不得直接改变承诺数量和日期。后续书面确认与口头信号不一致时，应形成差异和影响处理，而不是覆盖历史。

供应商门户确认、EDI报文、带身份的邮件或受控上传文件都可以形成书面证据。关键不在载体名称，而在于能够证明确认主体、确认内容、发生时间和对应的订单版本。

采购订单应支持行级和分批交付。供应商确认一张订单时，可以对不同订单行给出不同交期，也可以将一行拆成多个承诺批次。后续实际生产、检验和短装都要对应到这些批次，而不能只维护一个订单级“预计交货日”。

## 可出运供给池

“可出运供给池”是采购履约与出运计划之间的正式业务缓冲层。它统一表达未来或当前可用于出运组织的供给，但不等同于现货库存。

每个供给批次至少能够说明：

- 来源补货决策、采购计划和采购订单行。
- 供应商法律实体及实际生产工厂。
- SKU、物料、BOM和包装版本。
- 可供数量、已预占数量及剩余数量。
- 预计或确认的可出运时间窗。
- 集货地址和建议起运港。
- 箱数、体积、毛重、托盘及包装信息。
- 生产、质检、合规和异常状态。
- 目标市场限制、优先级及最晚到仓日期。
- 可拆分、不可拆分及批次保持要求。

### 进入规则

供应商已经提供可追溯的数量和时间信息后，供给可以进入供给池。质检未完成的供给允许进入预排范围，但必须明确标记为未释放。

### 正式释放规则

供给正式用于备货前，必须满足：

1. 产品、物料、SKU和包装版本可识别。
2. 数量、箱规、重量、体积和集货地点满足当前阶段要求。
3. 质检已经通过，或存在明确批准的例外放行。
4. 目标市场所需合规资料满足备货释放要求。
5. 短装、替代、批次和不可拆分约束已经明确。

## 可出运供给池向出运计划交接

出运计划可以预占未来供给，以支持舱位、仓容和集货规划，但必须展示：

- 供给尚未满足的释放条件。
- 当前预测兑现时间。
- 延误或数量不足风险。
- 对目标到仓、库存和销售的影响。
- 可替代供给或调整方案。

预占不等于备货释放，也不改变供给的质量或合规状态。

### 为什么需要供给池，而不是直接读取采购订单

采购订单代表商业约定，出运计划需要的则是具体时间窗内能够从某个工厂或集货点组织出运的数量。两者之间还存在供应商确认、排产、生产、检验、包装、合规和异常整改。

如果出运计划直接读取订单数量，就会把尚未确认、尚未生产或尚未放行的货物当成可用供给；如果等全部完成才让计划人员看到，又来不及安排舱位、仓容和拼柜。因此供给池既呈现未来供给，又明确其成熟度和未满足条件。

### 供给成熟度

| 成熟度     | 典型依据                             | 允许用途                 | 不能据此做什么     |
| ---------- | ------------------------------------ | ------------------------ | ------------------ |
| 候选供给   | 补货建议或未确认采购计划             | 远期能力、资金和情景模拟 | 订舱或释放备货     |
| 承诺供给   | 已生效订单及供应商书面确认           | 出运预排、舱位和仓容规划 | 当作已检验库存     |
| 待释放供给 | 已完成或接近完成，尚缺质检或合规条件 | 柜次预占、集货准备       | 正式备货和装箱放行 |
| 已释放供给 | 身份、数量、质量、合规和包装条件满足 | 正式分配并生成备货单     | 超出剩余量重复分配 |

成熟度只是交接视角，不取代生产、质检、库存和合规各自的真实状态。

### 供给池如何支持日常计划

计划人员可以看到未来数周各工厂预计完成的批次，并提前组合整柜或拼柜。某批货尚未检验时，可以暂时占据计划位置和舱位需求，但界面必须清楚显示“未释放”、缺少的条件和受影响柜次。

检验失败后，系统释放或调整预占，并提示受影响的国家、仓库、预计缺货和订舱安排。计划人员可以换用其他批次、调整装柜、改变运输方式或接受延期。原计划、变化原因和最终决定都要保留。

## 出运计划与分仓

出运计划按照以下顺序组织分配：

```text
国家
-> 渠道/履约模式
-> 仓库
-> 目标覆盖与到仓窗口
-> 目的港
-> 可用供给
-> 整柜/多供应商拼柜方案
```

Marketplace履约库存和海外仓库存属于不同库存池。多供应商拼柜必须明确集货点、交接责任、截止时间和异常处理。多仓装柜只有在拆分、单证、目的港和操作责任明确时才允许采用。

### 分仓为什么先于组柜

分仓首先服务销售和库存目标，组柜才是在已明确目的地的供给之间优化体积、重量、时间和运输成本。若先按供应商距离或柜容凑柜，再决定货物去向，容易造成某仓积压、另一仓缺货，也可能带来标签、单证和合规不匹配。

分仓建议按“国家 -> 渠道和履约模式 -> 仓库 -> 覆盖目标和到仓窗口 -> 目的港 -> 可用供给”推进。完成后，再结合起运港、供应商位置、货物就绪时间、混装限制、柜型、截港和缺货风险生成整柜、拼柜或延迟合并候选。

## 出运计划向备货交接

完成国家、渠道、仓库、目的港和装柜方案后，系统生成备货单。备货单至少关联：

- 出运计划及版本。
- 来源供给批次和分配数量。
- 供应商及出运港。
- 目标国家、渠道和仓库。
- 计划备货和集货时间。
- 整柜或拼柜组织方式。
- 质量、合规、包装和单证要求。

分仓后改变国家、渠道或仓库必须生成新的出运计划版本，重新评估库存、合规、单证、成本、港口和交期影响。不得直接覆盖原分配结果。

例如，同一采购批次原计划分配给法国仓和西班牙仓，运营随后希望将西班牙部分转给意大利渠道。即使产品实物相同，也要重新检查Listing、标签语言、税务、合规文件、目的港、仓容和到货窗口。确认可行后形成新的出运计划版本，并让采购、合规、仓库和物流看到变化及其影响。

如果货物已经进入冻结区，系统不直接接受数量编辑，而是先展示改单、换港、延误、费用和其他仓库缺货风险，再由授权人员确认。

## 交接失败时如何处理

### 信息不完整但对象可识别

例如包装体积尚未确认，但采购订单、SKU、供应商工厂和目标市场都明确。对象可以进入待补全，并限制依赖体积的装柜确认。系统说明缺失项、责任人和最晚补齐时间，而不是把整条需求当成失败。

### 无法识别或建立必要关系

如果找不到对应SKU、供应商工厂、采购来源或目标库存节点，接收方无法判断这批货是什么、来自哪里或发往哪里，应阻断正式交接并进入人工处理。

### 数量或版本冲突

如果多个计划同时占用同一供给，或者供应商确认的版本与采购当前版本不一致，系统先保留双方原始信息，展示冲突对象和影响，不使用最后一次上传静默覆盖。

### 下游已经执行

备货、装箱或订舱已经发生后，上游数量或目的地变化不能简单回写。系统应生成差异和变更请求，识别哪些动作仍可撤销、哪些需要补偿，以及哪些实际事实只能保留。

## 数量守恒与例外

- 补货需求可以拆分为采购、调拨和加急方案。
- 多个补货需求可以合并采购，但来源分摊必须守恒。
- 一个供给批次可以分配给多个出运需求，但不得超过可分配数量。
- 预占、正式分配、备货、装箱和实际出运数量分别记录。
- 短装、超装、替代、取消和重新分配必须形成业务事件和差异原因。

## AI和自动化边界

AI可以推荐供应商、预测兑现概率、提出出运分配和装柜方案，并解释风险。AI不能直接完成供应商定点、采购下单、质量放行、备货释放或突破冻结区。

## 验收标准

1. 每条采购需求可以追溯补货来源，每个供给批次可以追溯采购履约。
2. 计划人员能够区分预占供给、已释放供给和实际可用库存。
3. 质检未完成的供给不能被误操作为正式备货。
4. 分仓变化形成新版本，并展示对上下游的影响。
5. 从补货决策到装箱明细保持数量来源、分配和差异追溯。
