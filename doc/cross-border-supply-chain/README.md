## 一、唯一业务主链

```text
市场与经营信号
-> 选品与产品开发
-> 产品、变体、物料、BOM、SKU与Listing
-> 供应链寻源
-> 需求预测、库存策略与补货决策
-> 采购计划、采购执行、供应商履约与质检
-> 可出运供给池
-> 出运计划、分仓与组柜规划
-> 备货释放
-> 提空箱、装箱、VGM与出运交接
-> 实际出运与海运跟踪
-> 清关
-> 提柜、送仓或三方堆场
-> 卸柜与还箱
-> 费用、异常、绩效与持续改善
```

“可出运供给池”是采购履约与出运计划之间的正式缓冲层；“实际出运”是当前项目接入历史数据的运行起点，但不是业务蓝图的起点。导入、未来正常流程和外部接口最终进入同一Shipment、货柜、任务、事件和证据链。

## 三、统一边界

本目录描述岗位目标、业务流程、对象关系、所需信息、允许动作、失败恢复、权威事实和上下游交接。技术契约、DTO、状态码、数据库、迁移及实施任务仍由 docs/ 负责。

所有专题共同遵守：

- 信号、建议、计划、承诺和实际分开。
- 产品、物料、SKU与Listing分层但连续追溯。
- 补货需求可以形成采购、调拨和加急运输等多个执行方案。
- 多个需求可以合并采购，但必须保留来源分摊。
- 质检未完成的供给可以预排，不能正式释放备货。
- 出运计划可以预占未来供给，但必须显示兑现风险。
- 分仓后改变国家、渠道或仓库必须形成新计划版本。
- 一柜可以包含多个备货单，一个备货单也可以拆入多柜。
- 无SKU允许历史建档并进入待补全。
- AI只提供建议、解释和预测，不直接定点、下单、放行、发布计划或突破冻结区。
- 外部信息先形成证据候选，再按来源资格采信。
- 费用、时间、状态、事件、任务和文件各有唯一权威归属。

## 四、当前实施起点与未来衔接

当前项目从已实际出运货柜导入开始，先完成海运、清关、提柜、送仓、卸柜、还箱、费用和异常闭环。备货前及装箱专题不是另一套系统，而是同一业务链的前段权威设计。未来相关工作台上线时，通过已经定义的交接契约自然替换Excel入口，下游对象和流程不重建。
