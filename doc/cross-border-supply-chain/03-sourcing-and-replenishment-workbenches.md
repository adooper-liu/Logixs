# 寻源与补货工作台

## 目的与范围

本文按照“岗位目标 -> 操作流程 -> 所需信息 -> 允许动作 -> 可靠落库与反馈”定义寻源和补货工作台。工作台不是字段集合，而是岗位完成实际业务结果的操作入口。

工作台首先应回答“今天最需要处理什么”，而不是让用户先选择报表、再筛选几十个字段。每一项待办都应把业务原因、最晚处理时间、不处理的影响、建议方案和完成条件放在同一操作上下文中。

## 寻源工作台

### 岗位目标

在规定时间内建立符合成本、质量、交付、产能和合规要求的稳定供应方案，并为关键供给建立可执行的风险替代方案。

### 每日优先事项

- 等待回复或即将到期的询报价。
- 逾期样品、测试、验厂和整改。
- 待审核供应商和待审批定点方案。
- 即将失效的报价、合同、资格和认证。
- 缺少备供或切换周期过长的关键物料。
- 质量、交付、合规或财务风险显著上升的供应商。

### 操作时必须看到的信息

需求版本、候选供应商、法律实体和工厂、成本对比、MOQ、包装倍数、交期、产能、样品结论、认证范围、历史绩效、风险评分、主备状态和定点建议。

### 允许执行的动作

发起寻源项目、邀请候选供应商、发布RFI/RFQ/RFP、接收结构化报价、登记样品、安排测试或验厂、发起整改、比较场景、提交定点、分配份额、生效、暂停或退出供应关系。

### 前置条件

寻源需求必须明确产品或物料范围、目标市场、预估数量、质量和合规要求。量产定点前必须存在受控的规格、物料、BOM及适用版本。

### 失败及异常处理

报价不可比、资质过期、工厂不一致、疑似转包、样品失败、产能不足、知识产权、制裁或重大质量风险进入异常队列。系统必须说明阻断原因、所需证据和责任人，不得静默通过。

### 完成结果

形成已批准的供应关系，明确适用对象、工厂、价格、MOQ、交期、产能、份额、主备关系、切换时间和有效期。

### 权威落库事实

正式审批结论、原始报价、结构化成本、签样、测试或审核报告、合同、供应关系版本、风险豁免和整改结果。

### 对后续节点的交接

向补货和采购提供可用供应商、工厂、有效价格、产能、提前期、MOQ、包装倍数、主备关系及风险约束。

### 一次寻源如何完成

#### 1. 发起寻源项目

新品、降本、扩产、备份、质量改善或供应区域转移都可以发起寻源。发起人先说明产品或物料范围、目标市场、预计数量、成本目标、必须资质和希望量产时间。需求尚未稳定时可以先建立项目，但不能直接发出一份口径不清的正式询价。

需求版本冻结后再发出RFI、RFQ或RFP。后续规格变化形成新版本，并明确哪些候选供应商需要重新报价或重新打样，不能悄悄修改原询价。

#### 2. 建立候选供应池

候选供应商可以来自现有供应商扩品、行业展会、产业带、B2B平台、协会、公开企业信息或采购主动开发。工作台先完成预准入，核对企业和工厂真实性、受益所有人、制裁风险、关键设备、品类经验、质量体系、社会责任、财务风险和转包控制。

预准入的结果不是永久合格，而是说明该工厂目前可以进入哪类业务的下一轮评估。

#### 3. 选择合适的询价方式

- RFI用于了解工艺、设备、认证、产能和品类经验。
- RFQ用于规格已经明确、需要比较价格和交付条件的采购需求。
- RFP用于供应商需要同时提供设计、工艺、成本或交付方案的复杂需求。

供应商可以通过门户或受控导入回复。原始文件和结构化结果同时保留；如果币种、贸易条款、包装或付款条件不同，系统先提示不可直接比较，再展示归一后的总落地成本。

#### 4. 打样、测试与量产验证

样品建议按轮次推进：

```text
需求样
-> 供应商样
-> 修改样
-> 签样/封样
-> 小批试产
-> 量产首件
```

每轮都关联需求和BOM版本，记录样品编号、实物去向、测试结果、缺陷、整改、评审意见和批准范围。样品通过只说明当前样品满足要求，不自动表示供应商已准入、已经定点或可以量产。

#### 5. 比较方案并定点

定点比较不能只按价格排名。工作台应同时展示总落地成本、质量、历史交付、有效产能、扩产能力、合规和知识产权、财务和地域风险、工程协同、集货港距离以及拼柜适配度。

评审人可以比较单一来源、主供加备供、多供应商比例分配、按国家或渠道分供等方案。最终结论说明选择理由、未选理由、供应份额、有效期、产能上限和切换条件。

#### 6. 生效后继续治理

供应关系生效后，工作台持续跟踪质量、交付、成本、合规和协同表现。风险可以触发观察、整改、降低份额、暂停新品、暂停下单或退出供应池，但不能只凭一次模型评分自动取消供应商资格。

### 一个容易误判的场景

一个新品有三家候选工厂。A报价最低但只有单一生产线，B价格稍高但已有目标国认证，C离集货港最近且接受较低MOQ。首批试销时，C可能因为低MOQ而带来更小的库存风险；进入稳定销售后，B的质量和合规稳定性可能产生更低的长期成本。

工作台应允许按首批试销、常规补货和旺季放量分别比较，而不是给出脱离业务阶段的唯一排名。系统或AI可以推荐并解释，但定点仍由授权评审人完成。

## 补货工作台

### 岗位目标

在目标服务水平、库存风险、贡献利润和现金占用之间取得平衡，及时形成可执行的采购、调拨或加急需求。

### 每日优先事项

- 未来各时间窗口的预计缺货和销售损失。
- 建议下单日临近、逾期或已无法满足到货窗口的SKU。
- 在途延误、供应商延期和供给数量变化。
- 活动备货不足、新品放量或销量异常。
- 库存过量、滞销和清仓风险。
- 平台仓容、海外仓接收或现金预算冲突。
- 冻结区内需要人工决策的计划变化。

### 操作时必须看到的信息

预测版本、销量趋势、活动增量、各库存池、在途阶段、供应承诺、端到端时间轴、覆盖天数、缺货损失、库存过量、现金占用、落地成本、贡献利润、执行成功概率和最晚决策日期。

### 允许执行的动作

接受、修改或拒绝补货建议；比较采购、跨仓调拨、跨渠道再分配、供应商加急和运输加急方案；调整受权策略参数；锁定计划；申请冻结区变更；下达采购计划、调拨计划或加急需求。

### 前置条件

SKU、目标市场、库存节点和补货策略有效。采购方案必须存在有效供应关系；例外采购必须进入授权审批。数据新鲜度不足或库存存在争议时，不得自动转为执行计划。

### 失败及异常处理

无合格供应商、资金不足、合规受限、在途失真、需求异常或无法满足窗口时，系统应展示“不处理的影响”和可选方案。异常提醒必须能够进入处置、审批和关闭流程。

### 完成结果

形成带需求来源、目标库存节点、需求日期、数量、优先级、约束和决策依据的补货决策，并按需要拆分为多个执行方案。

### 权威落库事实

批准需求、补货运行批次、系统建议、人工决定、覆盖原因、计划版本、审批记录和后续执行关联。

### 对后续节点的交接

分别生成采购计划、库存调拨计划或加急运输需求，不直接生成不可撤销的采购订单或执行事实。

### 一次补货决策如何完成

#### 1. 先处理风险，而不是先看报表

用户进入工作台后，首先看到按预计业务损失和最晚决策日期排序的任务。例如“德国仓SKU-A预计六周后缺货，必须在三天内决定是否加急”，比单独显示一个红色库存天数更有行动意义。

#### 2. 在一条时间轴上理解原因

打开任务后，用户在同一时间轴查看实际销售、基准预测、活动增量、国内和海外库存、采购承诺、生产、海运、清关及预计可售日期。系统说明缺口来自销量上涨、活动、供应商延期、在途延误还是安全库存提高。

#### 3. 计算净需求但不隐藏假设

补货计算可以用以下结构理解：

```text
目标周期需求
+ 安全库存
+ 活动或旺季增量
+ 渠道最低库存要求
+ 已知损耗
- 节点可用库存
- 可兑现的在途库存
- 已确认采购供应
- 可调拨库存
= 初始净需求
```

初始净需求还要经过MOQ、包装倍数、供应商产能、生产和运输提前期、整柜经济性、仓容、平台预约、现金预算、保质期和合规有效期修正。系统必须展示关键假设，不能只给一个无法解释的结果数字。

#### 4. 同时比较多个执行方案

工作台至少比较同网络调拨、跨仓或跨渠道再分配、在途改配、供应商加急、新增采购和运输加急。每个方案展示预计到达时间、增量成本、缺货损失、现金占用、平台和合规限制、对其他仓库的影响以及成功可能性。

#### 5. 人工确认并拆分执行

用户可以接受、调整或拒绝建议。一个补货决策可以拆分成采购、调拨和加急运输多个方案。进入冻结区的变化需要先显示对订单、生产、订舱、库存和费用的影响，再提交授权审批。

#### 6. 用实际结果复盘

采购、生产、运输和入仓结果持续回写。工作台需要说明当初建议是否兑现、偏差来自需求还是供应，以及标准提前期、安全库存或供应商风险参数是否需要调整。

### 新品补货

新品没有稳定历史，建议结合类目基准、相似品、属性、目标价格、竞品、广告和流量计划以及首批测试量形成悲观、基准和乐观情景。

首批试销后，根据流量、转化、毛利、退货、评价和质量逐级放量。战略新品允许扩大首批数量，但要记录预算、风险承担人和退出条件。运营目标可以影响建议，不能伪装成已经发生的需求。

### 活动和旺季补货

活动计划需要记录销售窗口、平台入仓截止、折扣、预计流量、基础销量、活动增量、活动后剩余风险和最晚取消或降量日期。活动增量与基础预测分开保存，活动结束后单独复盘，避免一次大促永久抬高常态需求。

### 多级库存与调拨

发生缺货风险时，系统不应立即创建采购需求，而应依次评估同网络调拨、跨仓调拨、跨渠道再分配、在途改配、加急运输、供应商增产和新增采购。

跨国、跨渠道或跨仓调拨要检查商品和包装、Listing和条码、税务海关、库存所有权、平台规则、转运成本以及对原节点服务水平的影响。不能因为物理商品看起来相同，就认定库存可以自由互换。

### 典型方案比较

德国海外仓预计六周后缺货，国内已有一批货在生产，美国仓同时存在过量库存。系统可以提出三种方案：从美国仓调拨，提高国内生产优先级并走常规海运，或维持生产但将一部分改为空运。

用户看到的不只是到货日期，还包括美国库存能否满足德国标签和渠道要求、转运税务、增量运费、现金占用、对美国仓缺货风险及德国市场预计损失。如果美国库存不能直接转用，工作台应明确阻断原因，而不是继续把它当作可执行方案。

### 在途延误

海运或清关延误发生后，系统先更新预测可售时间和缺货影响，再比较改配、调拨、加急和活动调整。历史承诺日期仍然保留，用于供应链绩效和预测准确度分析，不能被新的预计日期覆盖。

## 工作台的共同反馈方式

- 成功后说明形成了什么业务结果、影响哪些下游对象以及下一责任人是谁。
- 阻断时说明缺什么、为什么阻断、由谁补充以及补充后如何继续。
- 冲突时同时显示当前版本、用户看到的旧版本和重新计算后的影响。
- 批量操作先预检，逐项说明可执行、待补全和阻断对象，提交结果必须可以对账。
- AI建议显示依据、数据时点、不确定性和可能遗漏的约束，允许用户接受、修改或拒绝。

## 人性化交互要求

1. 首页按业务损失和最晚决策日期排序，而不是只按记录创建时间排序。
2. 同一任务展示原因、影响、建议动作和完成条件，避免用户跨页面拼接结论。
3. 比较方案时同时展示成本、时间、库存、利润、现金和风险变化。
4. 人工覆盖必须容易操作，但必须说明原因并保留审计记录。
5. 批量操作必须先预检，清楚列出成功条件、阻断项和受影响对象。
6. AI建议必须显示依据、数据时点和不确定性，并允许用户接受、调整或拒绝。

## 验收标准

1. 岗位能够从优先事项进入任务，并在单一流程内完成判断、执行和确认。
2. 用户能够理解异常为何发生、不处理的影响以及有哪些可执行方案。
3. 所有关键动作具备权限、幂等、并发冲突和审计要求的业务入口。
4. 工作台产生的结论能够被采购和出运计划直接消费并追溯。
