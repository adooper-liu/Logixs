## 核心判断

### 决定 1：物料变化何时触发新 SKU

**1A. 双门判定，推荐**

先判断是否形成新标准物料/BOM 版本，再判断最终可售单元能否在库存、销售、履约、售后和合规上混用。只有第二道不通过才新 SKU。

收益：符合现行业务权威，控制 SKU 膨胀；成本：需要影响评估和证据；风险：判断责任不清时会等待；边界：未验证时进入待决定，不静默沿用；可逆性：高，尚未发布前可重新判断。

**1B. 强耦合**

任何不可互换物料都强制新 SKU。

收益：简单、保守；成本：SKU、Listing、预测和库存快速膨胀；风险：把内部工程变化错误变成商业身份变化；边界：只适合所有材料变化都会改变终端商品的品类；可逆性：低，下游引用后难合并。

**1C. 默认保留 SKU**

材料变化默认只建新物料/BOM，只有商业或合规负责人主动要求时才新 SKU。

收益：身份稳定、操作少；成本：高度依赖人工发现影响；风险：漏掉条码、认证、库存隔离或售后差异；可逆性：低，混货发生后难修复。

## 决定 2：报价关键物料如何成为 BOM

**2A. 证据候选 → 标准物料映射 → 采购 BOM 发布，推荐**

报价保留不可变原始版本；定点后采购执行归并，形成标准物料映射和采购 BOM 版本；定点交接冻结引用及来源。工程 BOM、包装/销售 BOM 继续独立。

收益：保留供应商原话和企业权威，支持换供应商与追溯；成本：增加归并任务、冲突处理和版本发布；风险：处理超时会阻塞依赖 BOM 的动作；可逆性：高，可追加新版本，不覆盖历史。

**2B. 中选报价直接成为采购 BOM**

选中报价时把 `keyMaterials` 原样升格为 BOM。

收益：流程最短；成本：没有标准物料身份和跨供应商归并；风险：供应商名称差异变成重复物料，历史版本仍不可靠；边界：仅适合一次性、无需库存与追溯的采购；可逆性：中低。

**2C. 报价只作成本证据，BOM 另行手工建立**

寻源不做映射，定点照常交接，之后由主数据岗独立建 BOM。

收益：职责最清楚；成本：重复录入、容易脱节；风险：需求、补货和采购可能先消费没有物料结构的 SKU；可逆性：高，但业务链长期有断点。

## 推荐及理由

推荐 **1A + 2A**。它保留此前专项讨论中正确的部分，同时修正两个根本问题：不把物料变化等同于商业身份变化，也不把供应商声明冒充企业 BOM。

## 对岗位与界面的影响

主数据工作台应显示产品/SKU 身份、标准物料、三类 BOM、Listing 及各自缺口，不能再用一个“齐了”覆盖全部。寻源工作台保留供应商原话，并在定点后提供逐项“挂接已有物料 / 新建候选 / 暂无法判断”；发生 SKU 影响时退回主数据队列，不允许寻源岗直接造 SKU。结果区必须显示发布版本、来源报价、未决项和恢复入口。

## 已定事项

1. **双门判定**：新物料/BOM 版本不自动产生新 SKU；只有最终可售单元在库存、销售、履约、售后或合规上不能混用时才新建 SKU。

**核心业务目的**

**结果指标与最低保障指标的区分**

业务结果指标：

- 因主数据身份错误产生的下游纠正或重新绑定率。
- 首次交接可直接使用率，即下游无需重新录入或补绑即可消费。
- 因错误身份而被纠正的采购、库存、出运、合规或 Listing 记录数量及影响金额。
- 从业务候选具备建档条件到下游首次可用的时间，并单列等待原因。

这些指标目前都缺少基线、分母和真实样本，不能宣称已改善。

最低保障指标不是产品成功指标，包括：跨租户访问为零、未授权写入为零、未知值不得静默升级为事实、已发布历史不得覆盖、审计链不断裂、幂等和并发冲突不产生重复身份。

仓库没有证明某条具体法律条文直接要求当前控制面，因此不能编造“法律强制”。适用市场的合规事实仍须由合规责任域确认。

**核心业务目的**

商品主数据治理岗在对象交给寻源使用前，保证下游引用的是正确、无歧义的产品或 SKU 身份，减少错绑、误合并、重复身份及由此产生的交易纠正。

控制面、发布动作和稳定编码只是保障，不是产品目标。

**目标岗位与责任边界**

- 商品主数据治理岗：身份查重、复用或新建、编码、发布、纠错和跨域变更治理。
- 产品岗位：产品家族、型号和变体结论。
- 研发/供应链：物料、可互换性和 BOM 结论。
- 商业运营：SKU 与 Listing 的商业结论。
- 合规岗位：法规属性和适用结论。
- 首个指定下游：寻源岗位。

主数据岗可按已定规则处理常规身份判断；一旦涉及原始业务语义变化，必须退回相应责任岗确认。

**优先损失**

1. 下游引用错误对象或把不同对象错误合并。
2. 同一对象重复建档或错误拆分，导致后续重新绑定和交易纠正。
3. 交接身份不可直接使用，导致寻源重新录入、等待澄清或绕开主数据。

真实备货样本已经证明同名不能代替 SKU、缺失 SKU 不能补造，但尚未证明这些风险在寻源岗位中的实际发生率和金额。

**完成语义**

一次业务结果只有在：

> 寻源岗位首次实际引用已交接身份，并且不需要重新录入、重绑、撤回或重建身份

之后才算完成。

发布成功、页面可用、接口成功、字段落库或状态为 `live` 均不构成完成。

**结果指标**

主要结果指标：

```
身份错误纠正率
= 观察期内首次使用时需要身份纠正的交接数
/ 同期被寻源首次使用的身份交接总数
```

纠正包括错绑、重复、误合并、错误拆分，以及由此发生的重绑、撤回或重建。

配套指标：

- 首次交接可直接使用率。
- 从具备建档条件到寻源首次使用的时间。
- 等待原责任岗确认的时间及原因。
- 错误影响的下游记录数和可核实金额。

发布前发现的重复或歧义作为“被阻止的损失”单列，不计入已发布错误率；不得把主动拦截当成岗位失败。

**最低保障**

不可关闭但不能冒充业务结果的保障包括：

- 租户隔离和服务端授权。
- 来源、责任决定和变更历史可追溯。
- 已发布历史不得被覆盖。
- 未知值不得静默变成事实。
- 幂等、并发冲突和重复身份明确处理。
- 主数据岗不得越权修改原责任域结论。
