**行业对照，不冒充项目规则**

[Stage-Gate 官方模型](https://www.stage-gate.com/blog/the-stage-gate-model-an-overview/)把立项门看成前瞻性的资源投入决定，而不只是资料完整性检查。其商业论证包含客户研究、技术可行性、价值主张、财务评价和风险；决定为 Go、Kill、Hold、Recycle，并同时确认资源、时间和下一决策点。

[Amazon 官方定价页面](https://sell.amazon.com/pricing)的收入计算需要品类、尺寸、重量、价格、配送和费用等输入，并比较 FBA 与自配送。这不能证明 Logix 应采用某个利润率，但能证明“利润可接受”不能只是一句自由文本。

[WIPO Global Brand Database](https://www.wipo.int/en/web/global-brand-database)支持商标、名称、商品服务和图像相似检索，并明确提示还可能需要查国家/地区注册库和咨询专业人员。因此知识产权筛查不能被“合规风险可控”一句话吞掉。

没有一手依据支持现在就硬编码“利润率至少多少、评论至少多少、增长率至少多少”。这些必须按品类、市场、履约模式和公司策略设定，不能由 AI 编造。

**推荐边界**

```
市场信号台：这是不是值得正式评估的可信机会？
选品立项台：是否值得承诺资源，成为一个正式产品项目？
NPI 工作台：能否把已批准项目验证并做成可发布产品？
```

选品不应承担完整供应商定点、详细工程验证或最终认证；但必须有足够的初筛证据，知道这些风险是否可接受、由谁在下一阶段验证。

决策 1，基本作业单位：

## 两台工作台的定位变化

**选品立项台**的定位从"四项填写门槛的审批表"改为"商业论证与投资门工作台"。核心变化有三点：
- **只接收可信机会：** 人工提议、老板指示、供应商推荐，也要先在市场信号台登记成可信机会。
- **数字必须可追溯：** 商业论证按"事实、假设、计算、人员判断"四轨分开，财务用区间和情景，不用一句"利润可接受"。
- **立项必须承诺资源：** 投入决定要写明立项责任人、下一阶段资源、目标日期和下一决策点，不能由点按钮的人自动充当负责人。

**寻源台**的定位从"一个 SKU 选一家供应商"改为"寻源项目 + 独立范围行"。完成点是批准的供应分配方案进入补货或采购的接收队列，并拿到接收回执；下游是否下单不算在寻源的完成条件里。
- 每个范围行一次批准一份完整方案，包括主供、备供或多供、份额、产能和切换条件。
- 关键范围必须有可执行的备供，或有效的风险豁免。
- 报价到期后不能再支持新的定点、增加份额或续期。
- 商业信息按账套主体和寻源项目隔离。

## Codex 没有点明的风险

1. **多项政策依赖处于 `blocked` 的基础任务。**
   - 立项责任人（R1）和寻源的分层责任（9A）需要人员目录和责任人选择机制，而系统里还没有。
   - 按账套主体归属和隔离（12A、14A）依赖 `tenant-account-owner-scope-v1`，该任务 `blocked`。
   - 准备、复核、决定分开的权限（P1、10A）依赖 `authz-default-deny-v1`，该任务也 `blocked`。

   这些政策写进规格没问题，但相关动作在基础任务解阻前无法真正实现。brief 里应把它们标为"受阻的动作"，不能用决策人或租户级权限临时顶替。

2. **"只接收可信机会"（E1）会给市场信号台加需求。** 人工提议要先在市场信号台登记来源，所以市场信号台需要一个人工登记入口。这属于新的跨工作台需求，应由 Claude 另开切片或写进市场信号 brief。它不能塞进我当前未完成的接管修复切片（C-TAKEOVER-FIX）。

3. **寻源的完成点（2A）需要下游接收方。** 补货和采购必须有接收队列，并能给出接收回执。如果下游工作台还没有这个能力，寻源台在业务上永远无法标为 `done`。brief 里需要明确接收方由谁、在哪个切片建设。

4. **存量数据需要迁移或只读策略。** 已有的 `reviewPoints` 自由文本 JSON 和单供应商定点快照，都无法自然映射到新模型，需要先定"历史只读、新版本按新结构"之类的策略。这属于数据迁移，按规则必须独立复审。

5. **范围很大，需要按最小闭环切分。** 两台规格都接近完整产品级。如果不按"一个真实业务步骤的五面最小闭环"切分，容易变成先建平台、后找消费者，这正是 `AGENTS.md` §1.1 禁止的做法。建议选品台第一刀放在"证据真实性校验 + 评审目录进入共享契约"，这两项是纯技术债修复，不依赖任何受阻的基础任务。

6. **结果指标没有基线。** Codex 已经声明不编造目标值，这一点正确。但结果反馈（M1）要能落地，必须先有 NPI 退回和上市结果的数据回流，所以它应排在后期切片。
