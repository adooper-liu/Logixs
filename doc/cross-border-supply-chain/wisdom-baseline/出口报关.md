进入“出口报关工作台”前置决策。本轮只讨论中国境内出口申报到出口放行，不把进口清关、出运执行或统一控制面带入。

**核心业务目的**

候选唯一结果：

> 在适用离港截点前，使本票全部必要出口申报案卷取得范围正确、来源可信的出口放行，并把结果交给出运工作台。

“资料已交报关行”“报关行已接单”“申报已发送”或部分案卷放行，都不能替代该结果。

**目标岗位与关键决定**

推荐目标岗位：内部出口关务/报关运营主责。

外部报关行是受托申报和事实协作方。需要负责人确认最终结果由内部岗位负责，还是直接把外部报关行作为目标岗位。

**优先减少的经营损失**

三类损失可以按每票业务选择偏重，不要求全局固定唯一：

- **放行时效型**：减少迟报、退单、补件、查验处置不及时造成的误船。
- **申报正确型**：减少错报、漏报及实质改单引起的查验、处罚和信用风险。
- **贸易权益型**：减少申报与合同、货物或后续凭证不一致造成的退税、收汇及经营损失。

无论采用哪种偏重，合法、真实申报都是不可关闭的底线，不能为了赶航次降低真实性要求。

**本台与上下游的结果边界**

```
出运计划/订舱
→ 提供货物范围、路线、航次和截点

备货/装箱
→ 提供实际货物、装载及适用单证事实

出口报关工作台
→ 组织申报、协调报关行、处理退单/补件/查验/改单

出运工作台
→ 消费出口放行，完成进港、装船和实际离港
```

- 出口报关台不拥有订舱、提空箱、装箱、装船或实际离港结果。
- 出运台不得自行把“已申报”推断为“已放行”。
- 现有 `customs` 应收窄为目的国进口清关；正式名称仍待后续写回权威。

**结果指标与最低保障指标的区分**

业务结果指标候选：

- 适用截点前全部必要案卷完整放行率。
- 出口报关原因造成的误船率。
- 首次申报取得接受或无需实质更正的比例。
- 实质改单、错报、处罚及退税/收汇异常率。
- 部分放行被误判为整票可出运的比例。

报关行回复时长、资料上传率、任务完成率和审计完整率只是过程或最低保障指标。

**对现有方案的 A/B/C/D/E 分类**

- **A**：组织申报案卷、协同报关行、处理退单/查验并取得全部必要出口放行。
- **B**：防止迟报误船、错报处罚、部分放行误判和贸易权益损失。
- **C**：申报真实性、法定资格、来源可信、租户隔离、授权和审计。
- **D**：全球通用关务规则平台、报关行市场、统一消息控制面。
- **E**：无真实样本支持的自动归类、自动申报、自动改单或风险评分。

**2～3 个业务方案**

1. **内部结果负责、报关行受托协作，推荐**

   内部出口关务岗追踪到全部必要案卷可信放行，并处理代理失败和业务升级。收益是责任连续、能够可靠交给出运台；成本是内部岗位必须掌握案卷范围和异常影响。报关行可替换，业务边界稳定。

2. **外部报关行直接承担工作台结果**

   报关行成为目标岗位，内部人员只验收结果。适合全面外包，但会把工作台变为外部协作产品，并增加外部身份、租户和责任追偿问题。现有样本不足以证明该模式。

3. **内部岗位只负责资料交接**

   内部岗位完成资料齐套和委托，放行由出运台或线下人员追踪。范围最小，但资料交接不等于放行，会重新造成责任悬空，不建议。

**最低保障**

- 未取得海关或可信法定来源结果时，不得显示为放行。
- 多案卷必须逐一判断，不能以部分放行推导整体放行。
- 申报真实性和适用法律要求不能由赶航次、成本或代理效率覆盖。
- 人员判断、报关行回执、海关结果、装船和离港事实必须分开。

**推荐及结果指标**

推荐方案 1，并建议首期以中国境内出口报关为明确法域边界。其他起运国可以继续作为未来候选，不能用中国样本直接泛化全球规则。

真实验证推荐“历史完整链路样本建立基线 + 前瞻试运行”，覆盖正常放行、退单补件、多案卷部分放行、查验、实质改单、未放行临近截点和报关原因误船。

2. 法域范围：`A` 首期只锁定中国境内出口报关（推荐），或 `B` 从首期覆盖所有起运国。

**核心业务目的**

无论采用哪种责任模式，都必须在适用离港截点前，使本票全部必要出口申报案卷取得可信放行，并把结果交给出运台。

**目标岗位与关键决定**

三种模式对应不同岗位：

- **内部结果负责**：内部出口关务/报关运营是结果责任人，报关行受托执行。
- **报关行直接负责**：获授权报关行是执行和结果责任人；内部仍须有明确的结果接收及异常升级岗位。
- **内部只负责资料交接**：内部单证/关务协调岗只对资料交付负责。

这里有一项不可省略的边界：第三种只是局部岗位的交接完成条件，不是整个出口报关工作台的最终完成条件。资料交出后，必须明确由内部结果责任人或报关行继续负责到出口放行；否则责任悬空，不能称为完整业务模式。

**优先减少的损失**

三种责任模式都需要减少：

- 迟报、退单、补件或查验处置不及时造成的误船。
- 错报、漏报及实质改单造成的处罚、信用和贸易权益损失。
- 多案卷部分放行被误认为整体放行造成的违规出运或现场滞留。

不同模式只能改变责任承接方式，不能降低申报真实性和完整放行要求。

**已证实事实**

样本证明同一出运业务可能有多票出口报关单分别放行。报关资料已发送、报关行已接收、海关已放行和货柜已离港是四种不同事实。

因此三种模式可以并存，但必须始终知道当前案卷的最终放行责任人是谁。

**本台与上下游的结果边界**

- 上游提供真实货物、交易、装载、航次和截点事实。
- 资料协调岗位可以完成交接，但不能把交接完成标记为海关放行。
- 当前结果责任人负责退单、补件、改单、查验及放行追踪。
- 出运台只消费可信出口放行，不接管报关专业动作。
- 责任模式发生变化时，未完成案卷必须有明确接收方；不能因更换报关行或内部责任人而丢失责任。

**结果指标**

所有模式共用：

- 截点前全部必要案卷完整放行率。
- 出口报关原因误船率。
- 实质改单、错报、处罚和贸易权益异常率。
- 部分放行误判率。
- 责任交接后无人继续处理的案卷比例。

还应按责任模式分别观察放行兑现和失败归因，但不能以报关行回复速度替代放行结果。

**A/B/C/D/E 分类**

- **A**：明确结果责任人、完成必要申报案卷并取得出口放行。
- **B**：防止责任悬空、迟报误船、错报及部分放行误判。
- **C**：法定资格、申报真实性、来源可信、责任交接、租户隔离和审计。
- **D**：通用代理管理、全球关务平台和跨法域统一规则。
- **E**：默认把资料交付视为完成，或在没有接收人的情况下允许退出。

**推荐及不成立条件**

推荐允许三种模式并存，但设置共同业务不变量：

若第三种模式无法指出交接后的责任主体，它只能作为过程步骤，不能作为工作台责任模式。

   便于统一排队，但可能诱导业务为了赶航次压缩必要核验，不适合作为全球政策。

3. **全局固定申报正确与贸易权益优先**

   风险更保守，但可能对低风险、强时效业务造成不必要延误。

**最低保障**

任何偏重都不能让系统、内部人员或报关行以赶航次、降低成本为由绕过真实申报、当地资格或可信海关结果。

**推荐及结果指标**

推荐方案 1。前瞻试运行应覆盖三类偏重，并分别证明误船、实质申报错误和贸易权益异常是否下降，而不是只证明案件处理更规范。

**请负责人定案**

请确认优先损失采用：

- `1` 三类损失按法域和业务场景选择偏重（推荐）；
- `2` 全局固定放行时效优先；
- `3` 全局固定申报正确与贸易权益优先。



确认：三种都是出口报关工作台可采用的经营策略，不设全局唯一默认。

- 在特定经营范围内统一采用放行时效优先。
- 在特定经营范围内统一采用申报正确与贸易权益优先。

策略只能改变队列和资源投入，不能改变合法、真实申报这一最低线。

**出口报关工作台决策输入摘要**

- **目标岗位**：出口关务结果责任岗。可由内部出口关务人员或获授权报关行承担；内部资料协调岗可以参与，但资料交接不是最终结果。
- **核心业务目的**：在已启用的起运法域，于适用离港截点前，使本票全部必要出口申报案卷取得范围正确、来源可信的出口放行，并交给出运工作台。
- **最终完成条件**：全部必要案卷已可信放行。资料齐套、已委托、报关行接单、申报发送或部分案卷放行均不代表完成。

**优先损失与可选策略**

三类损失：

- 放行延误造成误船、改船及港前损失。
- 错报、漏报、实质改单造成查验、处罚和信用损失。
- 申报不一致造成退税、收汇及其他贸易权益损失。

可选经营策略：

1. 按法域和业务场景动态选择偏重。
2. 在指定经营范围内固定放行时效优先。
3. 在指定经营范围内固定申报正确与贸易权益优先。

即使采用时效优先，也不得突破申报真实性、法定资格和当地法律要求。

**责任承接模式**

三种模式均可按业务场景采用：

- 内部关务对放行结果负责，报关行受托执行。
- 获授权报关行直接承担放行结果责任，内部保留明确的接收和异常升级岗位。
- 内部岗位只负责资料交接，但交接后必须存在明确的放行结果责任主体。

任何未完成案卷在任一时点都必须有唯一、明确的结果责任主体。第三种模式若没有后续接收人，只能算局部步骤，不能算工作台完成。

**法域范围**

- 任何起运国均可申请启用。
- 每个法域必须分别核对当地依据、责任资格、放行含义和真实样本。
- 完成逐国验证后才能正式使用。
- 当前只有中国出口脱敏样本，不能据此声称其他法域已经可用。
- 某一法域未验证只阻断该法域，不应阻断其他已验证法域。

**上下游边界**

- 出运计划和订舱提供路线、航次、截点及经营约束。
- 备货和装箱提供真实货物、装载及适用单证事实。
- 出口报关台负责申报、退单补件、改单、查验和出口放行。
- 出运台只消费可信出口放行，并负责进港、装船和实际离港。
- 出口放行不等于装船或离港。
- 现有 `customs` 是否正式更名并收窄为“进口清关工作台”仍待权威写回时定案。

**结果指标**

- 适用截点前全部必要案卷完整放行率。
- 出口报关原因造成的误船率。
- 首次申报无需实质更正的比例。
- 实质改单、错报、处罚及信用异常率。
- 退税、收汇或贸易权益异常率。
- 部分放行被误判为整体放行的比例。
- 责任交接后无人继续处理的案卷比例。

指标必须按法域、责任承接模式和经营策略分层观察。报关行回复时间、资料上传率和任务完成率不能替代结果指标。

**A/B/C/D/E 分类**

- **A**：组织必要申报案卷、处理异常并取得完整出口放行。
- **B**：防止报关原因误船、错报处罚、部分放行误判和贸易权益损失。
- **C**：当地法定资格、真实申报、可信海关结果、责任连续、租户隔离和审计。
- **D**：全球通用关务规则平台、通用代理管理和跨法域自动策略引擎，延期。
- **E**：未经逐国验证即默认启用、套用中国规则、自动归类或把资料交接视为完成。

## 已核实的事实

- **契约里没有出口放行的节点。** `lifecycle-nodes.json` 只有一个清关节点 `customs_clearance`，属于离港后的进口；canonical 事件里也只有 `customs_filed`。所以"出运只接收可信出口放行"目前在契约中没有承载。要新增节点或事件属于公共契约变更，需要契约独占锁和独立复审，不能由页面或某台工作台先自己发明一个状态。
- **样本边界和 Codex 说的一致。** 样本 007 和 012 都是中国出口，状态都是"待业务确认"。它们只能用来启动中国这一个法域的验证。

## 需要 Claude 处理的问题

1. **"内部只负责资料交接"不应该和另外两种并列为模式。** 对话自己也承认，它必须再交给一个明确的放行责任人，否则只是一个过程步骤。真正的责任承接模式只有两种：内部负责，或报关行负责。资料交接是这两种模式里都可能出现的交接步骤。如果写进权威时仍写成"三种模式"，就会出现"资料交完就算这一模式完成"的误读。

2. **"报关行直接负责"的首片做不了。** 这种模式下，外部报关行就是工作台的使用者，需要外部身份、报关行级别的对象范围和账户恢复。这和备货的供应商门户、装箱的外部现场负责人是同一个前置条件，而授权默认拒绝和租户范围两个任务目前都处于阻塞状态。首片只能是"内部负责"，报关行通过内部人员代录回执，或通过文件导入协作。

3. **两层"全部保留"都还没有选择规则。** 负责人已经把"策略和模式的选择及切换规则"列为未知。各台在这方面的形态现在已经出现分歧：

   | 工作台   | 策略怎么选                           |
   | -------- | ------------------------------------ |
   | 进口清关 | 经办人逐案选，没有默认               |
   | 出口报关 | 按法域和场景选，或者在某个范围内固定 |
   | 排柜调度 | 按场景设治理模式                     |

   进口和出口报关的岗位可能是同一批关务人员，两套选择规则会让同一个人在两台上的操作口径不同。这进一步说明需要我上次建议的"策略机制参考实现"，并且应该先在两台关务工作台之间统一。

4. **同一个经营意图被选了三次。** 出运计划选一次策略，订舱取舍再定一次，出口报关偏重又选一次，比如时效优先对应保航次。这三者应该是 Shipment 层面的同一个经营意图逐级传下来，而不是每台各自重新选。这是跨台事项"经营意图传递"的第三次出现。

5. **贸易权益损失发生在本台结果之后。** 这一条是行业候选，仓库里没有核实，需要中国样本确认。按我对中国出口实务的了解：
   - 报关单"放行"之后，还要经过装船、舱单核销，才算"结关"；
   - 出口退税依赖结关之后的电子数据；
   - 离港后，舱单和报关单不一致也可能需要改单。

   如果是这样，本台以"放行交给出运"结束，而退税和收汇异常要在离港后很久才显现。这就需要定两件事：贸易权益指标的观察窗口比本台结果更长；离港后的改单由谁负责，是本台延续负责，还是另外的责任方。

6. **"逐国申请启用"没有指定批准人。** 法域准入需要确认当地依据、责任资格、放行含义和样本，这是一个业务准入决定，但对话没有说谁有权批准某个国家"可正式使用"。另外，写回时应明确：首个启用法域是中国，目前待验证，不能写成"首期已覆盖所有起运国"。

7. **现有 `customs` 收窄并更名，属于和"20 台改 22 台"同一组的治理变更。** 改名会影响路由 `/workspaces/customs`、工作台代码、能力码和已完成的 brief 引用，应和扩台一起用仓库治理锁串行处理，不能单独改。
