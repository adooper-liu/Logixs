## 核心业务目的

当前权威只确定了业务位置：本台位于采购履约与出运计划之间，把生产、验货和整改事实转成可供出运计划使用的供给批次；它不是统一控制面。

**建议候选目的**：让供应履约负责人尽早、准确地确认“哪一批、多少数量、在什么时间窗内能够真实进入出运计划”，同时避免未完成质量或合规放行的货物被当成可用供给。

这仍需负责人定案，不能由现有页面反推。权威目前仅把本台列为“待逐台复审”：[08-role-workbenches.md (line 152)](/D:/Logixs/doc/cross-border-supply-chain/08-role-workbenches.md:152)。

## 目标岗位与关键决定

**关键业务时点**：采购订单和供应商书面承诺已经形成，生产开始至出运计划冻结前持续判断；生产、验货或整改出现偏差时立即重判。

**唯一核心结果候选**：形成一批“数量和兑现时间可信、质量与市场限制明确、能够被出运计划正确使用”的可出运供给；条件不足时明确阻断或降低可用数量，而不是制造“已就绪”。

## 优先减少的 1～3 类经营损失

建议按以下顺序锁定，当前均是**待真实样本证明的候选**：

1. **缺货与销售损失**：生产延期、短装或验货失败发现过晚，使目标市场发生断货、错过活动或延迟上架。
2. **无效物流投入**：不可靠的“可出运”判断导致舱位、集货、拼柜或出运计划冻结后取消、改配、加急和重复操作。
3. **质量逃逸损失**：不合格批次被释放后产生退货、退款、客诉、保修、召回或库存处置。

## 损失形成机制与现有证据

- **已证实项目事实**：采购订单只是商业承诺，不等于货物可出运；生产完成、检验通过、包装完整和目标市场合规是不同事实：[01-authoritative-business-chain.md (line 103)](/D:/Logixs/doc/cross-border-supply-chain/01-authoritative-business-chain.md:103)。

- **当前实现差距**：本台只有框架页面，没有专用 task brief、API、公共契约、供给批次 Schema 或生产验货结果模型。现有 Schema 只有产品级检验要求和备货行“是否需要商检”：[schema.prisma (line 524)](/D:/Logixs/database/schema.prisma:524)、[schema.prisma (line 1094)](/D:/Logixs/database/schema.prisma:1094)。

## 本台与上下游的结果边界

- **采购履约**：拥有采购订单、供应商书面承诺、商业条款、承诺变更和供应商履约偏差。
- **本台候选责任**：接收承诺，核对实际生产、检验和整改兑现情况，确认可用数量与时间窗，形成或更正可出运供给。
- **出运计划**：拥有国家、渠道、仓库、港口、整柜/拼柜选择及未来供给预占；不得反写生产或质量事实。
- **备货工作台**：执行已批准计划下的备货，不负责把未释放供给变成可用供给。
- 产品质量标准、法定检验要求和例外批准归谁，目前没有完整岗位权威，不能由本台默认吞并。

## 结果指标与最低保障指标的区分

**经营结果指标候选**

- 因生产、短装或验货未兑现造成的缺货天数、错失销量或活动损失。
- 出运计划冻结后因供给就绪判断错误造成的改配、退订、加急和额外物流成本。
- 已释放批次产生的退货、退款、客诉、保修或召回成本。
- 准时足量形成可出运供给的比例、风险首次暴露到下游完成调整的时间，只作领先指标，不能单独证明经营损失下降。

**最低保障指标**

- 未经可追溯质检结论或明确例外放行而正式释放：目标为零。
- 未满足目标市场强制要求而释放：目标为零。
- 跨租户、无授权释放、超量重复分配或计划覆盖实际事实：目标为零。
- 这些是底线，不是本台成功指标。

## 2～3 个互斥的业务聚焦方案

**A. 可用供给兑现，推荐**

目标岗位是供应履约协调负责人；核心结果是按真实数量和时间窗形成可出运供给。优先减少缺货和错误物流投入，质量逃逸作为制衡损失。最符合已确认的供给池定位。成本是必须打通生产、质量和下游损失样本；风险是质量职责可能被弱化，因此质量结论必须由权威岗位提供。边界清楚，可通过调整指标权重回退。

**B. 质量放行中心**

目标岗位是质量放行负责人；核心结果是阻止不合格批次出运并尽快释放合格批次。最直接减少退货、客诉和召回。成本是需要完整检验标准、抽样依据和质量组织责任；风险是生产延期、短装和出运计划损失无人统筹，也可能与产品质量治理重叠。适合真实数据证明质量逃逸为最大损失时采用，可逆。

**C. 生产按期兑现中心**

目标岗位是生产跟单负责人；核心结果是更早发现延期、短装和整改风险。实施范围最窄，可能最快减少等待和加急。风险是只形成进度看板，最终“多少货可以进入出运计划”仍无人负责，质量逃逸也可能悬空。只适合真实证据表明延期远高于质量和计划误投损失时采用，可逆。

## 推荐方案及不成立条件

推荐 **A**。理由是现行业务权威已把本台输出定义为供出运计划消费的供给批次，而不是检验报告或生产进度本身。

A 在以下情况下不成立：

- 真实样本显示退货、召回和质量事故损失显著高于缺货及计划扰动，应改选 B。
- 企业已有独立质量放行闭环，且本台主要问题只是生产延期，应收窄为 C。
- 生产、检验和下游损失无法按批次关联时，先做事实调查，不能宣称方案 A 已被验证。

反事实二：即使权限、状态、证据和控制面全部完美，只要缺货、错误物流投入和质量损失没有下降，本台就不算成功。

## 精简决策输入摘要

**核心业务目的**

让生产交付/供应履约协调负责人，把采购承诺转成数量、时间窗和限制条件可信的可出运供给，使出运计划能提前规划，但不把未完成质量或合规放行的货物冒充可用供给。

**唯一核心业务结果**

对每个适用供给批次确认“何时有多少货可以真实进入出运计划”；发生延期、短装、验货失败或整改未完成时，及时修正可用供给并交代下游影响。

**优先损失**

1. 生产、短装或验货偏差发现过晚造成的缺货、错失销量或活动窗口损失。
2. 错误就绪判断造成的计划冻结后改配、退订、加急和额外物流成本。
3. 不合格批次被释放后产生的退货、退款、客诉、保修、召回和库存处置损失。

**上下游边界**

- 采购履约拥有采购订单、供应商书面承诺、商业条款及其变更。
- 质量岗位拥有验货、复验和例外放行结论；本台不得改写结论。
- 本台拥有可出运数量、可信时间窗、当前限制和供给交接结果。
- 出运计划拥有国家、渠道、仓库、港口、整柜/拼柜方案及未来供给预占。
- 备货岗位执行已批准计划，不负责把未释放供给变成可用供给。

**结果指标**

- 由生产、短装、验货或整改偏差造成的缺货天数、未满足需求数量；只有存在可靠需求与利润依据时才折算错失销售或贡献利润。
- 因供给就绪判断错误产生的计划变更次数及可核验的退订、改配、加急和额外物流成本。
- 与已释放批次可追溯关联的退货、退款、客诉、保修、召回和处置数量或成本。
- 准时足量释放率、偏差首次出现到暴露的时间、暴露到下游调整完成的时间仅作领先诊断指标。

**验证与归因政策**

- 使用同一口径建立近期历史基线，并对后续适用批次进行前瞻试点。
- 只有能够证明“采购承诺 → 生产/验货偏差 → 供给判断或更正 → 下游损失”的批次才计入归因结果。
- 因果不明的损失标记为未知，不由人员或 AI 强行归因。
- 前后业务环境不一致时按 SKU、市场、供应商或业务窗口分层，不能直接汇总制造改善结论。

**已定事项**

- `A`：以可用供给兑现为业务聚焦。
- `M1`：经营损失指标与领先诊断指标并用。
- `S3`：历史基线与前瞻试点结合。
- `C1`：采用批次级因果链归因。

- 各产品和市场适用的法定检验、认证及放行要求。

**最低保障**

未经可追溯质量结论或明确例外、未满足目标市场强制要求、越权或跨租户、超量重复分配的正式释放均不允许发生。计划、预测和口头承诺不得覆盖实际生产、检验或数量事实。

**真实样本要求**

历史基线和前瞻试点均应覆盖：正常兑现、生产延期、短装、验货失败、整改复验、例外放行、计划冻结后变更，以及释放后发生客诉或退货。每个样本需能核对采购承诺、批次事实、验货与整改依据、供给判断、下游计划变化和最终损失；缺少任一环节时只作为未知或局部证据。

**主要风险**

最大的风险不是控制不足，而是没有完整因果数据却宣称降低了缺货、物流或质量损失。其次是本台越权替质量岗位放行，或把出运计划的分仓组柜责任吸收到本台。

该摘要是给 Claude 的只读决策输入，不是项目权威。Claude 仍需正式澄清指标口径，将结论写回现有业务权威和 task brief，并按高风险业务政策要求组织独立复审。Codex 到此退出，不修改代码、文档、brief、状态、Git 或 PR。



这一台的推进顺序也是规范的：先锁定目的、岗位、三类损失、指标口径，再定验证和归因政策，没有提前设计字段、状态或界面，Codex 输出的结论和现行权威也一致。

最大的悬空点在质量这一侧。本台把验货、复验和例外放行结论都划给"质量岗位"，但 20 台工作台里没有质量工作台，这些结论由谁、在哪里产出，目前没有着落。

## 有效口径

| 维度            | 结论                                                         |
| --------------- | ------------------------------------------------------------ |
| 目标岗位        | 生产交付/供应履约协调负责人                                  |
| 唯一结果        | 对每个供给批次确认"何时有多少货能真实进入出运计划"；出现偏差时及时修正，并说明对下游的影响 |
| 损失顺序        | 缺货与错失销售 → 错误就绪判断造成的计划变更和物流投入 → 质量逃逸 |
| 指标（M1）      | 经营损失指标为主，准时率、暴露时长等只作领先诊断             |
| 验证（S3 + C1） | 历史基线加前瞻试点；只统计能沿批次因果链证明的损失，证明不了的标记为未知 |

我核实了现行权威，和这一口径一致。ADR-013 第 15 行规定：质检未完成的供给可以参与出运预排，但不能正式释放备货；出运计划可以预占未来供给，但必须显示未满足的条件和风险。本台"不把未放行货物冒充可用供给"的底线就是从这里来的。

## 需要 Claude 解决的问题

1. **质量结论没有归属的工作台。**
   - `08-role-workbenches.md` 第 136 行列出的工作台里，只有"生产验货与可出运供给"这一台，没有独立的质量工作台。
   - 质量相关的规格只出现在 NPI 的 PVT 和 MP 段（第 236～257 行），管的是新品验证，不管日常量产批次的验货放行。

   所以"质量岗位提供验货、复验或例外放行结论，本台不改写"成立的前提，是有一个地方能产出这些结论。可选的承载方式有三种，需要 Claude 带给负责人定案：
   - 质量岗位作为协作岗位，在本台内录入结论，但能力上与本岗分离；
   - 接入外部检验或质量系统，按采信链接收结论；
   - 新增一台质量工作台，但这会突破 20 台的既定范围。

   NPI 已经定下"外部结果采信链"（E1，目前降为候选），本台接收验货报告的需求与它高度同构，可以考虑复用。

2. **质量逃逸损失的归因要分清责任环节。** 第三类损失计入本台，但如果是质量岗位作了错误的放行结论，损失应归给质量环节，而不是本台。C1 的因果链需要区分两种情况：本台把未放行的货当成了可用供给，属于本台；质量结论本身错了，不属于本台。否则这一项指标会把别人的错误记到本岗名下。

3. **"预排、预占"和"正式释放"必须是两层事实。** ADR-013 允许出运计划预占未来供给，而本台的核心结果是确认"真实可进入出运计划"的数量。摘要里没有说清，本台是只交"正式可释放"的供给，还是也交"可预排的未来供给及其未满足条件"。按 ADR-013 第 20～21 行，两者都应交给出运计划，并且要分别追踪预占、正式分配、备货、装箱和实际出运的数量。这一层要写清，否则出运计划要么看不到未来供给，要么把它误当成已就绪。

4. **上游交接仍未闭合。** 采购台交来的是版本化书面承诺，本台要接收它，并且在承诺变更时得到通知。采购台规定商业重新协商留在采购，本台只能"请求采购重新协商"，这一点两边一致。但"本台确认接收承诺"这个动作，两边都没设计，和前面几台的交接缺口是同一个问题。

5. **历史基线的可行性存疑。** 仓库里的脱敏样本有 15 条产品行，其中 5 条需要商检，但没有验货结果、整改、复验、放行或损失记录。S3 要求历史数据能连起采购承诺、批次、验货、计划变化和损失这条链，而摘要里"历史记录能否可靠连接"一项本身就是未知。如果连不上，S3 会实际退化成只有前瞻试点（S2）。这一点建议在 brief 里写成明确的降级条件。

6. **Codex 提到的 `doc/三体一面.md` 不存在。** 我确认当前检出里没有这个文件。如果你本地有这份未保存或未提交的文档，而且它是业务权威，需要先纳入仓库，Claude 才能引用。
