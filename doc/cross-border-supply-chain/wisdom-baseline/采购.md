## 当前损失形成机制

权威文档支持的因果链是：

```
补货需求获批 → 订单发出但未书面确认 → 计划误认为已有供给 → 偏差发现过晚 → 加急、缺货或库存损失
```

另外两条风险链是：

```
多需求合单但来源分摊丢失 → 供应不足时无法正确取舍
口头承诺或新预测覆盖旧承诺 → 无法判断谁在何时改变了什么 → 责任和损失无法归因
```

这些是已证实的设计风险，不是已经量化的企业损失事实。

## 行业候选与项目边界

- [GS1 Order Response 3.7.1](https://www.gs1.org/standards/edi-xml/xml-order-response/3-7-1)把 Order Response 定义为供应商对买方订单的响应，支持项目把“订单已发出”和“供应商已接受”分开；它不替项目决定确认时限、允许差异或岗位责任。
- [ICC Incoterms](https://iccwbo.org/business-solutions/incoterms-rules/)用于澄清交货中的任务、成本和风险；它不能证明供应商已经生产、检验或具备可出运条件。
- [ASCM SCOR](https://www.ascm.org/corporate-solutions/standards-tools/scor-ds/)把采购、订购及交付安排纳入 Source，并强调可靠性、响应性和韧性度量；其范围比本工作台更宽，不能直接决定本项目的损失优先级。

## 当前损失形成机制

统一使用一种策略会产生三种典型错误：

- 全部追求可靠性：可能接受过高成本或过多安全余量。
- 全部追求成本：可能为了低价和 MOQ 牺牲交期、库存健康度。
- 全部追求速度：可能仓促接受不完整、不可兑现或成本失控的承诺。

因此，工作台不能用一个全局排序抹平产品差异，但仍需防止采购人员每次临时选择最方便的策略。

- 采购订单、供应商承诺、生产完成、检验通过和可出运供给是不同事实。
- 口头反馈只是信号，可追溯的书面确认才构成承诺。
- 当前采购履约只有框架页，没有采购领域模型、公共承诺契约、专属 API 或业务路径测试。
- 当前没有能够量化三类损失的真实采购样本。
- 本轮聊天决定尚不是项目权威，必须由 Claude 写回现有 `doc/`、ADR 和采购履约 task brief。

## 当前损失形成机制

- 用统一策略处理所有产品，会抹平产品阶段和经营损失差异。
- 无依据自由选择策略，会产生事后合理化和指标漂移。
- 采购自行切换策略，会让谈判结果反向改变原经营目标。
- 采购承诺与生产、检验事实混合，会造成责任重叠和虚假可用供给。

## 行业候选与项目边界

GS1 Order Response、ICC Incoterms 和 ASCM SCOR支持订单响应、交付责任及可靠性/响应性/资产效率分轨，但不替项目决定产品策略、权重和岗位边界。

当前不设评分权重、损失阈值、自动选择或统一产品分类表。

## 2～3 个业务方案

- **已选：分层场景选择。** 生命周期作背景，最大损失决定本次策略，成熟数据评分辅助，产品经营责任方最终确认。
- **未选：完全自由选择。** 灵活但无法保证一致性和可复盘性。
- **延期：系统自动组合。** 等真实样本足以校准权重和阈值后再评估。

## 最低保障

- 产品经营责任方确定默认策略，并确认每项获批采购需求的本次策略。
- 采购只能提出策略调整并负责重新协商，不能自行切换。
- 每次只能有一个首要策略，其他两类损失仍作为约束和观测指标。
- 策略选择必须发生在接受供应商最终条件前，并保留当时依据。
- 商业重新协商留在采购；生产、检验和可出运事实归下一台。
- 质量、合规、供应商资格和事实真实性不可被任何策略牺牲。
- AI只能建议，不能选择策略、下单或接受供应商差异。

## 推荐及结果指标

共同指标：

- 有效书面承诺覆盖率。
- 需求获批至有效确认的 P50/P90 周期。
- 首次确认通过率。
- 未解决承诺偏差及其风险数量、金额和窗口。
- 采购原因造成的错失窗口、短采、超采、取消和应急费用。

策略指标：

- A：数量和日期兑现、偏差发现提前量、窗口损失。
- B：采购成本偏差、MOQ 超采、现金占用和后续积压。
- C：下单确认周期、错过最晚下单日比例、快速采购返工和溢价。

## 精简决策输入摘要

- **目标岗位**：采购计划与订单履约负责人。
- **核心结果**：按产品经营场景选择策略，形成可信书面承诺并处置承诺偏差。
- **优先损失**：A可靠性、B成本与现金、C响应速度；每次确定一个首要目标。
- **选择顺序**：生命周期背景 → 最大可避免损失 → 成熟数据评分辅助 → 产品经营责任方确认。
- **上下游边界**：上游交付获批采购需求及本次策略；本台交出版本化书面承诺。商业重新协商留在采购，生产、检验和可出运事实归下一台。
- **已定事项**：产品默认策略加单次受控调整；采购只能提议调整；禁止无依据自由选择和静默默认。
- **未知事项**：实际损失基线、评分权重、阈值、复审周期及具体产品分类。
- **主要风险**：事后更换策略、采购自行改变经营目标、三项目标同时最高、承诺冒充实际供给。
- **真实样本要求**：A、B、C 各至少一个真实或脱敏产品案例；样本整体覆盖正常、等待、拒绝、冲突、返工和恢复，并包含至少一个策略调整被接受或拒绝的案例。

## 需要 Claude 解决的问题

1. **策略选择和补货决策重叠。**
   - 补货台已定：先过滤硬约束，再按版本化政策对候选方案排序，比较的正是缺货、库存、利润、现金、时效和风险（ADR-012 第 20 行）。补货批准的结果，本身已经包含"重服务还是重现金"的取舍。
   - 采购台又让产品经营责任方对每项获批需求再选一次 A/B/C，取舍的还是同一组维度。

   如果两边各决定一次，就可能出现补货按现金优先批准、采购却按可靠性执行的情况，两者没有对齐规则。建议 Claude 给负责人一组选项：
   - 采购策略作为补货批准决定的一部分，随执行需求交接，采购只消费、不重选；
   - 或者明确两者分工：补货决定"要不要买、买多少、何时要"，采购策略只决定"怎样向供应商取得承诺"。

   在没有定案之前，"上游交付获批采购需求及本次策略"里的"上游"指谁也不清楚。

2. **"产品经营责任方"是新角色。**
   - 选品有立项责任人，NPI 有结果负责人和资源负责人，主数据把商业结论交给商业运营，补货由计划人员决策。
   - 采购这里新出现的"产品经营责任方"，要确定它对应其中哪一个，还是一个新岗位。否则"谁确认本次策略"会悬空，策略选择就会实际落回采购手里，而这正是本台明确禁止的。

3. **B 策略可能越过寻源的边界。**
   - 现行权威（`03-sourcing-and-replenishment-workbenches.md` 第 133 行）规定，采购方案必须存在有效供应关系。价格、MOQ、份额由寻源定点决定。
   - B 策略要减少"采购溢价"，如果意思是采购在单次订单里另行议价，或者绕开既有供应关系找更便宜的供应商，就进入了寻源的定点职责。

   建议写明：B 策略只能在有效供应关系的条款范围内做取舍，比如批量、时点、拆单；条款本身要变，必须退回寻源。

4. **C 策略的损失可能不在采购手里。**"内部等待、下单延误"有相当一部分发生在补货审批或双人复核阶段，不完全由采购造成。按"每类损失要归因到负责环节"的原则，C 策略的指标需要区分采购自身的等待和上游审批的等待。
