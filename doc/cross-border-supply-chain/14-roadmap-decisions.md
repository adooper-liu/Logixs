# 路线图与业务决策

> 状态分类：业务方向、治理规则和路线顺序已经确认；阶段日期可按资源调整，但不得改变已确认业务边界。合同、参数和外部接口样本属于实施输入。

## 一、已经明确的业务方向

1. 当前从真实已出运货柜导入开始，重点管理出运后生命周期。
2. 四类表是最小来源字段集，不是未来系统的四张业务表。
3. 导入时分别形成备货、装载、货柜、清关、运输和仓库等业务信息。
4. 未来正常流程与当前导入使用同一条业务链。
5. 无SKU允许建档并进入待补全。
6. 物料不等于SKU，两者采用灵活、可靠、可追溯的关系。
7. 外部信息先核验，计划、预计和实际分开。
8. 三方堆场纳入提送卸还的资源和成本决策。
9. AI是合规和运营的重要助手，但不能混淆建议、决定和事实。

以上决定已分别记录到[业务ADR目录](../adr/README.md)。`accepted-business`只代表业务方向确认，技术实现仍需通过任务简报、正式契约、迁移和测试完成。

## 二、为什么按这个顺序建设

路线图遵循“先可信事实，再岗位闭环，再外部协作和优化，最后向上游延伸”。如果身份、日期、证据和岗位结果还不稳定，就先做AI、甘特优化或大量外部接口，只会更快传播错误数据；如果先把采购和计划全部铺开，又无法利用当前真实货柜验证下游模型，建设周期和返工风险都会增加。

每个阶段必须交付可被岗位使用的业务结果，而不是只完成数据库、接口或页面。下一阶段建立在上一阶段真实运行数据之上，同时允许后续发现问题时修正规则，而不是推倒重建。

## 三、近期：巩固当前业务链

- 已完成20个真实货柜、4张维护表和10张详情表的结构与业务切片复核；下一步取得原系统字段字典，确认乱码表头和歧义字段，并形成可执行映射。
- 建立缺失、冲突、待补全和人工认领队列。
- 按岗位流程建设并验收装箱、出运、海运、清关、提柜、送仓、卸柜和还箱工作台。
- 建设费用与结算工作台，补齐计费、账单、分摊、争议、支付和关账。

完成标志：四类文件能够可靠导入并对账；Shipment、货柜、装载和日期事实可追溯；各岗位能从已出运货柜继续处理到还箱；缺失和冲突不会被静默默认。

## 四、中期：资源协同和合规深化

- 车队、车辆、司机、预约和移动端。
- 仓库月台、班组、容量和三方堆场。
- 甘特排程、计划版本和可解释优化。
- 法规来源库、HS Code、ISF、证书和报关行门户。
- AI辅助抽取、评审和风险排序。

完成标志：清关、车队、仓库和堆场能够通过受控任务协作；调度可以比较成本和风险并发布版本化计划；合规结论可以回到法规、证据和责任人。

## 五、中期：外部数据直连

- 统一供应商能力和配置管理。
- 优先船司、港口、码头、飞驼和云当联调。
- DCSA标准版本和一致性测试。
- 推送、增量同步、对账、降级和监控。

完成标志：至少一个真实来源通过统一连接器稳定运行；重复、乱序、更正和中断可恢复；工作台能够解释采用了哪个来源以及对计划的影响。

## 六、后期：向上游延伸

- 产品、物料、SKU、渠道商品和进化图谱。
- 采购和出运计划。
- 供应商备货协作。
- 完整装箱、VGM和订舱衔接。

完成标志：批准需求可以追到采购、供给、出运分仓、备货和实际装箱；正常流程与历史导入生成相同下游业务对象；不再依靠重复录入交接。

## 七、收敛决策与实施输入

Shipment拆分合并、主数据责任、AI权限、排柜优先级、伙伴最小可见范围和外部接入顺序已经收敛，以00号总览、12号确认规则及对应业务ADR执行，不再作为开放业务问题。

以下内容必须在实施或上线前取得，但它们是参数、合同或验证证据，不是业务设计缺口：

- 原系统字段字典、乱码表头解释及20柜以外的边界样本。
- 各国家、渠道和产品类别的法规原文、适用参数及合规负责人批准记录。
- 三方堆场、车队、仓库和报关行的合同责任、资源日历、费率与服务范围。

缺少实施输入时，相应连接、法域、伙伴或费率不得启用；系统进入配置待办或人工复核，不得用静默默认值补齐。

#### 开发前必须分析

##### 1. Shipment出运聚合

这是当前最重要的未决项。

需要确定：

- 什么构成“一次出运”；
- Shipment业务编号由谁生成；
- 一个Shipment与多个柜、提单、备货单的关系；
- 甩柜、改船、分批出运如何拆分；
- MBL、HBL、Booking和Shipment的基数；
- 出运级路线与柜级路线如何分工；
- 哪些字段属于Shipment，哪些属于Container；
- 出运关闭和重新打开的规则。

没有这个聚合，四表导入、工作台和后续接口都会继续围绕备货单或柜号拼接。

##### 2. 四表字段权威与完整映射

需要形成逐字段正式清单：

```text
来源表/列
-> 标准字段code
-> 目标对象
-> 数据类型
-> 计划/预计/实际语义
-> 来源权威
-> 必填阶段
-> 冲突处理
-> 是否进入生命周期事件
```

特别需要解决：

- `销往国家`实际是公司名称；
- `ETA修正`存在异常对象字符串；
- 出运日期和母船出运日期的区别；
- 提单号、MBL、HBL、AMS的关系；
- 箱数究竟表示包装件数还是柜数；
- 议付金额、FOB、CIF和海运费的币种及计算关系；
- 重复字段以哪张表为权威；
- 空值、不适用、未知如何区分。

##### 3. 联合导入产品设计

需要完整定义：

- 四文件如何组成一个批次；
- 文件缺失是否允许继续；
- 表类型如何识别；
- 跨表关联键；
- 一单多柜、一柜多单和一票多柜归组；
- 预检、人工复核、执行和对账页面；
- 部分成功策略；
- 重复导入；
- 新版本替代旧批次；
- 原始文件留存；
- 失败恢复；
- 当前文件导入和未来装箱平台交接如何共用接口。

##### 4. 已出运准入与生命周期起点

需要明确：

- `loaded`还是`departed`作为正式起点；
- 只有出运日期、没有具体时间时如何处理；
- 什么证据足以认定已出运；
- 来源状态与日期冲突如何处理；
- 导入时已到港、已清关甚至已还箱的数据如何补建；
- 是否重放全部历史节点；
- 后补事实如何处理时序；
- 哪些事实自动应用，哪些进入复核；
- Shipment状态与Container状态的聚合规则。

##### 5. 统一工作单与岗位权限

内部和外部人员都需要使用统一的任务体系，但权限不同。

需要分析：

- NodeTask、内部WorkOrder和ExternalWorkOrder的关系；
- 任务分配、接单、转派、拒绝、撤回；
- SLA和升级；
- 代办、代理和班组；
- 内外部任务交接；
- 一项事实由多个任务共同完成时如何聚合；
- 什么岗位可以确认实际时间；
- 什么岗位可以更正历史事实；
- 哪些动作需要四眼复核；
- 租户、组织、合作方和对象级权限。

##### 6. 单证与文件中心

清关、装箱、提柜、卸柜都会依赖文件，应统一建设。

需要确定：

- 文件类型目录；
- 文件与Shipment、Container、SKU、案件、任务的关联；
- 一个文件覆盖多个SKU的表达；
- 文件版本和替代；
- 有效期；
- 外部共享包；
- 下载权限；
- 水印、防病毒和内容哈希；
- 外部人员上传后的核验；
- 保存期限；
- 删除、冻结和法律保留；
- AI处理文件的授权范围。

#### 建议收敛顺序

接下来最合理的顺序是：

1. 冻结Shipment、Container及四表字段模型。
2. 冻结联合导入和统一出运交接契约。
3. 冻结生命周期起点和历史事实补建规则。
4. 设计统一文件、任务、外部合作方和证据底座。
5. 完成清关与提送卸还岗位闭环。
6. 建立费用和资源日历。
7. 实施三方堆场和智能排柜。
8. 建立合规知识生产线和AI能力。
9. 最后完成KPI、绩效和持续改善。

当前最应该先深入的是前三项。它们决定数据库主结构和所有后续模块的连接方式；如果这三项未冻结，继续设计页面或算法会不断返工。

#### 我建议的实际工作方式

不再逐点聊天扩展，而是建立一个总任务 brief，分四个决策包推进。

##### 决策包一：出运数据基线

输出：

- Shipment、Container、提单和备货引用的聚合关系；
- 四表字段逐列映射；
- 字段权威来源；
- 必填、可空和迟绑定规则；
- 已出运准入条件；
- 数据库目标模型；
- 历史数据兼容策略。

需要你确认：

- Shipment业务身份；
- `loaded`还是`departed`作为当前起点；
- 无SKU明细时是否允许先建档；
- 出运日期只有日期、没有时刻时的处理。

##### 决策包二：联合导入与未来交接

输出：

- 四文件联合导入流程；
- `shipment-handoff.v1`契约；
- 预检、复核、执行和对账；
- 幂等、冲突和更正；
- 当前Excel Adapter；
- 未来装箱平台Adapter；
- 无缝切换方案。

需要你确认：

- 四个文件是否必须同时上传；
- 是否允许部分成功；
- 冲突是整批阻断还是逐柜处理；
- 哪类缺失进入待补全而不是失败。

##### 决策包三：出运后岗位闭环

输出：

- 清关、提柜、送仓、卸柜、还箱工作台；
- 内部任务和外部工作单；
- 清关行、车队、仓库、堆场门户；
- 文件与证据；
- 允许动作；
- 完成条件；
- 异常和恢复路径；
- 服务端权限与状态推进规则。

需要业务岗位确认真实操作顺序和责任边界。

##### 决策包四：高级能力

输出：

- 三方堆场；
- 智能排柜；
- 资源日历；
- 费用规则；
- OR-Tools优化模型；
- 合规评审；
- 法规与标准知识生产；
- AI治理和评测。

这些建立在前三包稳定之后，避免高级功能反向影响主数据结构。
