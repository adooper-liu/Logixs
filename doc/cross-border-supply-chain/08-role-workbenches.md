# 岗位工作台

> 状态分类：工作台设计链为已确认原则；已上线能力以技术任务和现网投影为准；仓库、三方堆场、异常中心的独立工作台为建议方案，待实施评审。

## 一、共同设计原则

每个工作台围绕六个问题组织：今天先处理什么、为什么、还缺什么、可以做什么、失败怎么办、完成后交给谁。

页面共同组成：优先事项、对象上下文、缺口与风险、允许动作、证据和活动时间线、结果反馈。

工作台不是把同一张货柜详情复制给每个岗位。清关人员首先关心申报截止、资料缺口和Hold，调度员首先关心可提条件、车辆、仓库资源和费用，仓库首先关心预约、月台、班组和收货差异。大家查看的是同一批事实，但排序、上下文和允许动作由岗位目标决定。

### 一个任务怎样被处理

用户从“今天必须处理”的任务进入，而不是先记住箱号再搜索。页面先说明为什么现在需要处理、不处理的影响和最晚决定时间；随后集中展示作出决定所需的信息、来源和缺口。用户执行动作后，系统明确反馈形成了什么结果、哪些对象受影响、下一责任人是谁。

动作暂时不能执行时，页面说明缺少什么以及如何补齐，例如“尚未取得码头可提证据，不能确认提柜完成”，而不是只把按钮置灰。多个对象批量处理时先预检，提交后逐柜反馈成功、待补全、冲突和失败。

## 二、备货工作台

- 岗位目标：让供应商按时、按量并满足合规要求地备齐货物。
- 每日优先事项：临近承诺日期、缺货、合规阻断和装箱计划已锁定的备货单。
- 必须看到：备货单、SKU/物料、数量、供应商承诺、缺口、合规整改和装箱要求。
- 允许动作：确认接单、反馈缺口、调整承诺、上传凭证和申请备货完成。
- 前置条件：备货单身份明确，产品行可识别；缺SKU时显示待补全及受限动作。
- 失败处理：数量、身份或合规冲突进入补正，不用默认值替代。
- 完成结果：形成可装箱的备货结果，不表示已经装箱。
- 权威事实：供应商承诺、备货数量、有效证据及经核验的备货完成事实。
- 下游交接：向装箱工作台交付可装产品行、限制条件和所需凭证。

## 三、装箱工作台

- 岗位目标：准确记录一只柜实际装了什么，并完成箱号、封条和VGM交接。
- 每日优先事项：临近截港、装载冲突、超量分配、缺箱号/封条和VGM未接受的任务。
- 必须看到：待装产品、剩余数量、来源备货单、箱型、重量、冲突和凭证。
- 允许动作：分配和调整货物、绑定箱号、登记封条、记录称重和提交VGM。
- 前置条件：备货结果可用、装载对象可识别、数量单位一致并满足专业约束。
- 失败处理：超分配、重复箱号、重量异常或VGM拒绝进入补正，保留原版本。
- 完成结果：形成版本化实际装载；更正不能抹掉上一版。
- 权威事实：当前有效装载版本、箱号、封条、称重/VGM回执和装箱实际日期。
- 下游交接：向出运工作台交付柜内货物、运输设备身份和装船前合规状态。

## 四、出运工作台

- 岗位目标：确保满足条件的货柜完成进港、装船和离港交接。
- 每日优先事项：临近截点、VGM/单证缺失、进港异常、甩柜和船期变化。
- 必须看到：订舱、船名航次、港口、截点、VGM、单证、Hold和外部同步结果。
- 允许动作：补全运输资料、处理拒绝、确认运输路线和登记专业事实。
- 前置条件：货柜身份、装载、订舱和必要装船条件明确。
- 失败处理：身份、航次、港口或回执冲突进入复核，不用任务完成冒充事实。
- 完成结果：由可靠装船/离港事实证明货柜已经出运。
- 权威事实：进港、装船、离港的实际日期及对应来源证据。
- 下游交接：向海运可视和清关工作台交付路线、航次、单证和时间基线。

## 五、清关工作台

- 岗位目标：在时限内完成资料、申报、查验、缴税和放行。
- 每日优先事项：申报/ISF临期、资料缺失、回执拒绝、查验、Hold和临近到港货柜。
- 必须看到：国家规则、HS Code、文件齐套、接收方、传送回执、案件状态和截止时间。
- 允许动作：分派报关行、补件、复核、发送资料、登记回执和处理查验/放行。
- 前置条件：适用国家资料参数、清关接收方、必要附件和责任主体明确。
- 失败处理：发送失败、资料拒绝、规则冲突和来源不足分别进入重试、补正或复核。
- 完成结果：以海关或认可渠道的放行证据为依据。
- 权威事实：申报、查验、Hold及放行事实和相应文件/回执。
- 下游交接：向提柜工作台提供清关放行、未解除限制和可用证据。

## 六、提柜工作台

- 岗位目标：在码头、海关、船司和资源条件同时满足后完成提柜。
- 每日优先事项：临近最晚提柜日、已可提未预约、Hold、车队冲突和高费用风险。
- 必须看到：可提条件、Hold、预约、车队、仓库/堆场容量和成本风险。
- 允许动作：预排、锁定计划、派车、扫码、上传EIR和登记重柜出场。
- 前置条件：清关放行、船司放货、码头可提和预约资格满足。
- 失败处理：预约失败、司机/车辆变更和码头拒绝触发重排或升级异常。
- 完成结果：以可靠Gate Out证据确认。
- 权威事实：码头重柜出场实际时间、EIR及执行资源。
- 下游交接：向送仓或三方堆场工作台交付在途任务、目的地和预约。

## 七、送仓工作台

- 岗位目标：按预约把货柜送到正确仓库或堆场。
- 每日优先事项：在途超时、预约临近、仓库拒收、改送和司机异常。
- 必须看到：路线、车辆、目的地、预约、等待、改送方案和POD要求。
- 允许动作：确认接单、登记到场、申请改送和上传POD。
- 前置条件：有效提柜事实、目的地指令、预约和承运资源存在。
- 失败处理：堵车、拒收、错送和证据缺失分别进入改约、改送或补证。
- 完成结果：确认货柜到达指定地点，但不等于卸柜完成。
- 权威事实：实际到达、POD、承运资源和异常记录。
- 下游交接：直送仓交卸柜；送堆场交三方堆场保管和二次运输。

## 八、卸柜工作台

- 岗位目标：完成实物接收并处理差异。
- 每日优先事项：已到仓待卸、月台等待、部分卸货、短溢损和破损。
- 必须看到：预计和实际SKU/物料、数量、批次、破损、部分卸货和剩余量。
- 允许动作：扫码收货、登记差异、拍照、暂停/继续卸货和完成核对。
- 前置条件：货柜实际到场、卸货资源可用且收货对象可识别。
- 失败处理：未知SKU、数量冲突、破损或部分卸货形成差异和后续任务。
- 完成结果：货物实际卸出并完成规定核对。
- 权威事实：卸货进度、实收数量、差异、证据和卸柜实际完成时间。
- 下游交接：向仓库入库/WMS交实收结果，向还箱工作台交空箱状态。

## 九、还箱工作台

- 岗位目标：在截止时间前将符合要求的空箱还到指定场站。
- 每日优先事项：临近最晚还箱日、预约缺失、场站变更、箱损和费用风险。
- 必须看到：还箱场、截止时间、预约、箱况、EIR和费用风险。
- 允许动作：派车、登记到场、上传空箱回场凭证和发起损坏争议。
- 前置条件：卸空确认、可接受场站和有效预约/指令存在。
- 失败处理：场站拒收、预约失效或箱损争议进入改派、补证和费用处理。
- 完成结果：有可靠还箱接收证据，后续费用仍可继续对账。
- 权威事实：空箱场站接收时间、EIR、箱况和争议记录。
- 下游交接：向费用对账和绩效复盘交还箱结果。

## 十、仓库工作台

- 岗位目标：统筹未来到仓、月台、班组和收货能力。
- 每日优先事项：未来容量超载、预约冲突、长时间等待和高风险货物。
- 必须看到：未来到仓量、仓容、月台、班组、卸货时长和SKU限制。
- 允许动作：确认/调整预约、分配月台班组、拒绝或建议改送。
- 前置条件：送仓预测或指令、仓库能力日历和货物要求明确。
- 失败处理：容量不足时给出改期或三方堆场方案，不静默超排。
- 完成结果：形成可执行仓库接收承诺。
- 权威事实：仓库预约、资源承诺和实际接收结果。
- 下游交接：向调度提供可用时间窗，向卸柜岗位交付资源安排。

## 十一、三方堆场工作台

- 岗位目标：在仓库压力或港口费用风险下安全承接临时堆存。
- 每日优先事项：即将进场、临近转出期限、容量紧张和异常箱况。
- 必须看到：进出计划、容量、费率、保管责任、箱况和二次运输安排。
- 允许动作：确认接收、分配堆位、登记进出、提交箱况和费用证据。
- 前置条件：堆场准入、能力、报价、责任边界和运输任务有效。
- 失败处理：拒收、容量变化和箱损触发重排、改场或争议处理。
- 完成结果：形成临时保管和后续转运的可靠交接。
- 权威事实：堆场进出、堆位、箱况、费用和责任交接证据。
- 下游交接：向送仓/仓库交二次运输任务，向费用模块交计费事实。

## 十二、异常中心

- 岗位目标：集中处理跨工作台不能在正常路径内解决的问题。
- 每日优先事项：阻断主流程、临近法定/费用期限、高影响和长期未处理异常。
- 必须看到：对象、影响、来源证据、责任岗位、截止时间和关联任务。
- 允许动作：认领、分派、补证、升级、纠偏、解除和关闭。
- 前置条件：异常类型、来源事实和影响对象明确。
- 失败处理：无法判断时保持开放并升级，不用自由文本直接改变业务事实。
- 完成结果：异常原因得到解决或形成经批准的风险接受。
- 权威事实：异常、处理决定、补偿/纠偏结果和关闭证据。
- 下游交接：解除阻断后重放原业务事实或通知相应工作台继续执行。

## 十三、人性化要求

- 默认按截止时间、风险和影响排序。
- 禁止动作要说明缺少什么以及如何补齐。
- 批量操作先预览影响，再逐柜反馈。
- 外部提交区分“已发送、对方已收到、业务已接受”。
- 移动作业优先扫码、拍照、日期时间、定位和弱网补传。
- 页面只展示当前岗位需要判断和行动的信息。

## 十四、跨工作台协作示例

一只柜临近到港，清关工作台将其排入高优先级，因为ISF回执缺失。清关人员补件并取得海关放行后，提柜工作台仍显示“不可提”，原因是码头尚未卸船且船司Hold未解除。码头状态更新后，系统生成可提候选，调度员安排车辆和仓库预约。

司机完成Gate Out后，送仓任务自动获得可靠提柜事实。仓库临时无法接收，调度员选择三方堆场；堆场确认入场后，原送仓任务不是简单改成完成，而是形成一段已完成运输和新的二次送仓任务。最终到仓后，卸柜岗位记录部分卸货和破损，完成卸空后才把空箱交给还箱任务。

每个工作台只完成自己的业务结果，下一工作台通过可靠交接继续，不需要重新录入箱号、日期和附件，也不能用自己的“完成”替代其他岗位的事实。

## 十五、工作台验收方式

评审时不只检查页面有没有字段和按钮，应让目标岗位使用真实场景完成以下过程：

1. 从任务池识别最高优先级对象并说清原因。
2. 判断信息是否齐全，区分计划、外部反馈和实际证据。
3. 执行一个允许动作，并看到明确成功结果和下游影响。
4. 遇到缺失、冲突或并发变化时完成补正或退出，不产生错误事实。
5. 从活动时间线追溯谁在何时基于什么证据作出决定。

## 十六、导入记录与原生流程的操作差异

同一工作台需要明确标识记录来源，但不能形成两套生命周期。

| 工作台     | 当前已出运导入记录                                                                 | 未来原生流程记录                                      |
| ---------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 备货       | 以只读恢复为主，查看来源备货单和缺失项；只能发起补全或更正，不能重新执行已结束备货 | 接收采购履约，确认备妥、质检和释放，形成备货交接      |
| 装箱       | 查看或补全箱号、封号、装载、重量体积和证据；改变历史事实必须走更正                 | 从已释放备货分配装载，处理短装/超装，确认装箱版本     |
| 出运       | 以实际离港为运营起点，确认Shipment、货柜、路线、单证和时间基线                     | 接收装箱完成交接，完成订舱/单证/VGM门槛后确认实际离港 |
| 后续工作台 | 按同一事实、任务和证据继续执行                                                     | 与导入记录完全相同                                    |

历史记录不能显示仍可执行的“释放备货”“确认装箱”等误导动作。确需纠正时显示“发起历史更正”，并说明将影响哪些下游事实。

## 十七、任务池和详情页

每个工作台首页都应是可行动的任务池，而不是字段总表。默认分组包括今日必须处理、即将逾期、被阻断、等待外部回复、待我确认和近期已完成；支持按国家、港口、仓库、伙伴、责任人、时间窗和风险筛选。列表至少显示业务对象、下一动作、截止时间、阻断原因、当前责任人和最近变化。

详情页遵循稳定阅读顺序：

1. 顶部给出当前业务结论、下一动作、截止时间和不能执行的原因。
2. 展示完成判断所需的货物、路线、时间、文件、费用或资源上下文。
3. 将缺失、冲突、Hold和待外部回复集中列出，不让用户逐字段寻找。
4. 只提供服务端当前允许的动作，并在提交前说明结果和影响范围。
5. 操作完成后显示形成的权威事实、证据、下游接收方和失败恢复路径。
6. 历史、原始来源和技术身份放在审计区，不挤占主要操作路径。

## 十八、海运运营工作台

- 岗位目标：从实际离港开始持续掌握船舶、航段和货柜执行变化，使清关、提柜、仓库和调度能够基于最新且可解释的海运事实工作。
- 每日优先事项：ETA显著变化、中转衔接风险、甩柜/跳港/停航、长时间无更新、多来源冲突、即将到港但下游未准备。
- 必须看到：Shipment和货柜、当前航段、船名航次、港序、中转关系、当前ETA及历次修订、最新实际事件、来源、数据新鲜度和受影响任务。
- 允许动作：确认或驳回来源候选、关联换船或新航段、登记异常、锁定人工核验值、通知受影响岗位、请求补充跟踪条件。
- 前置条件：外部身份能够匹配本次运输实例；来源语义和地点明确；实际事件具备相应来源资格。
- 失败处理：无法匹配、来源冲突、状态倒退或接口陈旧进入复核；甩柜、改港和中转失败形成异常案件及影响分析。
- 完成结果：到港、卸船和可提等后续岗位获得最新裁决事实和变化通知，而不是一条被覆盖的ETA。
- 权威事实：航段和换船版本、外部观测、当前采用的计划/预计/实际时间、来源裁决、异常和通知回执。
- 下游交接：向清关提供到港窗口，向排柜提供卸船/可提预测和最后免费日依据，向仓库提供到仓影响，向费用提供可采信的计费起点。

港口或AIS显示船舶到港，不等于货柜已经卸船；货柜卸船也不等于已放货或可提。工作台必须将船舶、运输和设备三个层次分开呈现。

## 十九、费用与结算工作台

- 岗位目标：把生命周期产生的费用从估算、计提、账单核验、分摊、争议处理推进到支付或关账。
- 每日优先事项：即将跨过免费期、账单超过估算、缺少计费证据、重复收费、争议即将超期、物流已完成但财务未关闭。
- 必须看到：费用类型、计费对象、服务期间、费率版本、数量和阶梯、币种税费、估算/计提/账单/核定/实付、凭证和责任方。
- 允许动作：计算或刷新估算、建立计提、匹配账单、确认差异、发起争议或索赔、按规则分摊、提交审批和登记支付结果。
- 前置条件：计费起止事实、费率和币种明确；账单身份唯一；分摊基础可解释。
- 失败处理：缺计费事件进入补证；费率不适用进入合同复核；重复账单阻断；争议期间保留未决金额，不用零值表示。
- 完成结果：每项费用有核定结果、分摊去向和支付/争议结论，物流完成与财务关账分别可见。
- 权威事实：费率及版本、计费期间、估算、计提、供应商账单、核定、分摊、争议、审批和支付证据。
- 下游交接：向财务付款和经营分析交核定金额，向调度反馈实际成本，向供应商绩效交差异和索赔结果。

费用至少支持码头堆存、船司滞箱、车队运输与等待、三方堆场、仓库卸柜、清关及查验等类别。金额使用定点数并携带币种；跨币种分析保存采用的汇率来源和日期。分摊可以落到Shipment、货柜、备货单或SKU，但必须保留原始费用和分摊规则，不能只剩摊后结果。

## 二十、跨工作台反馈

下游发现问题时，不直接改上游字段。例如仓库发现短货，应登记实收差异并通知装箱/供应链核对；清关发现品名或HS资料不一致，应建立合规缺口和补件任务；费用岗位发现实际还箱时间缺证，应请求还箱岗位补证。原岗位处理后返回新版本或明确驳回，下游再决定重算、继续或升级异常。

### 各岗位工作台的人性化操作流程

> 追溯范围：原始对话第 1610-2210 行。建议仍为建议；已确认规则以本文前部、12号文档和业务ADR为准。

#### 共同交互原则

每个工作台都应有四个稳定层次：

1. **任务池**：告诉用户今天先处理什么。
2. **对象上下文**：在当前页面看全完成工作所需的信息。
3. **动作面板**：只显示当前状态真正允许的动作。
4. **结果反馈**：明确成功、等待、阻塞、冲突和下一责任人。

列表默认按风险和截止时间排序，不按创建时间机械排序。推荐筛选：

```text
我的待办 | 可执行 | 待他人 | 有异常 | 临期 | 已完成 | 历史导入
```

列表行应直接回答：

- 这是什么业务对象；
- 当前进行到哪里；
- 为什么需要我处理；
- 什么时候必须完成；
- 缺什么；
- 下一步能做什么。

### 备货工作台

#### 岗位目标

让供应商按要求完成 SKU 备货，并形成可交给装箱岗位的可靠备货结果。

#### 进入工作台

用户进入后首先看到待备货任务，而不是备货单数据库列表：

| 列表信息               | 用途                         |
| ---------------------- | ---------------------------- |
| 备货单号、供应商       | 确认处理对象                 |
| 目的国家、目的港、仓库 | 理解出运方向                 |
| SKU 数及总数量         | 判断任务规模                 |
| 要求完成时间           | 排定优先级                   |
| 齐套进度               | 判断是否可以交接             |
| 缺口                   | 直接指出未完成内容           |
| 状态和下一动作         | 避免进入详情后才发现不能操作 |

#### 单据操作流程

```text
打开备货单
-> 核对供应商、SKU、数量和交期
-> 记录每个 SKU 的已备数量
-> 标记缺货、延期、替代品或数量差异
-> 上传或关联备货证据
-> 系统校验齐套情况
-> 提交备货完成
-> 生成备货完成快照
-> 自动进入待装箱池
```

详情页按操作顺序排列：

1. 任务摘要与截止时间；
2. SKU 齐套明细；
3. 缺口和异常；
4. 文件及证据；
5. 完成条件；
6. 提交动作与结果。

不要要求用户逐个 SKU 重复点击保存。应支持表格内快速录入、批量确认和仅查看异常行。

#### 异常处理

用户不能完成时，提供明确动作：

- 数量不足；
- 供应商延期；
- SKU 不一致；
- 质量或合规问题；
- 需要拆批出运；
- 取消或等待业务决定。

异常提交后应显示责任人、处理时限和恢复条件，而不是只写一条备注。

#### 历史导入记录

已出运数据不进入待备货池，单独进入“历史导入”：

- 只读显示已知备货结果；
- 缺少 SKU 时显示“明细未提供”；
- 允许补全和发起更正；
- 不允许重新执行备货完成。

### 装箱工作台

#### 岗位目标

将已备货物准确装入指定货柜，确认柜号、装载明细和重量体积，并可靠交接给出运岗位。

#### 任务池

列表应展示：

| 列表信息                 | 用途                   |
| ------------------------ | ---------------------- |
| 装箱任务号、柜号或待绑定 | 确认任务               |
| 起运港、装箱地点         | 明确现场               |
| 供应商及备货单数量       | 判断是否拼柜           |
| 已备/待装数量            | 判断是否可开始         |
| 箱型与容量占用           | 防止超装               |
| 计划装箱时间             | 安排现场               |
| 阻塞原因                 | 直接识别缺货或资料问题 |

系统应把“可装箱”和“等待备货”分开，避免现场人员打开无法执行的任务。

#### 装箱操作流程

```text
打开装箱任务
-> 核对备货单和 SKU 范围
-> 绑定或扫描柜号
-> 录入封号
-> 按 SKU 确认实际装载数量
-> 系统实时核对多装、少装和单位
-> 录入件数、毛重、净重、体积、VGM
-> 上传装箱照片或文件
-> 查看未完成项
-> 提交装箱完成
-> 生成不可覆盖的装箱快照
-> 自动交接出运工作台
```

装载界面应按“备货单 → SKU”分组，同时提供整柜汇总。拼柜时必须清楚展示每个供应商和备货单贡献的货物，不让用户面对一张混合长表。

#### 防错设计

- 扫描柜号后显示标准化结果；
- 重复柜号立即阻断；
- 实装量超过可装数量立即提示；
- 数量单位不同不得直接相加；
- 件数、SKU 数量、重量和体积独立保存；
- 柜号、封号、重量等缺失时列出具体缺口；
- 装载版本变化时阻止使用旧页面提交；
- 已出运后只能发起更正，不能普通编辑。

#### 历史导入记录

四表导入只能形成外部装箱快照：

- 资料完整的显示“外部装箱结果”；
- 缺 SKU、封号或 VGM 的显示“资料待补全”；
- 不进入待装箱任务；
- 允许补证据、绑定 SKU、发起更正；
- 不允许再次点击“完成装箱”。

### 出运工作台

#### 岗位目标

确认货柜已经完成装船或离港交接，并持续管理到港、清关、提柜、送仓、卸柜和还箱。

#### 首页任务视图

出运工作台不应只是一张货柜列表，默认应展示：

```text
需要立即处理
即将到港
清关资料缺失
等待放行
最晚提柜临期
最晚还箱临期
异常与冲突
```

列表重点字段：

- 出运号、提单号、柜号；
- 船公司、船名航次；
- 起运港、目的港、仓库；
- 实际出运时间、最新 ETA；
- 当前节点和下一节点；
- 清关资料完整度；
- 最近截止时间；
- 责任岗位；
- 异常和阻塞原因。

#### 初始出运交接

正常流程：

```text
接收装箱快照
-> 核对柜号、装载版本、提单、船名航次
-> 补充出运资料
-> 上传装船或离港证据
-> 系统校验来源和时间
-> 确认实际离港
-> Shipment 进入已出运
-> 创建后续生命周期任务
```

当前四表导入：

```text
上传四表
-> 字段映射审核
-> 跨表关联和冲突检查
-> 查看逐柜预检结果
-> 确认执行
-> 生成 Shipment、Container 和已发生事实
-> 从实际离港节点启动生命周期
-> 进入出运工作台
```

#### 出运后操作

详情页顶部显示当前最需要处理的事情，其后才是完整信息：

```text
当前风险与下一动作
-> 航线和节点轨道
-> 清关操作区
-> 提柜与运输
-> 仓库交付和卸柜
-> 还箱
-> 单证、事件和审计历史
```

用户点击生命周期节点后，只展示该节点的：

- 完成条件；
- 已有事实；
- 缺失信息；
- 允许动作；
- 截止时间；
- 责任人；
- 证据；
- 历史记录。

#### 典型节点体验

清关：

```text
检查资料完整度
-> 补充/发送资料
-> 记录申报
-> 处理查验或扣留
-> 记录放行证据
-> 自动开放提柜计划
```

提柜与送仓：

```text
查看可提状态和最后免费日
-> 选择承运商
-> 安排计划提柜/送仓
-> 记录实际提柜
-> 跟踪运输
-> 确认送达仓库
```

卸柜与还箱：

```text
确认仓库接收
-> 记录卸柜进度
-> 确认卸空和差异
-> 安排空箱回收
-> 记录实际还箱
-> 核对费用和证据
-> 关闭货柜生命周期
```

### 三个工作台的交接体验

交接应由系统自动完成，不要求用户重新录入：

| 上一步结果   | 系统行为           | 下一岗位看到什么       |
| ------------ | ------------------ | ---------------------- |
| 备货完成     | 冻结备货快照       | 新的可装箱任务         |
| 装箱完成     | 冻结装箱和装载快照 | 待出运交接任务         |
| 实际离港确认 | 初始化出运后流程   | 在途货柜和后续节点任务 |
| 清关放行     | 开放提柜动作       | 可提柜任务             |
| 送仓完成     | 开放卸柜动作       | 待卸柜任务             |
| 卸空确认     | 开放还箱动作       | 待还箱任务             |
| 还箱完成     | 执行完整性核对     | 可关闭记录             |

每次交接后，上游用户应看到：

- 已交接给谁；
- 交接时间；
- 接收结果；
- 是否还有未解决异常；
- 后续发生更正时如何处理。

最关键的体验原则是：用户只处理自己当前能改变的事情；系统自动带入已有权威信息、隐藏非法动作，并把缺口、责任人和恢复路径直接呈现在当前工作页面。

> 清关、提柜、送仓、卸柜工作台的人性化操作分析

这四个工作台不是四张数据浏览表，而是四个连续岗位的操作闭环：

```text
清关放行
  -> 确认货柜可提
  -> 安排并完成提柜
  -> 运输并交付仓库
  -> 卸柜、核对差异并确认空箱
```

每个工作台都应回答五件事：

```text
今天先处理什么
当前为什么不能继续
完成本岗位还缺什么
现在允许执行哪些动作
完成后交给谁
```

#### 清关工作台

##### 岗位目标

在到港前准备完整单证，完成申报、查验处理和放行，为提柜创造条件。

##### 首页任务池

默认按业务风险分组：

```text
资料缺失
即将到港未申报
等待海关结果
查验或扣留
已放行待交接
```

列表直接显示：

- 出运号、柜号、MBL/HBL；
- ETA、实际到港时间；
- 清关公司、贸易模式；
- ISF/申报状态；
- 单证完整度；
- 换单状态；
- 查验、开箱和扣留情况；
- 最后免费日；
- 当前责任人和下一动作。

不要让清关人员逐柜打开后才知道缺哪份资料。列表应显示“缺发票”“缺箱单”“待换单”等具体缺口。

##### 操作流程

```text
打开清关任务
-> 核对提单、收发货人和贸易模式
-> 查看必需单证清单
-> 补充、发送或重新发送文件
-> 确认换单是否适用及完成状态
-> 提交 ISF/进口申报信息
-> 记录海关受理结果
-> 处理查验、开箱、扣留或补件
-> 上传放行证据
-> 确认实际放行
-> 自动交接提柜工作台
```

##### 页面布局

1. 顶部显示“当前结论、最后免费日、下一动作”；
2. 左侧显示清关进度；
3. 中间显示按要求分类的单证清单；
4. 右侧显示有限动作和不可执行原因；
5. 底部显示事件、文件版本和审计历史。

##### 关键防错

- “单证已齐”必须由文件要求规则计算，不能人工随意勾选；
- “已申报”和“已放行”必须分开；
- 清关完成必须有实际时间和证据；
- 查验、开箱和扣留是异常轨道，不覆盖清关主状态；
- 新文件形成新版本，不能覆盖旧文件；
- 未放行时不能开放普通提柜动作。

#### 提柜工作台

##### 岗位目标

确认货柜已放行且码头可提，在免费期内安排车辆并完成实际提柜。

##### 首页任务池

```text
待确认可提
可提待安排
已安排待执行
今日提柜
提柜失败
免费期临期
```

列表重点显示：

- 柜号、提单号、目的港和码头；
- ETA/ATA、卸船时间、可提时间；
- 清关放行状态；
- 换单和码头放货状态；
- 最后免费日；
- 计划提柜时间；
- 承运商、车辆或预约信息；
- 目的仓；
- 当前阻塞原因。

排序优先考虑最后免费日和预约时间，而不是记录创建时间。

##### 操作流程

```text
打开提柜任务
-> 查看联合可提条件
-> 处理缺失的放行、换单或码头状态
-> 选择承运商和运输方式
-> 安排计划提柜时间
-> 记录预约信息
-> 现场确认实际 Gate Out
-> 上传 EIR、提柜凭证或外部事件
-> 自动交接送仓工作台
```

“可提”应是服务端联合判断：

```text
海关已放行
+ 提单/换单条件满足
+ 码头已放货或可提
+ 没有有效扣留
```

##### 失败与恢复

提柜失败不能只写备注，应选择稳定原因：

- 码头未放箱；
- 海关重新扣留；
- 预约失败；
- 车辆问题；
- 柜号或提单不匹配；
- 费用未处理；
- 现场无柜；
- 其他受控原因。

提交失败后，应保留原计划，生成重新安排动作，并重新计算滞期风险。

#### 送仓工作台

##### 岗位目标

将已提货柜安全送到正确仓库，并完成仓库接收交接。

##### 首页任务池

```text
待派车
已提柜待发运
运输中
即将到仓
到仓待确认
配送异常
```

列表重点显示：

- 柜号、当前地点；
- 实际提柜时间；
- 计划仓库和实际仓库；
- 计划送达时间；
- 最晚送仓时间；
- 承运商、司机、车辆；
- 运输方式；
- 仓库预约或卸柜门；
- 延误和改仓风险。

地图或车辆轨迹只有存在可靠定位数据时才展示；不能用计划时间伪装实时位置。

##### 操作流程

```text
接收已提柜任务
-> 核对目的仓和预约要求
-> 确认承运商、车辆和司机
-> 确认计划送达时间
-> 记录发运
-> 处理途中延误、改仓或事故
-> 到仓签到
-> 仓库确认收柜
-> 上传 POD/签收证据
-> 自动交接卸柜工作台
```

##### 人性化重点

- 仓库、地址、联系人、预约窗口一次展示，不让司机或调度跨页面查找；
- 修改实际仓库必须走“改仓”动作并说明原因；
- 到仓不等于卸柜完成；
- 实际送达时间以可信签到、POD 或系统事件为依据；
- 运输异常单独管理，不通过修改计划时间掩盖延误。

---

#### 卸柜工作台

##### 岗位目标

按仓库能力完成卸柜，记录实收差异，确认货柜卸空并交给还箱环节。

##### 首页任务池

```text
已到仓待卸
今日计划卸柜
正在卸柜
部分卸货
差异待处理
已卸空待还箱
```

列表重点显示：

- 柜号、仓库、卸柜门；
- 到仓时间和等待时长；
- 卸柜方式；
- 计划/最晚卸柜时间；
- 备货单、SKU 和预期数量；
- 已卸数量和剩余数量；
- 破损、短少、多货情况；
- 空箱确认状态；
- 最晚还箱日期。

##### 操作流程

```text
接收到仓货柜
-> 分配卸柜门和卸柜人员
-> 核对封号及外观
-> 记录开始卸柜
-> 按备货单/SKU 记录实收
-> 保存部分卸货进度
-> 登记短少、多货、破损或错货
-> 上传照片、签收单和 WMS 结果
-> 确认全部货物已卸
-> 独立确认货柜已空
-> 自动交接还箱任务
```

“卸柜完成”和“空箱确认”必须分开：

- 卸柜完成：预定卸货作业已经结束；
- 空箱确认：柜内无剩余货物，具备还箱条件。

##### 差异处理

卸柜页面应提供结构化差异录入：

| 差异     | 必要信息                         |
| -------- | -------------------------------- |
| 短少     | SKU、预期、实收、差异数量、证据  |
| 多货     | SKU、实收数量、来源判断          |
| 破损     | SKU、数量、等级、照片            |
| 错货     | 实收 SKU、应收 SKU、数量         |
| 封号异常 | 原封号、实际封号、照片和处理决定 |
| 柜损     | 损坏位置、程度、照片和责任判断   |

有差异不一定阻止卸空，但必须形成异常案件并指定下一责任人。

---

#### 四个工作台的交接规则

| 完成结果                 | 自动交接                 |
| ------------------------ | ------------------------ |
| 清关放行且可提条件满足   | 提柜工作台出现可执行任务 |
| 实际提柜/Gate Out 已确认 | 送仓工作台进入运输中     |
| 到仓和签收证据确认       | 卸柜工作台出现待卸任务   |
| 卸柜完成且空箱确认       | 还箱任务开放             |

上一步未满足时，下一工作台可以看到对象，但只能显示等待原因，不能提前执行非法动作。
