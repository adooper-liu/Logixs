# 工作台需求澄清

本技能只约束澄清动作。它不是业务权威，也不复制 `AGENTS.md`。与 `AGENTS.md`、`doc/cross-border-supply-chain/08-role-workbenches.md`、已接受 ADR 或现行 brief 冲突时，以那些权威为准，并在输出里指出冲突。

下发澄清时，在 TASK 行后附上 `.agents/prompts/clarify.md`，并先回答其中三句。

`doc/cross-border-supply-chain/wisdom-baseline/` 是必读基线，不是权威。其中 `业务工作台持续打磨受阻原因.md`（2026-10-04）是交付节奏诊断，不是规则修订。

## 先读什么

1. `AGENTS.md` §1.2.1 与 §1.2.2 第 1～2 条。
2. `wisdom-baseline/README.md`、`全局.md`，以及该工作台对应基线文件。文件对应关系以 README 的表为准。
3. `08-role-workbenches.md` 中与该决定有关的条文，至少包括 §2.1、§2.5，以及该工作台的岗位结果。引用前打开文件；基线里的行号可能已漂移。
4. 若已有该工作台的 task brief，只读与本决定相关的段落。没有 brief 时不要为了澄清新建第二套需求文档。

权威已经写明的内容，不要重新包装成选择题。`AGENTS.md` §1.2.1 第 1 条要求同一节点继承已确认结论。

## 何时才澄清

只在下列事项尚未由负责人确认、并且会改变本步岗位结果时进入澄清：目标岗位、唯一核心业务结果、优先减少的损失、责任与交接、退出或退回、权限政策、风险接受、指标口径、不可逆投入。

局部代码结构、测试设计、命名和可逆实现，由主代理按 `AGENTS.md` §1.2 第 4 条负责，不要转成业务选择题。

业务目的和优先损失未锁定前，不设计字段、状态机、权限平台、契约或界面方案。这是 `AGENTS.md` §1.2.1 第 2 条，不是本技能新加的门禁。

## 每轮怎么做

每轮只推进 1～3 个真正待决的事项。顺序沿用 `08-role-workbenches.md` §2.5：

1. 先分开写：已证实的项目事实、负责人已定政策、当前实现差距、行业候选、未知。页面存在、API 可调用、字段已落库、测试通过、状态标为 `live`，都不能单独写成业务闭环。
2. 再给 2～3 个互斥且能执行的方案。推荐项放在第一位，并写明证据、收益、成本、风险、边界和可逆性。非推荐项同样写明它在什么条件下成立。
3. 指出证据冲突和弱假设。没有依据时不要迎合已有方案。
4. 负责人选定后，先复述这一条新决定，再进入下一个决定。不要重写整台背景。

节点上的第一轮，按 `AGENTS.md` §1.2.1 第 11 条的顺序输出。简单问题可以缩短篇幅，但保留业务目的、优先损失，以及事实与建议的分界。后续轮次不要重复这份长输出；同一节点不重置问题，依据是 §1.2.1 第 1 条。2026-10-04 诊断记录的是治理、复审和状态维护挤占了工作台交付，它没有废除第 11 条，也不能用来跳过第一轮的目的、损失和事实边界。

基线原文逐条标记 `沿用`、`修正`、`补强`、`存疑` 或 `与权威冲突`。`修正` 必须有负责人的新决定，或可核验的权威、样本依据。`存疑` 和 `与权威冲突` 交给负责人，不自行取舍。不要改写或删除基线原文。

## 行业材料

行业做法只按 `08-role-workbenches.md` §2.3 登记为候选：来源、适用理由、收益、成本、不采用风险、可逆性。缺任何一项就不要写入方案。

不要把某一公司的时限、阈值、样机数或良率写成 Logix 规则。`AGENTS.md` §1.2.1 第 4 条已有此限制。本技能不新增大批行业书目；具体外部对照由 `logix-same-slice` 与 `logix-risk-review` 在实施和评审时各处理一条，并保持候选地位。

## 阻塞怎么说

brief 状态只使用 `docs/planning/tasks/_template.md` 中的机器可校验值：`design`、`coding`、`review`、`fix`、`blocked`、`done`。不要发明 `code-ready`、`owner-decision`、`validation-blocked`、`deploy-blocked`。这些词只出现在上述诊断的建议里，尚未进入模板。

在正文里写明阻塞落在哪一类，并且只挡住依赖它的动作：

- 岗位目的、责任、状态语义、退出或权限政策未定：只阻塞依赖该决定的动作。其余事实核对和无关切片继续。见 `08-role-workbenches.md` §2.5 第 6 点。
- 外部身份、迁移环境或生产配置缺证据：阻塞部署和 task `done`，不阻塞不依赖该环境的本地实现、提交、PR 审查与合并。见 `AGENTS.md` §1.2 第 16 条。
- 尚无真实或脱敏的真实样本：阻塞 `WB-B10` 和“通过本轮复审”，不阻塞政策已定、可回滚的机制与界面切片。样本要求以 `08-role-workbenches.md` 的 `WB-B10` 原文为准，不要写成任意脱敏数据即可。

一个薄片已经合并、brief 回到 `blocked`，只说明下一片未被预授权。按 `AGENTS.md` §1.2 第 24 条写出下一片，或写出仍缺的决定以及不依赖它的部分。不要据此把所有工作台都解释为不能编码。

## 写回与禁止编造

聊天选择不是权威。只有主代理把负责人结论写入现有 `doc/`、ADR、公共契约或当前 brief 后，结论才能进入实现。本技能不授权新建手顺、第二份需求或 handoff 文件。决策顾问会话保持只读。

不得编造负责人原话、岗位样本、组织关系、阈值、审批、测试结果、来源或“已闭环”。缺少证据时写 `未知`、`候选`、`待负责人定案` 或 `待真实样本验证`。
