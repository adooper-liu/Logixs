# 经营链工作台视觉动线改版规范

> 状态：**设计决策草案** · 2026-09-28  
> 范围：
>
> - **详情页**（四屏）：市场与经营信号（活跃态 / 关闭态）、选品立项、产品开发与 NPI。
> - **枢纽页**（一屏）：业务工作台管道总览（`WorkbenchNetworkView`）。  
>   原则权威：[ROLE_WORKBENCH_HUMAN_CENTERED_DESIGN](./ROLE_WORKBENCH_HUMAN_CENTERED_DESIGN.md)  
>   视觉权威：[UI_SYSTEM](./UI_SYSTEM.md)（色值/字号/间距**只引用令牌**，不另造色板）

## 0. 两类页面 · 适用区分（先读）

| 类型       | 代表屏             | 用户打开时的问题                       | 动线                           | 骨架章节 |
| ---------- | ------------------ | -------------------------------------- | ------------------------------ | -------- |
| **详情页** | 信号 / 选品 / NPI  | 这一票结论是什么、还差什么、下一步动作 | **纵向沉淀**：结论→依据→证据   | §2       |
| **枢纽页** | 业务工作台管道总览 | 活现在卡在哪一节、该点哪个台进去       | **横向扫描**：全局→当前节→进台 | §12      |

**禁止**：把详情页的「结论上提 / 进度头 / 行动条」骨架直接套到枢纽页；也禁止把枢纽页的「阶段卡平铺 + 系统能力标签」套回详情页。

## 1. 三条总则

| #   | 总则                            | 禁止                                  | 可验收                                                           |
| --- | ------------------------------- | ------------------------------------- | ---------------------------------------------------------------- |
| T1  | **状态 = 整页形态开关（Mode）** | 把终态/关闭态写成角落标签，却继续催办 | 同一对象在活跃/关闭/已立项下，布局、可操作区、色彩饱和度同步切换 |
| T2  | **未完成 = 进度刻度**           | 「待补」当按钮文案；同一状态写三遍    | 完备度只在进度头出现一次；字段旁是动词动作                       |
| T3  | **上游数据自动下流**            | 答案已在标题/快照里却让人重填         | 可推导字段默认预填 +「已自动推导，确认即可」；一键确认           |

枢纽页另遵 **§12 总则 H1–H3**（管道自述状态、业务量优先于系统能力、交接在连接处）。

与既有决策对齐：`HW-D04` 因果动线、`HW-D09` 权威事实只录一次、`HW-D16` 状态分轨、`UI-D06` 逐层披露、`UI-D10` 人的结果优先。

## 2. 详情页通用骨架（四屏共用 · 不适用于枢纽页）

```text
┌─ ① 标题带（对象名 · 陈述句）────────── 责任人（二级灰）─┐
│ ①b 进度头 / 或关闭结论条（全页唯一最高权重）            │
├────┬────────────────────────────────────────────────────┤
│ ②  │ ③ 主体（结论/判断 → 依据 → 证据）                  │
│导航│    区块化 + 组内完成度；依赖未满足则后置区锁定       │
│收窄│                                                    │
├────┴────────────────────────────────────────────────────┤
│ ⑥ 常驻行动条：次要 ≤2 个 + 主 CTA 1 个（动词）           │
└─────────────────────────────────────────────────────────┘
```

| 层           | 职责                                 | 禁区                                           |
| ------------ | ------------------------------------ | ---------------------------------------------- |
| ① 标题带     | 陈述对象；责任信息降权               | 疑问句标题；把岗位元信息做成首屏主卡           |
| ①b 进度/结论 | 活跃：完备度；关闭/终态：Mode 结论条 | 「待补」文案墙；把决策结论与资料完备度揉成一句 |
| ② 导航       | 选票；关闭项降饱和                   | 与主体等权；关闭项当活跃焦点                   |
| ③ 主体       | 单向 ①→⑥；必填落点唯一               | 同权重填空墙；状态型按钮堆在底部               |
| ⑥ 行动条     | 主 CTA 固定终点                      | 页脚 >3 个动作；按钮写状态不写动词             |

**视线流铁律（详情页）**：一屏一个焦点；焦点是结论或进度，不是列表/按钮组。  
枢纽页视线流见 §12。

## 3. 屏一 · 产品开发与 NPI

> 2026-09-29 更新：本节只定义视觉层次，阶段业务闭环和门槛以
> `doc/cross-border-supply-chain/08-role-workbenches.md` 第五节为权威。早期按“结论 +
> 依据条数”计算齐/半/缺的方案已废止，不能作为推进或发布依据。

### 3.1 病灶（摘要）

三栏平权；阶段是纯文字；结论在弱位置；无退回；布尔「已核实」扫读差。

### 3.2 改造骨架

```text
① 标题带 + 阶段轨（概念─EVT─DVT─PVT─●MP）
② 窄队列 | ③ 当前阶段工作区：交付物 → 证据 → 问题 → 门槛决定
⑥ [退回/回开] [次要动作…] [主 CTA：领取 / 补首要缺口 / 提交评审 / 发布]
```

### 3.3 手法

| #   | 手法         | 口径                                                                                 |
| --- | ------------ | ------------------------------------------------------------------------------------ |
| 1   | 阶段轨可视化 | 当前实心、已完成连线填充；已完成节点打开不可变快照，不用连线代表业务已通过           |
| 2   | 缺口具体化   | 逐项显示缺什么、为何阻断、责任人、期限和恢复动作；不以百分比或附件数量代替           |
| 3   | 状态分轨     | 阶段、交付物、问题、外部观测和同步状态分开；警示色只突出当前最高优先级阻断           |
| 4   | 退回与回开   | 退回选品和 DVT 后回开均走正式写路径，先展示影响，理由和审计信息按业务规则强制        |
| 5   | 行动条沉底   | 主 CTA 随当前状态变化且全页只有一个；MP 未通过时不得出现可执行的“发布并交主数据”按钮 |

### 3.4 本屏不做

- 不用前端状态发明“通过、回开或发布”；动作必须来自服务端允许动作，退回和回开走正式写接口与加法迁移。

## 5. 屏三 · 选品立项中间区

### 5.1 病灶

填空墙；「已立项」与「仍待补」打架；placeholder 当说明；无进度；评审要点小作文。

### 5.2 改造骨架

```text
① 进度头：完备度 + 必填剩 N · [⚡带入] [存草稿]
② 区块A 市场定义 ●必填
③ 区块B 来源证据（推荐卡 + 带入）
④ 区块C 评审要点（选项化）○选填
⑥ [存草稿] [⚡带入] [→ 提交/已立项只读说明]
```

### 5.3 手法

| #   | 手法           | 口径                                                              |
| --- | -------------- | ----------------------------------------------------------------- |
| 1   | 两维拆开       | **决策结论**（已立项）vs **资料完备度**（进度条）                 |
| 2   | 已立项 = Mode  | 写入口关闭；缺口仅摘要；与屏二同构                                |
| 3   | 评审要点选项化 | **方案 A**：UI 单选大/中/小等，落库写成规范化短句（契约不改枚举） |
| 4   | 带入           | 交接快照市场/范围/证据一键入草稿                                  |

## 6. 屏四 · 市场信号 · 活跃态依据区（本批判屏）

### 6.1 病灶表

| #   | 现状                                           | 后果                         |
| --- | ---------------------------------------------- | ---------------------------- |
| 1   | 「待补」出现多次（字段区 + 正文 + 底部按钮墙） | 三重表达同一状态             |
| 2   | 按钮写「市场待补」                             | 状态当动作，不可预判点击结果 |
| 3   | 整块橙色底                                     | 警示色失效                   |
| 4   | 标题含美国站/品类，下方三项空                  | 答案在上文却要重填           |
| 5   | 事实‖判断等高且皆空                            | 可跳步写判断                 |
| 6   | 标题是疑问句「依据是什么」                     | 应是对象陈述句               |
| +   | 「尚待验证」标签 vs 「经营判断」               | 命名打架                     |

### 6.2 改造骨架

```text
┌─ {对象名} · 依据与判断 ──────────── 责任团队 ─┐
│ ① 进度头  依据完备度 ▓▓░░  必填剩 N            │
│    [⚡ 从走查样本预填]                           │
├────────────────────┬────────────────────────────┤
│ ② 已观察到 / 事实  │ ③ 经营判断（事实未齐则锁定）│
├────────────────────┴────────────────────────────┤
│ ④ 适用边界：市场/渠道/范围 选择器 + 全部确认    │
│ ⑤ 来源证据：推荐 + 带入（禁止「0 条」纯负面）   │
│ ⑥ [存草稿] [⚡预填] [→ 生成/保存经营判断]       │
└─────────────────────────────────────────────────┘
```

### 6.3 手法

1. **「待补」只留进度头一处**；删除底部状态型按钮墙。
2. **按钮动词化且就近**：字段旁「填写市场 / 选择渠道 / 添加证据」。
3. **橙色还给警报**：容器用 `--surface-2`；全页最多 **1** 处 `--warn` 指向当前唯一必填缺口。
4. **样本预填**：从标题/已有结构化字段推导市场·渠道·品类；「已自动推导」+ 一键确认。无法可靠解析则不强行假填，改为推荐候选。
5. **事实→判断依赖**：事实完备度未达门槛时，判断区灰化 + 锁定提示。
6. **标题陈述句**：`{短对象名} · 依据与判断`。

## 7. 视觉基线（以本仓库主题为准）

**唯一权威**：

1. 设计语义与令牌表：[UI_SYSTEM §7](./UI_SYSTEM.md)
2. 运行时实现：`apps/web/src/themes/logix/tokens.css`（含浅色/深色）

本规范**不定义、不覆盖、不抄写**独立色板。实现与评审只认 `var(--*)` 令牌；禁止为改版另起 hex、另造语义色，或把警示色当大面积容器底。

| 语义        | 令牌                                          | 用法                         |
| ----------- | --------------------------------------------- | ---------------------------- |
| 主色/主动作 | `--brand` / `--brand-strong` / `--brand-soft` | 主 CTA、阶段当前点、选中底   |
| 完成        | `--ok`                                        | 齐、已确认、已完成节点       |
| 唯一警示    | `--warn`                                      | 全页 ≤1 处，指向当前必动手项 |
| 风险/破坏   | `--risk`                                      | 仅失败、阻断、破坏性确认     |
| 进行中/提示 | `--info`                                      | 进行中、普通提示（非成功）   |
| 正文/次要   | `--ink` / `--ink-soft` / `--muted`            | 正文、helper、降权           |
| 表面        | `--surface` / `--surface-2` / `--ground`      | 主面、分组底、应用底         |
| 线框        | `--line` / `--line-strong`                    | 边界                         |
| 字号        | `--text-*`                                    | 禁止裸 `px` / `calc()` 字号  |
| 间距        | `--space-*`                                   | 禁止裸 `px` / `!important`   |

主题切换：只切换 `tokens.css` 下已有浅/深映射，业务页不得写死浅色假设。

## 8. 组件文案

### 8.1 按钮动词化对照

| 不合格（状态）   | 合格（动词）        |
| ---------------- | ------------------- |
| 市场待补         | 填写市场            |
| 渠道待补         | 选择渠道            |
| 商品类别待选择   | 选择商品范围        |
| 观察事实待补     | 添加事实            |
| 经营假设待补     | 填写经营判断        |
| 来源证据待补     | 添加证据 / 带入证据 |
| 仍待补（按钮墙） | 删除；改进度头      |

### 8.2 表单

- helper：**字段下方常驻灰字**；placeholder **只放示例**（如「如：美国站」）。
- 判断类：优先单选（大/中/小），补充说明才用文本框。

### 8.3 空状态三件套

禁止孤零「0 条 XX」。必须：**说明缺什么 → 推荐来源 → 一键带入/添加**。

## 9. 全量清单（打勾用）

### A. 状态一致性（优先于视觉）

- [ ] C1 必填/选填视觉区分？

- [ ] D1 同一状态是否只表达一次？
- [ ] D2 无「状态文案 / 字段区 / 按钮墙」三重重复？
- [ ] D3 页脚 ≤3 个动作且主 CTA 唯一？

### E. 动作可读性

- [ ] E1 按钮皆动词？
- [ ] E2 动作就近字段？
- [ ] E3 点击结果可预判？

### F. 色彩纪律

- [ ] F1 警示色未做大面积容器底？

- [ ] G1 上游数据可预填/带入？

- [ ] H1 有依赖的后置区在前置未完成时锁定？

## 10. 验收方法

| 方法        | 做法                | 通过标准（详情页）       | 通过标准（枢纽页）           |
| ----------- | ------------------- | ------------------------ | ---------------------------- |
| 5 秒 / 3 秒 | 扫一眼合上          | 能说出下一步唯一动作     | 能说出活主要压在哪一节       |
| 眯眼        | 模糊细节            | 仍能看出结论/进度焦点    | 第一落点是当前阶段节         |
| 动线编号    | 标 ①→⑥ / ①→③        | 无回跳、无双焦点         | 横向一次扫完、无上下回跳     |
| 遮罩        | 遮 80%              | 落点仍在第一个必填       | 仍能认出唯一高亮节           |
| 矛盾扫描    | 搜「已…」与「待补」 | 不同维分轨，或 Mode 已切 | 无「每卡同一系统能力标签」墙 |

## 12. 屏五 · 枢纽 / 管道总览页

> 实现入口：`apps/web/src/views/WorkbenchNetworkView.vue` + `workbenchNetwork.ts`。  
> **与 §2 并列**：本屏是枢纽页，不套用详情页骨架。优化目标不是「结论上提」，而是让五节管道自己说出状态。

### 12.1 病灶（6）

| #   | 现状                                                 | 后果                                            |
| --- | ---------------------------------------------------- | ----------------------------------------------- |
| 1   | 五节阶段卡等宽等权；编号+标题+说明+箭头样式一致      | 看不出「我现在在哪一节」；只能逐个读标题        |
| 2   | 卡上是「可工作 / 待接通」（系统能力）                | 缺业务状态：在办量 / 阻塞数                     |
| 3   | 绿色边框 = 已接通真实业务                            | 与「一片已核实绿」同病；绿铺满无区分度          |
| 4   | 每卡底部都有「交接」箭头                             | 每张都有 = 零信息；交接是节间关系，画在卡内错位 |
| 5   | 底部横向协同 / 费用结算 / 异常中心与主干五节同卡样式 | 流程阶段 vs 支撑模块维度不同，却视觉平权        |
| 6   | 无全局进度带                                         | 看不到整体流转与总压活量                        |

（截图右侧被涂鸦遮挡的区域不作判断。）

### 12.2 枢纽页专属骨架

```text
┌─ 业务工作台 ────────────────────────────────────────────────┐
│ ① 全局进度带                                                 │
│   在办 N · 本周流转 M · ⚠ 阻塞 K → [查看异常]               │
├─────────────────────────────────────────────────────────────┤
│ ② 主干管道（横向；连接线串联；交接标记在连接处）              │
│                                                              │
│  ①机会立项 ──⇄── ②产品主数据 ──⇄── ③供应采购 ──⇄── ④出运 ⇄─ ⑤到港
│  ▓▓▓ 收窄    │   ████ 加宽高亮  │   ░░░ 虚线     │  …        │
│  12 在办     │   6 在办 ⚠2      │   待接通/未开始 │            │
│  已完成态    │   ● 当前阶段     │               │            │
├─────────────────────────────────────────────────────────────┤
│ ③ 支撑模块区（浅灰底 `--surface-2`，与主干明确分层）          │
│   ［横向协同］［费用结算］［异常中心 ⚠K］                     │
└─────────────────────────────────────────────────────────┘
```

**动线**：① 看全局 → ② 一眼锁定当前阶段（唯一实心高亮节）→ ③ 按需进支撑模块。全程横向一次扫完，不回跳。

### 12.3 枢纽总则（H1–H3）

| #   | 总则                     | 禁止                         | 可验收                    |
| --- | ------------------------ | ---------------------------- | ------------------------- |
| H1  | **管道自述业务状态**     | 用系统能力标签当主信息       | 主信息为在办数 / 阻塞徽标 |
| H2  | **全页唯一当前阶段高亮** | 五节等权平铺；多块同时抢视线 | 不读标题也能指出当前节    |
| H3  | **交接画在连接处**       | 卡内重复放交接箭头           | 能看出哪两节之间卡住      |

### 12.4 手法（6）

| #   | 手法               | 口径                                                                                                                                              |
| --- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 卡片三态差异化     | **已完成**：收窄、降饱和、无边框强调。**进行中（当前）**：加宽约 1.4×、`--brand` 实心底、左侧竖条——全页唯一高亮。**未开始**：虚线描边、空心、置灰 |
| 2   | 业务状态替换能力态 | 删掉卡面主位的「可工作 / 待接通」；主信息改为 `N 在办` + `⚠K`。系统能力可降为管理角标或进配置页。表达优先级：**数字 > 说明文字**（说明一行灰字）  |
| 3   | 绿色只给「通」一瞬 | 禁止绿边框大面积铺开；「已接通」仅小尺寸角标 `--ok`；**已完成节不再显示接通绿**                                                                   |
| 4   | 交接上连接线       | 节间画 `⇄`；顺畅 / 卡住标在连接线上；卡内不重复箭头                                                                                               |
| 5   | 全局进度带         | 在办 N / 本周流转 M / 阻塞 K；阻塞可点进异常中心。总览第一职责是暴露异常                                                                          |
| 6   | 支撑模块分层       | 浅灰底容器 + 区标题「支撑模块」；与主干用背景分层；异常中心 `⚠` 为支撑区唯一警示锚点                                                              |

令牌纪律同 §7：表面用 `--surface` / `--surface-2`；当前节用 `--brand`；完成反馈 `--ok`；全页 `--warn` ≤1（指向异常入口）。

### 12.5 本屏不做

- 不在枢纽页做单票详情编辑（进对应详情工作台）。
- 不伪造在办/阻塞数字：无权威投影时显式「尚无业务量投影」，不得用静态假数充门面。
- 不把「框架已建立 / 交互样板」继续当卡面主标签；实施态降权为角标或说明页。

### 12.6 枢纽页专项检查清单

**阶段可见性**

- [ ] 不读标题，能否一眼看出当前处于哪个阶段？
- [ ] 五节是否做了三态差异化（已完成 / 进行中 / 未开始）？
- [ ] 全页是否只有「当前阶段」一个高亮块？
- [ ] 阶段之间是否有连接线表达顺序与流转关系？

**卡片信息有效性**

- [ ] 卡片主信息是否是业务状态（在办数 / 阻塞数），而非系统能力状态？
- [ ] 是否存在「每张卡都显示同一个标签」？（有则删或移出）
- [ ] 卡片内是否有数字，而不只是标题 + 说明？
- [ ] 说明文字是否已降权为一行灰字？

**交接与阻塞**

- [ ] 交接标记是否在连接处而非卡内？
- [ ] 能否看出「哪两节之间卡住了」？
- [ ] 阻塞数是否可点击直达异常中心？
- [ ] 顶部是否有全局指标带？

**分层与色彩**

- [ ] 支撑模块是否与主干在视觉上明确分层（背景色 / 分区标题）？
- [ ] 绿色是否还被用作边框大面积铺开？（是则改为小尺寸角标）
- [ ] 全页警示色是否 ≤1 处，且指向唯一异常入口？
- [ ] 已完成阶段是否已降饱和，不再抢夺视线？

**动线验证**

- [ ] 视线能否横向一次扫完找到落点，无需上下回跳？
- [ ] 3 秒测试：能否回答「活现在主要压在哪一节」？
- [ ] 眯眼测试：第一落点是不是当前阶段那一节？
