# 智能 Excel 导入工作流定义（P0-02 / P0-03 / P0-04）

> 状态：**已确认（初版基线）** · v0.1.2 · 2026-09-12 · 首个纵向闭环。真实现状/样本等输入按 [RAID](../../planning/RAID.md) 占位跟踪。
> 与实现一致性的锚点：[架构 §8.3 智能导入](../../architecture/AI_WORKFLOW_TECHNICAL_ARCHITECTURE.md)、统一状态机 §11、风险分级 §9。

## 1. 场景

运营人员拿到外部发来的业务表（`.xlsx/.xls/.csv`，可能含多 Sheet），需要把表内容转换为 Logix 标准业务对象并写入系统。AI 负责“建议标准字段映射与归一化”，人负责确认，系统保证确定性校验、预检与可审计写入。

**自动/审核策略（本导入闭环）：首批 AI 映射建议全部人工确认。** 这是上线期导入控制，不代表每个物流节点都审批；日常作业按风险/冲突触发复核。AI 不自动写库；自动执行仅在 P7-09 升级条件满足后、对白名单低风险项开放。

## 2. 现状与目标流程（P0-02）

### 2.1 典型现状（占位假设，现场观察跟踪中，见 RAID I-02）

```text
邮件/共享盘收到文件 → 人工打开 Excel → 逐个复制粘贴进系统表单
→ 靠经验对列名/口径 → 出错后才发现 → 无留痕难回滚
```

等待点：人工逐格核对、跨系统对口径。错误点：列对应错、格式/币种/单位不一致、重复录入、字典名不匹配。

### 2.2 目标流程

```text
上传文件（幂等键）                      -- 操作员
  -> 确定性解析：Sheet/列/类型/安全检查    -- 确定性层
  -> AI 识别列语义并建议标准字段映射       -- 能力：suggest_import_mapping（含证据/置信）
  -> 低置信度项等待人工确认               -- 审核点（全部建议均需人工确认）
  -> 确定性数据验证（必填/字典/格式/去重） -- 确定性层
  -> 生成预检报告；未通过禁止写入         -- 硬闸
  -> 事务导入（业务 API 唯一写入口）       -- 记录来源/批次/逐行结果
  -> 自动对账：展示成功/跳过/失败         -- 对账报告
```

参与者与系统：导入操作员（Web）、审核主管（Web）、Logix API、Import Workflow（Temporal）、AI Service（映射建议）、PostgreSQL/MinIO（存储）。写入只经业务 API。

## 3. 输入 / 输出

### 输入

- 文件：多 Sheet `.xlsx/.xls/.csv`；行数/列数/大小默认上限见 [NFR](../NON_FUNCTIONAL_REQUIREMENTS.md) §3。
- 目标字段模板：本次导入要落到哪一类标准对象与字段集合（业务管理员维护）。
- 来源标识与幂等键：同一来源+文件指纹重复上传应被识别。

### 输出

- 导入批次与逐行结果（含错误原因/来源追溯）。
- 映射建议列表（源列 → 标准字段、证据、置信度、差异标记）。
- 预检报告（通过与失败，失败项给出原因与修复路径）。
- 对账差异报告（成功/跳过/失败，可回查批次）。
- 审计：操作者、原因、前后值摘要（写操作）。

## 4. 人工审批点（全部人工策略下）

1. 低置信度或冲突的**列映射建议**：人工确认/修正后才进入下一步。
2. **预检失败项**：不提供“忽略强制校验”的绕过开关；必须修正源或模板后重试。
3. 高影响写入（L3 语义）：由业务 API 按审批令牌执行，AI 不绕过。

批次状态主路径（本段是状态码唯一权威，与 §2.2 叙事一致）：

`pending → running → awaiting_review → awaiting_precheck → approved → executing → completed`

任意阶段可进入 `failed / rejected / cancelled / expired`。

| 状态                | 含义                               |
| ------------------- | ---------------------------------- |
| `pending`           | 批次已建，文件验收中或刚入队       |
| `running`           | 确定性解析或生成映射建议           |
| `awaiting_review`   | 映射建议待人工确认（首批全部确认） |
| `awaiting_precheck` | 映射已确认，待预检或预检进行中     |
| `approved`          | 预检无 blocker，允许执行写入       |
| `executing`         | 经业务写端口逐行落账               |
| `completed`         | 对账齐全                           |

顺序不得颠倒：没有已确认的列映射，不能对行值做预检。废止 `awaiting_validation`（曾出现在架构一览：既与上传期 `VALIDATION_*` 撞名，又把预检放在审核之前）。

## 5. 异常路径与处理

| 异常                           | 处理                                       | 是否可重试   |
| ------------------------------ | ------------------------------------------ | ------------ |
| 解析失败/类型不符/安全扫描拦截 | 批次标 failed，报告原因                    | 修源后重试   |
| 未识别列/列冲突                | 该列建议置低置信，待人工映射               | 是           |
| 字典值无匹配                   | 进待处理队列，不擅自生成含糊字典项         | 人工补主数据 |
| 重复行/重复批次（幂等键命中）  | 标记重复，不重复写入                       | 拒绝并说明   |
| 模型不可用/超时                | 明确降级：可人工映射或失败关闭，不错误写入 | 是           |
| 部分行失败                     | 事务级隔离，逐行结果落库，成功行可单独对账 | 是           |
| 用户取消/批次超时              | 取消或 expired，可重建批次                 | 是           |

## 6. 验收示例（P0-06）

| 场景                            | 期望结果                                                 |
| ------------------------------- | -------------------------------------------------------- |
| 同义列：`ETD` 与 `预计离港时间` | 都建议到同一标准字段，低置信项待人工确认                 |
| 字典归一：`Yantian` / `盐田`    | 归一同一主数据并附别名依据；无法判断时返回待确认而非硬猜 |
| 必填缺失/币种缺失               | 预检报告标红，禁止写入                                   |
| 相同幂等键重复提交              | 识别为重复，不产生脏数据                                 |
| 模型全部不可用                  | 能人工映射或明确失败，错误写入率为 0                     |

## 7. 本闭环“完成”的非功能要求

- 全链路关联 Trace（浏览器→API→Workflow→AI→写库）。
- 任意成功写入可回溯到来源批次与操作者。
- 错误写入率为 0（人工确认+校验+对账兜底）；超过阈值立即停写并告警（P8）。
- 容量/延迟目标见 NFR（初版基线，P8 校准）。
