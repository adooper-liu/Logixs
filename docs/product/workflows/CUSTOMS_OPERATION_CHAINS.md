# First Mile 货柜物流运营证据链（7 组闭环）

> 状态：**负责人业务规则 + 系统映射候选 v0.3** · 2026-09-06 · 来源：负责人业务描述（First Mile/清关环节“如何做好 + 数据如何驱动”）。
> 一句话：原表单用于识别计划、执行、状态、周期、费用、异常和会议之间的业务证据关系；目标系统在统一数据模型上提供角色视图，不照搬七组表单结构。**柜号是跨表业务追踪线索，不是永久主键**。
> 🗣️ 白话：一套环环相扣的表——先排计划，再记有没有做到，柜子到哪、花多久、花多少钱，出了问题怎么回流——最后开会看数据定下一年，转回来再排计划。
> 七组定义以 [PRINCIPLES §1.6](../PRINCIPLES.md) 为单一权威；本文只记录 First Mile/清关实例与表单依赖。

## ① 可落库清单：7 组表单（组/表/一句话/关系）

| 组               | 表/流                                                                                                                             | 一句话               | 关系                                                                    |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------------- | ----------------------------------------------------------------------- |
| ① 计划·能力分解  | 年度资源计划 → 月度能力分解(载体待定) → 周清关计划(+货柜信息·清关) → 货柜到港计划(目的港条件) → 周/日拖卡卸柜计划(+货柜信息·物流) | 做什么、用多少运力   | 年度清关行/拖车资源逐层分解到月/周/日；到港计划是拖卡卸柜计划的前置输入 |
| ② 执行·达成跟踪  | 货柜信息表(清关/物流) → 物流状态跟踪 → 周拖卡卸柜跟踪 → 周日计划与达成报表                                                        | 计划→执行→计划vs达成 | 计划表单→执行明细→达成比对                                              |
| ③ 生命周期状态链 | 出运货柜 → 在途&到港货柜 → 查验报表/记录 → 货柜入库交接                                                                           | 一柜一档：柜子走到哪 | **主数据流**，按货柜记录首尾相连、柜号供业务追踪；④⑤从此取数            |
| ④ 周期时效分析   | 海运周期 + 清关拖卡周期 + 卸柜周期                                                                                                | 三段拼=完整运输周期  | KPI(到港→提柜天数)来自③时间戳                                           |
| ⑤ 费用结算       | 清关拖卡实际费用汇总(正常费用) + 超期费用(Demurrage/Detention/Storage，按月/柜/柜·天投影)                                         | 花了多少钱           | 正常费用+已确认超期费用=单柜总成本；底数关联③事件、合同规则与账单       |
| ⑥ 异常与反馈     | 退运分析 + 异常清关处理 + 收费标准更新                                                                                            | 出问题怎么办         | 异常处理结果、费用差异与根因回流①年度资源/规则/价格                     |
| ⑦ 会议机制       | Sub./HQ 物流例会、供应商月度会议                                                                                                  | 报表、绩效与改善决策 | 读取③④⑤⑥并产生有负责人/期限的决议，闭环回①                              |

### 1.1 表单前后依赖（不是并列菜单）

| 上游表单/事实                    | 下游表单/动作       | 传递内容                                        | 约束                                        |
| -------------------------------- | ------------------- | ----------------------------------------------- | ------------------------------------------- |
| 年度资源计划                     | 月/周清关计划       | 清关量、清关行/拖车能力、目标与容量缺口         | 逐层分解后总量与能力口径须可对账            |
| 周清关计划 + 货柜到港计划        | 周/日拖卡卸柜计划   | 可安排货柜、目的港条件、预计/实际到港、清关条件 | 未满足到港/可提等前置条件时不得伪装为可执行 |
| 计划表单                         | 货柜执行明细/任务   | 货柜、服务商、责任人、计划日期和所需资料        | 每条任务关联货柜记录与节点                  |
| 执行明细/任务结果                | 计划与达成报表      | 已确认动作、实际日期、未达成原因                | 未同步或业务校验未通过不计达成              |
| 出运/在途/到港/查验/入库交接事实 | 周期与费用投影      | 节点实际时间、事件、来源和证据                  | ④⑤只读③的权威事实，不另填一套时间           |
| 周期/费用偏差                    | 异常处理            | 超时、滞港、异常费用及影响                      | 异常独立跟踪，不覆盖货柜状态                |
| 状态/周期/费用/异常              | 例会与供应商月会    | KPI、明细、责任与趋势                           | 指标可下钻到柜、节点、任务和证据            |
| 会议决议/异常根因                | 下一轮年度/月周计划 | 资源、供应商、规则、价格和改进动作              | 决议必须有负责人、期限与关闭证据            |

## ③ 领域口径对齐（防止表单定义反向污染主模型）

1. **贯穿线索，不是数据库主键**：柜号是装箱后至卸柜前跨表追踪的业务线索；系统内部使用稳定 `containerRecordId` 关联，保留备货单号建档锚。不得把柜号复制成各表独立事实或假定其全局永久唯一。
2. **“查验/入库”是运营表单链位置**：查验映射为清关事件/异常；“入库”=卸柜后的 WMS 收货交接。二者不新增货柜主状态码，货柜主链仍继续到卸空和还箱。
3. **超期费用口径**：Demurrage、Detention、Storage 按各自合同选择起止事件、免费期、日历、阶梯与账单权威，详见 [FEE_DEMURRAGE](../domain/FEE_DEMURRAGE.md)；未评审前不把简化公式写死。按月/柜/柜·天只是同一已确认底数的三种投影。
4. **到港计划包含目的港条件**：它不仅是一列日期，还为拖卡/卸柜计划提供港口能力、可提、放行等前置条件；具体条件清单待 W4/W10 与样本确认。
5. **人工复核按风险/冲突触发**：来源冲突、关键证据缺失、密封历史纠正、重大费用差异和需独立验证的异常关闭可以触发复核；同值重复、幂等重放和规则可确定的低风险动作不审批。具体等级、阈值与权限仍待样本定稿。
6. **会议不是作业表单流**：Sub./HQ 例会和供应商月度会议只读取③④⑤⑥的报表/绩效投影，并输出决议、责任人与期限；不产生另一套货柜状态或周期/费用底数。
7. **表单是 `R` 级证据，不是目标表结构**：保留其字段、责任、动作、前后依赖和统计口径作为迁移输入；相同货柜事实只入统一对象一次，再投影为任务视图、计划视图和管理视图，禁止让员工跨表重复填报。
8. **闭环不是固定收数顺序**：权威状态事件可先到、任务后补；撤船、甩柜、查验、返工和外部更正形成分支。系统按发生时间、来源权威与更正关系重放投影，并把缺口/冲突送对账或人工纠偏。

## ④ 闭环数据流

```text
年度资源/供应商能力 → 月/周/日计划与柜级分配 → 任务/动作
          ↑                         ↓              ↓
下一轮计划 ← 会议决议 ← 分析投影 ← 一柜一档事件事实 ← 外部权威事件
                       ↑              ↕
                  异常/返工/纠正 ← 对账与人工纠偏
```

箭头表达业务依赖，不要求数据严格按箭头到达；投影应能从不可变事件和更正记录重建。
