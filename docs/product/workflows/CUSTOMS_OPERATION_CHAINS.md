# 清关环节运营表单链（7 组闭环）· 收录与映射

> 状态：**候选（业务素材收录）** · 2026-09-05 · 来源：负责人业务描述（清关环节"如何做好 + 数据如何驱动"）。
> 一句话：计划(①)→执行跟踪(②)→状态沉淀(③)→周期·费用(④⑤)→异常反馈(⑥)→会议复盘(⑦)→回年度计划，构成闭环；**柜号是所有表单共享的主键**。
> 🗣️ 白话：一套环环相扣的表——先排计划，再记有没有做到，柜子到哪、花多久、花多少钱，出了问题怎么回流——最后开会看数据定下一年，转回来再排计划。

## ① 可落库清单：7 组表单（组/表/一句话/关系）

| 组 | 表/流 | 一句话 | 关系 |
| --- | --- | --- | --- |
| ① 计划·能力分解 | 年度资源计划 → 周清关计划(+货柜信息·清关) → 周/日拖卡卸柜计划(+货柜信息·物流) → 货柜到港计划(目的港条件) | 运力逐层分解到周计划 | 到港计划=卸柜前置(船到港才能派拖卡) |
| ② 执行·达成跟踪 | 货柜信息表(清关/物流) → 物流状态跟踪 → 周拖卡卸柜跟踪 → 周日计划与达成报表 | 计划→执行→计划vs达成 | 计划表单→执行明细→达成比对 |
| ③ 生命周期状态链 | 出运货柜 → 在途&到港货柜 → 查验报表/记录 → 货柜入库 | 一柜一档：出运→在途→查验→入库 | **主数据流**，按柜号首尾相连；④⑤从此取数 |
| ④ 周期时效分析 | 海运周期 + 清关拖卡周期 + 卸柜周期 | 三段拼=完整运输周期 | KPI(到港→提柜天数)来自③时间戳 |
| ⑤ 费用结算 | 正常费用汇总 + 滞港费 ×3(按月/柜/柜·天) | 单柜总成本=正常+滞港 | 滞港费=(提柜−到港)×费率，依赖③时间 |
| ⑥ 异常与反馈 | 退运分析 + 异常清关处理 + 收费标准更新 | 异常与费用回流年度计划 | 闭环回① |
| ⑦ 会议机制 | Sub/HQ 例会、供应商月度会 | 读③④⑤做月度复盘决策 | 消费端 |

## ③ 需要对齐的口径（据此回写设计，待确认）
1. **"入库"语义**：该链把终点定为"货柜入库"（查验后入仓）。与我们 L14 的"入库归 WMS、非容器主链"要拉齐——建议：**"入库"= 卸柜后 WMS 收货确认(交接终)**；"还箱/卸空"仍属容器链，若该环节实际不做可不在此链展开。
2. **滞港费公式与口径**（应写入 PRINCIPLES P4 / 费用字段）：
   - 公式：`滞港费 = max(0, 提柜时间 − 到港时间 − 免费期) × 日费率`（此处描述"到港→提柜差×费率"，免费期另核）
   - 三种聚合：按月 / 按柜 / 按柜·天——同一底层(时间+费率)三种投影。
3. **③ 查验节点**：链内有"货柜查验报表/记录"——对接 EVENT `inspection` + 五主体(海关) 与 文件对象（此前 D3 待深化）。
4. **计划到港=目的港条件**：对应 港口能力/必填与条件配置（W4/W10），而非简单日期。
