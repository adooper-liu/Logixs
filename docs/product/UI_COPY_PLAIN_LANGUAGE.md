## 0. 这一刀改什么、不改什么

现场员工、计划和经理对着屏幕说话。字要能从嘴里说出来：装箱、提柜、卸柜、记下了。API、工单、落账、投影、规范事件留在接口和文档里。

- **改**：按钮、页题、状态短标签、任务说明、空态、回执三阶段的**屏幕字**；以及任务/子任务要讲清的目的、内容、步骤、风险、时间。
- **不改**：视觉令牌、侧栏结构、API 码、数据库列、契约 ID。调试页 `/real-tasks` 本来就不进作业导航，本稿只点名，不把它当产品入口。
- **同一件事只用一个动词**走完全程。固定动词链：**待领取 → 领取 → 已领取 → 进行中 → 完成工单 → 已入账**。不要按钮「领取」、提示「已落账」两套说法并存。
- **任务不是改个名就完**：队列和详情都要能回答五个问题。缺数据就空着或写「还没有」，不准编。

## 8. 任务和子任务要讲清什么

上一节是换词。这一节是**一张任务该长什么样**。你点的目的、内容、步骤、风险、时间，按现场作业的常见做法收成五个问题。契约里仍叫 NodeTask / WorkOrder，屏幕上不出现这两个词。

### 8.1 屏幕上的两层（不要叫工序子任务 / 作业工单）

| 契约对象  | 屏幕怎么叫        | 人问的那一句     | 现在产品路径                                       | 你的叫法 | 采用 |
| --------- | ----------------- | ---------------- | -------------------------------------------------- | -------- | ---- |
| NodeTask  | 任务              | 这一站要达成什么 | 任务台左侧列表 + 右侧标题                          |          |      |
| WorkOrder | 子任务 / 眼前这件 | 眼前具体干什么   | 现在多半只有一颗「完成工单」按钮，看不出这是一件活 |          |      |

一层只回答一层：

- **任务**：目的、这柜、该完的时间、整站风险、子任务进度。
- **子任务**：内容、干活步骤、这件自己的截止、这件自己的险、报完成。

点「报完成」只结束眼前这件。这一站齐了，任务自己合上。不要一颗按钮既像完成子任务又像完成这一站。

### 8.2 五个问题（现场一眼要能答）

来源是现场工单/仓配作业的常见结构（做什么、在哪、何时、为何、怎么做、有什么险），再对齐本仓库已有约束：标题回答结果（UI_SYSTEM §9.3）；人工、系统和等待不要塞成同一条步骤（NODE_PDCA 对 BPMN 的采纳）；对象、时间、地点、步骤、来源要分得开（GS1 事件语义的原则）。**不是新状态机**，只规定屏幕上必须出现哪些人话。

| 问题       | 人话栏名   | 任务上写什么                  | 子任务上写什么                        | 现在实际                              | 建议                                                                                             | 你的改法 | 采用 |
| ---------- | ---------- | ----------------------------- | ------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------ | -------- | ---- |
| 要达成什么 | 目的       | 这一站做成什么样，用结果说话  | 可省略；继承任务目的                  | 标题经常只是站名「装箱定稿」          | 任务标题＝目的：「装箱完成」；站名单独一行叫「装箱」                                             |          |      |
| 具体干什么 | 内容       | 一句总括，或列出子任务短名    | 这一件要干的事（核对封号、卸完实收…） | 通用句「完成可执行工单」              | 子任务写具体活，不写系统词                                                                       |          |      |
| 做到哪了   | 步骤       | 子任务进度：1/2 件已记下      | 这一件的干活步骤 + 记下三步           | 步骤条是领取/前置/资料/证据/提交/落账 | 拆成两条，见 8.3                                                                                 |          |      |
| 有什么险   | 风险与预警 | 整柜/整站：超期、查验、危险品 | 这一件：缺封号、柜号不符、短少        | 真任务常空；演示才有风险字            | 有就直说；没有就不占位。预警（快到期）和风险（已经出事）分开颜色也分文字                         |          |      |
| 何时该完   | 时间       | 这一站该完、已经过了多久      | 这一件窗口/截止                       | 真任务「无截止」                      | 有计划/免费期/预约就写；没有写「没有截止」，不要编。临近用「还剩 4 小时」，逾期用「已过 2 小时」 |          |      |

还可以按需出现、但不要挤进标题的：

| 栏           | 何时出现       | 建议说法                                                 | 你的改法 | 采用 |
| ------------ | -------------- | -------------------------------------------------------- | -------- | ---- |
| 原因         | 为什么派了这件 | 「到港了，还没核对能不能提柜」                           |          |      |
| 还缺什么     | 前置没齐       | 「海关还没放行」                                         |          |      |
| 单证和照片   | 这一件必须留证 | 「箱封照片、装箱清单」                                   |          |      |
| 做成了会怎样 | 是否推进货柜   | 「记下后这一柜变成已装箱」或「只记下结果，货柜状态不动」 |          |      |
| 干不下去     | 次要入口       | 「这件做不了」                                           |          |      |

### 8.3 两条步骤，不要拧成一条

现在任务台中间那条「领取 → 前置 → 资料 → 证据 → 提交 → 落账」是**系统准备度**，不是装箱/卸柜的干活顺序。现场会把它理解成作业 SOP，对不上。

| 条       | 回答             | 谁在变                   | 建议屏幕名 | 例子                                  | 你的改法 | 采用 |
| -------- | ---------------- | ------------------------ | ---------- | ------------------------------------- | -------- | ---- |
| 干活步骤 | 这一件现场怎么干 | 随任务定义变；没有就不画 | 怎么做     | 核对柜号 → 装货点数 → 拍封号 → 报完成 |          |      |
| 记下步骤 | 系统接没接住     | 几乎每件都有             | 记下了没有 | 接下 → 报上去 → 记下                  |          |      |

规则：

1. 干活步骤来自这件的定义，没有就不要画空条。监控类任务（盯到港）可以没有干活步骤。
2. 记下步骤始终是收到 / 接下 / 记下，只有报过之后才展开，空闲不占位（现网已如此）。
3. 不要把「我来做」画成装箱的第一步。

### 8.4 列表和详情各看什么

**待我处理（列表）** 一行要能扫：目的、柜、时间、险。不要把完成标准铺在列表里。

```text
装箱完成                          还没人接
MSKU1234567 · 装箱                今天 16:00 该完
⚠ 免费期还剩 4 小时
```

**点开之后（详情）** 建议块序，仍服从 UI_SYSTEM「同一时刻只突出一件」：

```text
装箱 · 我在做
装箱完成                         目的
这一柜按清单装好，记下箱号封号     内容（若有多件，下面列子任务）

MSKU1234567  场站 A              对象
今天 16:00 该完 · 还剩 4 小时     时间
⚠ 超限货，封号必须拍照            风险

子任务 1/1  核对箱号封号并报完成   眼前这件
怎么做  ①柜号  ②点数  ③封号  ④报完成
[ 报完成 ]

记下了没有   收到 · 接下 · 记下    报完才出现
```

| 块                                                  | 现在                              | 建议                                                                                             | 你的改法 | 采用 |
| --------------------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------ | -------- | ---- |
| 列表截止                                            | 有截止才显示；真任务常「无」      | 有则写「今天 16:00 该完」；没有写「没有截止」                                                    |          |      |
| 列表风险                                            | 有 `task.risk` 才显示；真任务常空 | 有预警/风险才占一行，空不占位                                                                    |          |      |
| 详情「原因 / 下一步 / 完成标准 / 安全边界」四段常驻 | 真任务被通用工单句填满            | 目的进标题；内容一句；完成标准只在未完成且不与内容重复时出现；安全边界改叫「小心」且仅有险时出现 |          |      |
| 「落账后推进货柜 / 不推进货柜」                     | 系统口径，还带结果事件码          | 「记下后这一柜变成已装箱」或「只记下，货柜状态不动」                                             |          |      |
| 子任务列表                                          | 几乎看不见，只剩按钮              | 多件时列出短名+状态；一件时标题即内容                                                            |          |      |

### 8.5 样例：装箱（给人看结构，不是正式公式）

下面用目录站名「装箱」。若你在第 3 节把站名改成「装箱完成」，这里跟着改。拆分粒度来自 NODE_PDCA 候选，**不能当 Seed**。

**任务**

| 栏   | 建议写                               | 你的改法 | 采用 |
| ---- | ------------------------------------ | -------- | ---- |
| 目的 | 装箱完成                             |          |      |
| 内容 | 按清单把货装进这一柜，箱号封号对得上 |          |      |

**子任务（候选拆法，供你删改）**

| 子任务目的 | 内容                                 | 干活步骤                   | 风险与预警                     | 时间       | 你的改法 | 采用 |
| ---------- | ------------------------------------ | -------------------------- | ------------------------------ | ---------- | -------- | ---- |
| 安排好再装 | 空箱、场地、人到位                   | 不画或只显示缺口           | 没有空箱 / 危险品条件不够      | 计划开装前 |          |      |

### 8.6 时间和风险怎么说（有数才写）

| 情况             | 不要写           | 建议写                               | 你的改法 | 采用 |
| ---------------- | ---------------- | ------------------------------------ | -------- | ---- |
| 有预约/计划窗    | 截止 09-16 08:00 | 今天 16:00–18:00 送仓                |          |      |
| 有最晚提柜/还箱  | 无截止           | 最晚明天 12:00 前提柜 · 还剩 18 小时 |          |      |

| 监控任务         | 待领取           | 不用你点 · 等到港记下                |          |      |

真任务路径现在 `dueAt`、原因、风险经常是空的。界面先把栏位留对；**没数就显示「没有截止」或整栏不出现**，等计划/超期端口有数再填。不准为了版面好看去编 16:00。
