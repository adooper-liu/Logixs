# 产品简报（P0-01 / P0-06）

> 状态：**已确认（初版基线）** · v0.1.5 · 2026-09-06。建议默认值已由业务方确认采用，P7 评测 / P8 实测校准前有效；真实输入项（现场观察、黄金样本）按 [RAID](../planning/RAID.md) 占位跟踪，不阻塞推进；负责人：刘志高。

## 1. 产品愿景

Logix 以货柜为核心业务对象，把从备货单到还空箱的主流程、员工任务作业和管理改善连成高可视化 PDCA 工作系统。员工以任务为入口，完成工作物料领取、扫描作业、报工和一键异常上报；系统负责减少信息查找与重复录入。AI 嵌入具体工作步骤，而不是做成与业务割裂的对话窗口。

**可靠性是硬约束**：流程实例、工序任务、作业工单、数据同步和数据状态独立记录；工单结果按规则聚合为工序任务结果，只有合法实际事件才推进主流程。权威关系见 [PRINCIPLES](./PRINCIPLES.md) §1。

每个主流程节点统一按“计划与能力、执行与达成、货柜状态、周期、费用、异常改善、会议复盘”七组 SOP 组织；清关/First Mile 是第一个完整样板，权威规则见 [PRINCIPLES](./PRINCIPLES.md) §1.6。

产品形态：**内部自用为主，数据与权限按多租户建模预留 SaaS 化能力**。当前用“已出运货柜列表”的文件导入与审核建立可靠数据起点；导入能力保持通用，但首个业务对象已经收敛为已出运货柜。

## 3. 核心问题

1. 外部发来的业务表列名/口径/格式不统一，靠人工复制粘贴进系统，耗时且易错。
2. 无统一预检与留痕：错误数据进了业务库才发现，缺来源与回滚依据。
3. 列映射、值归一化（同义词、字典别名）等判断适合 AI 辅助，但需要“建议可解释、写入可审计”。

## 4. 明确不做（首批范围外）

- 不做统一聊天入口承载所有 AI 能力；能力必须紧贴业务对象展示。
- AI 不自主删除、不变更权限、不确认费用、不向未知对象发送通知（L4 禁执）。
- 不无证据自动写库：首批所有映射/建议均需人工确认后由确定性流程写入。
- 首版不承诺万行流式与任意复杂版式；规模上限默认值见 NFR §3（初版基线，P8 校准）。

## 5. 首个数据接入闭环：智能 Excel 导入与审核

定义见 [IMPORT_WORKFLOW](./workflows/IMPORT_WORKFLOW.md)。当前业务用例：运营人员上传包含已出运货柜的多 Sheet `.xlsx/.xls/.csv` 业务表 → 系统确定性解析列结构 → AI 给出标准字段映射建议并附证据/置信 → 后端执行确定性校验与预检 → **低置信度与高风险项全部由人确认** → 通过后事务导入 → 自动对账展示成功/跳过/失败 → 形成可追溯的已出运货柜列表。

该闭环解决可靠建档与数据进入问题，为主流程节点提供基础数据，不替代产品的员工任务入口。UI 框架的首条作业验证链为：获取任务上下文 → 校验前置条件 → 执行适用动作并采集必要证据 → 提交结果或异常 → 服务端三段确认 → 产生合法业务事实后更新主流程。领取、工作物料和扫描只是可选能力，不是统一步骤。

## 6. 成功标准（用数字判断）

P0 门禁：团队能用同一套词汇描述该闭环，并能用数字判断成功与否。可量化目标（初版基线，见 [NFR](./NON_FUNCTIONAL_REQUIREMENTS.md)）：

- 映射准确率 Top-1 与关键字段漏提率、人工修改率满足 P7 评测门禁。
- 预检未通过的批次不得写入业务表（硬约束）。
- 错误写入率目标 0（人工确认 + 事务写入 + 对账兜底）。
- 导入全流程耗时与单批次 AI 成本在预算内。
- 任意写入可追溯来源批次、逐行结果与操作者。

| 示例     | 输入                              | 期望结果                               |
