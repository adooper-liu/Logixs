# 产品简报（P0-01 / P0-06）

> 状态：**已确认（初版基线）** · v0.1.1 · 2026-09-04。建议默认值已由业务方确认采用，P7 评测 / P8 实测校准前有效；真实输入项（现场观察、黄金样本）按 [RAID](../planning/RAID.md) 占位跟踪，不阻塞推进；负责人：刘志高。

## 1. 产品愿景

Logix 把 AI 嵌入物流业务的具体工作流步骤，而不是做成与业务割裂的对话窗口。**可靠性是硬约束**：AI 参与业务流程，但不拥有业务事实和最终执行权。系统让“低质、异构的业务表（Excel/CSV）进入系统”这一高频环节变得可预测、可审计、可回滚。

产品形态：**内部自用为主，数据与权限按多租户建模预留 SaaS 化能力**；首个闭环不绑定某一家物流子域，按“通用结构化导入 + 审核”落地，由具体用例逐步收敛。

## 2. 目标用户与角色（默认清单采用；具体人选随 RAID 指定，跟踪中）

| 角色 | 职责 | 首批范围 |
| --- | --- | --- |
| 导入操作员 | 上传文件、查看映射建议、逐项确认/修正 | 是 |
| 审核主管 | 复核高影响写入、异常与升级处置 | 是 |
| 业务管理员 | 主数据字典、字段模板、权限与阈值配置 | 是 |
| 数据分析/合规 | 对账、导出、审计追溯 | 后续 |

## 3. 核心问题

1. 外部发来的业务表列名/口径/格式不统一，靠人工复制粘贴进系统，耗时且易错。
2. 无统一预检与留痕：错误数据进了业务库才发现，缺来源与回滚依据。
3. 列映射、值归一化（同义词、字典别名）等判断适合 AI 辅助，但需要“建议可解释、写入可审计”。

## 4. 明确不做（首批范围外）

- 不做统一聊天入口承载所有 AI 能力；能力必须紧贴业务对象展示。
- AI 不自主删除、不变更权限、不确认费用、不向未知对象发送通知（L4 禁执）。
- 不无证据自动写库：首批所有映射/建议均需人工确认后由确定性流程写入。
- 首版不承诺万行流式与任意复杂版式；规模上限默认值见 NFR §3（初版基线，P8 校准）。

## 5. 首个纵向闭环：智能 Excel 导入与审核

定义见 [IMPORT_WORKFLOW](./workflows/IMPORT_WORKFLOW.md)。一句话：运营人员上传多 Sheet 的 `.xlsx/.xls/.csv` 业务表 → 系统确定性解析列结构 → AI 给出标准字段映射建议并附证据/置信 → 后端执行确定性校验与预检 → **低置信度与高风险项全部由人确认** → 通过后事务导入 → 自动对账展示成功/跳过/失败。

## 6. 成功标准（用数字判断）

P0 门禁：团队能用同一套词汇描述该闭环，并能用数字判断成功与否。可量化目标（初版基线，见 [NFR](./NON_FUNCTIONAL_REQUIREMENTS.md)）：

- 映射准确率 Top-1 与关键字段漏提率、人工修改率满足 P7 评测门禁。
- 预检未通过的批次不得写入业务表（硬约束）。
- 错误写入率目标 0（人工确认 + 事务写入 + 对账兜底）。
- 导入全流程耗时与单批次 AI 成本在预算内。
- 任意写入可追溯来源批次、逐行结果与操作者。

## 7. 关键示例（验收口径，具体以评审为准）

| 示例 | 输入 | 期望结果 |
| --- | --- | --- |
| 同义列 | 列头 `ETD` 与 `预计离港时间` 并存 | 均映射到同一标准字段，差异项待人工确认 |
| 字典归一 | `Yantian` / `盐田` | 归一为同一港口主数据，给出别名依据 |
| 重复提交 | 相同来源+幂等键再次上传 | 识别为重复，不产生脏数据 |
| 预检拦截 | 必填缺失/币种缺失 | 预检报告标红，禁止写入 |
