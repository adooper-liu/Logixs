### 1.1 三类费用不得混算

| 类型      | 常见责任区间（仅作识别）        | 起止事件与免费期                          | 权威依据                            |
| --------- | ------------------------------- | ----------------------------------------- | ----------------------------------- |
| Demurrage | 重箱在码头/场站内超期           | 按合同选择卸船、可提等起点及提离场等截止  | 船司/码头生效费率与账单；具体规则 C |
| Detention | 设备提离场后在场外超期使用      | 按合同选择提柜、还空箱等事件              | 船司设备使用条款与账单；具体规则 C  |
| Storage   | 码头/仓储方对货物或场地占用收费 | 由码头/仓库规则定义，未必与设备免费期相同 | 码头/仓储方费率与账单；具体规则 C   |

“常见责任区间”不能直接生成费用；最终必须以适用合同、地点、责任主体、箱型、事件证据和账单为准。

## ④ 计算口径（框架 O；具体参数 C，待样本定稿）

- **规则选择维度**：费用类型、收费主体/合同、港口/码头/仓库、箱型、运输方式、生效区间、起算事件、截止事件、免费期、自然日/工作日、首尾日是否计费、阶梯区间、费率和币种。缺少匹配规则时必须阻断预计或进入复核，禁止套系统默认值静默算账。
- **计费天数**：先按合同选择起止事件，再按免费期、日历和首尾日规则展开可计费日期；不能统一写死为日期相减。
- **阶梯费用**：按每个可计费日期命中的费率阶梯分别计算后求和；不得假设全程单一日费率。金额使用定点十进制并携带币种，跨币种汇总另需汇率来源与日期。
- **暂停/豁免/争议**：海关查验、码头原因、节假日或合同豁免是否暂停计费由合同规则决定；未知时保留争议项，不自动减免。
- **预计 vs 实际（关系）**：同一引擎、两种输入——
  - **预计费用**：用计划/预计/已发生事件 + 生效标准前瞻计算，用于事前预警；它是投影，不是应付事实；
  - **计算应计**：用实际事件 + 生效标准计算系统认为应收/应付的金额，用于对账；
  - **账单金额**：来自收费主体单据；**审核确认金额**来自内部对账/审批；**支付事实**来自财务系统或其回执。
  - 关系：四者并存并记录差异，不能用账单覆盖系统应计，也不能把审核通过写成已支付。
- **三种聚合**（同一底层）：按柜（单柜明细）/ 按柜·天（天级计费日）/ 按月（月度汇总）——仅投影不同，不重复存。

## ⑤ 其它口径/注意

- 依赖③组的权威事件时间与合同/费率标准；到港→提柜只能作为部分 Demurrage 风险观察区间，不能代表 Detention 或 Storage 的统一计算区间（PRINCIPLES P8：禁止单公式固化）。
- 正常费用(清关拖卡汇总) + 已确认超期费用 = 单柜总成本；超期费用是“预计可归零”的杠杆类费用（PRINCIPLES P4）。
- 五主体中 `运费 SRSD/SRSE` 是"运费未结放行"状态，与本费不同（FIVE_PARTY 保留）。

## ⑦ 白话注解（🗣️）

🗣️ 一句话：先问“收的是什么费、谁按哪份合同收、从哪个事件到哪个事件、哪些天免费、后面是否涨价”，再逐日计算；系统算的预计、系统应计、对方账单、内部确认和财务支付各自留账，最后才能解释差异。
