# 时间链与状态链一致性规范（LIFECYCLE_CONSISTENCY）

> 状态：**候选（初稿，待 P2 评审）** · v0.1 · 2026-09-04 · 负责人：刘志高。
> 定位：把负责人给出的全流程**时间链 / 状态先后序列 / 状态验证序列**的完整性逻辑系统化：
> 备货、出运、离港、海运、中转、目的港、海铁联运、拖卡、送仓、卸柜、卸空、还箱、入库。
> 原则句：**下一节点时间不能小于前一节点时间；下一状态已更新后，不可再更新前面状态的时间。**
> 关联：[CONTAINER_LIFECYCLE](./CONTAINER_LIFECYCLE.md)（阶段链）、[CONTAINER_STATUS_MODEL](./CONTAINER_STATUS_MODEL.md)（状态权威）、[INTEGRATION_BOUNDARIES](./INTEGRATION_BOUNDARIES.md)（来源权威）、AS-IS [快照](./AS_IS_LEGACY_BASELINE.md)。

## 1. 目标

保证每条货柜流转记录（ContainerRecord）在**多源、分时、迟绑定**写入下，其时间与状态始终构成
自洽的顺序序列：不出现时间倒挂、状态回退、改写已发生历史，且每次更新都符合来源权威。

## 2. 规范节点列表 L（已定稿 2026-09-04）

起运侧三级分工（装箱/出运/离港分开）、清关单列、卸空独立、入库归 WMS。容器主链 14 节点（2 个可选）；`入库` 不在容器主链。

| # | 节点 | 可选 | 主链状态 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 备货 | 否 | `not_shipped`（计划） | 备货完成/期望出运 |
| 2 | 装箱 | 否 | `not_shipped`（已装未出） | 装柜定稿：真实重量/件数/体积/封号、**箱号迟绑定起点**；前置事件=提空箱 |
| 3 | 出运 | 否 | `shipped`（已发运/装船确认） | 与装箱、离港分开 |
| 4 | 离港 | 否 | `shipped`（离港） | 船实际离港（atd） |
| 5 | 海运 | 否 | `in_transit` | 航行 |

## 3. 时间链规则（候选）

- **R0 时间术语**：按外部规范统一 `S计划 / E预计 / A实际 × TD离 / TA抵`（`std/etd/atd`、`sta/eta/ata`）；预计 ETD/ETA 不得当计划用（对标 [INDUSTRY_STANDARDS_ALIGN](./INDUSTRY_STANDARDS_ALIGN.md) P1，候选）。
- **R1 时间单调**：沿 L 相邻节点的实际时间满足 `t(k+1) ≥ t(k)`；等值允许（如同日多事件）。
  违反（下一节点时间 < 前一节点）→ 更新拒绝，进对账/预检失败。
- **R2 状态单调**：状态只沿 L 前向推进，不回退；对可选节点（中转/海铁）允许"跳过"，跳过需证据或默认未发生。
- **A6 节点语义（出运 vs 离港）**：出运(#3，已发运/装船确认) ≤ 离港(#4，实际离港 atd)，同一链上实际时间允许相等；若系统仅有离港时点而无独立出运时点，出运记同值并标 same-as（口径随 P6 定稿）。
- **R3 密封历史**：当链已推进越过节点 k（k+1 及以后已有实际值），则 **≤k 节点的历史时间/状态不可再更新**。
  这是"下一状态已更新，不可再更新前面状态的时间"的落点；确需回改须走例外审批（记录原因，ENGINEERING_RULES §14）。
- **R4 写前验证序列**：更新节点 k 时校验（a）前置节点已具备必要时间/状态；（b）满足 R1；（c）若 k 之后节点已更新 → 触发 R3，本次拒绝。
  即允许更新的窗口 = 当前最前"未密封且其后未推进"的节点（迟绑定补全/前进式写入）。
- **R5 初建整链回填**：从外部快照（导入）一次性建立记录时可同时带多个后续节点时间，仅需内部自洽（满足 R1）；R3/R4 约束的是**建立后的增量更新**。
- **R6 来源权威相交**：任何节点时间/状态更新必须先通过 [INTEGRATION_BOUNDARIES](./INTEGRATION_BOUNDARIES.md) 的来源权威（如手工锁：手工值仅手工可改）。

## 4. 三条序列的同一性

- **状态先后序列** = 沿 L 的状态取值顺序（R2）。
- **时间先后序列** = 沿 L 的实际时间序列（R1）。
- **状态验证序列** = 写入顺序约束（R3/R4）：必须先建立前置、不得越过密封线、不得回写历史。
三者互为约束：状态推进以时间为序，时间更新不得越过已推进的状态。

## 5. 实现与强制（候选）

- 在 Shipment 统一写端口（`applyContainerRecordPlan`）内强制，服务端权威，非前端判断。
- 节点时间/状态变更记录来源、操作者、前后值与时间（P2-07 审计）。
- 违反不静默：进预检失败 / 对账差异 / exception 处置，例外经审批（对应 R3/R6）。
