# 费用与对账业务样本 013：七类费用引出与多粒度对账

> 状态：**真实脱敏样本 · 待费用负责人确认**  
> 样本日期：2026-09-10  
> 适用范围：加拿大进口单柜样本；不得外推为其他国家、港口、合同或供应商规则  
> 消费者：费用结算、清关、拖卡、生命周期时间线、数据导入、查询投影及后续 Schema 设计

## 1. 样本来源

本样本来自同一批次导出的七份工作簿：

| 样本 | 主表行数 | 主表列数 | 业务视角 |
| --- | ---: | ---: | --- |
| 滞港费引出 | 1 | 40 | 货柜级超期费用、关键作业日期及四类收费分项 |
| 清关手续费引出 | 12 | 21 | 货柜级总额加费用小类明细 |
| 清关拖卡对账辅助引出模板 | 12 | 162 | 多费用域横向拼接的对账辅助视图 |
| 进口 VAT 引出 | 1 | 8 | 货柜级 VAT 总额及审核金额 |
| 关税引出 | 3 | 20 | 货柜级关税总额加 SKU/HS Code 明细 |
| 海运费引出 | 1 | 12 | 货柜级标准、审核及分摊金额 |
| 内陆运输费引出 | 1 | 30 | 货柜级拖卡总额加费用小类明细 |

七份表使用相同的单据、备货单、箱号和 MBL 关联到同一业务对象。本文只保存结构与脱敏结论，不复制真实公司、供应商、箱号、单号、SKU 或完整金额明细。

## 2. 已观察到的对象和粒度

| 粒度 | 稳定关联候选 | 样本字段 | 结论 |
| --- | --- | --- | --- |
| 费用案卷 | 单据编号、海外公司、备货单号 | 状态、创建/修改/审核主体与时间 | 一张单据可以聚合多种费用 |
| 货柜费用汇总 | 单据编号 + 集装箱号 + 费用类型 | 总收费标准、总已审核、总分摊金额、币种 | 标准、审核和分摊是不同事实，不得覆盖 |
| 费用小类行 | 费用案卷 + 费用小类编码 + 行标识 | 单价、单位、数量/天数、免费个数、收费标准、已审核、收款单位 | 清关和内陆运输存在明细计费行 |
| 商品税费行 | 费用案卷 + SKU + HS Code + 行标识 | FOB、重量、体积、税率、关税金额、已请款 | 关税在 SKU/HS Code 粒度计算或解释 |
| 超期费用分项 | 费用案卷 + 超期费用类型 + 日期/区间 | 滞港、堆存、滞箱、滞港与滞箱组合项 | 不同收费语义必须分项保存 |
| 作业时间事实 | 货柜 + 事件类型 | 到港、卸船/火车、提柜、还箱、送仓、卸空、取空、堆场日期、最后免费日期 | 费用依赖生命周期事实，但不拥有这些时间 |

业务编号用于导入识别和对账，目标公共引用仍使用 `GC-007` 的 UUID 和租户范围。

## 3. 七类费用映射

| 费用视角 | 费用性质 | 主要粒度 | 关联工序/管理模块 | 样本已证明 |
| --- | --- | --- | --- | --- |
| 海运费 | 运输服务费 | 货柜/提单 | 海运与费用结算 | 标准、审核、分摊分字段存在，且有币种与收款单位 |
| 内陆运输费/拖卡费 | 运输服务费 | 货柜 + 费用小类 | 提柜、送仓与费用结算 | 依赖运输方式、柜型、仓库、作业特征和日期 |

| 进口 VAT | 监管税费 | 货柜/申报案卷 | 清关专业事实与费用结算 | 独立于关税保存总额和审核金额 |
| 滞港/堆存/滞箱 | 超期及场地/设备费用 | 货柜 + 类型 + 时间区间 | 费用结算管理闭环 | 四种列组并存，不能合并成一个滞港费字段 |
| 对账辅助视图 | 查询/导出，不是费用类型 | 多粒度横向拼接 | 对账与查询投影 | 汇集上述费用、作业时间、供应商、审核和审计字段 |

## 4. 样本对账结果

| 检查 | 观察结果 | 设计含义 |
| --- | --- | --- |
| 清关手续费明细合计 | 7 条非空收费标准之和等于货柜级清关手续费总收费标准 | 空收费行仍可能是有效费目；聚合只对有金额且适用的行计算 |
| 清关费目完整性 | 共 12 个费用小类，但只有 7 条产生收费标准 | 费目存在、适用、免费、计价和金额必须分开 |
| 关税明细合计 | 3 条 SKU 关税金额之和等于货柜级总关税金额 | 货柜总额是明细聚合投影，不是第四条税费明细 |
| 辅助表行粒度 | 12 行以清关费目为主；前三行并排放置 3 条 SKU 税费，其余 SKU 为空 | 横向行号不表达跨域业务关系，禁止按行把费目和 SKU 建立关联 |
| 重复汇总值 | 货柜级海运费、清关费、货值等在辅助表每行重复 | 导入必须按明确粒度去重，不得直接按列求和 |
| 公式检查 | 七份工作簿均无 Excel 公式 | 文件提供导出结果和结构证据，不证明计算公式或费率规则 |
| 审核数据 | 多数已审核、已请款及付款相关值为空 | 空值表示当前样本未提供事实，不得解释为审核拒绝、零金额或未发生 |

## 5. 已证明与未证明

### 5.1 样本可以支持的事实

1. 费用结算是货柜主流程之外的管理闭环，不产生新的生命周期节点。
2. 一个费用案卷可以同时包含运输费、服务费、税费和超期费用。
3. `收费标准`、`已审核`、`分摊金额`、`已请款` 和后续支付必须分轨。
4. 金额必须携带币种；同一案卷可出现不同币种，不能无汇率依据直接汇总。
5. 关税和清关手续费具有不同明细粒度，不能放进一张无类型约束的通用行表。
6. 作业日期是费用计算输入或证据引用，权威仍属于生命周期或专业模块。
7. 导出辅助表是读模型，不是领域模型、数据库表或导入目标 Schema。

### 5.2 仍不能升格为业务规则

- 单个样本中的关税税率、费用小类、单价、免费个数和供应商价格；
- VAT、关税和清关费的法定计算公式、计税基础、舍入及汇率规则；
- 滞港、滞箱、堆存和组合收费的起止事件、免费期、日历、阶梯与暂停规则；
- 状态 `处理中` 对应案卷、审核、请款或支付哪一阶段；
- `总收费标准` 是预算、合同标准、系统应计还是供应商账单；
- `总分摊金额` 的分摊对象、算法、精度、尾差和锁定时点；
- 空审核字段表示尚未处理、未适用还是源系统未导出；
- 辅助表各列的必填性、唯一键及更新覆盖规则。

以上项目必须通过真实合同、费率表、供应商账单、审核/请款/支付回执和负责人说明确认。

## 6. 目标领域边界建议

建议在现有 `Charges Settlement` 限界上下文内拆分下列聚合，不新增微服务：

| 聚合/对象 | 负责内容 | 不负责 |
| --- | --- | --- |
| `ChargeCase` | 单据、货柜、公司、业务范围、案卷状态和参与方 | 生命周期状态 |
| `ChargeAssessment` | 版本化预计/应计结果、规则和输入事实引用 | 供应商账单真相 |
| `SupplierCharge` | 供应商账单、费用类型、金额、币种和证据 | 内部审核结论 |
| `ChargeLine` | 费用小类、计价单位、数量/天数、单价和金额 | 跨粒度行号关联 |
| `TaxChargeLine` | SKU、HS Code、计税基础、税率和税额 | 清关手续费行 |
| `ChargeReview` | 审核决定、确认金额、差异、操作者和时间 | 支付事实 |
| `ChargeAllocation` | 分摊对象、方法、比例/金额、尾差和版本 | 审核或支付状态 |
| `PaymentRequest` | 请款申请和审批引用 | 实际支付 |
| `PaymentFact` | 财务系统付款及回执 | 业务费用计算 |

费用类型使用稳定代码；具体费目采用版本化目录。不同币种分别聚合，跨币种投影必须保存汇率、汇率日期和来源。

## 7. 与全局契约的关系

| 全局契约 | 本样本提出的实例化要求 |
| --- | --- |
| `GC-004` 时间线 | 费用引用实际/预计时间及事件 ID，不复制或覆盖时间事实 |
| `GC-005` 任务工单 | 录入账单、对账、审核、请款、支付可形成不同工单和完成谓词 |
| `GC-006` 证据权威 | 合同、账单、海关税单、审核决定和支付回执各自验证 |
| `GC-007` 跨模块引用 | ChargeCase、费用行、工单、证据、事件和货柜使用逻辑 UUID 关联 |
| `GC-008` 动作权限 | 审核、撤销、调账、分摊锁定和付款确认需要服务端授权及审计 |
| `GC-009` 同步可靠性 | ERP/财务回执分三阶段，不以接口成功视为审核或支付完成 |
| `GC-010` 查询投影 | 辅助引出应由规范对象投影生成，明确粒度并避免重复汇总 |
| `GC-011` 公共错误 | 未知费目、币种缺失、粒度冲突、汇率缺失和版本冲突明确失败 |

## 8. 后续定稿顺序

1. 由费用负责人确认五阶段事实：预计/应计、账单、审核、请款、支付。
2. 补充至少一套合同费率、供应商账单、内部审核及财务支付闭环样本。
3. 定稿费用类型目录、费目目录、案卷及费用行状态机。
4. 定稿计价单位、金额/币种、税费、汇率、舍入和分摊契约。
5. 用实际到港、卸船、提柜、还箱等事件验证三类超期费用区间。
6. 定稿费用任务/工单、动作权限、证据资格和查询投影。
7. 在后续独立任务中建立 Schema、数据库迁移、导入预检及对账测试。

## 9. 验收样例

后续实现至少覆盖：

1. 七份导出按同一货柜和费用案卷对齐。
2. 清关费目汇总与货柜总额一致，免费或未计价行不丢失。
3. SKU 关税明细汇总与货柜总额一致。
4. 辅助表重复汇总字段不被重复计入。
5. 多币种不在缺少汇率事实时合计。
6. 空审核/请款/支付字段不被转换为 false 或零。
7. 同一导出重复导入幂等，同键异载荷进入冲突。
8. 逐行错误能够定位未知费目、未知单位、缺币种和粒度不一致。
9. 审核、请款和支付分别推进，不因前一阶段完成自动完成后一阶段。
10. 生命周期时间更正后重算预计/应计，但不覆盖供应商账单和历史审核。
