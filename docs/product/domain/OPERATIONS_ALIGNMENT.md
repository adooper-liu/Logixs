# 22 个运营环节 → 14 节点系统主链映射方案（OPERATIONS_ALIGNMENT · v1.0）

> 状态：**已定 v1.0（映射边界与执行模型）** · 2026-09-08 · 负责人：刘志高。
> 一句话：冻结22个运营环节到14节点主链的映射，并规定“流程实例 → 工序任务 → 作业工单 → 动作/数据”的执行模型。
> 证实度：S=规范 · R=现网 · O=负责人 · C=候选(待对拍/待业务补)。
> 🔗 关键上游前提：[SHIPMENT_FLOW_OVERVIEW §A0](./SHIPMENT_FLOW_OVERVIEW.md) 已预言"计划→采购→备货→订舱→出运"上游切片；本报告的"未来上游"缺口在该切片定稿后承接。

## ⓪ 定稿决策

| 决策码 | 已定方案 | 实施约束 |
| ------ | -------- | -------- |
| OA-01 | 统一称“22 个运营环节”和“14 节点系统主链” | 22是管理粒度，14是货柜流程状态粒度 |
| OA-02 | 14节点主链保持单一权威 | 不因运营环节、任务、工单或指标增加流程状态 |
| OA-03 | 货柜流转记录承载 FlowInstance 主流程实例 | 正常主链同一时刻只有一个当前节点 |
| OA-04 | 进入节点激活 NodeTask 工序任务 | 每个节点必须有工序完成政策 |
| OA-05 | NodeTask 生成一张或多张 WorkOrder | 按责任、事务等待或独立验收结果拆单 |
| OA-06 | 动作必须关联具体工单并形成操作、数据、证据与同步回执 | 动作是写入入口，不是流程状态 |
| OA-07 | 状态按“工单 → 工序任务 → 合法事件 → 主流程”推进 | 禁止越级改流程状态 |
| OA-08 | 外部权威事件可先于内部工单 | 先按事实推进，再生成关闭、补录或对账工单 |
| OA-09 | 费用、归档、绩效复盘属于管理闭环 | 不产生货柜主流程状态 |
| OA-10 | 未知外部值不得默认映射 | 显式失败或进入复核队列 |

**关键判据（决定映射口径）：**

- 主链原则（LIFECYCLE §③⑤）："节点 = 状态/里程碑；子里程碑(进场/靠泊/可提/放行)记在事件流，**不加节点**""别把子里程碑塞成主链节点"。→ 22 个运营环节里大量"环节"不是状态，而是**事件/任务**。
- [NODE_PDCA §④](./NODE_PDCA.md) 已有 14 节点 → 任务拆分，比 22 个运营环节更细（派拖/送货预约/还箱…）。→ 22 个运营环节里"该干嘛"的环节多数已由任务承接。
- [SHIPMENT_FLOW_OVERVIEW §A0](./SHIPMENT_FLOW_OVERVIEW.md)：订舱(Booking)为候选未来前端对象。→ 22 个运营环节 **#1–3（订舱/放箱/提空箱）不是主链节点**，归"未来上游"切片。

**定稿结论：** 22个运营环节按主链节点、事件/子里程碑、工序任务/工单、未来上游和管理视图承载，不扩充为22个流程状态。

## ③ 缺口处理方案

### A. 未来上游切片缺口（#1 订舱 / #2 放箱）

- 现象：22 个运营环节把订舱/放箱列为起运前核心环节；主链从"备货"开始，无订舱节点。
- 归属：[SHIPMENT_FLOW_OVERVIEW §A0](./SHIPMENT_FLOW_OVERVIEW.md)"未来前端"切片；Booking 为候选对象。
- 建议：随上游切片定稿时，补 BOOKING 对象 + 事件码（`booking_confirmed`/`container_released` 候选，C 级），**不新增主链节点**。登记入 NODE_PDCA §⑦ / SHIPMENT_FLOW 待办。
- #3 提空箱：事件 `empty_picked_up` 已存在，仅需上游切片承接"提箱单/EIR"单据环节，**非主链缺口**。

### B. 到港清关子环节缺口（#12 换单 D/O / #14 缴税放行）

- 现象：22 个运营环节把换单、缴税单列为到港清关的子环节；主链到港段无显式"换单/缴税"子里程碑。
- 归属：清关(#7)到港段的事件/任务层（NODE_PDCA §③/§④ 清关任务细分）。
- 建议：登记候选事件码（`delivery_order` = D/O 换单、`duty_paid` = 缴税完成）或候选任务（`convert_delivery_order`/`pay_duties`），C 级，待 P2-12 样本回验。**不新增主链节点**——按 LIFECYCLE 原则，子环节记事件流。

### C. 任务承接（#16 派送预约 / #19 验箱 等已覆盖或待补）

- 已覆盖：派送预约→`schedule_warehouse_delivery`；拆柜卸货→`schedule_unload`/`execute_unload`；还箱→`execute_empty_return`。
- 待补候选：验箱/修箱费核验任务（关联七组⑤费用）——建议入 NODE_PDCA §④ 候选行，待样本。

### D. 管理视图对齐（#20 费用 / #21 归档 / #22 复盘 + KPI/SLA + RACI）

- 承接：NODE_PDCA 七组 ④周期(KPI/SLA) · ⑤费用(Demurrage/Detention/Storage) · ⑦会议(复盘/供应商绩效/决议)。
- RACI 责任角色 → 任务定义 `ownerRole`/`assignmentMode`（NODE_PDCA §① 任务定义骨架）。
- 不产生主链节点；KPI/SLA 为运营管理口径，非系统状态。

## ⑦ 验收标准与影响边界

- 22个运营环节逐行有归属，14节点顺序不变。
- 每个节点有一个工序任务定义，每个工序任务至少生成一张执行或系统工单。
- 单张工单完成不得直接推进主流程。
- 工序任务只有形成来源权威、证据齐全且转换合法的实际事件才能推进主流程。
- 动作具有幂等键、操作记录、数据版本、证据和追踪ID。
- 未知值显式失败或进入复核；更正追加版本，不覆盖历史。
- 本方案不直接修改状态码、事件码、数据库或API；物理契约与迁移另行评审。
