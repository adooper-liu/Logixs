> 状态：治理基线  
> 版本：1.0  
> 最后更新：2026-09-09  
> 适用范围：货柜全生命周期、14 节点主链及各限界上下文

## 1. 目的与边界

本登记表是全局公共契约的唯一治理入口，用于跟踪契约所有权、成熟度、权威文档、消费者、阻断项和下一动作。它只记录治理元数据和已批准决策的索引，不复制状态枚举、事件映射、字段定义或业务规则；具体定义始终以“权威文档”列指向的契约为准。

登记为“已确认决策”只表示该项规则已获得业务选择，不代表所属契约整体已经批准、实例化或发布。

## 2. 阶段门禁

| 门禁 | 名称 | 进入条件 |
| --- | --- | --- |
| `D0` | 未开始 | 尚无明确范围、所有者或权威草案。 |
| `D1` | 设计中 | 已明确范围和候选规则，正在形成独立权威契约。 |
| `D2` | 待负责人评审 | 契约文档已具备完整评审内容，尚未取得全部必要批准。 |
| `D3` | 业务批准 | 业务语义、所有者和跨模块边界已正式批准，遗留项不影响实例化。 |
| `D4` | Schema 已实例化 | 已形成唯一公共 Schema 源，并完成 DTO、OpenAPI 或生成类型的一致性校验。 |
| `D5` | 代码与数据库已实现 | 运行时代码、迁移、Adapter 和消费者已按契约实现。 |
| `D6` | 验证通过 | 契约、数据库、API、集成和关键流程验证均通过且证据可追溯。 |
| `D7` | 已发布 | 已进入目标环境，具备版本、监控、兼容与回退记录。 |

门禁原则上单调推进。任何回退都必须记录原因、影响和重新准入条件。`D4` 至 `D7` 必须附可验证的产物或检查链接；没有证据不得自行升格。

## 4. 已确认决策索引

以下决策进入相关契约评审基线，详细语义仍以对应权威契约为准：

- `cargo_ready` 按“一备货单一次有效确认”；可由人工、ERP、供应链系统或导入确认。
- 箱号尚未产生时不进入货柜生命周期主管道，只处于备货管理状态。
- `rail_handover` 表示铁路主体或场站实际接收货柜，不表示仅接单或预约。
- 规范事件保留 `completionEligibleNodeCodes`；事件接收按 `eventId` 幂等，节点事实应用按 `(eventId, nodeInstanceId)` 幂等。
- `sailing` 不完成节点；`transit_arrived` 可申请完成 `ocean_transit`；`arrived` 可申请完成 `ocean_transit` 与 `destination_arrival`。
- `delivered` 和 `warehouse_arrival` 均可申请完成 `warehouse_delivery`；前者要求 POD 或签收证据，后者要求仓库、WMS 或门岗权威来源。
- `container_customs_completed` 可申请完成 `customs_clearance`；单案卷 `release` 本身不直接完成货柜节点。

## 6. 更新规则

1. 每项契约只有一个 `contractId`、一个业务所有者和一个权威入口；没有明确负责人时不得进入 `D3`。
2. 负责人字段登记角色，评审记录另行登记具体签署人、日期和结论。
3. 契约负责人在状态、阻断、下一动作或权威入口变化时更新本表，并同步最后更新日期。
4. 枚举、事件载荷、业务守卫、错误码和字段定义不得复制到本表；发现不一致时以已批准的权威契约为准并发起纠偏。
5. `D3` 必须有业务与技术边界共同批准记录；`D4` 必须通过跨语言、OpenAPI 和 JSON Schema 一致性检查；`D5` 以后必须关联迁移和实现；`D6` 必须关联可复现验证结果。
6. 新增全局契约须先证明其跨越三个或以上模块，或属于稳定的安全、数据、集成边界；模块私有规则不得进入本表。
7. 版本升级必须说明兼容性、消费者影响和迁移策略，不得原地改写已发布语义。

## 7. 实施准入检查

任何依赖全局契约的开发任务进入实现前，至少确认：

- 所依赖契约已达到任务要求的门禁，且权威入口唯一可访问。
- 任务 brief 明确引用 `contractId` 和版本，不在模块内重新定义公共枚举或规则。
- 若契约尚低于 `D3`，任务只能制作原型、验证假设或完善契约，不得将候选语义作为生产契约实现。
- 涉及公共边界时，已规划 Schema、DTO、OpenAPI、数据库映射和消费者的一致性验证。
