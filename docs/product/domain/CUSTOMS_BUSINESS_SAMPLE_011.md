# 业务样本 011：LMS 清关单据需求矩阵

> 状态：真实需求工作簿 · 评审输入 · 待业务确认 · 2026-09-08
>
> 边界：本样本来自一份跨国家清关单据需求工作簿，不是单票业务案卷，也不是已生效的权威契约。工作簿中的国家矩阵、文件规则、时间规则、邮件模板和字段取值仍存在冲突、待开发项与待确认项，不能直接硬编码。

## 1. 样本定位

工作簿包含 8 个工作表，覆盖：

1. 八个目的国的清关文件需求矩阵。
2. 文件来源、生成、同步和传递规则。
3. 清关单据聚合状态。
4. 邮件正文、收件人和发送时限。
5. 清关单据传递汇总及逐文件发送记录。
6. Product Photo 的名称、描述、HS Code 和图片取值。
7. 进口海关编码及产品描述、材质、尺寸字段调整。

其中两个工作表被隐藏，仍包含真实邮箱、历史业务编号和邮件样例。隐藏不等于脱敏；这类数据必须按敏感配置和历史证据治理。

## 2. 证据登记

| 证据 ID  | 来源                      | 允许证明                                                      | 不允许证明                                           |
| -------- | ------------------------- | ------------------------------------------------------------- | ---------------------------------------------------- |
| EVD-1101 | LMS 清关单据需求工作簿 v2 | 当前需求草案包含哪些国家、文件、状态、生成/发送规则和报表字段 | 规则已审批、系统已经实现、文件已经发送或海关已经清关 |

原始工作簿未复制进仓库。真实邮箱、主体、历史业务号、箱号、提单号、商品号及邮件正文样例未写入本文件。

## 3. 文件目录候选

工作簿覆盖的稳定文件类型候选包括：

| 分组          | 文件类型候选                                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 基础贸易/运输 | B/L、Packing List、Invoice、ENS、AN/E-manifest                                                                                        |
| 商品资料      | Product Info/Product Photo、Nameplate、Energy-related Products                                                                        |
| 美国专项      | End Use Certification、CPC/ASTM、Textile、Lacey Act                                                                                   |
| 欧盟/英国专项 | Pharmaceutical Control 声明、Phytosanitary Certificate、BL Authorization/Power of Attorney、ROHS、测试报告、CE/符合性声明、砍伐证链条 |

同一概念在不同页中存在名称差异，例如 Product Info/Product Photo、CPC & test report/CPC & ASTM、End Use Certification/Agriculture。进入契约前必须建立稳定 `documentType`，显示名称和外部文件名作为版本化别名。

## 4. 国家适用矩阵

工作簿覆盖 US、CA、UK、DE、FR、IT、ES、IE。基础 B/L、PL 和 Invoice 普遍要求；ENS、商品资料、植检、授权书和专项声明按国家及产品条件变化。

当前矩阵只能作为候选，原因如下：

| 冲突/缺口                                           | 影响                         |
| --------------------------------------------------- | ---------------------------- |
| 主矩阵与生成规则页对 ENS 的国家集合不一致           | 无法判断某国“全部必需文件”   |
| Product Info 的适用国家在不同区域不一致             | 可能漏生成或误生成文件       |
| 植检/符合性文件带“部分需提供”“是否查验时提供”等疑问 | 缺少产品条件和触发时点       |
| 某些文件标为“新增待开发”或“手动上传”                | 不能按自动生成能力验收       |
| HS Code 取进口、出口、进出口或不需要，按国家变化    | 必须由国家+方向+商品规则决定 |

最终矩阵必须版本化，并至少包含 jurisdiction、direction、documentType、applicabilityRule、requiredLevel、effectiveFrom/effectiveTo、authority 和 confirmationStatus。

## 5. 文件责任分离

工作簿中的“来源”列把多个责任混在一起。目标模型应拆为：

| 责任              | 含义                               |
| ----------------- | ---------------------------------- |
| dataAuthority     | 字段事实的权威来源                 |
| contentProvider   | 提供原始数据或文件的系统/主体      |
| documentGenerator | 生成文件的系统                     |
| evidenceStore     | 保存文件及哈希的系统               |
| sender            | 对外传递文件的系统或人员           |
| recipientPolicy   | 按国家、清关公司和生效期选择收件人 |

SCM、LMS、人工上传和外部机构必须落入上述明确角色，不得继续共用一个 `source` 字段。

## 6. 单据状态模型

工作簿给出五个聚合状态：

| 工作簿状态 | 工作簿定义           |
| ---------- | -------------------- |
| 未生成     | 任一所需文件都未生成 |
| 部分生成   | 部分所需文件已生成   |
| 全部生成   | 所有必需文件已生成   |
| 部分传递   | 部分所需文件已发送   |
| 全部传递   | 所有必需文件已发送   |

该状态适合作为只读聚合投影，不适合作为单一业务状态机。每份 `DocumentRequirementInstance` 应分别保存：

| 状态维度      | 候选值                                         |
| ------------- | ---------------------------------------------- |
| applicability | unknown/not_applicable/required/conditional    |
| generation    | not_started/generating/generated/failed/stale  |
| review        | not_required/pending/approved/rejected         |
| transmission  | not_sent/queued/sent/delivery_failed/delivered |
| evidence      | missing/present/verified/invalid               |

代码名称仍是候选。聚合值必须由同一规则版本下的必需文件集合计算。“全部传递”只表示文件作业完成，不代表清关公司已接收、海关已受理或货柜已放行。

## 7. 生成与时间规则

工作簿多处使用“min(ETA, 目的港到达日期, 目的港卸船/火车日期) 减 14 天”生成文件，部分备注又使用减 10 天。当前表达存在歧义：

1. planned ETA、实际到港和实际卸船不是同一时间性质。
2. 实际时间通常晚于生成计划，直接取最小值可能长期等于较早 ETA。
3. 缺值、ETA 调整、实际事件晚到和文件已人工锁定后的重算政策未定义。
4. 10 天与 14 天规则的权威优先级未定义。

目标规则必须保存 triggerType、sourceTimeField、offset、timezone、ruleVersion、evaluatedAt 和 manualLock。候选执行方式应由业务确认后定稿，不能直接照抄自然语言公式。

## 8. 传递与审计

| 观察                           | 目标要求                                         |
| ------------------------------ | ------------------------------------------------ |
| 按提单维度自动或手动发送       | 保存 transmissionBatch、适用文件、提单和货柜范围 |
| 所需附件齐全后自动发送         | 发送前重新计算同规则版本的完整性并校验人工锁     |
| 邮件附件大小有限制，超出时拆分 | 记录拆分序号、总批次、每份内容哈希和完整性       |
| 同一文件可多次发送             | 每次尝试仅追加，不能覆盖历史                     |
| 汇总表区分未传递和缺少文件     | missing 与 not_sent 分开                         |
| 记录自动/手动、时间和操作者    | 系统身份、人类身份、原因和 traceId 完整审计      |

“sent”只证明发送端完成技术操作。若要认定 delivered，必须取得邮件服务或目标渠道回执；对方业务接收和海关受理仍是后续独立事实。

## 9. Product Photo 与海关编码

工作簿提出按 SKU、国家和语言获取名称、描述、材质、尺寸、HS Code 和图片，并在缺少本国数据时回退到其他国家数据或调用翻译服务。

规则候选：

| 规则 ID  | 规则                                                                | 失败处理                       |
| -------- | ------------------------------------------------------------------- | ------------------------------ |
| S011-P01 | 商品字段按 SKU+jurisdiction+language+field 保存来源和版本           | 禁止跨国家静默覆盖             |
| S011-P02 | 进口和出口 HS Code 分开，并保存 suffix 和适用日期                   | 不把不同方向代码拼成一个字段   |
| S011-P03 | 翻译输出标记为机器生成候选，保留源语言文本、模型/服务版本和人工审核 | 未审核译文不得冒充权威商品描述 |
| S011-P04 | 缺值保持缺失并进入资料复核                                          | 不用其他国家值静默兜底         |
| S011-P05 | 图片按 SKU 和内容哈希关联                                           | 文件标题或位置不作为唯一键     |
| S011-P06 | 产品材料、尺寸和标题分别建模                                        | 不拼成不可解析的长描述         |

## 10. 安全与配置

1. 邮件收件人不得硬编码在业务规则、前端或模板中。
2. 收件人策略按国家、清关公司、文件类别和生效期版本化，并需要授权维护。
3. 日志不得记录完整邮箱、邮件正文、附件内容或业务编号。
4. 邮件模板与业务事实分离；模板变更不能修改历史发送证据。
5. 隐藏工作表中的历史邮箱和业务样例迁移前必须脱敏、去重和确认保留依据。
6. 自动发送属于外部副作用，必须支持审批、幂等、失败重试、熔断、撤回边界和审计。

## 11. 工单与模块落位

| 模块                 | 责任                                     |
| -------------------- | ---------------------------------------- |
| shipment-registry    | 提单、货柜、备货单、运输时间和商品引用   |
| customs-compliance   | 国家文件需求、清关案卷、证据和业务完整性 |
| work-execution       | 文件生成、补件、审核、传递和异常工单     |
| integration/adapters | SCM/CL/翻译/邮件服务的同步与回执         |
| lifecycle-control    | 只消费权威规范事件，不消费“全部传递”     |

一个国家文件矩阵不应成为新的主链。文件要求在相应清关节点内生成一组条件化工单。

## 13. 对开发方案的贡献

本工作簿足以形成清关单据目录、需求矩阵、逐文件状态、生成/传递工单和发送审计的数据结构草案。冲突矩阵、自然语言时间公式、隐藏邮箱和待开发项完成业务评审前，不得升格为公共契约或自动执行规则。
