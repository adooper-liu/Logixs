# 关键节点 PDCA 闭环分析（NODE_PDCA）

> 状态：**候选（初稿，待 P2 评审）** · v0.1 · 2026-09-04 · 负责人：刘志高。
> 需求（负责人）：全生命节点中**每个节点都有 计划→派发工单与任务→Check→改善（PDCA）** 的运营闭环；
> 需从全流程**设定关键节点**，明确每节点：**关键要素 / 关键动作 / 关键输入与输出 / 问题与风险预警**。
> 本文给出分析与初稿。分层约定：**状态机（LIFECYCLE_CONSISTENCY L）管"状态、顺序、密封、合法性"；
> 本文 PDCA 管"每个节点要完成的运营作业闭环"**；两者叠加由可视化工作台呈现
> （[UX_CONTAINER_WORKBENCH](../UX_CONTAINER_WORKBENCH.md)），一键动作复用 [ACTION_CATALOG](./ACTION_CATALOG.md)，标记卫式复用 [MARKER_CATALOG](./MARKER_CATALOG.md)。

## 1. 通用 PDCA 模板（作用于每个关键节点）

| 环 | 内容 | 落到现有机制 |
| --- | --- | --- |
| P 计划 | 目标/前置条件/计划时间与 SLA、触发规则、输入就绪 → 生成"待办/工单"草稿 | 动作推导引擎（UX §4）+ 状态机可写窗口 R3/R4 |
| D 派发执行 | 把工单/任务派给角色或系统，带默认载荷/期限；一键下达指令、转发、派单 | ACTION_CATALOG（指令/邮件/派单）、工单对象（见 §4） |
| C Check | 校验关键证据/结果：时间、单证、标记卫式、预检、完成度；未通过→退回或异常 | 确定性校验 + 预检（IMPORT_DOMAIN_MODEL）+ exception |
| A 改善 | 记录结果与根因；规则/模板/字典回写沉淀（稳定判断固化）；升级残留问题 | audit + exception-management + ENGINEERING_RULES §3.3（配置沉淀） |

每个节点由模板生成 P/D/C/A 四类任务与预警；模板本身**数据可配置**（字典/契约），不散落硬编码（D11–D13）。

## 2. 关键节点抽取（8 个，K1–K8）

关键性判据：数据定稿 / 不可逆 / 外部依赖与单证 / 免费期·滞留 / 异常高发 / 交接边界。节点号指 L 规范链（LIFECYCLE_CONSISTENCY §2）。

| 节点 | 定位（why 关键） | 对应 L 节点 |
| --- | --- | --- |
| K1 备货就绪 | 计划→货量与船期前提，影响后续全部 | #1 备货 |
| K2 装箱定稿 | 真实数据/箱号/危险品·植检·温控标记定稿点 | #2 装箱 |
| K3 出运确认 | 承运承诺/船期/订舱信息进入 | #3 出运 |
| K4 离港 | 截关截港、出运开始、不可逆窗口关闭 | #4 离港 |
| K5 在途/中转监控 | 变更/延误/甩柜高发，可选节点 | #5/#6 海运·中转 |
| K6 清关 | 单证齐全性、扣货/查验风险高 | #7 清关 |
| K7 到港→提柜(拖卡) | 免费期计时、派单时效、滞留风险 | #8/#10 目的港·拖卡 |
| K8 卸柜/卸空→还箱 | 交接对账、空箱归还关闭设备链 | #12–#14 卸柜·卸空·还箱 |

## 3. 每关键节点的四要素与风险预警（初稿）

### K1 备货就绪
- 关键要素：备货单号、客户/PO、货量件数/CBM、需否装柜、期望出运窗口、供应商备货完成状态。
- 关键动作：确认备货就绪；派发"装箱排期/装箱指令"待命；到期未就绪→预警升级。
- 关键输入：外部计划系统（备货单，先导入后直连，见 INTEGRATION_BOUNDARIES）。输出：备货就绪时间 + 装箱待办进入 K2。
- 风险预警：备货延期 vs 期望出运 → 延误预警；货量/体积超计划 → 需复核柜数与箱型。

### K2 装箱定稿
- 关键要素：装箱完成时间、真实毛重/件数/体积、封号、箱号（迟绑定）、柜型、标记（危险品/植检/致冷剂/超限）。
- 关键动作：`confirm_stuffing` 一键确认定稿；标记触发动作（DG/植检/温控）；派发装箱清单/单据转发。
- 输入：装箱数据（导入/手工）。输出：定稿记录、标记集合、`confirm_stuffing` → 状态机置"已装未出"。
- 风险预警：真实重量/体积超限 → 预检 blocker；危险品/植检等标记未处理 → 后续节点卫式未达；缺箱号（迟绑定）标记待补。

### K3 出运确认
- 关键要素：船司/船名航次、订舱号、起运/目的港、ETD、承运承诺单证（订舱确认/BL 草稿）。
- 关键动作：确认船期/出运；`notify_arrival` 类预到通知草稿；船期变更→通知受影响方。
- 输入：订舱确认/船司（导入/API）。输出：出运确认记录、预计窗口锚定。
- 风险预警：船期顺延/甩柜倾向 → 延误预警并进 K4 前复核；目的港/航次与备货单不一致 → 冲突。

### K4 离港
- 关键要素：实际离港 atd、截关截港确认、危险品等卫式达成（放行证据）。
- 关键动作：`confirm_departure` 一键确认；未达成卫式→阻塞并升级。
- 输入：atd/船司事件。输出：`shipped→`在途、密封线前移（R3 生效点）。
- 风险预警：atd 晚于 ETD 超阈值 → 延误指标；截关前文件未齐 → 紧急补单任务。

### K5 在途/中转监控
- 关键要素：ETA/ATA、中转港到·离（可选）、甩柜/改配/滞留信号。
- 关键动作：到港前 `notify_arrival`；中转延迟/甩柜→`notify_delay` + `dispatch_exception`。
- 输入：船司/AIS/飞驼等外部事件（INTEGRATION_BOUNDARIES ②）。输出：在途位置/预计变更、异常记录。
- 风险预警：ETA 漂移超阈值、中转滞留、甩柜改配 → 时效与客户 SLA 预警。

### K6 清关
- 关键要素：清关单据（商业发票/箱单/植检/危险品声明）、计划/实际清关、放行证据、扣货/查验状态。
- 关键动作：`request_phytosanitary`/`issue_dg_declaration`/转发单据；放行→`confirm` 进入提柜窗口。
- 输入：海关/报关行/单证（API/手工）。输出：清关放行 + **提柜前置条件达成（卫式：放行先于拖卡）**。
- 风险预警：查验/扣货（customs hold）→ 异常升级；单据缺失 → 预检 blocker；免费期/到期临近。

### K7 到港→提柜(拖卡)
- 关键要素：到港 ata、可提/免堆期、默认拖车商、派拖时间窗、目的仓库、司机/车牌。
- 关键动作：`confirm_arrival`；`order_trucking_pickup` 一键派拖；超窗→`dispatch_exception`。
- 输入：码头/港口到港与可提（API/导入）+ 运输公司（INTEGRATION ③）。输出：提柜时间、拖运在途。
- 风险预警：免费期将尽/滞留费（detention）、派拖超时、到港但清关未放行 → 卡点预警。

### K8 卸柜/卸空→还箱
- 关键要素：送达/卸柜/卸空时间、收货(WMS 确认)、还箱时间与还箱点、空箱对账。
- 关键动作：`confirm_unstuffed` 卸空可还；`schedule_empty_return` 安排还箱；收货对账异常→`dispatch_exception`。
- 输入：WMS 收货/卸空回传（INTEGRATION ④）+ 拖卡/还箱数据。输出：还箱 `returned_empty`（关闭设备链）、交接对账结果。
- 风险预警：卸空与 WMS 收货不一致、还箱超期/还箱点不符、空箱未返 → 对账与费用预警。

## 4. 落地要素（新增/复用）

- **工单/任务对象（新增，候选）**：`task = { id, nodeKey, phase(P/D/C/A), assigneeRole/人, due, checklist[], evidenceRef, status, sourceTask(actionCode), escalateTo }`；由节点模板生成，经动作一键派发/认领/完成；完成即 Check 输入。工单状态机（候选：`open→dispatched→in_progress→checking→done` / 例外 `escalated/overdue`）后续契约化。
- **预警 = 规则数据**：风险预警统一为"预警规则"（字典），触发 → 节点徽章红点 + `notify_*`/`dispatch_exception`；预警可配阈值（时间偏差、免费期、SLA）。
- **可视化**：rail 每个关键节点加 任务徽章/PDCA 按钮/风险预警角标；动作中心＝当前节点 P→D→C→A 待办（UX V2+）。
- **模板可配置**：节点模板（要素/动作/预警阈值）为契约+字典数据；`Check` 的校验项来自预检与标记卫式（不重复造轮子）。
