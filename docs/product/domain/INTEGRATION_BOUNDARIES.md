# 外部集成边界（INTEGRATION_BOUNDARIES · v0.4 人话重构）

> 状态：**候选 v0.4** · 2026-09-06 · 负责人：刘志高。
> 一句话：和外部(计划系统/海关/港口/船司/飞驼/拖车/WMS)在哪个环节对接、以什么键、听谁的，一张表说清。
> 冗余/故障转移设计见 INTEGRATION_REDUNDANCY；事件码归一见 EXTERNAL_EVENT_MAPPING。
>
> **项目定位（负责人确认）**：系统可连接飞驼等任意第三方 API 获取外部证据，用于更新货柜业务状态与流程节点位置；任何供应商均不得直接写领域状态，必须经过原始证据留存、显式映射、对象关联、幂等/时序校验和生命周期守卫。
> V1 证据对象、来源身份、权威策略和冲突裁决唯一引用[证据与来源权威契约 V1](./EVIDENCE_SOURCE_AUTHORITY_CONTRACT_V1.md)；本文保留集成场景说明，不再作为来源枚举权威。

### C. 渠道分级

### D. 字段/事实级来源权威（D7 修正）

不存在“手工 > 导入 > API”的全局排名。权威取决于**业务字段或事件类型、责任主体、事件时间、证据和适用范围**；导入/API 只是接入渠道，人工是纠偏方式，不是天然更可信的事实来源。

| 事实类别               | 原则上的权威主体                                           | 其它来源的角色                   | 冲突处理                                             | 证实          |
| ---------------------- | ---------------------------------------------------------- | -------------------------------- | ---------------------------------------------------- | ------------- |
| 备货单与已出运交接基础 | 上游计划/业务系统                                          | 文件导入是当前载体；人工补证     | 缺失/冲突进预检或复核，不以渠道新旧决定              | O；字段明细 C |
| 船期与海运里程碑       | 船司/码头等事件责任主体                                    | 飞驼/AIS 为聚合、预测或辅助证据  | 预计与实际分开；同一实际事件冲突按事件类型策略裁决   | O·R；优先级 C |
| 海关申报、查验、扣放   | 海关；清关行只对其申报/跟进动作负责                        | 邮件、人工上传、聚合接口承载证据 | 清关行“已处理”不得冒充海关“已放行”；无官方证据进复核 | O；证据清单 C |
| 派车、提柜、送达       | 拖车公司对派车/司机/运输动作负责；码头闸口对进出场事实负责 | 人工用于异常补报                 | 运输报告与闸口事件并存，对状态推进按事件类型配置     | O；字段明细 C |
| 收货、卸柜/卸空        | WMS/仓库对货物接收和仓内事实负责                           | 物流人员提供交接证据             | WMS 与现场扫描冲突进入对账，不静默覆盖               | O             |
| 还空箱                 | 承运人/码头的设备交接回执                                  | 拖车报告用于在途跟进             | 司机报工不直接等于承运人已接收空箱                   | O；具体凭证 C |
| 费率与账单             | 生效合同/费率标准；服务商账单；内部审核分别负责各自事实    | 系统只计算预计与差异             | 预计、账单、审核确认、支付分开，不互相覆盖           | O；规则参数 C |

字段级权威策略至少包含：`businessField/eventType`、允许来源及责任角色、证据要求、预计/实际语义、事件时间适用规则、冲突动作（采纳/拒绝/复核）、人工纠偏权限、密封后更正方式和生效版本。没有匹配策略、来源未知或证据不足时必须进入待处理/对账，禁止使用默认来源静默落账。

### E. 接入模式（订阅/查询/邮件）

订阅→subscriptionId 轮询/回调、按国家路由、businessNo 回显、业务码 20000；邮件式交付(如查验进度)——见规范与 INTEGRATION_REDUNDANCY。

### F. 当前入口的可替换适配器边界

| 接入适配器       | 输入形态                                | 共同输出                                   | 不得绕过                                                               |
| ---------------- | --------------------------------------- | ------------------------------------------ | ---------------------------------------------------------------------- |
| 文件导入（当前） | 经隔离解析的 `.xlsx/.xls/.csv` 批次与行 | 进入 Shipment 应用写入边界的标准化货柜数据 | 字段映射、未知值处理、预检、人工审核、幂等、事务、逐行结果、对账、审计 |
| 上游直连（后续） | API、事件或受控数据接口；具体协议待定   | 与文件导入相同的标准化货柜业务输入         | 边界校验、外部码映射、幂等、事务、冲突处理、对账、审计                 |
| 三方证据适配器     | 飞驼或任意供应商 API/Webhook 的原始载荷 | 外部证据、同步回执与规范事件候选             | 来源/渠道分离、原文留存、对象关联、映射、幂等、时序、守卫、对账、审计   |

适配器只负责把来源数据转换为统一输入，不拥有货柜业务事实，也不直接推进货柜状态。直连替换文件传递时，已出运货柜列表的身份、历史和下游消费者保持不变。

## ② 定义与澄清

- “渠道”只讲怎样进入；“来源主体”说明谁声明事实；“业务标识”说明关联哪条记录；“来源权威策略”决定特定字段/事件在何种证据下可被采纳。四者不得混用。
- 外部数据一律不可信：隔离解析、校验、未知进待处理。
- 写库只经业务 API；外部永不直写。
- “已出运货柜列表”是当前下游数据起点；其接入渠道可以替换，业务写入边界不能替换或绕过。
- **入口权威 ≠ 字段权威（PRINCIPLES P6）**：”已出运货柜列表”对”哪些货柜进入系统”拥有入口权威（交接基础事实）；对后续字段（到港/清关/提柜/卸空/还箱等）不是最终权威——后续字段由各自责任主体按 §D 字段/事件级策略更新。

## ③ 规则与约束/边界

- provider 轮换或导入/API 切换 ≠ 数据可信度；每个标准化事实必须携带来源主体、接入渠道、业务发生时间和证据引用。
- 入口快照只在交接时刻有效：已出运列表承载的字段是交接快照，后续更新以该时刻之后的责任主体与证据为权威（P6），不得用交接快照静默覆盖更新。
- 人工纠偏不是万能覆盖：只有字段策略授权且提供理由/证据时才能形成更正；与更高权威事实冲突或越过密封线时进入复核，并保留原值和更正关系。
- 冲突裁决按字段/事件策略执行，不使用“最后写入胜出”、全局来源排名或“首次导入优先”。
- 接入须 超时/重试/幂等/去重；密钥经密钥管理。
- 文件导入与直连必须复用同一标准化校验和 Shipment 应用写入语义；渠道切换不得形成第二套货柜记录或状态规则。

## ④ 流程（怎么接一个新源）

1 确定业务段/标识/事实责任主体 → 2 注册来源与接入适配器 → 3 为字段/事件配置权威与冲突策略 → 4 转换为统一输入并完成事件码映射 → 5 未覆盖进待处理 → 6 经同一业务写入边界校验/对账 → 7 上线监控未命中、冲突和降级（见 REDUNDANCY）。

## ⑤ 注意事项（坑）

- 别把主键混用（备货单号段不能用去问海上，箱号段不能用备货单号问）。
- 别把供应商 API 直写业务表。
- 别让“改成直连”演变成绕开导入链已有的校验、幂等和对账保障。
- 别把人工输入当作天然最高权威；人工纠偏和外部更正都必须保留原事实、证据和审计关系。
- 别为"能跑"牺牲校验（未知静默→老反例 A1/A2）。

## ⑥ 白话注解（🗣️）

🗣️ 现在是文件把“已出运柜子清单”送进来，以后改成系统直接送。换的是送货通道，不是事实的主人：船期听船司/码头，放行听海关，提柜运输听拖车与闸口，收货听 WMS。人工能纠错，但必须拿证据并留下痕迹。
