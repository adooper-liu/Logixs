## ② 定义与澄清

- "渠道"只讲从哪拿；"主键"决定拿什么（箱号段 vs 备货单号段）；"来源权威"决定听谁的。
- 外部数据一律不可信：隔离解析、校验、未知进待处理。
- 写库只经业务 API；外部永不直写。

## ③ 规则与约束/边界

- provider 轮换 ≠ 数据可信度（可信度由 D7/source 决定）。
- 手工值锁：任何外部到达不覆盖手工值（进对账提示）。
- 导入 vs API 冲突：首次/冲突填充以导入值为准；其后 API 可更新导入值。
- 接入须 超时/重试/幂等/去重；密钥经密钥管理。

## ④ 流程（怎么接一个新源）

1 确定 段/主键/渠道 → 2 注册 source+适配(订阅/查询) → 3 事件码对拍补映射 → 4 未覆盖进待处理 → 5 上线监控未命中/降级(见 REDUNDANCY)。

## ⑤ 注意事项（坑）

- 别把主键混用（备货单号段不能用去问海上，箱号段不能用备货单号问）。
- 别把供应商 API 直写业务表。
- 别在手工锁值上静默覆盖。
- 别为"能跑"牺牲校验（未知静默→老反例 A1/A2）。

## ⑥ 白话注解（🗣️）

🗣️ 系统跟外面打交道就四句话：**在哪个环节、用哪个号去问、走哪条通道、最后听谁的**。外面给的消息一律先当"来路不明"检查一遍；重要数据谁最后改的、是手工/导入/API 都有记录，手工写的最金贵，谁也不能偷偷改它。
