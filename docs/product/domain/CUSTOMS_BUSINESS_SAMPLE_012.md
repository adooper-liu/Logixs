# 海关业务样本 012：中国出口双报关单放行与 CIF 单证链

> 状态：真实脱敏纵向样本 · 待业务确认 · 2026-09-08
>
> 边界：本样本包含商业发票、五页关务资料、海运单和议付单界面截图。关务资料中两票报关单分别带有海关审核放行通知，是强放行证据候选；商业发票、海运单及内部议付状态不能替代海关裁决。

## 1. 样本目的

验证同一货柜/运输业务拆成两票出口报关案卷后，如何分别接收放行证据，再聚合为货柜级海关节点结果；同时厘清 CIF 商业发票、运输单证、内部费用分摊和海关放行之间的边界。

## 2. 证据登记

| 证据 ID  | 文档/页面          | 结构                               | 允许证明                                                                 | 不允许证明                                |
| -------- | ------------------ | ---------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------- |
| EVD-1201 | Commercial Invoice | 4 页，CIF 商品明细及认证信息       | 商业发票、价格条款、商品行、币种、金额和附加声明已经形成                 | 应收账款入账/收款、海关估价接受、海关放行 |
| EVD-1202 | 中国出口关务资料   | 5 页，两票报关单及两份审核放行通知 | 两个独立出口报关案卷均出现海关审核放行事实候选                           | 码头放行、已装船、目的国进口清关          |
| EVD-1203 | Sea Waybill        | 1 页                               | 承运关系、船舶航次、货柜/封条、港口、运费预付及运输条款                  | 出口海关放行、货款结算、货柜已装船        |
| EVD-1204 | 议付单及明细界面   | 3 张截图                           | 内部议付审核、销售确认、附件、EBS 同步、物流费用、汇率和商品分摊字段结构 | 款项已收到、会计凭证已过账、海关已放行    |

原始 PDF 和截图均不进入仓库。真实主体、人员、地址、货柜号、封条号、提单号、报关单号、商品、证书号、金额、汇率和时间未写入本文件。

## 3. 案卷与证据关系

关系候选：

ContainerRecord -> Shipment/SeaWaybill -> CustomsExportNodeTask -> DeclarationCase-A + DeclarationCase-B -> ReleaseEvidence-A + ReleaseEvidence-B -> container-level customs release aggregation。

| 关系               | 判定                                                 |
| ------------------ | ---------------------------------------------------- |
| 货柜到报关案卷     | 一票货柜业务对应两票独立出口报关单                   |
| 报关案卷到放行     | 每票报关单各有对应审核放行通知，必须分别关联         |
| 发票到货物         | 商业发票覆盖多个商品行及 CIF 总额                    |
| 海运单到货柜       | 海运单提供货柜、封条和运输范围                       |
| 议付明细到商品     | 内部界面按商品行展示数量、FOB/CIF、费用、汇率和分摊  |
| 内部业务到外部证据 | 附件齐全和内部审核可建立证据引用，但不能自产海关放行 |

不能仅凭文件名或相似业务号关联。实现时需要通过 typed invoice、shipment、container 和 declaration references 以及适用商品范围建立确定性关系。

## 4. 海关放行事实

两份通知均表达“电子报关单数据业经海关审核放行”。该文字在本样本中是中国出口报关单级强放行候选，但仍需：

1. 保存通知全文或不可变原始证据、内容哈希、来源和采集时间。
2. 明确每份通知对应的报关单和适用货物范围。
3. 校验报关单、货柜、提单和当前 CustomsExportNodeTask 的对象一致性。
4. 确认通知版本、签发/下载渠道及撤销或改单机制。
5. 检查同一货柜的全部必需报关案卷均已取得有效放行。

规范事件统一使用已登记的 `release`；出口方向、司法辖区和案卷类型分别进入 `context.direction=export`、`context.jurisdiction` 与案卷字段，不通过方向化事件码复制同一放行语义。最终应用仍需公共契约与证据守卫评审。

## 5. 双案卷聚合守卫

| 场景                 | 处理                                            |
| -------------------- | ----------------------------------------------- |
| 两票均未放行         | NodeTask 等待，主链不推进                       |
| 只有一票放行         | 保存该案卷事实，整体保持阻塞                    |
| 两票均放行且范围完整 | 生成货柜级海关工序完成候选                      |
| 一票删单/改单        | 旧案卷封存或失效，重新计算必需案卷集合          |
| 放行通知重复导入     | 证据和事件去重，不重复完成工序                  |
| 旧的未放行消息晚到   | 保留历史并标记乱序，不回退较新有效裁决          |
| 放行后收到权威撤销   | 建立撤销/异常事实并进入人工对账，不静默删除历史 |

货柜级聚合键必须包含申报批次版本和完整案卷集合，不能仅统计“收到两条 Release”。

## 6. 财务与费用边界

| 状态/字段                                  | 语义                       | 禁止推断                   |
| ------------------------------------------ | -------------------------- | -------------------------- |
| 议付状态/审核                              | 内部财务作业状态           | 款项已收或海关放行         |
| 销售确认                                   | 内部确认事实               | 外部客户已付款             |
| EBS 同步成功                               | 系统间技术同步结果         | 会计业务过账或结算成功     |
| 附件齐全                                   | 所需内部附件集合已满足候选 | 附件内容已验证、海关已接受 |
| CIF/FOB 金额                               | 商品与价格条款下的金额投影 | 海关估价最终结论           |
| 海运、保险、包干、报关、拖卡及国内物流费用 | 费用分配输入               | 已开票、已支付或应收已确认 |

PDF 文件名中的“应收发票”不能覆盖文档正文的 Commercial Invoice 类型。AccountingInvoice/Receivable 与 CommercialInvoice 必须使用不同文档类型和状态。

## 7. 金额与汇率规则候选

| 规则 ID  | 规则                                                  | 失败处理                     |
| -------- | ----------------------------------------------------- | ---------------------------- |
| S012-P01 | 所有金额使用定点十进制并携带币种                      | 缺币种时不得计算             |
| S012-P02 | 销售币种、物流币种、报关币种和本位币分别保存          | 不用界面显示符号猜测币种     |
| S012-P03 | CIF = FOB + 可计入运费 + 可计入保险费的规则必须版本化 | 未确认估价口径时只做对账     |
| S012-P04 | 汇率保存类型、来源、生效日、精度和舍入规则            | 不使用浮点默认值             |
| S012-P05 | 商品行费用分摊保存分摊基础、规则版本和舍入差额        | 行合计与总额不平时进入复核   |
| S012-P06 | 商业发票、议付投影和报关单金额分别重算                | 不因总额相同自动视为同一事实 |

## 8. 单证与认证边界

商业发票包含 FSC 相关声明和证书引用，内部明细也有 FSC 字段。证书引用、行级声明和是否适用必须分别保存；出现证书号不等于每个商品均具备 FSC Claim，更不影响海关放行事实。

Sea Waybill 显示 Freight Prepaid 和“费用支付后方可交付”的运输条款。它说明承运合同条件，不证明当前费用已支付，也不能取代码头或船司 Release。

## 9. 工单设计

| 工单                | 完成证据                     | 对主链影响             |
| ------------------- | ---------------------------- | ---------------------- |
| 商业发票核对        | 发票行、总额、币种和条款对账 | 不直接推进             |
| 报关案卷 A 放行核验 | 对应放行通知验证成功         | 更新案卷 A             |
| 报关案卷 B 放行核验 | 对应放行通知验证成功         | 更新案卷 B             |
| 海关工序聚合        | 必需案卷集合全部有效放行     | 产生工序完成候选       |
| 运输单证关联        | 海运单和货柜/提单范围确认    | 为后续运输节点提供证据 |
| 议付与费用对账      | 金额、汇率、分摊和同步回执   | 只更新财务子任务       |

海关工序完成和财务子任务完成保持正交。除非权威生命周期规则明确要求，财务未完成不应反向篡改已确认的海关放行事实。

## 10. 待确认

1. 两份审核放行通知的官方来源、真实性验证和发生时间字段。
2. 两票报关的完整案卷集合如何确定，以及删改单后的版本规则。
3. 中国出口海关放行后进入下一主链节点还需哪些码头、配载或装船守卫。
4. 议付状态、销售确认、EBS 同步和会计过账的正式状态定义。
5. CIF/FOB、海运费、保险费和国内物流费的正式估价及分摊口径。
6. FSC 证书、Claim 和商品适用范围的权威校验方式。
7. Commercial Invoice 与真正应收会计发票之间的生成和引用关系。

## 11. 对契约的贡献

本样本首次为中国出口提供“两票报关单分别放行后聚合货柜工序”的真实闭环，可用于定稿案卷级放行证据、聚合守卫、重复/乱序规则，以及带方向 context 的注册规范事件。财务状态、金额分摊及会计边界仍需财务负责人确认。
