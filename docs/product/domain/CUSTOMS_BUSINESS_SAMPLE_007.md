# 海关业务样本 007：中国出口报关平台作业

> 状态：真实脱敏现网界面样本 · 待业务确认 · 2026-09-08
>
> 边界：三张截图及一组报关合同、装箱单、发票、报关单和汇总 PDF 展示同一出口报关作业的界面与单证结构。它们证明现有系统的数据结构、操作入口和报关资料集已经形成，不证明数据已被海关受理、货物已经放行或退税已经完成。

## 1. 样本目的

验证一票货柜业务如何按报关主体和申报范围拆成多个报关案卷，并把货物 BOM、装箱汇总、报关票、报关明细、申报要素和 SKU 金额投影保持可追溯关联。

## 3. 已观察对象关系

关系链：Container / declaration preparation order -> Cargo BOM lines -> one or more CustomsDeclarationCase -> declaration header/lines/elements -> SKU valuation projection -> terminal data reconciliation。

| 关系 | 观察结论 |
|---|---|
| 一柜到报关票 | 同一货柜业务按字母分组和不同报关主体拆成两票 |
| BOM 到报关明细 | 多个 SKU/货号聚合为较少的报关品名行 |
| 报关票到报关明细 | 每票有独立箱数、重量、体积、分提单引用和发送结果 |
| SKU 到金额 | SKU 层同时展示报关币种、销售币种、FOB/CIF 单价及分摊金额 |
| 装箱对账 | 系统箱数/重量/体积与装箱数据并列，并显示差异 |
| 码头对账 | 码头进门数据是独立来源；截图中的空数据不能视为零 |
| 源表到 PDF | 汇总 PDF 复现源工作簿中的报关资料类别 | 建立同一 DocumentSet 下的源文件/呈现文件关系，不重复生成业务事实 |

## 3.1 单证文件观察

| 观察 | 处理结论 |
|---|---|
| 四个文件扩展名为 `.xls`，文件签名实际为 XLSX | 导入按文件签名识别格式，扩展名不作为解析器唯一依据 |
| 合同、装箱单、发票和报关单各只有一个工作表 | 分别作为有类型的独立文档，不按 Sheet 名猜测文档类别 |
| 工作表大量使用合并单元格 | 抽取器必须按版式定位和标签语义读取，不能按普通首行表头导入 |
| 合同仅观察到少量公式，其他工作簿未观察到公式 | 所有数量、重量、体积和金额合计必须由系统独立重算 |
| 汇总 PDF 共 6 页且包含多种报关资料 | 按页识别子文档边界，同时保存整包证据哈希和页级引用 |

## 4. 状态和动作边界

| 类型 | 截图所示 | 目标语义 |
|---|---|---|
| 备货单状态 | 内部业务状态 | 不代表报关状态 |
| 报关状态 | 平台作业状态 | 不直接等于海关裁决 |
| 报关匹配/审校状态 | 数据质量和审校过程 | 不代表接口发送或海关放行 |
| 发送结果 | 外部操作回执候选 | 必须解析结构化载荷、来源和阶段 |
| 码头数据 | 外部实物流转证据 | 不代表海关状态 |
| 退税配置 | 财税处理标记 | 不代表退税申报或到账 |

页面包含保存、打印、提交/取消报关、挂起、单证复核、数据推送、商检校对、资料发送/下载、刷新和外部模板导出等动作。每个动作必须成为有权限、有前置条件、有幂等策略和审计记录的独立命令，不能用按钮颜色或是否可见推断后台状态。

## 5. 规则候选

| 规则 ID | 规则 | 失败处理 |
|---|---|---|
| S007-P01 | 一个货柜允许关联多票报关案卷，每票必须保存独立申报主体和适用货物范围 | 不允许把一票结果广播到整柜其他案卷 |
| S007-P02 | BOM/SKU 到报关明细使用显式聚合关系，保留源行、数量和金额分摊 | 聚合无法对平时阻止提交 |
| S007-P03 | 系统、装箱和码头的箱数、毛重、净重、体积分别保存来源 | 空值不按零处理，差异进入对账 |
| S007-P04 | 报关数量、出运数量及其单位分别保存并校验换算规则 | 单位未知或不兼容时明确失败 |
| S007-P05 | 海关编码、申报中英文品名、货源地、品牌、申报要素分别建模 | 禁止拼成不可解析备注 |
| S007-P06 | FOB/CIF 金额使用定点十进制加币种，并记录从销售金额到报关金额的分摊规则版本 | 缺币种、汇率或分摊依据时阻止确认 |
| S007-P07 | 发送请求、技术接收、平台受理和海关终态使用分阶段回执 | 发送成功不得自动改为海关完成 |
| S007-P08 | 取消报关和挂起是独立命令，必须记录原因、操作者、版本和外部结果 | 仅修改本地状态不得伪造外部撤销 |
| S007-P09 | 商检、退税和海关裁决保持正交 | 任一标记不得代替另一业务事实 |
| S007-P10 | 外部模板、打印和下载只消费权威投影 | 不在前端复制金额、状态或分票规则 |
| S007-P11 | 文件解析以签名、MIME 和内容结构为准，扩展名只作提示 | 格式冲突显式告警并进入受控解析 |
| S007-P12 | 合同、装箱单、发票、报关单和汇总 PDF 使用 typed document reference 关联 | 禁止仅凭相似文件名合并 |
| S007-P13 | 对数量乘单价、商品金额、重量、体积和各层合计独立重算 | 静态合计或公式结果不对平时阻止确认 |
| S007-P14 | PDF 页与源工作簿内容相同或重叠时只建立证据呈现关系 | 不重复创建商品行、费用或状态事件 |
| S007-P15 | 报关资料集形成、平台提交、技术接收、海关受理、审结和放行分开 | 单证齐全不得生成海关终态 |

## 6. 对管道模型的贡献

| 层级 | 本样本候选落点 |
|---|---|
| 主任务 | 货柜及其出口申报业务 |
| 节点子任务 | 出口报关工序任务 |
| 工单 | 资料准备、分票、商品归类、申报要素、商检校对、单证复核、发送、异常处理 |
| 海关案卷 | 每一报关票一个 CustomsDeclarationCase |
| 外部操作 | 每次提交、取消、查询或数据推送一个 ClientOperation |
| 证据 | 请求快照、分阶段回执、报关单证、码头数据和人工复核 |
| 主链推进 | 只由适用范围明确且经验证的权威规范事件触发 |

报关平台显示“已完成”只能作为现有平台状态事实。未取得状态字段定义、外部回执和海关裁决证据前，不得将它直接映射为 `customs.release.confirmed`。

## 7. 待确认

1. “已报关”“已完成”“报关匹配状态”和单证复核各自的正式状态定义。
2. 两票报关的分票依据、字母分组含义及与报关主体的唯一约束。
3. “报关数据推送”和“报关资料发送”的目标系统、请求及三阶段回执。
4. 发送结果字段中的结构、状态码、幂等键和失败重试行为。
5. 码头进门数据与海关申报数量的对账时点及允许差异。
6. FOB/CIF、海运费、保险费、汇率和 SKU 分摊算法。
7. 商检、退税、取消报关和海关放行的权威证据样本。
8. 本出口报关工序在 14 节点主链中的位置及下一节点守卫。
9. 源工作簿与汇总 PDF 的生成关系、签章版本和最终提交版本。
10. 合同、装箱单、发票、报关单之间数量、重量、金额和申报行的业务容差。

## 8. 对契约的贡献

本样本可以支持一柜多报关案卷、SKU 到申报行聚合、多来源装箱对账、多币种估价和分阶段外部操作的契约草案。它暂不能锁定中国出口海关状态码、放行证据等级或主链转移事件。

后续真实放行闭环见 [海关业务样本 012](./CUSTOMS_BUSINESS_SAMPLE_012.md)：该样本包含两票报关单及各自审核放行通知，可用于验证多案卷聚合，不反向把本样本的界面状态升格为海关事实。
