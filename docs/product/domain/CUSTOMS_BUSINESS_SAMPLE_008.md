## 3. 外部码解释

| 外部组合 | 当前候选含义 | 规范落点 | 生命周期政策 |
|---|---|---|---|
| `SRM + Hold` | 其他监管主体扣留 | `hold`，party/category=`SRM` | 创建或更新监管 Hold；不得映射为 customs inspection |
| `TML + Hold` | 码头扣留 | `hold`，party/category=`TML` | 创建或更新码头 Hold |
| `CUS + Hold` | 本截图未出现 | 海关 Hold 候选 | 不得因缺行推断 Release |
| availableStatus = NO | 当前不可提箱投影 | pickup eligibility=false | 只表达综合结果，不替代各 Hold 原因 |

`SRM`、`TML` 和 `CUS` 是类别上下文，不是可以脱离 `holdStatus` 使用的独立状态码。只有相同类别的有效 Release/解除事实才能关闭对应 Hold；一个类别解除不得清空其他类别。

## 4. 状态聚合候选

关系链：ProviderRawPayload -> HoldObservation(category, status, occurredAt) -> category-specific HoldLifecycle -> ContainerHoldProjection -> PickupEligibilityProjection -> lifecycle guard。

建议可提箱守卫至少检查：

1. 适用货柜和码头一致。
2. `CUS/SRM/TML` 各类别当前投影不存在阻断性 Hold。
3. 所需船司、费用和预约条件满足。
4. 事件来源、发生时间、接收时间和映射版本有效。
5. 空值、未知类别、乱序或相互冲突的数据已完成对账。

## 5. 规则候选

| 规则 ID | 规则 | 失败处理 |
|---|---|---|
| S008-P01 | Hold 业务键至少包含 provider、country/terminal、container、category 和发生时间/外部引用 | 对象或类别缺失时进入复核 |
| S008-P02 | 原始 `holdCategory` 与 `holdStatus` 分列保存，映射按组合和版本执行 | 未知组合禁止静默归类 |
| S008-P03 | 每个 Hold 类别维护独立生命周期和当前投影 | 单一 Release 不清空其他 Hold |
| S008-P04 | 事件发生时间、供应商更新时间、接收时间和重订阅时间分别保存 | 后到数据不按接收顺序覆盖 |
| S008-P05 | 可提箱状态是派生投影，同时保留形成结果的全部守卫和证据 | 不允许只存一个布尔值 |
| S008-P06 | 免费期截止是费用/预警输入，不是 Release 或可提箱事实 | 到期只触发预警/费用工单 |
| S008-P07 | Hold 描述为空时保留空值，不根据类别生成伪造描述 | UI 展示规范名称，但标明来自映射 |
| S008-P08 | 重订阅和刷新只改变同步操作，不改变 Hold 业务事实 | 同步成功不等于解除 |

## 6. 工单和主链影响

| 外部事实 | 工单候选 | NodeTask/主链处理 |
|---|---|---|
| `SRM + Hold` | 监管 Hold 核查、补件或协调 | 节点保持阻塞；不得标记海关查验完成 |
| `TML + Hold` | 码头 Hold 处理 | 提柜前置条件不满足 |
| 多 Hold 并存 | 综合放行对账 | 所有必要类别解除后重新计算可提箱资格 |
| 数据长期未更新 | 飞驼同步核查 | SyncRecord 异常，不覆盖 Hold 投影 |

Hold 是正交异常/守卫事实，不应增加 14 节点主链节点。它可以触发工单并阻止进入提柜节点。

## 8. 对契约的贡献

本样本可以支持 `HoldObservation`、分类 Hold 生命周期、可提箱派生投影和提柜守卫的契约草案。它不能支持 `customs.inspection` 或 `customs.release.confirmed` 的定稿。
