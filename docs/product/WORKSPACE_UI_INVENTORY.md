## 3. 「干活」和「看档」的边界

两页读**同一份** `GET /containers`，不是两套货柜。分开是为了**动作不同**，所以表名就是动作（UI-D09）：

|      | 干活               | 看档               |
| ---- | ------------------ | ------------------ |
| 问题 | 这一柜现在要做什么 | 这一柜实际走到哪了 |
| 点击 | 我的任务           | 一柜一档           |
| 角色 | 现场也能进         | 只有计划/经理      |

目标中观页还应有：一批/一票对比、完整迷你轨道、风险、待办数、计划偏差（见 UX §1.2）。现在只有已落库站点迷你轨，没有计划时间和风险。看起来像重复表时，优先补中观投影，或收成「一张表、两个动作」，不要再复制第三份名单。

总览（`/dashboard`）目标是全局 KPI 与风险下钻（UX 全局层）。现在只有柜数，避免和货柜表抢「干活」入口。
