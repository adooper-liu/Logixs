# GC-012 G1: Provisional Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Register and instantiate a provisional GC-012 contract for cross-workbench handoff metadata, append-only dispositions, responsibility windows and typed time references without adding persistence or production behavior.

**Architecture:** G1 consumes G0's single 23-workbench catalog. JSON Schema defines small composable `$defs`; a handoff-type catalog references existing domain payload schemas. Validator and fixture guards reject domain-state leakage and semantic drift. No application, database or Web runtime changes are allowed.

**Tech Stack:** Markdown contract authority, JSON Schema draft 2020-12, AJV, generated TypeScript, Node tests, pnpm 10.

**Spec:** `docs/superpowers/specs/2026-10-03-gc12.md`

## Global Constraints

- G0 must be merged and provide one 23-code technical catalog before G1 begins.
- Register GC-012 as provisional; D2/D3/D4 maturity follows registry governance, not implementation optimism.
- Do not reuse GC-009 reception/decision/commit states as handoff responsibility semantics.
- Do not reuse shipment `raised/claimed/closed`, product opportunity intake state or common `TimeKind` as GC-012 enums.
- Do not expand GC-007 EntityType in G1; use a narrow versioned authority reference owned by GC-012.
- Public contract contains no domain status, qualification status, amount, currency, mutable current state or embedded domain payload.
- No `database/**`, `apps/api/**` or `apps/web/**` production changes.
- GC-012 remains provisional after D4 until G2/G3 controlled real/de-identified role receipts pass.

## Review Focus

1. `received` and `claimed` inputs must not be schema-valid responsibility-transfer boundaries.
2. `closed`, mutable `status/state/updatedAt`, amount/currency and embedded payload objects must fail schema validation.
3. A derived time without source inputs/rule version/timezone/as-of must fail; no `dueAt` alias is allowed.
4. Handoff-type definitions must reference compiled domain payload schemas and only G0 catalog codes.
5. JSON Schema proves shape only; docs and tests must not claim append-only persistence or responsibility uniqueness has been implemented.
