# 通用办理型工作台 UI 标准 · 设计

> 状态：**负责人已确认，待实施计划** · 2026-10-11
> 一句话：**用稳定办理壳把“定位 → 进展 → 缺口 → 任务 → 动作 → 回执”连成一条业务动线；统一布局与交互，不统一业务判断。**
>
> 业务权威：[岗位工作台](../../../doc/cross-border-supply-chain/08-role-workbenches.md)
> UI 权威：[UI_SYSTEM](../../product/UI_SYSTEM.md)
> 技术映射：[角色工作台以人为中心的设计契约](../../product/ROLE_WORKBENCH_HUMAN_CENTERED_DESIGN.md)

## 1. 目的与成功判据

本标准解决三个问题：

1. 每台工作台重复实现 PageHeader、责任上下文、三栏、断点、折叠、空态和移动布局，搭建成本高；
2. 相同区域在不同页面表达不同语义，等待、失败、完成和只读状态还会改变整页结构；
3. 页面展示了大量信息，却没有形成与岗位结果强相关的连续办理动线。

统一验收问题是：

> 用户是否无需来回寻找，就能知道：**我在哪、进展到哪、具体卡在哪、现在做什么、完成条件是什么，以及操作后结果与责任去向是什么。**

标准只统一信息责任、布局原语、交互方式和验收，不统一各台的队列优先级、领域事实、完成条件、权限政策、责任转移或业务状态机。

## 2. 设计边界

### 2.1 沿用现有主题

- 不改变项目现有颜色系统、主题身份、亮暗模式、字体和令牌；
- 不复制原型中的色值、渐变、阴影、圆角或字体定义；
- 业务视图继续只依赖稳定 UI 门面，不直接导入 `themes/*`；
- 视觉层级使用现有令牌表达：高优先级、待办理和已完成可以使用同色相明度层级，但状态仍须有文字或形态编码；
- 原型 `D:\aosom\Downloads\选品立项工作台_界面优化原型.html` 只作为布局、动线和可视化参考，不是生产主题或业务契约。

### 2.2 不建立万能工作台

通用层不得计算或推断：

- 完成几项、真实分母、能否提交；
- 当前用户是否有权执行；
- 状态码对应哪个责任人或下一阶段；
- 缺失事实能否按 `0` 或默认值处理；
- 等待、失败、只读或完成时是否删除栏位；
- AI 建议是否已经采信或业务是否已经落账。

这些值必须由领域服务、服务端允许动作或受控查询投影提供。

### 2.3 不做独立全站视觉翻新

共享标准由真实工作台消费者验真；其余工作台随各自业务切片逐台迁移。不得用一次横扫 `apps/web/src/**` 的改造替代逐台业务目的、事实、动作和结果验收。

## 3. 稳定页面结构

办理型工作台的标准顺序为：

```text
AppShell
└─ PageHeader：正式工作台身份 + 工作会话切换 + 关联子功能入口
   └─ 岗位 / 对象 / 责任上下文
      └─ 决策条：结论摘要 + 可选进展 + 可办缺口 + 唯一主动作
         └─ 办理区：左队列 + 中详情 + 右动态上下文
```

同一视口内，任务状态只能切换中栏和右栏内容，不得改变以上区域的存在、顺序、职责或栏宽。布局变化只允许来自视口变化或用户显式折叠、抽屉、分屏操作。

## 4. PageHeader：身份、切换与关联子功能

### 4.1 正式工作台身份

PageHeader 左侧固定表达：

1. **眉题：岗位类别**——谁使用这台工作台；
2. **主标题：正式工作台名称**——当前属于哪个业务节点；
3. **主标题描述：唯一主要业务目的**——帮助该岗位基于什么可信事实完成什么关键结果，并形成什么可交接价值。

主标题描述用于功能和价值引导，不是营销副标题。它必须来自正式业务权威生成的稳定投影，并满足：

- 不随当前对象、任务状态、失败、等待或完成结果变化；
- 不写“智能化、一站式、高效赋能”等营销语；
- 不罗列“查看列表、填写表单、提交”等组件或操作；
- 不把当前 `N/8`、缺口或状态写进工作台目的；
- 窄屏允许自然换行，不截断核心业务目的。

### 4.2 PageHeader 右侧职责

右侧固定保留两个入口：

1. **切换**：管理已经打开的并行工作现场；
2. **更多功能**：发现并打开与当前工作相关联的独立子功能。

二者都不得承载当前对象的提交、审批、接收、退回、补证、冲突处置或失败恢复。这些动作属于右侧动态上下文。

### 4.3 “切换”管理并行工作现场

切换器用于：

- 查看当前、待续办、草稿已保存、仅保留现场、冲突和已完成的工作会话；
- 在多个工作台和任务现场间切换；
- 暂停未完成工作会话并稍后恢复；
- 相同 `workbenchCode + subjectRef + taskRef` 已打开时切回原现场，不重复创建。

打开切换菜单不改变当前页面。只有目标会话完成草稿处理、重新授权、数据重读和版本校验后，才原子切换：

- 目标会话成为唯一“当前”；
- 原会话移除“当前”，按真实保存结果显示续办状态；
- PageHeader 名称、业务目的、切换按钮摘要及三栏现场同时更新；
- 切换失败时当前标记不移动，原界面不变化，也不得短暂出现两个“当前”或无“当前”。

工作会话状态与业务状态分轨：

- 工作会话状态：当前、待续办、草稿已保存、冲突、关闭；
- 业务状态：办理中、等待、失败、退回、已完成等领域事实。

切换不能暂停 SLA、释放领取、转移责任或改变业务状态。

### 4.4 “更多功能”扩展业务边界

“更多功能”不是工具菜单。其每个入口都是与当前工作相关联的**独立子功能**，必须具备：

- 独立业务目的、目标用户和优先损失；
- 独立数据事实、权限、状态、动作、回执与恢复；
- 独立 PageHeader 和完整界面；
- 独立 task brief、实现和验收；
- 与来源工作台之间明确的业务对象、任务、事项和版本引用。

打开关联子功能时：

```text
保存或保留当前工作会话
→ 创建子功能工作会话
→ 传递受控来源引用
→ 子功能重新授权并读取自己拥有的事实
→ 打开独立界面
```

来源只传稳定引用，不复制领域数据。未经过独立业务定案和实现的候选功能不得出现在生产菜单中，也不得显示“即将开放”空入口。

## 5. 岗位、对象与责任上下文

PageHeader 下方的责任上下文至少能承载：

- 当前对象与来源；
- 本次要形成的岗位结果；
- 当前责任；
- 下一责任；
- 截止时间；
- 等待对象与等待原因。

通用组件只负责排版和响应式，不根据角色名、状态码或工作台 code 推导责任。值来自领域事实、责任投影或交接记录。

## 6. 决策条：结论前置、缺口直达、动作同线

决策条位于责任上下文和三栏办理区之间，负责当前对象的首屏摘要：

- 当前结论或办理状态；
- 可选的结构化进展；
- 可直接办理的缺口；
- 唯一主动作或其明确禁用原因。

### 6.1 进展表达

- 只有存在有限、稳定、可验证的完备项时才使用分段计数；
- 选品立项可使用 `N/8`，其他工作台必须使用自己的真实阶段、门槛或缺口，不机械复制八段；
- 不使用无法反推出实际剩余项的泛化百分比；
- `0` 只能表示已知为零，未知或未接通必须显式显示未知、未定义或不可用。

### 6.2 缺口可直接办理

缺口不是静态文案。可办理缺口必须能定位中栏对应事项，并保留键盘焦点、滚动位置和高亮反馈。缺口的存在、类型和影响由服务端投影，前端不得自行推断。

### 6.3 主动作与条件同线

主动作保持可见。不可执行时必须就地说明缺少哪些事实、证据、权限或责任前置，并提供定位或恢复入口，不能只显示灰按钮或把原因藏进 Tooltip。

## 7. 满高三栏与双侧折叠

### 7.1 桌面满高

在桌面视口，左、中、右三栏共同占满 PageHeader、责任上下文和决策条以下的剩余视口高度：

```text
可用栏高 = 视口高度
          − AppShell 顶栏
          − PageHeader
          − 责任上下文
          − 决策条
          − 页面安全间距
```

规则：

- 每栏内容区独立滚动，栏头、折叠按钮和关键摘要保持可见；
- 切对象、切状态或打开右侧编辑器不得推动整个浏览器页面上下跳动；
- 左右栏折叠后的窄轨保持相同满高；
- 单栏滚动不应意外改变其他栏的滚动位置。

### 7.2 左栏：唯一定位源

左栏只负责对象或任务定位：

- 项目或任务名称；
- 文字状态与状态点；
- 真实进展摘要；
- 当前责任、到期或等待的必要提示。

它不与中栏竞争主视觉，不再铺陈详细事实，也不创建第二套选择器。

### 7.3 中栏：事实、缺口与推进任务

中栏回答“哪项需要处理”：

- 待完成事项置顶并展开；
- 已完成事项折叠、下沉并降低视觉权重；
- 适用时使用“目标 → 事实 → 证据 → 判断 / checklist”推进，而不是平铺同权卡片；
- 中栏按钮只选择具体事项，并把编辑、补齐或处置上下文交给右栏。

### 7.4 右栏：动态操作与上下文

右栏回答“如何处理当前事项”，始终保留栏位，支持受控视图栈：

1. 当前对象操作上下文；
2. 中栏事项触发的编辑视口；
3. 任务全程档案；
4. 任务内协作对话；
5. AI 辅助与确认执行；
6. 当前上下文的导出、布局偏好与帮助。

右栏顶部始终显示当前任务、当前事项、当前模式和返回上一级入口。保存、取消或完成后回到对象操作上下文，并恢复中栏选中事项、滚动位置和焦点。

右栏不是固定 CTA 集合，也不承载“更多功能”中的独立子功能完整页面。

### 7.5 双侧折叠

左、右栏可由用户独立折叠，也可同时折叠：

- 折叠是显式布局行为，任务状态不得自动触发；
- 桌面折叠后保留满高窄轨，不彻底删除栏位语义；
- 左轨至少保留当前对象、进展和待办数；
- 右轨至少保留阻塞数、可执行动作数和恢复入口；
- 展开恢复原宽度、选择、滚动和焦点；
- 折叠控制支持键盘操作和可访问的展开/收起状态；
- 折叠偏好是个人界面偏好，不是业务事实，也不跨用户共享。

## 8. 响应式策略

### 8.1 `1440×900`

- 左队列、中详情、右动态上下文三栏并列并共同满高；
- 左右栏均可折叠为窄轨；
- 中栏事项与右侧编辑器保持相邻。

### 8.2 `1024×768`

- 左栏默认收为窄轨，可展开为覆盖式抽屉；
- 中栏与右侧动态编辑器继续并列；
- 不采用“队列 + 动作在第一行，详情在第二行”的错误顺序；
- 决策条可换行，但结论、缺口和主动作关系保持清楚。

### 8.3 `390×844`

- 不把三栏无限向下堆叠；
- 使用明确的“队列 → 详情 → 编辑”分屏推进；
- 编辑屏保留当前对象和事项面包屑；
- 返回详情恢复滚动和焦点；
- 底部动作不得遮挡正文或系统键盘。

跨视口始终保持：

```text
对象定位 → 事实与缺口 → 选择办理事项 → 编辑办理 → 结果回执与责任去向
```

## 9. 状态稳定性

办理中、等待、失败、冲突、退回、只读和已完成只改变中栏及右栏内容：

| 状态      | 中栏                             | 右栏                              |
| --------- | -------------------------------- | --------------------------------- |
| 办理中    | 事实、缺口与待办                 | 允许动作、条件与编辑              |
| 等待      | 已完成事实与等待事项             | 等待谁、到期、催办/撤回或恢复入口 |
| 失败      | 保留输入、失败事实与最近成功版本 | 稳定错误码、追踪 ID、重试与恢复   |
| 冲突      | 当前版本、服务端版本与差异       | 重读、比较和重新提交              |
| 只读/完成 | 冻结结果、证据与时间线           | 结论、责任去向和后续入口          |

所有状态都保留：

- 正式工作台身份与业务目的；
- 当前对象和左队列唯一选择；
- 当前责任、下一责任和时间事实；
- 右侧操作上下文或只读结果上下文。

完成后不得切成另一整页模式；等待或只读时不得删除右栏；失败后不得清空已填内容或只弹 toast。

## 10. 内容克制与 Toptip

工作台不是培训材料。常驻内容只保留完成当前业务动作所需的事实、缺口、条件、动作和结果。

### 10.1 常驻显示

- 当前对象、状态、进展和责任；
- 具体事实、来源、缺口和期限；
- 允许动作、完成条件和结果回执；
- 会改变用户当前决定的信息。

### 10.2 Toptip / Tooltip

只承载不会改变当前决定的轻量解释：

- 不熟悉术语的一句话定义；
- 统计口径；
- 图标含义；
- 格式示例。

Toptip 必须支持 hover、键盘 focus、点击和触屏关闭。字段名已能说清时不再追加解释。

### 10.3 必须就地显示

- 禁用原因；
- 缺失证据；
- 权限范围；
- 失败、冲突和拒绝；
- 等待对象与到期时间；
- 恢复动作；
- 数据是否真正落账；
- 结果与责任去向。

禁止培训教程墙、制度宣讲、泛化免责、重复字段解释、AI 总结式长段落和没有真实 AI 能力却出现的 AI 免责声明。

## 11. 可恢复工作会话

### 11.1 目标

用户可以同时保留多个工作台和任务的办理现场；当前任务未完成时可暂停个人工作现场，切换后再精确恢复，而不必重新寻找工作台、任务、事项和编辑器。

### 11.2 工作会话不拥有业务事实

服务端工作会话建议只保存可重建指针：

- `ownerActorId`、状态、版本和最后打开时间；
- `workbenchCode` 与受控 `RouteContext`；
- `subjectRef`、`taskRef/workOrderRef/handoffRef`；
- `draftRef + versionSeen`；
- 当前中栏事项和右栏模式；
- 可恢复的折叠、滚动锚点和移动分屏；
- 标签顺序与显示摘要缓存。

不得保存任意 Vue 组件状态、业务表单万能 JSON、前端推断权限、证据正文、Token、PII 或自由 URL。

### 11.3 本地与服务端边界

- URL：可分享的工作台、对象、任务和只读 view/filter；
- `sessionStorage`：当前浏览器标签页的临时折叠、分屏、滚动锚点和 active session 指针；
- `localStorage`：非敏感布局偏好和最近会话 ID 缓存；
- 服务端：跨刷新、跨设备或跨班次需要恢复的工作会话、领域草稿引用、版本、责任、等待、期限和业务事实。

### 11.4 打开新工作台

当前任务未完成时打开新工作台：

1. 无未保存改动：静默保存恢复指针并打开新会话；
2. 有改动且领域支持正式草稿：提供“保存草稿并打开 / 放弃本地改动并打开 / 留在当前页”；
3. 有改动但领域无草稿：不得伪装保存，只能明确放弃、留下，或在新的浏览器标签页打开以保留当前内存现场。

如果保存失败，则不切换，并在当前右栏显示原因与重试入口。

### 11.5 暂停工作会话与暂停业务任务分轨

暂停工作会话仅表示用户稍后继续：

- 不停止 SLA；
- 不释放 claim；
- 不转移责任；
- 不改变领域状态；
- 不暂停业务计时。

暂停业务任务只能调用领域正式的 `defer / block / wait / partial` 等动作，并记录原因、等待对象、恢复条件、时限影响和责任去向。

### 11.6 续办与冲突

恢复顺序固定为：

```text
重新授权
→ 重读对象、任务和领域草稿
→ 比较 versionSeen
→ 恢复工作台、对象、事项和右栏模式
→ 恢复折叠、滚动和焦点
```

对象已被他人处理、关闭或撤权时，不恢复陈旧按钮，必须显示冲突、当前版本和可用恢复路径。

## 12. 任务全程档案

任务交接后仍保留在原岗位左栏的“已交接待跟进 / 已完成”分组。用户在自己的工作台选中原任务即可查看后续，不必进入下游工作台。

中栏显示：

- 原岗位冻结结果与交接快照；
- 当前下游事实摘要；
- 当前缺口或等待原因；
- 跨工作台进程链。

右栏“任务全程档案”显示按时间组织的引用式组合投影，并分轨标识：

1. 业务事实；
2. 任务与工单变化；
3. 责任交接；
4. 操作回执；
5. 协作对话；
6. AI 建议、采信和执行轨迹。

档案不是新的业务事实表或全局审计。每项必须保留来源模块、来源 ID、版本、发生时间和记录时间；完整详情读取来源领域。投影延迟时显示 `asOf`、来源版本和追平状态，不冒充实时完整历史。

## 13. 任务内协作对话

第一版只建设与 `subjectRef + workRef` 绑定的结构化协作线程，不建设频道、私聊或社交型 IM。

对话至少支持：

- 消息与回复；
- Mention；
- 可见范围；
- `EvidenceRef` 附件引用；
- 链接正式业务动作、结果或证据的来源引用。

严格分轨：

- `@某人` 只是提醒，不转移责任；
- 消息写“已完成”不等于任务完成；
- 文件名不等于证据已上传或核验；
- 对话已读不等于任务已领取；
- 对话中的重要结论必须通过独立正式动作落账。

如果消息促成正式动作，业务记录可以保存 `sourceMessageRefs`，但业务事实拥有自己的结构化输入、结果、证据和版本。

## 14. AI 辅助与确认执行

### 14.1 第一阶段权限

负责人确认采用：**建议 + 确认执行**。

AI 可以：

- 解释当前事实；
- 汇总任务进程和协作对话；
- 识别缺口、冲突和版本差异；
- 生成结构化动作候选；
- 推荐下一步并定位正式办理入口。

AI 不得直接：

- 修改业务状态或责任；
- 接受、关闭或发布任务；
- 确认证据、费用或权限；
- 执行任意 SQL、HTTP、文件或代码工具。

### 14.2 确认执行链

```text
AI 读取受控上下文
→ 生成结构化动作候选
→ 右栏展示依据、影响和风险
→ 用户明确确认
→ 服务端重新验证身份、capability、对象范围、前置和版本
→ 正式业务 API 幂等执行
→ 返回操作回执
→ 领域事实成功落账
→ 任务档案记录采信与执行结果
```

用户确认不能替代服务端授权和领域规则。服务端仍可因无权、证据不足、状态变化或版本冲突拒绝执行。

### 14.3 来源与治理

AI 输出至少区分 `rule / model / fallback`，并记录：

- 能力 ID 与版本；
- 模型、Prompt 和 Schema 版本；
- 输入事实引用和快照哈希；
- 生成时间与覆盖范围；
- 风险等级；
- 采信、修改或拒绝状态；
- 确认人和确认时间；
- 工具或业务 API 执行结果；
- Execution ID、Trace ID 和操作回执。

未采信时必须显示“未采信，不改变业务状态”。

当前仓库只有 provider-neutral Gateway、确定性规则/Mock 和只读助手。真实模型、工具白名单、审批令牌、统一 AI 审计与自动执行未接通前，生产界面不得显示相应可用入口。

### 14.4 长流程

含长期等待、人工信号、外部回调、重试、超时或补偿的流程由 Temporal 编排。模型调用只能发生在 Activity 中；AI 不替代领域状态机或正式业务工作流。

## 15. 通用组件边界

### 15.1 中性布局原语

建议建立：

- `WorkbenchLayout`：稳定区域、满高、响应式、双侧折叠与焦点顺序；
- `WorkbenchDecisionStrip`：呈现外部给定的结论、进展、缺口和主动作；
- `WorkbenchResponsibilityBand`：呈现对象、目标、责任、期限和等待；
- `WorkbenchPane`：统一 pane 标题、计数、loading、empty、error、receipt 和 retry；
- `CollapsibleRail`：桌面窄轨、移动抽屉、偏好与焦点恢复；
- 工作会话切换器与 `RouteContext` 注册；
- 右栏受控视图栈。

这些组件属于通用模式层，不进入主题适配器，除非未来存在两个真实主题实现需要替换同一契约。

### 15.2 业务层继续拥有

- 队列优先级与为什么现在处理；
- 事实、证据、缺口、风险和阶段；
- 完成条件与真实进展分母；
- 服务端允许动作、拒绝原因、幂等和恢复；
- 责任转移与不可变交接；
- 生命周期 rail、阶段轨、领域 checklist 和结果回执。

## 16. 可执行视觉契约与防漂

文字语义规范不能单独保证视觉实现一致；讨论期原型和静态截图也不能单独成为长期权威。单元一必须同批交付以下四层视觉契约：

1. **标准线稿板**：集中展示标准区域关系和关键变体；
2. **可执行参考页**：使用生产 `WorkbenchLayout` 原语、稳定 UI 门面和当前主题令牌渲染，禁止复制一套仅供演示的 CSS；
3. **版本化基准截图**：由 Playwright 在标准三视口生成并纳入版本控制；
4. **结构断言与人工核对清单**：自动拦截区域、顺序、溢出和像素漂移，人工核对业务主线与视觉层级。

### 16.1 标准线稿板必须覆盖

- 默认桌面满高三栏；
- 左栏折叠、右栏折叠、双栏同时折叠；
- 中栏事项触发右栏编辑视口；
- 办理中、等待、失败、冲突、只读/完成；
- 工作会话切换、唯一“当前”迁移、dirty 草稿处置；
- PageHeader “更多功能”打开独立关联子功能，而不是切换右栏工具；
- 任务档案、任务内对话、AI 建议与确认执行在右栏中的分轨；
- `1440×900`、`1024×768`、`390×844` 三种响应式结构。

线稿使用真实岗位术语和代表性内容，但永久标明为结构参考；演练数据不得冒充生产记录。

### 16.2 可执行参考页

参考页必须：

- 直接组合通用布局原语，不复制消费者页面 DOM 和 CSS；
- 直接消费现有 `PageHeader`、主题令牌、字号、间距、圆角和动效规范；
- 通过固定、合成、无敏感数据的场景 fixture 切换全部关键变体；
- 不接生产写 API，不进入业务导航，不宣称任何工作台已完成；
- 只在开发/测试参考入口提供，生产菜单不可见；
- 参考页与真实消费者共用组件契约，任何公共组件变化必须同时更新参考页、截图和变更理由。

参考页不是第二套 UI 权威。`UI_SYSTEM.md` 和本设计说明语义；参考页把语义实例化为可检查的视觉契约。

### 16.3 基准截图与自动门禁

Playwright 至少保存以下基准：

- 三视口默认态；
- 桌面双侧栏各自折叠及同时折叠；
- 右栏编辑态；
- 等待、失败、冲突和只读结果态；
- 工作会话切换器展开及切换后状态；
- “更多功能”展开与独立子功能来源上下文；
- 浅色与深色模式的代表性默认态。

自动检查至少覆盖：

- PageHeader、责任上下文、决策条、队列、详情、右栏的存在、顺序和稳定角色；
- 页面级与各受控滚动容器无横向溢出；
- 桌面三栏实际填满头部以下可用高度；
- 1024 下左窄轨且中栏和右栏并列；
- 390 下队列、详情、编辑为显式分屏；
- 状态切换不改变栏数、区域顺序和工作台身份；
- “当前”工作会话始终且仅有一个；
- 键盘焦点、折叠恢复和 `prefers-reduced-motion`。

像素基线只负责发现变化，不自动证明设计正确。任何基准更新必须附变化原因，并由主代理逐张核对：首屏优先级、动线、状态真实性、主动作、重复文案、内容克制和恢复入口。

### 16.4 实际工作台仍需独立截图

参考页通过不能替代真实消费者验收。选品立项和第二个差异化工作台仍须在三标准视口提供真实页面截图，验证领域内容进入槽位后没有产生新卡片墙、重复状态、错误顺序或主动作漂移。

## 17. 参考消费者

共享标准至少由两个结构差异明显的真实消费者验真：

1. **选品立项**：验证 `N/8`、缺口直达、待完成优先、证据链、动态右栏和状态稳定；
2. **市场与经营信号**：不用 `N/8`，改用自身验证状态与去向缺口；验证关闭态仍保留责任上下文和右栏，证明组件未被选品语义污染。

第二消费者可因当前业务优先级调整，但必须具备不同的进展、队列和动作语义。一个消费者不足以证明通用抽象成立。

## 18. 五个交付单元与顺序

### 18.1 单元一：办理型工作台布局标准

- 增量写入现有 `UI_SYSTEM.md`，不建立第二套 UI 权威；
- 实现中性布局原语；
- 同批交付标准线稿板、真实组件参考页、版本化基准截图和结构/视觉防漂门禁；
- 先以选品立项验证，再以第二真实工作台验真；
- 不修改主题颜色系统。

### 18.2 单元二：可恢复工作会话

- 建立稳定 `RouteContext`、工作会话和页面 adapter；
- 先接已有强服务端草稿的工作台；
- 再接一个“无通用草稿、动作即落账”的工作台验证边界；
- 不建设万能草稿 JSON。

### 18.3 单元三：任务全程档案

- 先接两个真实领域来源；
- 建立只读组合投影与来源引用；
- 不把活动投影冒充全局审计或第二套业务事实。

### 18.4 单元四：任务内协作对话

- 建设任务/对象绑定的消息、回复、Mention 和 EvidenceRef；
- 正式业务动作与对话严格分轨；
- 不建设频道、私聊或社交功能。

### 18.5 单元五：AI 辅助与确认执行

- 先补能力版本、来源信封、采信记录、授权与审计；
- 第一阶段实现建议与人工确认；
- 工具治理未成熟前不开放自动执行。

五个单元共享一套 UI 标准，但分别建立 task brief、精确写域、风险门禁和真实消费者验收，不合成一个大 PR。

## 19. 验收范围

### 19.1 视觉与布局

- `1440×900`：满高三栏、双侧折叠、右栏编辑不推动页面；
- `1024×768`：左窄轨/抽屉，中栏与右编辑器并列；
- `390×844`：队列 → 详情 → 编辑分屏；
- 无页面级横向溢出、遮挡或状态切换引起的布局跳动；
- 真实截图由主代理逐张人工核对，不能以组件存在、bounding box 或测试全绿替代视觉判断。

### 19.2 状态与交互

- 办理中、等待、失败、冲突、只读之间往返，身份、责任上下文、队列、栏位和宽度保持稳定；
- 左右栏折叠、展开后选择、滚动和焦点恢复；
- 中栏触发右栏编辑，保存/取消后回到对象上下文；
- 禁用原因、失败与恢复就地可见；
- 键盘焦点按业务因果顺序移动，状态不只靠颜色。

### 19.3 工作会话

- 多会话切换时“当前”唯一且实时迁移；
- dirty 草稿保存失败时不切换；
- 相同任务已打开时切回原会话；
- 恢复时重新授权、重读并处理版本冲突；
- 暂停工作会话不改变任务责任、期限或业务状态；
- 无草稿能力时不伪装保存成功。

### 19.4 档案、对话与 AI

- 档案每项可追溯到来源模块、ID、版本和时间；
- 对话、业务事件和 AI 建议视觉与语义分轨；
- Mention、消息和附件不直接改变责任、任务或证据状态；
- AI 未采信时不改变业务状态；
- 用户确认后仍由服务端重授权、校验版本并返回正式操作回执；
- 未注册、未授权或尚未实现的能力不显示空入口。

## 20. 非目标与延期

本设计不直接批准：

- 新的业务子功能或“更多功能”菜单项；
- 23 台工作台一次性迁移；
- 全局审计系统或万能 Activity 表；
- 通用社交聊天、频道或私聊；
- 真实模型供应商、模型选择或自动 Tool 执行；
- 用工作会话暂停替代领域暂停、阻塞、等待或 partial；
- 用前端可见性替代服务端 capability 与对象范围授权。

以上能力必须在各自交付单元和真实消费者中独立定案、实现和验收。
