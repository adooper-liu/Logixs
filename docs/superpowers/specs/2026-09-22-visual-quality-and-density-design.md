## 1. 问题：一致性做完了，品质的空档还在

一致性收编（前序 spec）把字号与间距从"各处自己拍"收成了令牌，全站违规 1390 → 0。但**只解决了"值不一致"，没解决"层级不清楚"**。2026-09-22 用 CDP 量真实渲染的计算样式，发现三个空档：

### 1.1 字重档位不存在规范

| 实测在用        | 文档说           |
| --------------- | ---------------- |
| 400 / 700 / 800 | 区块标题 **650** |

`UI_SYSTEM §7.2` 写「页名 20px/700；区块标题 15-16px/**650**；正文 14px」。**650 在代码里从未出现**；实际是 400/700/800，而 800 全站仅一处（侧栏品牌符号）。所以"标题该多重"目前是每处自己拍的。

### 1.2 行高有 8 个互不相干的值，还有一个是 `normal`

```text
21.7px ×13   17.05px ×8   18.6px ×2   18px ×1
normal ×1    26px ×1      23.25px ×1  20.15px ×1
```

主力是 1.55（`21.7 / 14`、`17.05 / 11`），但它不是规则 —— 而且**有一个元素完全没设行高**，落到浏览器默认。行高是"读起来舒不舒服"的头号因素，现在它只是碰巧一致。

### 1.3 动效基本没上

两页的文字元素上**零过渡**。`--motion-fast: 120ms` / `--motion-normal: 180ms` 已定义，但除侧栏收起外几乎无人使用。

### 1.4 层级靠"双重降级"承载（最核心的问题）

`--muted` 在 `/workspaces/cargo-ready` 一页出现 **20 次，且几乎总配 11px**：

| 页面                      | 最高频组合                                      |
| ------------------------- | ----------------------------------------------- |
| `/workspaces/cargo-ready` | `11px` + `--muted` × **20**                     |
| `/containers`             | `11px` + `--muted` × 12，`12px` + `--muted` × 6 |
| `/tasks`                  | `11px` + `--muted` × 7                          |
| `/container/:id`          | `11px` + `--muted` × 7                          |

`UI_SYSTEM §7.1` 说 `--muted` 是"辅助信息"，但实际它已经变成**"把它变小变灰"的默认动作**。后果是：**辅助信息被罚了两次**（缩小 + 变浅），而不同性质的信息挤在同一个视觉分量里 ——

> 例：备货工作台一行里，「装载 50 carton」（元数据，扫过即可）与「责任方 采购 · 下一步 补齐电池证书」（用户做判断的依据）**长得一模一样**，都是 11px 灰。用户分不出哪条更要紧。

### 1.5 密度：一屏 19 行，现场要 25 行

`/containers` 实测：

```text
表格行高   40.7px
主区可用高 782px
一屏容纳   19 行
单元格字号 12px，内边距 8px
```

现场需要一屏看到"几十行"。**40.7px 一行对数据表偏高**（密排表格通常 28–32px），问题不在字号而在行高。

### 1.6 与前序 spec 的关系

前序 spec 的 §6.2 阶段 6 就是本文。一致性收编是它的前提 —— **没有令牌，就没有可执行的品质规则**。

## 2. 目标与非目标

**目标**

1. 把**层级**从"缩小 + 变浅"里解耦：字号由内容类型决定，颜色由信息等级决定。
2. 补齐**字重 / 行高 / 动效**三个空档，并写进 `UI_SYSTEM`。
3. 表格/队列密度从 19 行提到 **25 行**，**不缩字号**。
4. 把字重与行高**纳入现有门禁**，防止规则再次漂移。

**非目标**

- **不改信息动线**：页面"显示什么、什么顺序、单一选择源、例外优先"由 [角色工作台以人为中心的设计契约](../../product/ROLE_WORKBENCH_HUMAN_CENTERED_DESIGN.md) 的 `HW-D01`～`HW-D10` 管，本文不碰。
- 不改颜色值本身（`--ink` / `--ink-soft` / `--muted` 的色值不变，只定**用法**）。
- 不改字号档位表（6 档已定，见前序 spec D3）。
- 不做重设计、不换视觉语言。

## 3. 设计决策

### D1 · 两条独立的轴

> **字号**由「区域密度档 × 内容类型」决定；**颜色**由「信息等级」决定。
> 两者独立，**不得互相替代**。提高密度只收内边距，不缩字号。

**推论**：一条 14px 的内容若要降级，**不得缩成 11px** —— 只换成 `--muted`。反过来，元数据用 12px 是因为它**是**元数据，不是因为它"次要"。

### D2 · 密度是区域的属性，不是降级动作

一个区域（表格、队列、面板、详情）声明自己的密度档；区域内的尺寸按内容类型取该档的值。**不允许在同一个区域内为了突出/弱化某条信息而单独改字号。**

### D3 · 字重收成 3 档：400 / 600 / 700

**取消文档里的 650** —— 它不是真实字重、代码里从未出现。600 才是该有的那一档（比 700 轻，避免"到处加粗"）。

| 档位 | 用途                                     |
| ---- | ---------------------------------------- |
| 400  | 正文、元数据、辅助                       |
| 600  | 强调：对象名、当前值、区块标题、次级按钮 |
| 700  | 仅页名与主按钮                           |

800 仅保留给侧栏品牌符号（纯装饰，不属语义层级）。

### D4 · 行高收成 4 档

```text
1.3  标题（15 / 20px）
1.4  紧凑区（表格、队列）
1.55 正文
1.6  长文本段（说明、理由、空态文案）
```

**必须消除 `normal`** —— 无显式行高的文本元素一律视为缺陷。

### D5 · 动效只用两个令牌，且限定用途

- 只用 `--motion-fast`(120ms) / `--motion-normal`(180ms)
- **该有**：hover 背景、展开/折叠、状态点变化、抽屉与浮层
- **不该有**：文字颜色、字号、布局位移
- 必须尊重 `prefers-reduced-motion`

### D6 · 门禁扩展到字重与行高

现有 `findStyleScaleViolations` 只查 `font-size` 与间距属性。**不扩展的话，阶段 6 定完规则照样会被漂掉**。

## 4. 详细设计

### 4.1 尺寸轴：区域密度档 × 内容类型

| 密度档   | 适用区域             | 基础 | 元数据 | 对象名 | 行高 | 行内边距 |
| -------- | -------------------- | ---- | ------ | ------ | ---- | -------- |
| **紧凑** | 表格、队列（扫行）   | 12px | 11px   | 13px   | 1.4  | **4px**  |
| **常规** | 面板、详情（读判断） | 14px | 12px   | 15px   | 1.55 | 8px      |
| 页级     | 页名                 | 20px | —      | —      | 1.3  | —        |

**内容类型的归属**（决定用哪一列）：

| 类型               | 归属     | 例                             |
| ------------------ | -------- | ------------------------------ |
| 非必读元数据       | 元数据列 | 时间戳、来源、单位、编号、版本 |
| 表格单元格、字段值 | 基础列   | 状态、数量、日期               |
| 对象身份           | 对象名列 | 箱号、单号、SKU 号、人名       |

### 4.2 颜色轴：信息等级

| 令牌                              | 含义                 | 典型位置                       |
| --------------------------------- | -------------------- | ------------------------------ |
| `--ink`                           | **必须先读**         | 对象身份、当前动作、结果       |
| `--ink-soft`                      | **支持判断**         | 事实、数值、责任方、下一步     |
| `--muted`                         | **可跳过**           | 时间戳、来源、单位、编号、版本 |
| `--brand`                         | _可交互_（不是层级） | 链接、导航激活                 |
| `--ok` `--warn` `--risk` `--info` | _状态_（不是层级）   | 已完成 / 临期 / 风险 / 进行中  |

**判据**（决定一条信息用哪档）：

> **如果这条信息读错了会导致用户做错事，它就是 `--ink` 或 `--ink-soft`；只有读不读都不影响决策的，才是 `--muted`。**

按此判据，`/workspaces/cargo-ready` 中现有的 20 处 `11px + --muted` 里，**大部分应升为 `--ink-soft`**（"责任方""下一步""缺口原因"都是判断依据）。页面的整体"灰"会明显变少 —— **这是本次最直观的变化**。

### 4.3 令牌新增

加在 `themes/logix/tokens.css` 的 `:root[data-ui-theme="logix"]` 内（与字号/间距令牌同处，暗色块内不重复定义）：

```css
/* 字重：UI_SYSTEM §7.2 的档位 */
--weight-body: 400;
--weight-strong: 600;
--weight-page: 700;

/* 行高：UI_SYSTEM §7.2 的档位 */
--leading-title: 1.3;
--leading-dense: 1.4;
--leading-body: 1.55;
--leading-prose: 1.6;

/* 密度：区域属性，不是降级动作 */
--density-dense-row-padding: var(--space-1); /* 4px */
--density-regular-row-padding: var(--space-2); /* 8px */
```

### 4.4 门禁扩展

在 `findStyleScaleViolations` 的检查属性里加入：

| 属性          | 允许                                           | 禁止                                                               |
| ------------- | ---------------------------------------------- | ------------------------------------------------------------------ |
| `font-weight` | `var(--weight-*)`、`inherit`、`normal`、`bold` | 任何数字字面量（含 `500`、`650`）                                  |
| `line-height` | `var(--leading-*)`、`inherit`                  | **一切其他写法** —— 含单位less 数字（`1.2`）、`px`/`rem`、`normal` |

> **`line-height` 为什么连无单位数字也禁**：D4 要求行高收成 4 档。若允许写 `1.2`，就等于允许任意值 —— 收成档位的前提是**档位之外写不进去**。
>
> **`font-weight: normal` / `bold` 为什么放行**：它们是关键字，语义等价于 400 / 700，已在档位内；禁掉只会让 `font: inherit` 这类重置写法无法表达。

**附带一条独立检查**：声明了 `font-size` 的元素若同时包含直接文本子节点、却没有任何 `line-height` 来源，报错 —— 这就是 §1.2 里那个 `normal` 的来源。

> **误报控制**：该检查必须限定为「**同一选择器内同时声明 `font-size` 与直接文本**」，否则会误报大量"容器设字号、子元素继承行高"的正确写法（见 §7.5）。

### 4.5 验收方法

沿用前序 spec 的 CDP 审计脚本（`.superpowers/ui-review/`），逐页量：

- `font-weight` 是否只出现 400/600/700
- `line-height` 是否只出现 4 档（且无 `normal`）
- `--muted` 的使用次数是否降到合理量级
- `/containers` 一屏行数是否达到 25

## 7. 风险与未决

1. **`--muted` 减量是最大的观感变化。** 阶段 3 后页面会明显"不那么灰"。若某些区域（如密集表格）变灰后反而变吵，需要在阶段 3 用真实页面复核。**这是本设计最需要目视验证的一条。**
2. **密度与"行高按内容类型"可能冲突**：紧凑区行高 1.4、基础 12px → 行内容高 16.8px + 内边距 8px = 24.8px，比目标的 ~31px 还紧。**实施时以真实渲染为准**，必要时内边距取 4px 与 8px 之间 —— 但那会引入非档位值，需先改 `--space-*`。
3. **600 字重的实际渲染**：`system-ui` 在 Windows 上对 600 的映射可能与 700 视觉相近（无真正的 SemiBold 字重时浏览器会合成或就近取整）。**阶段 4 需在目标平台实测**，若 600 与 700 不可区分，退回 400/700 两档并改文档。
4. **暗色主题未验证**：前序 spec 已确认字号间距在暗色下无独立漂移，但**颜色分级规则在暗色下的对比度未验证**（`--ink-soft` 与 `--muted` 在暗色下更接近）。阶段 3 需补暗色实测。
5. **"有字号无行高"检查会大量误报**：仅在容器上设字号、子元素继承行高是常见且正确的写法。**实施时需限定为"声明了 font-size 且包含直接文本子节点的选择器"**，否则该检查不可用。
6. **与 `HW-D05`（例外优先披露）的交叉**：该规则要求"正常项汇总或折叠"，会直接改变视觉密度。**两者不冲突但需并读** —— 折叠后的汇总行应按紧凑档处理。

## 8. 测试策略

- **门禁**：`scripts/check-repository.test.mjs` 用内存 records 覆盖字重、行高、`normal` 三类用例。
- **令牌齐备**：`findMissingStyleScaleTokens` 的清单加入新令牌（现有机制，自动生效）。
- **迁移验证**：每阶段用 CDP 审计脚本量数字（§4.5），数字达标才算完成。
- **目视复核**：阶段 2（密度）与阶段 3（颜色）**必须**用真实页面目视确认 —— 这两项是观感变化，数字达标不等于好看。
- **回归**：每阶段跑 `pnpm --filter @logix/web validate` + `pnpm repo:check`。
