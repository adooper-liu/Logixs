## 1. 原文怎么用

原文是执行主线，不是随手笔记。

- 阶段要按顺序。前面的门禁没过，不进依赖它的后面。
- 方框：`[ ]` 没开始；`[x]` 做完并验收；`[!]` 卡住；`[-]` 决定不做。
- **只改勾、不附文档/测试/运行记录，不算完成。**
- 真正写代码时，每一刀用 `docs/planning/tasks/` 里的任务单交接。同一时刻只允许一个进行中。没有验证证据，不能标完成。

清单上没勾，不等于仓库里没有草案。原文 P2 自己就写了：没勾是门禁没过，不表示没写过设计。

## 2. 十条阶段（人话）

总顺序原文是：

```text
P0 想清楚要解决什么
→ P1 把技术选择写死
→ P2 把业务词和数据边界说清楚
→ P3 把开发工具和仓库底座搭齐
→ P4 让本地能跑、能重置
→ P5 在写业务和 AI 之前把安全和权限卡住
→ P6 打通第一条真业务
→ P7 用数字决定 AI 能不能自动跑
→ P8 出了事能看见、能恢复
→ P9 才能谈生产上线
```

P0 到 P3 是规模写业务之前的必要功课。**第一条纵向业务还没跑通，不并行铺一堆业务模块。**

### P0 项目定义

先问：给谁用、解决什么、第一刀做什么、怎样算成功、明确不做什么。

第一刀选定的闭环是：**智能 Excel 导入**——把已出运货柜表送进系统。AI 只猜列名，人确认，预检不过不许写库。

门禁（人话）：大家能用同一套词说出第一个闭环，并能用数字判断它成没成。

### P1 架构决策

把底座选择写成可追溯的决定，避免做着做着改主意。例如：业务 API 用模块化单体（不先拆微服务）、Postgres + Prisma、Temporal 跑长流程、Python 单独做 AI、身份用 OIDC。

门禁：影响底座的选择都有决定、备选、风险和怎么撤销。

### P2 领域与数据

写页面和接口之前，先把「货柜、状态、导入批次、租户、错误码」说清楚。业务事实、AI 建议、人审核、最终写入，必须能分开追。

门禁：这四类结果分得开、追得上。  
现状：契约和领域文档已经很多，原文多数格子仍空着——表示**负责人评审 + OpenAPI + 库表 + 运行时**这套门禁还没过完，不是「完全没设计」。

### P3 工程环境

让所有人和 CI 用同一套工具：装得上、查得了、类型过得了、测试跑得了。`validate` 本地和 CI 要一致。

已有仓库、前端/后端/AI、最小 CI、主分支保护。还有版本钉死、提交前检查、密钥扫描、代理技能包等没勾完。

### P4 本地基础设施

一条命令能起数据库和工作流，能健康检查，能重置。Postgres 和 Temporal 已经在用；对象存储、备份演练、测试容器等还在后头。

### P5 安全与 AI 治理

业务写入和模型动手之前，权限、租户隔离、文件扫描、模型白名单、审批必须在服务端，不能靠界面挡。原文这一段几乎还没勾。开发期写接口现在用请求头带租户和操作者，这是过渡，不是 P5 完成。

### P6 第一条纵向业务

原文目标很具体：**端到端打通智能 Excel 导入**，用来验证整套技术底座。上传 → 校验 → 长流程 → AI 猜映射 → 人审 → 预检硬闸 → 落库 → 对账 → 失败能恢复。

门禁：脱敏样本能反复导入；AI 挂了可以人工映射或明确失败，不能悄悄写错。

这是代码推进的「第一刀业务」，不是 14 站都做完。导入只是把柜子送进系统。柜子进了之后，作业壳、工单、过站、证据、同步，是 P6 里后面再切的刀，**原文 P6-01～P6-14 只覆盖导入闭环**，没有把作业壳写成这一段的勾选。

### P7 / P8 / P9

- P7：用可复现的分数决定 AI 能不能自动执行。不够格就只许建议。
- P8：出了问题能发现、能按手册恢复。
- P9：安全、数据、质量、运维、业务一起签字才能上生产。

这三段原文基本都还没开始。横着还要一直做的事（原文 C-01～C-07）：改行为就改契约和测试、例外记下来、定期查漏洞和 AI 费用、删掉死代码和过期文档。

## 3. 同一时刻只干一件

写代码不按「今天把 14 站全铺完」，按任务单：

1. 开一份 `docs/planning/tasks/….md`
2. 写清目标、不做什么、怎么验收
3. 做完、跑最近的检查、记下证据
4. 才能标完成，再开下一份

卡住就标 blocked，写原因。不允许同时两份「正在写」。

所以人话可以这么记：**地基、导入、现场作业和内陆计划计算已有第一刀，威胁与角色能力边界也已画清，但还不是生产可用系统。下一步接 OIDC，并让每个请求在服务端按能力和对象范围默认拒绝越权；完成后再做计划确认占用。开发身份头仍不是正式权限。**
