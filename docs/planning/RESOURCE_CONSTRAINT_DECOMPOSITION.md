# 节点资源与约束拆解表（候选工作纸）

> 状态：**候选工作纸** · 2026-09-13  
> 用途：给 14 个生命周期节点填「用什么资源、开哪几层门槛、约满了怎么办」。  
> 不是正式契约，不能当 Seed/API/费率公式。节点代码以 [LIFECYCLE_NODE_CATALOG_V1](../product/domain/LIFECYCLE_NODE_CATALOG_V1.md) 为准。  
> 任务拆分候选见 [NODE_PDCA](../product/domain/NODE_PDCA.md)；费用三类分开见 [FEE_DEMURRAGE](../product/domain/FEE_DEMURRAGE.md)。

## 怎么用

每个节点（或一对紧挨着共用资源的节点）填一张表。空着的层写「本仓/本场关闭」，不要删列。限额、日历、层开关、约满听谁的、备选怎么挑，一律填进表或策略，**不要写进代码**。

三层门槛可多选、可叠加：全场日限额、工位（月台/闸口/场地）、班次。约一个窗口必须过**已打开的全部层**。开哪几层是参数，不是源码默认。

预约、计划日期不能完成节点。真正发生的事件才能推进货柜状态。

约满时不要只说「约不上」：给出下一可约日，并按合同算出「继续等」和「改去备选场地」两条路的**预计**费用，等人选。缺合同就写「算不了、要复核」，不准套系统默认免费天数。

## 样例：#11 送仓 + #12 卸柜（共用目的仓）

送仓和卸柜抢的是同一座仓，填一张，不要拆成两套互不相认的限额。

| 栏              | 填写                                                                                                                                                                                                                                                                     |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 节点            | `warehouse_delivery` 送仓（必做）+ `container_unloading` 卸柜（必做）。所有者：`inland-fulfillment`                                                                                                                                                                      |
| 争不争资源      | 是。目的仓门口和卸货班组有限                                                                                                                                                                                                                                             |
| 资源场地        | 目的仓（主数据里的仓库）。WMS 上架/拣货不在本表                                                                                                                                                                                                                          |
| 层 A 全场日限额 | 可开。例：一天最多 10 柜。小仓可以只开这一层                                                                                                                                                                                                                             |
| 层 B 工位       | 可开。例：2 号月台，每 2 小时 1 柜                                                                                                                                                                                                                                       |
| 层 C 班次       | 可开。例：白班 8 柜、夜班 2 柜                                                                                                                                                                                                                                           |
| 日历            | 仓自己的工作日历；周日容量可以是 0                                                                                                                                                                                                                                       |
| 占用动作        | `schedule_warehouse_delivery` / `schedule_unload` 预约成功占 1 柜（或 1 个时窗）。改约、取消必须退回                                                                                                                                                                     |
| 上游计划        | 目的港 ETA 或到港实际为参考日（选取策略可配；飞驼采集；未接 API 前可导入或手工，须带来源）。是否倒推清关最晚完成日读清关与排程策略。没有参考日/目的仓不能占仓。清关未完成不得派提柜执行                                                                                  |
| 下游被限制      | 卸柜能力用尽后，当天不能再往该仓送。车队余力只能考虑场外缓冲，不能把多出来的柜硬塞进仓                                                                                                                                                                                   |
| 约满备选        | 随内陆顺序策略。当前登记 `warehouse_unload_first`：车队先按卸柜能力送仓。仓满或该柜当天进不了仓时：车队无余力 → 只能等仓；车队有余力 → 评估滞港 vs 送该车队堆场。另找仓仍须人指定                                                                                        |
| 比价（预计）    | **路 A 继续等目的仓**：等到下一可约日的码头超期（Demurrage）+ 合同里若有的码头堆存（Storage）+ 一次港到目的仓拖车。**路 B 交给已分配车队缓冲**：尽快提柜后的场外用箱（Detention，若已提）+ 车队堆存/操作 + 港→缓冲拖车 + 以后缓冲→目的仓拖车。三项超期费和拖车费分行列出 |
| 人拍板后才改    | 进仓的柜不比价。争仓、占用时机、多车队都读配置；争仓必须能走人工决策。只有「当天进不了仓 + 车队有余力」的柜才出示滞港 vs 堆场分项预计。不自动改、不在仓库上预绑堆场                                                                                                      |
| 参数与策略      | 卸柜日限额、层开关、清关缓冲、拖车时间、争仓、多车队、内陆顺序均来自配置。样例数字 10/15/18 只是验算，不是系统默认                                                                                                                                                       |
| 完成节点靠什么  | 送仓：`delivered`（要签收/门岗）或仓库权威 `warehouse_arrival`。卸柜：`unloaded`。预约、预计到仓、进了车队缓冲，都不能写成已送到或已卸完                                                                                                                                 |
| 第一刀          | 读配置。以 `warehouse_unload_first` + 层 A 为例：卸柜能力定当天进仓数；车队先送仓。有余力且有柜进不了仓时才算滞港 vs 车队堆场。车队无余力或未声明堆场能力则只等仓。缺合同费率则显示算不了                                                                                |

### 样例验算（人话，不是公式）

明天仓能卸 10 柜，车队能跑 15 趟，港上待提 18 柜。第 11 柜当天进不了仓。

1. 先排 10 柜提了直送仓，占卸柜名额和 10 趟车。这 10 柜不做滞港/堆场比价。
2. 还剩 8 柜在港，车队还剩 5 趟 → 最多 5 柜进入比价；另 3 柜只能等仓。
3. 路 A（滞港）：按码头合同算等到仓下一可约日的 Demurrage 等（有合同才出金额）。
4. 路 B（送车队堆场）：车队甲声明了堆场能力且缓冲名额够，列出 Detention、堆存、多截拖车。不出现具体堆场名。
5. 调度在这 5 柜上选 A 或 B。选 B 才占车队缓冲。货柜状态仍是在港或已提，不是已卸。

若车队只能跑 6 趟：当天只送 6 柜进仓，路 B 不开。

金额必须带币种。预计 ≠ 账单 ≠ 已审核 ≠ 已支付。

## 和现有对象怎么对（避免填表时写错地方）

```text
产能配置、预约占用     → 计划/产能（尚未建模块）
工单领取/完成         → work-execution（不管容量数字）
实际到港/送达/卸完    → lifecycle-control 事件
预计/应计/账单        → 费用结算（三类超期费分项）
```

预约成功 ≠ 节点完成。进车队缓冲 ≠ 已送到目的仓。不在仓库上预绑具体堆场。
