# 业务纵向交付路线图

> 状态：**负责人确认的实施路线 v1** · 2026-09-20 · 负责人：刘志高。
> 一句话：底层主干已经够用，主线转入“主数据与 SKU/装载事实 → 合规评审 → 生命周期门禁 → 对应岗位工作台”；动态属性后台、全量 UI、助手深化和通用自动化后置。

## 1. 为什么调整

日期事实、来源权威、证据、Inbox/Outbox、任务池、路线和生命周期状态机已经形成可复用主干。继续脱离具体业务补通用机制，会延后真正的合规和岗位作业闭环；反过来一次铺开全部合规字段、八个工作台和动态配置后台，也会让候选设计过早固化。

新的交付单位固定为一条可演示纵向切片：

```text
权威数据/证据
-> 专业业务事实
-> 评审或任务
-> 生命周期查询门禁
-> 对应岗位最小工作台
```

每刀只补当前闭环暴露出的底层缺口，不为假想需求扩建通用平台。

## 2. 两条基础数据线

### 2.1 商品与装载事实

```text
Product/SKU 主档
-> 备货单产品行（本次交易快照）
-> ContainerCargoAllocation（实际装载分配）
-> 结构化合规档案/证书
-> 合规评审
```

- Product/SKU 稳定身份归 `master-data`。
- `ReplenishmentOrderLine` 和 `ContainerCargoAllocation` 归 `shipment-registry`。
- 电池、危险品、制冷剂、受监管组成和证书采用结构化模型；低风险差异属性才进入版本化 JSONB。

### 2.2 参考字典与业务伙伴

主数据分为[参考数据、地点设施、业务伙伴、供应商映射](../product/domain/MASTER_DATA_DICTIONARY.md)，禁止建立一张万能字典表。国家只建一份；出口国、进口国、原产国、销售市场国和公司注册国通过关系角色引用。飞驼、云当可提交港口、码头、船司等候选和能力覆盖，但不能直接发布权威主数据。

跨国时间与金额统一遵守[时区与币种参考数据契约 V1](../product/domain/TIME_CURRENCY_REFERENCE_CONTRACT_V1.md)：IANA 时区身份、UTC 持久化、RFC 3339/ISO 8601 交换、ISO 4217 币种码和定点金额。标准先冻结为所有切片的输入纪律，运行时目录随地点、费用和当前纵向业务按需交付，不另起长期横向平台，也不因此推迟 `cargo_ready` 合规闭环。

## 4. UI 交付纪律

- 备货、出运、船务、单证、清关、内陆运输、入库、还箱是组织工作台，不是八套后端状态机。
- 每个工作台消费同一套 14 节点、全局任务池、证据和允许动作，只按角色、范围和任务类型裁剪。
- 每个纵向切片同时交付最小可用页面；不先建设八个无真实投影的空壳。
- 一柜一档继续作为跨岗位事实总览；专业页面不复制货柜状态或日期计算。

## 5. 参考主数据插入规则

主数据不单独形成长期横向大项目。业务切片需要某类身份时，按以下次序补齐：

1. 冻结稳定实体和标识。
2. 建立候选、别名、审核和版本模型。
3. 让 API、导入、人工共用解析 Port。
4. 接入飞驼/云当候选与 `ProviderCapability`。
5. 业务模块改为稳定 ID + 当时快照。

第一批随主线交付 SKU、国家、港口/码头和船司；清关行、拖车公司、仓库运营方随对应专业切片交付。

## 7. 每刀完成门槛

- 单一 task brief、单一主题分支和可演示闭环。
- 公共契约、数据库、应用用例、权限/幂等和最小 UI 同步完成；若本刀明确不含 UI，brief 必须写明后续承接点。
- 数据库切片验证空库升级、旧版本升级、约束与恢复边界。
- 中风险运行受影响模块门禁；数据库、公共契约或跨模块高风险切片运行 `pnpm validate` 与专项迁移门禁。
