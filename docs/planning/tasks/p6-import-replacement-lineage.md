# 任务：导入替代批次与解析版本血缘

## 目标

允许操作人从旧导入批次重新上传原文件或拆分修正后的文件，创建独立新批次并保存替代血缘。旧批次、原始行、AI 建议和人工审核不可原地覆盖；解析器升级后，同一文件可生成可审计的新解析批次。

## 边界 / 不做

- 权威边界见 `../../../ENGINEERING_RULES.md` §4.3、`../../product/domain/IMPORT_DOMAIN_MODEL.md` 和 `../../product/domain/PRECHECK_RULES.md`。
- 本切片不保存原始文件体，不声称能够在后台无文件重放；重新解析必须由操作人重新提供文件。
- 不自动复制旧映射、旧审核或旧执行结果，不自动执行新批次，不修改旧批次状态。
- 不在本切片解析混排纵向货柜详情；不猜数量单位、状态或实际时间。

## 兼容性与影响

- API 批次响应加法新增 `parserVersion` 与可空 `replacesBatchId`，旧消费者可忽略。
- `import_batch` 追加解析版本和同表替代关系；历史批次回填 `legacy-v1`，不修改历史业务事实。
- Web 批次详情新增“重新上传替代”文件控件；领域校验仍由服务端执行。

## 验收

- [x] 普通上传和替代上传分别幂等；有效键包含服务端解析器版本，重复请求返回同一新批次。
- [x] 替代目标必须存在于同一租户；跨租户按不存在处理。
- [x] 新批次保存 `parserVersion`、`replacesBatchId` 和独立来源快照，旧批次保持不变。
- [x] 前端可从批次详情选择文件并跳转到新批次；错误保持在原页面展示。
- [x] 迁移通过现有库与空库链路验证，公共 DTO、前后端类型和 OpenAPI 描述一致。
- [x] 相关测试与 `pnpm validate` 通过。

## 方案

1. `ImportBatch` 追加解析器版本和可空自关联；迁移只做 expand/backfill/constraint/index。
2. 创建批次用例在解析前校验替代目标租户，并由服务端把解析器版本与替代目标纳入有效幂等键。
3. multipart 可选接收 `replacesBatchId`；批次 DTO 展示版本与血缘。
4. 前端 API 继续用文件内容哈希作为客户端幂等基键，批次详情通过独立上传组件发起替代上传。
