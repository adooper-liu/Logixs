## 边界 / 不做

- **不做 BOM、Listing、关键属性** —— 各自需要业务定义，各留一片，本片不猜。
- 不做物料的独立身份（等 BOM 那片一起看，避免先造一个没人用的表）。
- 不改 `product_sku` 既有 wire value 与既有行；只做加法（加一列可空的 `product_id`）。
- 不改已共享迁移。
- **不投 outbox**：与 3 号一致，没有消费方就先不造事件。
- **不覆盖既有 SKU 身份**：`register-product-sku` 的原路径保持可用，本片是"在产品下建档"，不是替换它。

## 验收

- [ ] 首屏是**待建档的已发布产品设计**队列，每条写明来自哪一票、规格、NPI 阶段、发布时间
- [ ] 建档后产品的**内部代理键与对外产品号都在**，且产品号可改而不影响内部键
- [ ] 一个产品下能建多个 SKU；同一产品下 SKU 编号唯一
- [ ] 同一票重复发布不产生第二份产品（幂等）
- [ ] 发布写下不可变交接快照，**并显式列出还缺什么**（BOM / Listing），不得让人以为已经齐了
- [ ] 并发建档用版本乐观锁，冲突拒绝而不是覆盖
- [ ] 跨租户不可见
- [ ] 相关质量门禁全绿

## 方案

1. **契约加法**：`ProductIdentityV1`、`ProductSkuIdentityV1`、`ProductIdentityDraftCommandV1`、
   `SellableSkuReleaseCommandV1`、`SellableSkuReleaseHandoffV1`。
2. **加法迁移**：
   - 新表 `product`（产品 / SPU 身份：内部代理键 + 对外产品号 + 来源发布快照）。
   - `product_sku` **加一列可空的 `product_id`** + 外键 —— 存量 SKU 不受影响。
   - 新表 `product_identity_release`（可售 SKU 发布的不可变交接快照）。
3. **领域规则**：建档（编码、幂等、并发）、SKU 归属与编号唯一、发布门槛（身份齐备即可发布；
   BOM/Listing 记为待补而非阻断）。
4. **仓储 / 服务 / 控制器**：读待建档队列、建档、发布。
5. **前端**：`/workspaces/master-data` 接真实 API，三区（待建档队列 → 产品与 SKU → 建档与发布）。

### 落地记录（2026-09-28）

**关键属性按 GDSN 的分层规则落两层**：产品（SPU）层放同款共享的（品类、品牌、型号、
原产国、HS 编码、认证、温度、危险品分类、订货条件）；SKU 层放逐个不同的（颜色、
尺寸重量、包装层级、条码、电池）。**分层不是取舍，是标准要求** —— GDSN 规定一批属性
只能在 Base Unit (Each) 层编辑，「每层项数／完成层数」只能在非基本单元层编辑。

**查证纠正了三处**：① 分层是 GDSN 硬规定；② 漏了 Order Information（提前期、
最小/最大订货量、订货倍数）—— 而询价的输入正是它；③ 危险品不是「有没有」一个标记，
是 UN 编号/类别/包装类别/运输名称/技术名称/闪点一组，电池再叠形态与瓦时分档。

**重量落两个**：净含量（报关单要的净重，不含包装）与毛重。

### 两处实现取舍

1. **SKU 从产品下移走是「解除归属」而不是删除** —— 下游 `ShipmentCargoLine` 可能在
   引用它们，删了既断链又会被外键拦住。
2. **SKU 编号是租户级唯一的**（既有约束比"同一产品下唯一"更严）。我先前为此加的那条
   部分唯一索引是多余的，已从迁移里去掉；撞号翻成明确的 `PRODUCT_IDENTITY_SKU_CODE_TAKEN`。
