# 模块实施规格模板

> 用途：把一个限界上下文从架构定义拆解为可直接排期、编码、测试和验收的实施规格。
> 本模板不创建新的公共契约；状态、枚举、事件、DTO 必须引用仓库内的权威定义。

| 负责人     | `<owner>`                                                |
| 关联 ADR   | `<links>`                                                |
| 上游/下游  | `<modules>`                                              |
| 版本与日期 | `<version/date>`                                         |

## 2. 目标与边界

### 2.1 业务目标

- 用户与业务结果：`<可量化结果>`
- 本期范围：`<能力清单>`
- 非目标：`<明确排除>`

### 2.2 所有权

| 本模块拥有         | 本模块不拥有         | 只读投影         |
| ------------------ | -------------------- | ---------------- |
| `<聚合/规则/数据>` | `<其他上下文所有物>` | `<查询所需快照>` |

依赖方向必须符合 `UI / Transport -> Application -> Domain <- Infrastructure`。跨模块只通过公开命令、查询、事件或 Port 交互，禁止引用对方内部实现或共享数据库表。

## 3. 领域模型

### 3.1 聚合与不变量

| 聚合根        | 实体/值对象 | 标识   | 核心不变量 | 并发版本    |
| ------------- | ----------- | ------ | ---------- | ----------- |
| `<Aggregate>` | `<members>` | `<id>` | `<rules>`  | `<version>` |

逐条列出成功、拒绝和边界规则。规则必须位于 Domain，不得散落在控制器、Repository 或 UI。

### 3.2 状态机

| 当前状态  | 命令/权威事件 | 前置条件  | 下一状态  | 副作用           | 拒绝码          |
| --------- | ------------- | --------- | --------- | ---------------- | --------------- |
| `<state>` | `<trigger>`   | `<guard>` | `<state>` | `<event/outbox>` | `<stable-code>` |

说明终态、重试、撤销、超时、乱序、重复和人工接管策略。未知业务值必须明确失败。

## 4. 数据设计

### 4.1 逻辑结构

| 表/集合        | 用途        | 主键   | 外键/引用 | 唯一约束        | 审计/时间字段  |
| -------------- | ----------- | ------ | --------- | --------------- | -------------- |
| `<snake_case>` | `<purpose>` | `<id>` | `<refs>`  | `<constraints>` | `<UTC fields>` |

- 数据库、实体和 DTO 使用显式映射。
- 迁移只允许新增到 `database/migrations/`；生产环境禁止自动同步 schema。
- 写入定义事务边界、乐观并发、幂等键、软删/保留与恢复策略。
- 金额使用定点十进制并携带币种；时间以 UTC 存储、ISO 8601 交换。

### 4.2 数据生命周期

说明创建、修订、归档、保留、脱敏、审计、数据修复及历史回放规则。

## 5. 应用用例

| 用例              | Actor/权限 | 输入       | 事务边界         | 幂等/并发    | 输出          | 失败码    |
| ----------------- | ---------- | ---------- | ---------------- | ------------ | ------------- | --------- |
| `<Command/Query>` | `<role>`   | `<schema>` | `<aggregate(s)>` | `<strategy>` | `<DTO/event>` | `<codes>` |

Application 负责编排权限、事务和 Port；Controller 只解析输入、调用用例并转换响应。

## 6. 公共契约与集成

| 类型                      | 名称     | 生产者     | 消费者     | Schema 权威位置 | 兼容策略       |
| ------------------------- | -------- | ---------- | ---------- | --------------- | -------------- |
| `command/query/event/DTO` | `<name>` | `<module>` | `<module>` | `<path>`        | `<versioning>` |

- 事件由事务 Outbox 发布，消费者使用消息 ID/业务幂等键去重。
- 外部系统经 Port/Adapter 接入，供应商模型不得进入领域模型。
- 定义超时、退避、死信、重放、乱序、可观测性及数据对账策略。
- 候选代码只能标记为候选，完成样本验证和契约评审后才能成为权威定义。

## 7. API 规格

| Method/Path     | 用例         | 请求 Schema | 响应 Schema | 权限       | 幂等键         | 并发             | 错误码    |
| --------------- | ------------ | ----------- | ----------- | ---------- | -------------- | ---------------- | --------- |
| `<method/path>` | `<use case>` | `<ref>`     | `<ref>`     | `<policy>` | `<header/key>` | `<ETag/version>` | `<codes>` |

输入在边界校验；列表必须分页、限制最大页大小并稳定排序；错误返回稳定错误码与追踪 ID，不泄露内部结构。

## 8. 前端实施规格

| 路由/视图 | 用户目标 | 数据查询  | 可用动作     | 权限       | 加载/空/错/冲突状态 |
| --------- | -------- | --------- | ------------ | ---------- | ------------------- |
| `<route>` | `<job>`  | `<query>` | `<commands>` | `<policy>` | `<states>`          |

对每个视图补充：信息层级、字段与来源、表单校验、动作确认、撤销/重试、实时刷新、键盘与无障碍、响应式断点、审计入口。UI 只展示服务端判定的能力和状态，不复制业务状态机或权限规则。

## 9. 可观测性与运营

定义结构化日志、追踪跨度、指标、告警、审计事件、业务对账视图和运行手册。日志不得记录密钥、Token、Cookie 或非必要个人数据。

## 11. 验收样本

每条样本包含：初始数据、Actor、命令或外部事实、证据、期望状态、期望事件、期望投影、拒绝码/追踪 ID。至少覆盖正常、拒绝、重复、并发、乱序、外部事实先到和人工对账。

## 12. 交付拆分与完成定义

按“契约 -> 迁移 -> Domain -> Application -> Adapter/API -> UI -> E2E/运维”拆成可独立评审的小任务。进入 `ready` 前必须完成规则与样本评审；进入 `done` 前必须满足：

- 权威契约唯一且兼容性检查通过；
- 迁移、回滚/恢复与数据验证方案完整；
- 成功、失败、边界、并发和重放测试通过；
- API 鉴权、授权、幂等、追踪和审计已验证；
- UI 的加载、空、错误、冲突与权限状态可验收；
- 文档索引、运行手册和已知风险已更新。
