# 任务：已出运标准导入模板 V1

## 目标

提供一份明确、可直接填写的“已出运标准导入模板 V1”，作为出运工作台的次级规范批量工具，完成上传、预检、接管和待补交接。既有货柜、清关、物流、仓库四表仅作为兼容来源；模板和四表都不决定工作台默认流程。

## 边界 / 不做

- 遵循 `docs/product/POST_DEPARTURE_WORKBENCH_DELIVERY_BASELINE.md` 的 `departed` 起点、待补/阻断分轨、单文件原子和逐柜冲突规则。
- 遵循 `docs/product/domain/IMPORT_DOMAIN_MODEL.md` 与 `docs/product/domain/SHIPMENT_FLOW_OVERVIEW.md` 的来源保留、幂等、预检、事务及审计边界。
- V1 只负责“已出运接管”时已经产生的 Shipment、货柜、提单、备货引用和可选 SKU 装载事实。清关、物流节点、仓库收货在其事实产生时使用后续独立标准更新模板，不塞入本次接管模板，也不提前写未发生事件。
- 不新增业务表或字段；复用已存在的 ImportBatch、Shipment Handoff、Shipment 待补和生命周期初始化能力。追加一条检查约束迁移，使 `shipment_handoff_record.source_profile` 接受标准模板来源。
- 不删除四表适配器，不修改历史来源含义；只在界面和代码边界上将其降级为“兼容导入”。

## 验收

- [ ] 出运运营可在现有出运工作台下载并打开经过视觉校验的 `.xlsx` 标准模板
- [x] 模板明确区分必填身份、建议填写和可后补字段，并提供标准值、示例和填写说明
- [x] 标准模板按固定表名和固定字段码确定性解析，不调用 AI 猜列、不要求人工映射
- [x] 单个标准文件原子接收；同文件重复上传幂等；同幂等键异内容明确冲突
- [x] 缺普通业务字段或 SKU 明细仍可预检、接管并进入持久待补
- [x] 缺 Shipment/货柜身份、非法已填写值、无效引用或不兼容活动 Shipment 关系明确阻断
- [x] 同一 Shipment 的多柜、同一柜的多备货单与多 SKU 可正确归组
- [x] 正常候选可批量接管；异常候选保留逐条恢复路径
- [x] 标准模板收拢到工作台“批量工具”，四表标记为“兼容导入”；两者都不作为默认主路径
- [x] 公共契约、API、Web、真实 PostgreSQL 集成和关键 E2E 通过，最终执行 `pnpm validate`

## 工作台避坑检查

- [x] 模板能力可被工作台收拢为次级批量工具，不要求首屏先下载或上传文件
- [ ] 系统产生批次、哈希、分组、内部 ID、重复判断和待补；人员只填写其掌握的业务事实
- [ ] 模板和页面均不要求数据库 UUID、人工归组键或重复录入已有权威事实
- [ ] 每个阻断/待补返回字段、行号、当前值、影响动作和直接处理入口
- [ ] “模板必填”只等于当前文件身份/语法必需，不把理想完整度误作流程阻断
- [ ] 生命周期、资料完整度、异常和来源解析结果分轨显示
- [ ] 接管后从服务端重读 Shipment 与待补结果，不使用前端临时成功状态代替落库结果

## 方案

1. 在公共契约中建立 `post-departure-standard-import-v1` 字段/工作表目录，作为模板、解析器和测试的单一权威。
2. 生成并视觉校验 V1 工作簿。工作簿包含“填写说明”“已出运接管”“SKU装载明细”“标准值”“代码字典”“真实示例”六页；“代码字典”在下载时读取数据库 active ISO 3166-1 与 UN/LOCODE 发布，并为销往国家、起运港和目的港提供“标准代码｜中文显示名｜官方英文名”下拉，解析时只保存标准代码。国家中文显示名来自 ICU/CLDR；港口中文名只使用数据库已确认或候选别名，候选和缺失显式标注，不伪造译名。两张导入数据页中，“SKU装载明细”允许整页为空。下拉用于减少录入错误，上传预检仍使用同一 active 权威目录做最终校验。
3. 扩展 ImportBatch 解析配置：标准模板按固定表名/表头解析并保存，不经过 AI 映射；原四表继续走 `tabular-v2`。
4. 给 Shipment Handoff 增加标准来源 profile 和规范化输入，复用现有预检、冲突检查、批量接管及持久待补链路。
5. 在现有出运工作台的次级“批量工具”中提供标准模板下载、上传和预检；四表上传继续折叠为“兼容旧系统文件”。
6. 用真实样本值制作成功、缺 SKU、非法码、重复、同柜冲突和多柜多单 fixture，覆盖 API、集成和 E2E。
7. 更新出运后工作台交付基线与导入领域权威，仅记录稳定决策并链接契约，不复制字段目录。
