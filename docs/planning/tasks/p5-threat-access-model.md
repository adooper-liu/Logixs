# 任务：P5 威胁模型与最小访问模型

## 目标

完成 P5-01 威胁建模，并收敛 P2-05 的租户、用户、角色、能力和数据范围最小模型，为 P5-02 Keycloak OIDC 与服务端授权实现提供可执行基线。

## 边界 / 不做

- 权威来源为 `ADR-008`、`GC-008`、`PRODUCT_BRIEF` 和技术架构 §12。
- 本任务只定义威胁、控制、角色能力和范围语义，不接入 Keycloak，不签发或校验 JWT，不实现 Guard、策略引擎、病毒扫描或数据库 RLS。
- 不把现有 `X-Tenant-Id` / `X-Operator-Id` 开发头描述为正式认证；它们是生产阻断项。
- 不绑定具体员工姓名，不定义组织和地点主数据；人员分配与 IdP 组映射属于 P5-02。
- 不复制动作状态机、业务前置或错误码；分别引用 `GC-008`、专业领域契约和 `GC-011`。

## 验收

- [x] 威胁模型覆盖租户隔离、文件上传、提示注入、Tool 越权，以及身份伪造、服务身份、敏感数据和重放。
- [x] 每个高风险威胁具有生产阻断条件、目标控制、验证方式和后续任务归属。
- [x] 最小访问模型定义稳定角色码、能力码、数据范围和固定服务端授权顺序。
- [x] 明确用户身份、服务身份、前端投影和 AI/Tool 不得互相冒充或扩大权限。
- [x] INDEX、启动清单、人话进度和 RAID 与新基线一致。
- [x] `pnpm docs:check`、`pnpm repo:check`、格式检查与 `git diff --check` 通过。

## 方案

1. 在架构层建立 `SECURITY_THREAT_MODEL_V1`，登记资产、信任边界、威胁、控制和上线阻断项。
2. 在领域层建立 `IDENTITY_ACCESS_MODEL_V1`，定义角色只是能力包，授权按租户、能力、范围、对象、业务守卫逐次执行。
3. 回填 P2-05、P5-01 和下一步 P5-02，不提前勾选任何运行时认证或授权实现。
