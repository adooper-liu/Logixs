# 任务：通用办理型工作台 UI 标准设计

> 本 brief 只承载已获负责人逐项确认的通用标准设计。正式设计见
> `docs/superpowers/specs/2026-10-11-universal-workbench-ui-standard-design.md`。
> 五个交付单元分别建立后续 task brief、精确写域和风险门禁，不在本任务一次实施。

## 路线图位置与业务主线

- **位置**：横跨 23 台岗位工作台的通用办理壳与视觉动线标准；不替代任何一台的业务复审。
- **目标岗位**：需要在多个工作台和任务之间连续办理、暂停、续办并跟进结果的业务操作人员。
- **核心业务结果**：用户在稳定界面中看清“在哪、进展到哪、卡在哪、现在做什么、完成条件和责任去向”，并能保留未完成工作现场。
- **优先减少的损失**：减少重复找任务、页面结构漂移、未保存输入丢失、完成/等待/失败语义混淆，以及跨工作台跟进必须来回跳转造成的时间损失。
- **主线关系**：本设计提供低成本一致容器；每台工作台仍须按自己的业务目的、优先损失、事实、权限和动作逐台验真。

## 已证实事实

1. `UI_SYSTEM.md` 已固定 `PageHeader → 岗位/交接上下文 → 队列 + 详情 + 操作上下文`，但共享实现只覆盖部分货柜类页面，其他页面重复实现布局和断点。
2. `WorkbenchPageHeader` 已从正式权威投影工作台名称和目的，应继续作为稳定身份入口。
3. `RoleWorkbenchFrame` 有可复用 slot 和响应式基础，但强绑定货柜实体，不能直接扩成 23 台万能壳。
4. 选品页已有状态切换保持三栏的正面样例；市场关闭态删除右栏是不得固化的反例。
5. 当前没有通用工作会话、多标签、统一草稿、任务内人际对话、全局任务档案或 AI Tool 执行层。
6. 当前 AI 是 provider-neutral Gateway + 确定性规则/Mock + 只读助手；真实模型、工具治理、AI 版本审计尚未接通。
7. 当前 ObjectActivity、领域事件、交接、任务和操作回执分散存在；它们不能被 UI 拼接后冒充全局审计或第二套业务事实。
8. 原型文件只提供布局与视觉动线参考，不得改变项目颜色系统和主题。

## 已批准设计

负责人于 2026-10-10 至 2026-10-11 逐项确认：

- 采用“分层原语 + 真实消费者验真”，不采用只补规范或万能配置组件；
- 左右栏桌面可独立折叠，折叠后保留满高窄轨；
- 三栏在电脑桌面占满头部以下剩余视口；
- 中栏事项触发的编辑视口进入右侧动态上下文；
- 1024 宽度优先左窄轨并保持中栏与右栏并列，移动端使用队列 → 详情 → 编辑分屏；
- PageHeader 主标题描述承载每台工作台唯一主要业务目的；
- 界面保持干净，必要解释用 Toptip，禁用、失败、冲突和恢复必须就地显示；
- 右栏完整承载任务档案、任务内对话、AI 辅助和确认执行；
- AI 第一阶段采用“建议 + 用户确认 + 服务端重授权执行”；
- PageHeader 的“切换”管理并行工作现场和暂停续办，当前标识随成功切换实时迁移；
- PageHeader 的“更多功能”打开与当前工作关联的独立子功能，不是档案、AI、导出、偏好和帮助工具菜单；
- 五个交付单元、实施顺序和验收范围按设计稿执行；
- 视觉一致性不能只靠文字语义，单元一必须同批交付标准线稿板、真实组件参考页、三视口基准截图和结构/像素/人工视觉防漂门禁。

## 五面映射

| 面       | 本设计承接                                                             | 不越界                                                             |
| -------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 岗位任务 | 稳定动线、并行工作会话、暂停续办、原岗位持续跟进                       | 不决定每台队列优先级、完成语义或责任政策                           |
| 数据事实 | 只展示领域事实、版本、来源、缺口和回执；工作会话只保存恢复指针         | 不建万能业务事实表、万能草稿 JSON 或全局审计替身                   |
| 前端 UI  | PageHeader、责任带、决策条、满高三栏、折叠、动态右栏、三视口与内容克制 | 不换主题，不把业务状态做成整页模式                                 |
| 技术底层 | RouteContext、工作会话、引用式活动投影、对话和 AI 治理边界             | 本设计不直接批准 Schema/API/模型供应商或自动 Tool 执行             |
| 权限边界 | 所有恢复、档案、对话、AI 候选和子功能打开都重新服务端授权              | 不用菜单、按钮可见性、会话存在或 AI 建议代替 capability 与对象范围 |

## 五个后续交付单元

1. 办理型工作台布局标准；
2. 可恢复工作会话；
3. 任务全程档案；
4. 任务内协作对话；
5. AI 辅助与确认执行。

每个单元必须建立独立 brief。单元一先以选品立项和一个差异化真实工作台验真；单元二先接一个有正式服务端草稿的工作台，再接一个无通用草稿、动作即落账的工作台；单元三至五按真实契约和消费者逐项接通。

## 边界 / 不做

- 不在本 brief 修改生产代码、数据库、迁移、API、公共契约、主题或业务权威。
- 不批准任何具体“更多功能”子功能；每项另作业务需求。
- 不一次迁移 23 台工作台。
- 不建设全局审计、社交 IM、万能 Activity、万能草稿或自动 Agent 执行。
- 不把工作会话暂停等同领域暂停、阻塞、等待或 partial。
- 不让当前已有页面、API、Mock AI 或设计稿冒充 operational / validated。
