# 任务：市场与经营信号机会雷达 V1

## 已锁定的业务目的

本台不是机会治理或控制面平台，也不以规则数量、评分模型、字段完整度或共享契约为产品结果。

- **主目标**：减少真实机会遗漏或响应过晚。
- **制衡目标**：减少弱信号误判造成的选品及后续产品、供应链资源浪费。
- **首个岗位闭环**：发现优先信号 → 完成一次有效验证 → 决定是否形成可信机会。
- **首批运营结果指标**：信号进入至完成分类的时间、到期验证按时完成率、可信机会被选品首次接收的比例、因证据不足或方向错误被退回的比例。
- **最低可信保障**：来源、证据、责任、期限、资格校验、不可变交接、权限、幂等和恢复。

四项首批指标用于观察流程响应和下游质量，不能单独证明核心经营损失已经下降。正式宣称业务目的达成前，还须用真实样本定义至少一个机会漏失或市场窗口响应结果观测，以及一个下游无效投入结果观测；不得通过少登记、少交接或只选择容易样本让指标表面改善。

共享契约、细粒度 capability、三阶段回执和统一 UI 壳只能在真实业务闭环证明需要后作为支撑切片进入，不能成为本台主线或首个产品决定。

## 当前已证实事实

- 项目业务链要求市场与经营阶段判断是否存在稳定、可盈利的需求，并保留信号来源、观察周期和数据时点，避免把短期峰值当成稳定需求。
- 当前实现已经具备信号登记、事实和假设补充、证据引用、观察、交给选品、不采纳、作废、归档、选品退回、幂等、乐观并发和版本化交接快照等局部能力。
- 这些实现只能作为当前物理事实，不能反向定义“可信机会”、优先级、验证方法、退出政策或完成标准。
- 现行已实现政策允许已交接信号作废或归档后使当前 handoff 失效。是否改为显式撤回、纠错或版本取代仍是待负责人定案的业务政策，不得由本 brief 静默覆盖。

## 当前设计边界

本 `design` 切片只允许：

1. 以真实或脱敏样本解释机会为何被遗漏、为何响应过晚，以及弱信号如何造成下游无效投入；
2. 定义首个岗位闭环的开始、结束、责任边界和反证；
3. 定义四项首批指标的分母、起止点、暂停和排除口径；
4. 提出能直接支撑业务结果、避免已定损失或属于不可关闭不变量的最小保障候选；
5. 把负责人结论写回业务权威。

当前不授权 Schema、迁移、公共契约、API、能力码、共享 UI 或生产页面修改。进入生产实现前，必须将 brief 转为 `coding`，按已定切片收窄写入范围，并补齐数据库、迁移、公共契约或安全控制面所需的独占锁。

### 现有结构能支持与不能支持的观测

| 当前可验证的物理承载                          | 能观察什么                                                    | 不能据此推导什么                                               |

| `MarketSignal` 与判断历史                     | 信号登记/更新时间、当前去向、判断类型与时间、`nextReviewDate` | 业务首次发生或观察时间、有效验证完成、真实市场窗口和“可信机会” |
| 版本化 `MarketOpportunityHandoff`             | 市场交给选品的版本、时间、待补项和 superseded 关系            | handoff 的商业可信度、选品首次业务认可或机会质量               |
| `ProductInitiative` outcome/completion/reason | 选品 approve/defer/reject/return 等流程决定及时间             | 决定原因的稳定分类、真实投入量或经营收益                       |

### 样本与指标证据分级

#### 解锁下一薄片的最低样本包

负责人需要提供或指定受控来源。原始文件可以保留在仓外，但仓内至少保存脱敏摘要、内容哈希、允许证明/不允许证明和受控引用。

1. **一个正向纵向案例**：真实或脱敏稳定 `caseId`；市场/渠道/品类；来源类型、保管人、受控引用和 SHA-256；业务发生、首次观察、登记三种时间；观察窗口和数据时点；含绝对量、分母、基期及单位的原始观测；责任、验证期限、验证动作和结论；交选品、首次领取/接受和后续结果；可解释的市场窗口。若尚无独立事后结果，只能验证发现与验证机制并标为推进候选，不能称机会已被证明。
2. **一个反向纵向案例**：同样的来源与时间链；表面热度的绝对量、周期和基线；持续性、转化、利润、退货、合规、供给、季节窗口或数据污染等反证；真实不采纳、不立项、退回或终止。若尚无真实投入量，只能验证阻止误判的机制，不能宣称已经减少下游浪费；估值方法必须由负责人批准，禁止 AI 编数。
3. **可取得的独立结果来源指针**：说明后续将从哪份完整选品会候选、期间新品/Listing 发布与终止、类目窗口、销售/供应链/客户发现清单或其他受控系统观察漏失与下游投入；当前不要求先完成全量抽取。
4. **两个案例的来源 manifest**：文件别名、格式、大小、SHA-256、解析状态、保管位置、敏感等级、脱敏方式及允许证明/不允许证明，格式参考现有真实备货与海关样本。

两份案例及独立结果来源指针完成核验后，切片 A 可进入只承接已证明机制的下一设计薄片；仍不得发布指标或声称总体经营损失下降。

#### 指标发布与总体损失声明的后续证据 gate

1. **一份完整业务周期的全量信号 cohort**：包含成功、等待、退回、不立项、再交接和排除对象，不只给成功案例；至少包含来源发生/首次观察/登记、首次分类、验证 due/completed/暂停、handoff 版本、选品首次 claim/accept、首次与最终结果、受控原因、superseded 和排除理由。
2. **一份独立事后机会/结果集**：来自市场信号登记流程之外；关联 signal/initiative 允许为空，空关联行是测量漏失所必需的，不能预先删除。
3. **完整来源 manifest 与脱敏审批证据**：商业敏感字段的仓内摘要必须有负责人或数据责任方确认，不能仅凭 AI 判断可发布范围。

完整 cohort 与独立结果集未到位时，可以验证最短业务机制，但不能正式启用四项指标，不能校准阈值，也不能宣称机会漏失、窗口响应或下游无效投入已经总体改善。

当前任务保持 `blocked`：不定义“可信机会”阈值、不发布指标、不创建生产实现切片，也不下发 Cursor。
