# 任务：选品立项中间区 Mode 与评审要点选项化

> 本文件是执行、评审与交接的唯一载体。状态只看 frontmatter。  
> 权威改版：[WORKBENCH_VISUAL_FLOW_REDESIGN](../../product/WORKBENCH_VISUAL_FLOW_REDESIGN.md) §5、§7。  
> 评审要点覆盖对齐已合入（`initiative-review-point-coverage-v1` / #73）；本片做**动线与选项化 UI**。

## 目标

选品负责人在立项中间区：进度头一眼看见完备度；**已立项 = 整页 Mode**（与信号关闭态同构）；
评审要点用 **方案 A**（UI 单选大/中/小等 → 规范化短句落库，契约枚举不改）；
可从机会交接快照一键带入。

## 边界 / 不做

- 不改立项硬门槛条数与 gate 政策（#73：非门槛项不得混进「还差 N」）。
- 不把方案 A 做成新的 wire 枚举；落库仍是规范化短句/既有字段形态。
- 不做 NPI 退回（另立 `product-npi-visual-flow-return-v1`）。
- 不做选品手工新增入口（`product-initiative-manual-intake-v1`）。
- **交接后补可见性**另立 [product-opportunity-handoff-live-projection-v1](./product-opportunity-handoff-live-projection-v1.md)（方案 A）；本片「带入」在投影落地后应读合并视图。
- 色与主题只认项目令牌；禁止另造色板。
- 串行：建议在活跃态依据区与后补投影之后解锁。

## 验收

- [ ] 顶部进度头：完备度 + 必填剩 N；「待补」不在按钮墙重复
- [ ] `initiated`（已立项）触发整页 Mode：写入口关闭；缺口仅摘要；结论条优先
- [ ] 区块分组：市场定义 ●必填 / 来源证据 / 评审要点 ○选填（选填降权或默折）
- [ ] 评审要点方案 A：判断类优先单选（大/中/小等），落库为规范化短句；补充说明才用文本框
- [ ] 「⚡带入」：交接快照市场/范围/证据一键入草稿；有「已自动带入」标识
- [ ] helper 常驻字段下；placeholder 只放示例
- [ ] 页脚 ≤3 动作；主 CTA 动词化
- [ ] 相关单测通过；`repo:check` 通过

## 业务与数据协同设计

| 业务步骤与岗位结果 | 信息产生时机/前置事实    | 操作时需要看到什么                  | 系统允许做什么           | 数据如何可靠保存与反馈     |
| ------------------ | ------------------------ | ----------------------------------- | ------------------------ | -------------------------- |
| 补齐再立项         | 机会已接受；门槛字段现算 | 进度头、必填落点、带入入口          | 存草稿 / 带入 / 提交立项 | 既有立项写接口；待补持久化 |
| 回看已立项         | 去向已立项               | Mode 结论、只读要点与证据、缺口摘要 | 只读；不可改写结论       | 无新写；刷新仍只读         |
| 快速填判断强度     | 要点需结论               | 单选档位 + 可选补充说明             | 选档写入规范化短句       | 落库形态与既有字段兼容     |

## 工作台避坑检查

- [x] 系统可带入 vs 人必须确认的责任边界写清

## 方案（design）

1. `ProductSelectionWorkbench` / Outcome+Review 面板：进度头；已立项整页 Mode（参考 `MarketSignalsWorkbench` closed）。
2. `ProductInitiativeReviewPanel`：选项化控件 → 规范化短句；契约枚举不变。
3. 带入：从 handoff/机会快照映射到草稿字段。
4. 单测：已立项无写入口；选项化写入短句；进度头文案。
