# 任务：日期事实复核与采信闭环

> 承接统一日期事实与来源权威主线。本刀让复核岗位处理人工录入的实际日期：核验证据后追加已核验、已确认的新版本，并自动执行来源权威裁决、生命周期应用和待应用事实重放。

## 目标

让 `review_supervisor` 从跨柜待复核队列定位实际日期声明，看到原始时间、来源、地点、录入人、证据状态和不能批准的原因；满足四眼原则与证据条件时，以追加更正的方式形成 `verified + confirmed + effective` 当前版本，并返回真实的 `applied / pending_application / review_required` 结果。

## 边界 / 不做

- 复核只处理当前 `actual + review_required` 日期事实，不修改计划或预计日期。
- 原事实不可原地改写；批准必须通过 `supersedesFactId` 追加版本并保留来源、时间、地点和证据。
- 原录入人不得自批；列表和批准均要求服务端 `evidence.review` 能力。
- 证据核验与日期事实采信是两个决定；证据全部 `verified + effective` 后，日期事实仍须经过来源权威和生命周期守卫。
- 前序或专业条件不足时保留 `pending_application`，由既有自动重放机制继续处理。
- 本刀不实现日期声明驳回、批量审批、通用审批引擎或新的物流节点。

## 验收

- [x] 复核岗位能分页查看跨柜当前待复核实际日期，排序稳定且租户隔离。
- [x] 队列展示货柜、节点/事件、发生时间与时区、来源、地点、录入人、证据状态、缺口和允许动作。
- [x] 证据未全部核验、原录入人自批、旧事实或投影版本冲突时明确拒绝。
- [x] 合法批准追加确认版本；同幂等键同载荷可重放，异载荷冲突。
- [x] 批准后自动进行来源权威裁决、生命周期应用及 pending 重放，并向界面反馈真实状态。
- [x] 前端覆盖加载、空态、选择、阻塞、批准、结果反馈、失败恢复和窄屏主路径。
- [x] 公共契约、API/Web 类型、权限与测试保持一致；高风险门禁通过。

## 业务与数据协同设计

| 业务岗位要完成什么       | 操作时需要看到什么                                                    | 系统允许做什么                             | 数据如何可靠保存与反馈                                                                      |
| ------------------------ | --------------------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 找到待核验的人工实际日期 | 柜号/备货单、节点事件、原始值与 UTC、来源时区、地点、录入人、等待时长 | 按稳定队列选择单条声明；无权限时服务端拒绝 | 只查询当前 `actual + review_required`，租户隔离、游标分页、稳定排序                         |
| 判断证据是否足以证明发生 | 每份证据的核验与有效状态、缺失或失效原因                              | 证据不合格时只读，不允许批准               | 从证据权威模型读取实时状态，不复制或信任前端声明                                            |
| 四眼批准日期事实         | 原声明、当前投影版本、审批原因与预期结果                              | 不允许原录入人自批；只批准当前版本         | 追加 `verified + confirmed + effective` 更正版本，关联 `supersedesFactId`，幂等与乐观锁保护 |
| 处理批准后的业务结果     | 新事实版本、来源权威裁决、应用/等待/复核原因                          | 根据结果补策略、补前序或继续处理下一条     | 共用 `RecordLifecycleDateFact`，自动申请过站并重放本柜 pending；绝不从页面直接改状态        |

## 方案

1. 在公共日期事实契约增加复核队列、证据摘要和批准命令/结果，保持新增兼容。
2. 扩展日期事实仓储的租户级待复核分页查询，并通过证据读取端口补全实时资格。
3. 新增批准用例，校验 current、actual、review_required、四眼原则、证据和投影版本，再复用统一日期事实写入链。
4. 新增受 `evidence.review` 保护的日期事实复核列表与批准端点。
5. 新增日期事实复核工作台，按“队列、上下文、动作与结果”组织，不在 UI 重做领域裁决。
6. 以领域/应用/控制器、Vue 组件和 Playwright 覆盖主路径与失败路径，最终运行高风险门禁。
