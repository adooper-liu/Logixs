# 任务：迟到来源自动吸收已有 Shipment

> 路线图：`POST_DEPARTURE_WORKBENCH_DELIVERY_BASELINE.md` 的 `UI-01` 收口切片。
> 前置交付：PR #49 已完成任一来源上传、批量接管和持久待补。
> 权威规则：`WB-D11`～`WB-D17`、`IMPORT_DOMAIN_MODEL` 第 2～4 节。

## 目标

当清关、物流或仓库来源晚于货柜来源到达时，系统按柜号识别其唯一活动 Shipment，明确告诉操作人员“将补入哪票”，并把新来源作为独立 Handoff 吸收进原 Shipment。不得重复创建 Shipment、不得重复或改写已有柜关系，也不得要求人员再次输入内部 Shipment ID。

## 边界 / 不做

- 本切片只处理“Shipment 已存在、迟到来源随后到达”的自动匹配与吸收。
- 仓库来源先到且 Shipment 尚不存在时仍允许上传、预检和登记待复核；跨独立来源包的自动重组另开下一切片，不在本轮用浏览器状态或模糊最新值拼接。
- 不新增数据库表或迁移；复用 Shipment、活动柜关系和不可变 Handoff。
- 不导入清关/物流/仓库专业域全部字段；本切片先保证来源归属、幂等、关系稳定和可追溯，专业事实映射按后续工作台切片进入各自权威域。
- 不自动吸收多票匹配、无活动关系或与现有 Shipment 核心事实冲突的来源。

## 验收

- [x] 单份迟到来源预检时，柜号唯一命中一票活动 Shipment，候选返回系统匹配的 Shipment 业务身份和并发版本。
- [x] 界面直接显示将补入的 Shipment 编号/柜数语义，不要求人员填写或确认内部 ID。
- [x] 接管迟到来源只追加 Handoff；原 Shipment ID 和原活动柜关系 ID 保持不变。
- [x] 重放同一来源返回 duplicate；新来源用独立幂等身份吸收。
- [x] 同柜命中不兼容 Shipment、并发版本变化或核心事实冲突时逐柜返回稳定业务冲突，不影响其他候选。
- [x] 无 Shipment 匹配时维持现有“新建独立出运/选择现有出运”处理方式，普通字段缺失继续待补。
- [x] 公共契约为加法兼容；JSON Schema 是唯一权威，生成类型和 API/Web 消费者同步。
- [x] API 单元与 PostgreSQL 集成、Web 组件/组合式函数、契约漂移及完整 `pnpm validate` 通过。

## 工作台避坑检查

- [x] 当前岗位结果是把迟到资料补入正确 Shipment，不是维护数据库关系。
- [x] Shipment 匹配和内部 ID 由系统产生，人员只处理真实冲突。
- [x] 已有柜关系自动复用，不重复录入柜号、路线或 Shipment 身份。
- [x] 普通资料缺失仍为待补；只有多票/关系/并发/核心事实冲突阻断当前柜。
- [x] 页面继续使用现有候选队列作为唯一主选择源。
- [x] 生命周期、完整度和来源吸收结果分开表达。
- [x] 正常项继续支持批量接管，冲突项逐柜恢复。

## 方案

1. 在 `shipment-registry` 增加稳定查询 Port：按租户和柜号返回无匹配、唯一活动 Shipment 或冲突。
2. 预检候选增加可选 `existingShipmentMatch`，由 JSON Schema 生成 TS 类型；这是系统事实，不冒充人工 correction。
3. 接管归组和 Handoff 命令优先使用人工 correction，其次使用系统唯一匹配；并发版本始终来自服务端查询。
4. Handoff 持久层在追加来源时复用同 Shipment 的活动柜关系；不同 Shipment 仍冲突，实际新增柜才创建新关系。
5. 现有候选详情和接管面板展示“补入已有 Shipment”，不新增自由输入或空确认按钮。
6. 先写回归测试，再实现 Port、映射、持久化和 UI；最后运行专项与全量门禁。

## Review notes

- 业务：迟到来源只在柜号唯一命中且 Shipment 仍满足既有 `departed` 接管政策时自动补入；无匹配保持原处理方式，多匹配仅拒绝当前柜。人工归组是责任动作，始终优先于系统建议。
- 数据：新来源追加不可变 Handoff；同票同柜复用活动关系 ID，不覆盖或伪造新版本。当前来源包已产生的 Handoff 从自动匹配中排除，保证同包重放仍命中原幂等载荷。
- 契约：`existingShipmentMatch` 为可选加法字段，JSON Schema 已生成 TypeScript 类型；数据库 schema 无变化。
- 交互：候选详情和单条动作显示业务 Shipment 编号，不新增自由输入、空确认或第二选择源。普通字段缺失仍保留为待补。
- 风险检查：已覆盖多活动关系、关系版本冲突路径、来源身份与柜记录不一致防线；完整质量门禁已通过。
