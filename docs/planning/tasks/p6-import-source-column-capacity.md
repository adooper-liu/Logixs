# 任务：校准导入源文件列数上限

## 目标

根据负责人提供的真实备货单与货柜明细样本，把源文件列数上限从无法容纳样本的 50 列校准为 128 列。行数或列数越界时分别返回实际值和上限，避免合并错误让操作人猜测。

## 边界 / 不做

- 保留 5000 数据行、10MB 和受支持文件类型限制。
- 不改变目标字段目录、映射规则、预检、落库模型或公共错误码。
- 不新增数据库迁移，不修改当前工作树中的其他导入闭环改动。

## 权威与证据

- `docs/product/NON_FUNCTIONAL_REQUIREMENTS.md` §3：初版容量基线，可经真实样本与容量实测校准。
- 负责人于 2026-09-16 提供的代表性源表：备货单 51 列，货柜明细约 90 列，并要求按目标模型优化而非屈从旧数据限制。

## 验收

- [x] 51 列真实备货单结构可通过上传解析。
- [x] 129 列明确返回列数实际值与 128 列上限。
- [x] 5001 数据行明确返回行数实际值与 5000 行上限。
- [x] NFR、RAID、实施规格和上传页提示一致。
- [x] `pnpm validate` 通过。

## 方案

保持文件大小和数据行上限不变，只把物理源列上限校准到 128。应用层先分别检查行、列并返回确定性错误；不把源列数量等同于目标字段数量，未映射列仍由人工映射/预检流程处理。
