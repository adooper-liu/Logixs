## 对外物料号的生成（负责人 2026-09-28 已定：A + C）

产品号是**派生**的：`P-` + `sha256(sourceHandoffId)` 前 8 位
（[product-identity.ts:68](../../../apps/api/src/modules/master-data/domain/product-identity.ts#L68)），
因为产品有稳定来源（3 号节点发布的设计）。**标准物料没有来源可派生**——它是归并时新建的。
所以「复用产品身份的口径」在这里有一格落不下去。三个候选与选定：

| 选项                                  | 代价                                   | 收益                                      |
| ------------------------------------- | -------------------------------------- | ----------------------------------------- |
| **A. 归并时人工给，系统只兜底**       | 人可能不给；兜底号不好念               | 物料号是采购/仓库天天要念的，人工给才有用 |
| B. 系统流水号 `M-000001`              | 需要序列或并发重试；泄漏租户的物料数量 | 可读、有规律                              |
| C. 系统短 hash `M-3F9A2C1B`（纯兜底） | 不可读、无规律                         | 无并发问题、不泄漏数量                    |

**选定 A + C**：人工可给，未给时落库兜 `M-` + 内部代理键 sha256 前 8 位（大写），
与 `productNumberFor` 同一形状；内部键稳定，兜底号因此也稳定。
沿用产品身份已定的两条 —— 内部代理键无含义且永不变、对外号可改
（[product-identity-master-data-v1.md:29](./product-identity-master-data-v1.md)）。

**不采用 B（流水号 `M-000001`）**：它把一个可配的数字变成了并发约束（发号器 + 并发重试），
而换来的可读性，人工给已经覆盖了。

> **对外物料号 NOT NULL**：兜底发生在写入时，所以每一行始终有号 —— 唯一约束是普通唯一索引，
> 不需要部分索引（部分索引在这里会留下「可空即不校验」的缺口）。
> 人工号与兜底号共用同一个唯一约束：撞号（含兜底 hash 碰撞）走与 SKU 编号相同的路径 ——
> 明确拒绝、返回稳定错误码，不静默改名。

## 归并时的候选检索（负责人 2026-09-28 已定：做）

采购手上是**供应商的原话**，与我们的规范名称对不上，没有检索就只能靠记忆 ——
这是本片必须提供检索的原因。但**「是不是同一个」是人的判断**，所以本片只提供
**检索**，不提供**判定**：

- **查什么**：在已有标准物料里找候选，按**规范名称或规格包含关键字**匹配
  （不区分大小写、去首尾空白；多关键字按 AND）。
- **返回什么**：内部代理键、对外物料号、规范名称、规格、版本。
- **不返回什么**：**不给相似度分、不给「建议归并到哪一条」** —— 那等于替人下判定，
  而判据是「能否无差别互换」，需要现场信息，系统看不到。
- **精确查**：按内部代理键或对外物料号精确命中（采购可能直接从上一批采购单上念号）。
- **边界**：结果按稳定排序、限制最大条数；关键字长度低于下限时明确拒绝，不做全表扫描。

> 若真实使用证明关键字匹配不够用，再按真实数据加相似度 —— 那时才有调参的依据。

## 目标（一个业务结果）

**标准物料有一套租户内唯一、可长期引用的身份**，使 5 号节点归并在定点之后能
**挂接或新建**，并让该身份作为 `supplier_nomination` 交接的第六项随行。

本片交付的是**身份能力**，不是归并流程。归并流程由 5 号节点归并片承接。

## 上游事实（已有，本片不改）

**无。** 本片不消费任何上游交接——标准物料不是从产品设计派生的。

它消费的输入（供应商物料清单）此刻还不存在为身份：5 号节点第一片的
`keyMaterials` 是报价快照里的**字符串数组**（`QuotationKeyMaterialV1`），
不是可引用的对象。本片**不去读它**，也不回填它。

| 下游业务步骤与岗位结果       | 信息产生时机 / 前置事实            | 操作时需要看到什么                                 | 系统允许做什么                               | 数据如何可靠保存与反馈                                                     |

| 归并（5 号节点，**非本片**） | 定点完成后，该家报价的关键物料清单 | 每项物料：供应商原话名称与规格、**是否已有同物料** | 挂接到已有标准物料 / 新建标准物料            | 映射长期保留；对外物料号租户内唯一，撞号是业务冲突，明确拒绝而不是自动改名 |

**本片交付后仍缺的（承接切片）**：

1. **5 号节点归并片** —— 归并动作、供应商物料 → 标准物料的映射、交接改六项。
2. **①（实质变化）的退回路径** —— 归并片不能自己建 SKU（那是主数据侧产物），
   需要一条退回/请求路径。判据已定，工作流等真实场景。
3. **物料 ↔ SKU 关系与 BOM 版本** —— 跟在归并之后。

## 边界 / 不做

- **不做归并动作本身** —— 那是 5 号节点归并片。
- **不做归并判定** —— 本片给检索候选，但不给相似度分、不给「建议归并到哪一条」；
  判据是「能否无差别互换」，需要现场信息，系统看不到（见「归并时的候选检索」）。
- **不做 BOM、物料 ↔ SKU 关系** —— 挂在标准物料上，跟在归并之后。
- **不做 Listing 与别名** —— 销售侧身份，另需业务定义。
- **不做 UI / 不新增 HTTP 端点 / 不新增权限** —— 本片无页面消费者，
  能力经模块 port 在进程内暴露（与 `RESOLVE_PRODUCT_SKUS` 同一做法）。
- **不读也不改报价的 `keyMaterials`** —— 那是 5 号节点的快照，跨模块不写别人表。
- 不改已共享迁移；不投 outbox（与 4 号节点前几片一致：没有消费方就先不造事件）。

## 验收

- [ ] 标准物料有**内部代理键**（无含义、永不因业务变化而变）与**对外物料号**（可改），二者分列；改号不动内部键
- [ ] 对外物料号**租户内唯一**；撞号返回稳定错误码，**不静默改名**（沿用 `PRODUCT_IDENTITY_SKU_CODE_TAKEN` 的做法）
- [ ] 未给号时由系统兜底生成 `M-` + 内部代理键短 hash；**对外物料号非空**，唯一约束是普通唯一索引而非部分索引
- [ ] 同一幂等键重复建立不产生第二个物料；同键异载荷明确冲突
- [ ] 并发建立冲突时拒绝而不是覆盖
- [ ] 跨租户不可见
- [ ] port 已声明进 `module.manifest.ts` 的 `publicPorts`，暴露「建立标准物料」「按内部键/对外号精确读取」「按名称或规格检索候选」三项，**不暴露归并判定**
- [ ] 候选检索按规范名称或规格包含关键字匹配（不区分大小写、去空白、多关键字 AND）；**结果不含相似度分或推荐**
- [ ] 候选检索限制最大条数并稳定排序；关键字过短时明确拒绝，不做全表扫描
- [ ] 领域规则覆盖成功、失败与边界路径（唯一、幂等、并发、非法输入）
- [ ] 相关质量门禁全绿（`pnpm validate`；高风险面为迁移与公共契约，按 [AGENTS.md](../../../AGENTS.md) §8 走完整门禁）
