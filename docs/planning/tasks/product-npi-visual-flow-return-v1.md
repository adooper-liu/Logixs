# 任务：NPI 视觉动线、齐/半/缺与退回选品

> 本文件是执行、评审与交接的唯一载体。状态只看 frontmatter。  
> 权威改版：[WORKBENCH_VISUAL_FLOW_REDESIGN](../../product/WORKBENCH_VISUAL_FLOW_REDESIGN.md) §3、§7。  
> 前置：领取 `product-npi-intake-v1`、定义与发布 `product-definition-npi-release-v1` 已合入。  
> **澄清**：本片「退回选品」是 **NPI → 选品** 新回程，**不是** `product-initiative-return-path-v1`（选品 → 经营）。

## 目标

产品负责人在 NPI 工作台：阶段轨与结论条一眼可读；四宫格用 **齐 / 半 / 缺** 表达完成度；
可对已领取立项 **退回选品**（理由必填才关闭）；选品侧队列可见「NPI 退回」。

## 边界 / 不做

- 不发明无后端的「重开」；退回必须正式写接口 + 迁移加法（若需新状态/事实）。
- 不改发布硬门槛与主数据交接契约既有 wire value；只做加法。
- 不做转交/放手（领取片已明示无真实诉求则不摆假按钮）。
- 不把「退回选品」混进发布去向枚举的既有语义而不经契约评审。
- 色与主题只认项目令牌；齐/半/缺用 `--ok` / `--warn` / `--muted` 等既有语义，不伪造百分比。
- 串行：含写路径，建议排在活跃态依据区 / 选品 Mode 的 P0 之后，或单独占唯一 `coding` 槽。

## 验收

- [ ] 阶段轨可视化：概念─EVT─DVT─PVT─●MP（当前实心、已完成连线填充）
- [ ] 完成度离散档 **齐/半/缺**：齐=有结论且有依据；半=仅其一；缺=皆无；不伪造 %
- [ ] 结论条为活跃推进时的最高权焦点之一；全页 `--warn` ≤1
- [ ] 行动条沉底：`[退回]` 左置 + 主 CTA 右置（领取 / 推进 / 交主数据）
- [ ] 产品负责人可退回选品：理由必填才关闭；同事务留下可追溯退回事实
- [ ] 选品侧可见「NPI 退回」分组或等价投影；旧 NPI/交接事实可审计
- [ ] 缺理由：保存但不关闭、**不**回推选品
- [ ] 相关单测 + 集成（真实 PG，覆盖退回事务）+ 触及 E2E；契约/迁移门禁按风险通过

## 业务与数据协同设计

| 业务步骤与岗位结果 | 信息产生时机/前置事实     | 操作时需要看到什么             | 系统允许做什么     | 数据如何可靠保存与反馈                |
| ------------------ | ------------------------- | ------------------------------ | ------------------ | ------------------------------------- |
| 判断本阶段还差什么 | 已领取；阶段结论/依据现算 | 阶段轨、齐/半/缺四宫格、结论条 | 就地补结论/依据    | 既有阶段推进写路径                    |
| 发现立项本身不可做 | 已领取且未发布终态        | 退回影响、必填理由             | 退回（理由齐才关） | 同事务：NPI/立项侧退回事实 + 选品可见 |
| 选品接手被退回立项 | NPI 已退回                | 「NPI 退回」、理由、原快照     | 按选品既有动作重判 | 投影来自服务端；旧交接不可变          |

## 方案（design）

1. **视觉**：`ProductNpiWorkbench` + `ProductDefinitionAdvancePanel` — 阶段轨、结论条、齐/半/缺、行动条。
2. **退回契约**：新增 Port/命令（命名待 design 敲定）；选品侧投影「NPI 退回」；迁移只追加。
3. **与 HW-D18**：属按需回退层；不作废/删除。
4. 单测 + 集成：理由缺不回推；理由齐同事务可见于选品；幂等与租户隔离。
