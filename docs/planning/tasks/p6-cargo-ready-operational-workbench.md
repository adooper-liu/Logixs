# 任务：2.1b 备货岗位可操作闭环

> 承接 [`DOMAIN_VERTICAL_DELIVERY_PLAN`](../DOMAIN_VERTICAL_DELIVERY_PLAN.md) `2.1`。上一刀 `2.1a` 已验证公共岗位壳和真实只读投影，本刀让备货岗位在同一上下文中完成“找工作、判齐备、处理当前动作、确认结果”。

## 业务目标

备货人员进入工作台后，不再先选一只柜再自行拼接多页信息，而是从备货任务池定位优先工作，看到该柜各 SKU 的备货与合规缺口、责任方和下一步，并执行后端当前允许的领取或完成动作。系统明确区分生命周期任务与合规整改，不把提交成功、工单完成或合规补证误写成货柜已经过站。

## 四项协同映射

| 业务步骤           | 操作时需要看到什么                                                     | 系统允许做什么                                                 | 权威事实、落库与反馈                                                                       |
| ------------------ | ---------------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 找到下一项备货工作 | 我的任务、可执行、阻塞、临期、全部；截止时间、责任人、货柜号、备货单号 | 选择任务；仅在服务端返回领取动作时领取                         | 读取 `NodeTask`/`WorkOrder` 与独立 `ExternalWorkItem` 投影；领取走幂等写用例并展示三段回执 |
| 判断 SKU 是否齐备  | 装载数量与单位、电池/危险品/制冷剂/检验/证书状态、具体缺口             | 打开对应任务或合规处理上下文，不允许前端自行放行               | 读取当前装载集合和已保存的合规评审快照；未知与未评审明确显示，禁止猜测                     |
| 处理缺口           | 缺口原因、影响 SKU、责任岗位、所需证据、下一步                         | 进入合规评审；已有后端动作时执行；没有写能力时只给清晰承接路径 | 合规整改继续作为独立 `ExternalWorkItem`；本刀不伪造整改完成或证据上传结果                  |
| 完成当前备货工单   | 完成条件、系统已采用的装载/合规事实、当前允许动作、操作结果            | 仅执行 `nextAction` 指定的领取或完成动作                       | 复用受权应用服务和幂等键；展示“已接收→业务接受→事实落账”，失败保留可恢复原因               |

## 边界 / 不做

- 不新增生命周期事件、状态或前端过站逻辑；生命周期是否推进仍由后端工单聚合、合规门禁和状态机决定。
- 不把合规整改 `ExternalWorkItem` 合并成 `NodeTask`，也不把整改项显示为可完成工单。
- 不在缺乏当前评审时推断某 SKU 已安全；统一显示“未评审”。
- 不新增通用动态表单、产品主档编辑器或全岗位页面。
- 不扩展证据文件上传，也不提供不会落库的自由文本“证据”输入。备货完成复用已有装载和合规事实；真正附件存储另立切片。
- 不改变公共 API 或数据库。本刀以现有稳定 DTO 组合岗位投影，避免为了页面重复建立权威事实。

## 组件图

| --------------------------- | ------------------------------------------------------- | ----------------------------------------------------------- |
| `CargoReadyWorkbench.vue`   | 路由查询参数与工作台区域组合                            | 输入 URL；输出货柜/任务选择事件                             |
| `useCargoReadyWorkbench`    | 加载全局备货任务池和当前货柜投影，执行真实领取/完成动作 | 输入当前货柜/任务；输出派生队列、SKU 齐备度、回执与重载方法 |
| `CargoReadyWorkQueue.vue`   | 以岗位语言筛选、排序并选择备货任务，独立列出专业整改    | props 队列与筛选；emit 任务/整改选择                        |
| `CargoReadySummary.vue`     | 展示各 SKU 齐备度、缺口、责任和下一步                   | props 装载与评审投影；无业务写入                            |

## 交互与视觉方向

- 对象：跨境备货岗位；单一任务是把一柜货从“信息散落”推进到“可判断、可行动、结果明确”。
- 结构：左侧任务池，中间 SKU 齐备表，右侧当前动作与缺口；窄屏按“任务→齐备→动作”纵向排列。
- 视觉：沿用现有 Operations Shell 的中性工作界面；用风险/等待/完成色表达业务含义，不引入装饰性卡片或营销式版面。
- 识别点：SKU 每行是一条“齐备带”，同一行把装载事实、监管要素、缺口和责任放在一起，减少跨页比对。

## 验收

- [x] 首屏提供“我的任务 / 可执行 / 阻塞 / 临期 / 全部”过滤，并按紧迫度和截止时间稳定排序。
- [x] 任务行使用岗位语言，展示货柜/备货单、责任、截止时间与不可执行原因，不以内部定义码作为主标题。
- [x] 选择任务后同步定位货柜，显示每个 SKU 的数量、电池、危险品、制冷剂、检验和证书齐备状态。
- [x] 未评审、待确认、缺失、已满足严格区分；每个阻塞项显示责任岗位和明确下一步。
- [x] 只显示服务端 `nextAction` 允许的领取/完成动作；复用已有装载和合规事实，不收集不会落库的重复输入。
- [x] 操作结果展示三段回执，业务拒绝和技术失败有不同恢复提示，重试复用原幂等键。
- [x] 生命周期任务与合规整改分开呈现；进入合规页保留当前货柜上下文。
- [x] 成功、空态、部分投影失败、并发旧响应、操作拒绝、重试与窄屏有自动化覆盖。

## 影响与验证计划

- 影响范围：`apps/web` 备货工作台、任务 API 消费和用户可见操作反馈；不涉及数据库、迁移、公共 API、安全策略或后端领域规则。
- 兼容性：加法式 UI 调整；保留 `/workspaces/cargo-ready?containerId=...` 深链，新增任务选择参数时保持旧链接可用。
- 最近验证：相关 composable、组件和路由页 Vitest；`pnpm --filter @logix/web lint`、`typecheck`、`test`、`build`；关键流程需要时运行相关 Playwright。
