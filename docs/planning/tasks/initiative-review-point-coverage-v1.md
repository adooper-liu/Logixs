# 任务：评审要点与专业要求的覆盖对齐

> 负责人 2026-09-28 实测报出：选品立项界面上「本机会适用的专业要求」与「四项评审要点」
> 看起来像两套内容。查下来是**两处真实的不对称**。

## 问题

| 现象                                               | 后果                                                                 |
| -------------------------------------------------- | -------------------------------------------------------------------- |
| 专业要求「售后原声」**没有对应评审要点**           | **证据收了却没有地方形成结论** —— 比不收更糟：人会以为系统在管这件事 |
| 要点「目标用户与市场」「合规风险」**没有生成要求** | 人分不清"系统认为不需要"与"系统漏了"                                 |

代码里两者**本来就是连着的**（要求面板登记的证据进信号证据链、成为要点的可引依据），
但**界面上一个字没说**，名字又对不上（要求「竞争供给证据」↔ 要点「竞争供给」），
所以看起来像两套。

## 做法

1. **补一条评审要点 `customer_feedback`（客户反馈与痛点）** —— 让「售后原声」有落点。
   **它不进立项硬门槛**：加第 5 项门槛会让**存量记录追溯性变成不合格**。
   门槛是政策，改它要连存量一起算，不能顺手加。
2. **要求 → 要点显式映射**：`REQUIREMENT_REVIEW_POINTS` 用 `satisfies` 保证每一种要求
   都映射到一条要点 —— 漏了编译器当场拦住。
3. **界面说清两件事**：
   - 要求面板每条写明"补进去会成为「xx」要点的依据"；
   - 要点面板对**没有生成要求**的那两条，写明"依据来自上游信号与你自己的判断，
     不是系统漏了"。
4. **非门槛缺口单独列**：「还可以补（不挡立项）：…」，**不混进"还差 N 项"** ——
   混进去会让人以为非补不可。

## 边界 / 不做

- **不加门槛。** 见上，存量记录会追溯性不合格。要加得单独评估存量。
- 不重排要求与要点的生成规则本身（该在什么前置条件下生成，保持原样）。
- 不改既有 wire value；`customer_feedback` 是**枚举加法**。

## 两处口径必须一起动（已写进代码注释）

- 服务端 `PRODUCT_INITIATIVE_GATE` ↔ 网页 `REVIEW_POINTS[].gating`
- 服务端 `productInitiativePendingFieldCodes` ↔ 网页 `reviewPointMissing`
