## 一、Logix 是干嘛的

一句话：**管进口货柜的。**

一个货柜从「还没上船」到「空箱还掉」，中间要经过 14 站，每站要有人干活、有消息推进、有时间记录。Logix 就是把这一整条路管起来，并且让 AI 帮忙干「从 Excel 里认字段」这类累活——但**关键的数据落库，必须人确认**。

## 二、一柜货的 14 站旅程

```
备货 → 装箱 → 出运 → 离港 → 海运 → [中转] → 清关 → 到港 → [海铁] → 拖卡 → 送仓 → 卸柜 → 卸空 → 还箱
```

大白话：货柜像走一条「流水线」，一站一站往前。[中转] 和 [海铁] 是**可停可不停**的站（没有就走直线）。这是柜子的业务顺序，不是仓库写代码的顺序。

## 三、柜子怎么往前走（主链）

正确顺序不是「表进来 → 状态机看表现在在哪 → 事件派任务」。正确顺序是：

```text
已出运货柜表（入口）→ 系统里有了这一柜
  → 启动主流程，停在当前站
  → 这一站打开任务和工单
  → 人干活，或外部权威事实先到
  → 工单可以先做完
  → 核过的实际发生记录
  → 完成本站、打开下一站
  → 下一站再派新活
```

记住四句：

1. **进站才派活。** 不是事件先派任务。
2. **干活不等于过站。** 领取、提交、页面成功、工单做完，都不等于柜子进了下一站。
3. **过站要实际发生。** 计划、ETA、最晚提柜日、外部接口改个字段，都不能单独过站。
4. **外部接口是证据来源，不是遥控器。** 供应商不拥有我们的流程状态。

已出运货柜表只决定柜子进不进系统，不决定后面每个字段算不算已经发生。14 站位置和 8 个粗状态也不是同一句话。全文对照、七条常见误解见 [货柜怎么往前走](./人话-货柜怎么往前走.md)。

## 四、几个绕不开的词（人话版）

- **货柜 vs 发生记录**：货柜是「谁」，发生记录是「真的发生了什么」。只有核验过的**实际**发生，才可能过站。预计、AIS、点按钮不算。
- **过站**：把当前这一站做成完成；做成之后通常打开下一站。精确说法见术语表「过站」。
- **任务 / 工单**：货柜到一站，不等于事自动做完，而是「派活」——这一站要干的活拆成一张张工单。人可以领取、处理、交证据、报完工；也可以是系统或外部先把事实送来。
- **状态 + 时间链**：货柜从头到尾就 8 个「阶段词」（没出运 → … → 已还箱，加一个取消）；**时间只能往前，过了的站不许回头改**（叫「密封」）——因为改错代价大。过了一站，粗状态不一定翻页。
- **谁的话算数（来源权威）**：船开没开听船司的，柜卸没卸听仓库的。不是「谁最后写的谁赢」，而是「对这件事负责的人说了算」。
- **迟绑定**：箱号是装箱后才有的，所以货柜可以先建档（用备货单号当身份）、后补箱号。
- **Outbox（发件箱）**：系统办完一件事时，把「业务已经变化」和「还要通知别人」一起记进数据库。后台再从发件箱发送；网络临时出错就重试。这样不会出现柜子已经离港，但通知半路丢了。
- **Inbox（收件登记簿）**：接收方先把消息登记下来，再判断有没有处理过。相同消息重复送来，只办一次，不会因为发送方重试就让柜子重复过站。
- **死信（问题件区）**：消息格式不对、业务条件不满足，或多次重试仍失败，就先放进问题件区。它不会被悄悄丢掉，也不会无限重试；人员查明原因后，可以修正并重新投递。
- **补偿（冲正单）**：事情已经办成，后来发现需要纠正时，不删除原记录，也不假装从未发生，而是新增一条有原因、有责任人、可追踪的纠正动作。它像财务红字冲销：原账保留，再记一笔纠正账。

把这四个词连起来，就是：

```text
业务操作完成 → 写入 Outbox → 发送消息 → 接收方写入 Inbox
→ 幂等处理业务 → 失败则重试 → 多次失败进入死信
→ 已经成功但后来需要纠正，则走补偿
```

最关键的区别：**死信管「消息还没办成」，补偿管「事情已经办成，但后来需要纠正」**。补偿不是数据库回滚，也不是删除历史。精确定义以 [同步可靠性契约 V1](./product/domain/SYNC_RELIABILITY_CONTRACT_V1.md) 为准。

## 五、第一个要做的业务：智能导入

现在系统先从「已经出运的货柜清单」接手。怎么接手：

1. 上传一份 Excel（已出运货柜表）
2. AI 猜「这列是箱号、那列是港口」——**只猜，不写库**
3. 人逐列确认 / 改
4. 预检：缺了必填的、说不清是否已出运的，**拦下不让写**
5. 确认无误 → 落库
6. 对账：哪些成功了、哪些跳过、哪些失败

核心铁律：**AI 只出主意，人拍板，写库有硬闸。** 这样保证「错误写入率目标 0」。
