# Logix 人话导读

> 这份文档不讲术语，用大白话说清楚 Logix 到底是什么、怎么转的、文档去哪找。
> 给第一次接触这个项目的人（包括未来的运营、业务、开发）。10 分钟读完。

## 一、Logix 是干嘛的

一句话：**管进口货柜的。**

一个货柜从「还没上船」到「空箱还掉」，中间要经过 14 站，每站要有人干活、有消息推进、有时间记录。Logix 就是把这一整条路管起来，并且让 AI 帮忙干「从 Excel 里认字段」这类累活——但**关键的数据落库，必须人确认**。

## 二、一柜货的 14 站旅程

```
备货 → 装箱 → 出运 → 离港 → 海运 → [中转] → 清关 → 到港 → [海铁] → 拖卡 → 送仓 → 卸柜 → 卸空 → 还箱
```

大白话：货柜像走一条「流水线」，一站一站往前。[中转] 和 [海铁] 是**可停可不停**的站（没有就走直线）。

## 三、几个绕不开的词（人话版）

- **货柜 vs 事件**：货柜是「谁」，事件是「发生了什么」。比如 `arrived`（到港了）这个事件发生，货柜才能从「海运中」走到「已到港」。是事件在推着货柜往前走。
- **任务 / 工单**：货柜到一站，不等于事自动做完，而是「派活」——这一站要干的活（清关、拖卡……）拆成一张张工单让人去干。
- **状态 + 时间链**：货柜从头到尾就 8 个「阶段词」（没出运 → … → 已还箱，加一个取消）；**时间只能往前，过了的站不许回头改**（叫「密封」）——因为改错代价大。
- **谁的话算数（来源权威）**：船开没开听船司的，柜卸没卸听仓库的。不是「谁最后写的谁赢」，而是「对这件事负责的人说了算」。
- **迟绑定**：箱号是装箱后才有的，所以货柜可以先建档（用备货单号当身份）、后补箱号。

## 四、第一个要做的业务：智能导入

现在系统先从「已经出运的货柜清单」接手。怎么接手：

1. 上传一份 Excel（已出运货柜表）
2. AI 猜「这列是箱号、那列是港口」——**只猜，不写库**
3. 人逐列确认 / 改
4. 预检：缺了必填的、说不清是否已出运的，**拦下不让写**
5. 确认无误 → 落库
6. 对账：哪些成功了、哪些跳过、哪些失败

核心铁律：**AI 只出主意，人拍板，写库有硬闸。** 这样保证「错误写入率目标 0」。
