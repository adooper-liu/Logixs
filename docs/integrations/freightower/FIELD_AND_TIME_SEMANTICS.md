# 飞驼字段与时间语义

## 事实等级

| 等级 | 示例 | 生命周期政策 |
|---|---|---|
| 原始权威事实 | CBP 原始记录、海关/码头实际事件 | 保留原文，经对象和规则核验后可形成规范事件 |
| 供应商转述事实 | 船公司/港区 `ACT` | 可作为候选，必须核验来源、时效、幂等 |
| 供应商推断 | `source=2`、AIS 推导挂靠 | 仅供核查和预警 |
| 预计/计划 | `EST`、ETA/ETD、船期 | 不推进实际流程 |
| UI 展示 | iframe、地图轨迹 | 不作为领域证据 |

`authority` 表示事实权威来源（如 CBP、海关、码头、船公司），`provider` 表示数据传输方（飞驼）。两者必须分别保存。

## 时间规范

- 原始时间文本、原始时区和解析结果同时保存；无法确认时区时不得默认为 UTC。
- Logixs 按 UTC 存储、ISO 8601 交换、用户时区展示。
- 计划、预计和实际分别建模，后到的预计值不得覆盖已确认实际值。
- AIS `updateTime` 文档标为北京时间；经纬度除以 `1e6`，航向除以 `100`，速度单位为 mm/s。
- 航空计划使用 UTC；单次查询窗口最多 10 天。
- ETA/ETB/ETD 与 ATA/ATB/ATD 必须保持独立字段。

## 标识符与原始值

- 提单号、箱号、报关单号、MMSI、IMO、订阅 ID 等按字符串处理，保留前导零和原始大小写。
- 保存 `rawPayload`、供应商文档/接口版本、接收时间、载荷哈希、关联订阅和解析版本。
- 原始提单号与规范化提单号可导致重复事件；幂等键不能只依赖展示号。
- RORO 的 `RORO000001` 等伪箱号禁止进入真实货柜主数据。

## 已知契约冲突

1. `/container/match` 在 Query 与 Body 同时定义 `businessNumber`，示例值不一致。
2. 中国港区推送的复数字段示例为单对象，解析器应兼容对象/数组并记录偏差。
3. EIR `yardCode` 在 schema 中必填，但说明称仅青岛使用。
4. 两个中国海关 GET 查询称“已订阅”，其副作用、计费和幂等语义不明。
5. 船舶档案尺寸单位与示例冲突，`shiptype` 定义异常。
6. 历史挂靠的 `departureName`、RORO 拥堵过滤、Bond 字段拼写存在疑点。
7. GeoJSON 实例坐标按 `[longitude, latitude]` 解释；接口不提供时间和置信度。

## 现网部分数据样本

2026-09-08 的脱敏现网界面样本显示：船公司跟踪投影可能只有 MBL、货柜和承运人基础引用，而 firstVessel、currentStatus、places、routes、terminalPlan、containers/status、vessel、packinglist 与 VGM 均为空。此类页面必须标记为 unknown/partial，并结合订阅与同步回执解释；“暂无数据”不得生成否定业务事实，也不得清除既有事件。详见 [业务样本 009](../../product/domain/CUSTOMS_BUSINESS_SAMPLE_009.md)。

这些冲突必须在 Adapter 契约测试中固化已验证行为；确认前不得在领域层猜测。
