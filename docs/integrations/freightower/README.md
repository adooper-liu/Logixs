# 飞驼知识库

## 1. 文档定位

本目录集中保存 Freightower（飞驼）接口、事件码、字段语义、覆盖能力及接入约束，作为 Logixs 供应商适配器的设计和核验依据。

飞驼是首个已整理的第三方证据供应商，不是系统唯一数据源。Logixs 采用供应商中立的 Port/Adapter 架构；未来接入海关、港口、船公司、运输商、仓库或其他聚合平台时，复用相同的证据、映射、规范事件与生命周期守卫机制。

本文档集不是 Logixs 领域状态机的权威定义。飞驼返回值必须依次经过原始证据留存、供应商映射、规范事件转换和生命周期守卫，才可影响主流程：

```text
飞驼原始载荷 -> 飞驼码表/字段映射 -> Logixs 规范事件 -> 生命周期守卫 -> 流程状态
```

文档状态：外部供应商核验知识库（review input）。接口行为、覆盖范围和码表可能随供应商版本变化；上线前须以已签约租户的最新飞驼文档及联调结果复核。

## 2. 与 Logixs 主流程的关系

```text
ContainerRecord -> FlowInstance -> NodeTask -> WorkOrder(s)
-> ClientOperation -> 数据/证据/同步回执
-> WorkOrder 状态 -> NodeTask 聚合 -> 规范事件
-> 生命周期转换 -> 下一节点
```

- 货柜是主任务载体，节点工序形成子任务，子任务内部产生一张或多张工单。
- 飞驼适配器只产生外部证据、同步回执和规范事件候选，不直接修改 `FlowInstance`。
- 工单状态先影响子任务聚合；只有满足来源、对象、时效、幂等和生命周期守卫的规范事件才推进主链。
- 预计事件、预警和推断不得冒充实际业务事实。

## 4. 状态分层

以下状态必须独立存储，不得复用同一枚举：

1. API 调用状态：HTTP/业务响应是否成功，例如 `statusCode=20000` 仅表示接口调用成功。
2. 供应商同步状态：`START/PROCESS/COMPLETE/NODATA/ABNORMAL`；`COMPLETE` 只表示飞驼停止或完成更新。
3. 事件时间性质：计划、预计、实际。
4. 业务事实状态：海关放行、码头放行、装船、卸船等经证据支持的事实。
5. Logixs 生命周期状态：由领域规则和守卫统一决定。
