## 1. 使用边界

飞驼“60+ 节点”是外部事件字典，不等于 Logixs 的 14 节点主链，也不直接等于 22 个运营环节。

    飞驼原始证据
    -> 飞驼字段与事件码映射
    -> Logixs 规范事件候选
    -> 22 个运营环节中的子任务/工单
    -> 生命周期守卫
    -> 14 节点主链

| 状态层 | 示例 | 可否直接推进主链 |
|---|---|---|
| API 调用状态 | statusCode=20000 | 否 |
| 供应商同步状态 | START/PROCESS/COMPLETE/NODATA/ABNORMAL | 否 |
| 事件性质 | EST/ACT | 仅合格的实际事件可进入守卫 |
| 外部业务事实 | 海关放行、重箱进港、装卸船 | 先形成规范事件候选 |
| Logixs 生命周期状态 | FlowInstance.status | 仅由领域状态机修改 |

🗣️ 白话：飞驼告诉系统“看到了什么”，Logixs 仍要判断“这是什么事实、属于哪个货柜、证据是否够、当前节点能不能往下走”。

## 4. 跨能力落位规则

| 外部信息 | 系统对象 | 处理方式 |
|---|---|---|
| 供应商订阅 | ProviderSubscription | 保存本地 ID、外部 ID、能力、对象和版本 |
| 原始响应/推送 | ProviderRawPayload | 不可变保存、哈希、接收时间、来源和解析版本 |
| API/同步结果 | ProviderSyncReceipt | 与业务事实状态分离 |
| 飞驼事件 | ExternalEventCandidate | 显式映射，未知码进入复核队列 |
| 规范事件 | CanonicalEvent | 通过对象、来源、时效、幂等和守卫后发布 |
| 覆盖清单 | ProviderCapability | 国家、港口、方向、单/箱条件和生效期版本化 |
| 飞驼预警 | TrackingAlert | 可触发异常工单，不直接推进主链 |

幂等键至少组合订阅、业务对象、事件码、预计/实际、地点和发生时间；有供应商事件 ID 时优先纳入。保留原始事件、规范事件、映射版本、撤销/更正记录和 receivedAt。

## 5. 外部事件到主链的候选聚合

下表只表示研判方向，具体代码和守卫以 [EVENT_CODE_CATALOG.md](./EVENT_CODE_CATALOG.md) 及 Logixs 权威生命周期文档为准。

| 运营语义 | 飞驼候选 | 限制 |
|---|---|---|
| 提空箱 | STSP、GTOT+EMPTY | 匹配箱号、方向和场站 |
| 装箱 | STUF | 实际事件且对象一致 |
| VGM/单证就绪 | RELS+VGM | 单证就绪不等于主链整体完成 |
| 海关放行 | PASS、RELS+CUS、PAS | 区分报关单、提运单、结关和动态确报 |
| 码头放行/配载 | TMPS、PRLD | 不得与海关放行合并 |
| 重箱进港 | GITM、GTIN+LADEN | 区分码头和堆场返场 |
| 装船/离港 | LOBD、DLPT | 船舶事件不能传播到全部货柜 |
| 中转 | TSBA/TSCA/TSDC/TSLB/TSDP | 作为运输子段和工单 |
| 到港/靠泊/卸船 | BDAR/POCA/DSCH | 预计事件只更新计划 |
| 提柜/送仓 | STCS/STRP | 与目的港放行条件联合判断 |
| 还空箱 | RCVE、GTIN+EMPTY | 匹配场站和箱号 |

铁路、驳船、支线、卡车和仓库事件属于主节点内部运输子段或作业工单，不因外部事件数量增加主链节点。

## 6. 待供应商确认

1. Webhook 配置、验签、唯一投递 ID、重试、超时、重放和补拉协议。
2. 接口限流、计费、SLA、保留期及沙箱与生产差异。
3. 中国港区推送对象/数组正式 schema 和漏推恢复方式。
4. container/match 的 businessNumber 参数优先级。
5. EIR yardCode 在青岛和非青岛场景的必填规则。
6. 中国海关 GET 是否创建订阅、是否收费及如何停止。
7. 美国海关事件方向、撤销关系和多类 Hold 聚合规则。
8. 船舶尺寸单位、历史挂靠字段、RORO 过滤及 Bond 字段拼写。
9. 港口、EIR 和船公司覆盖清单的版本、生效日和变更通知。
10. iframe 的短期令牌、来源限制、CSP 和最小权限方案。
11. 航空距离/时长单位、货机识别和代码共享归并规则。

## 7. 开发准入结论

现有资料足以支持 Adapter 骨架、原始载荷模型、订阅模型、同步回执和候选事件映射设计；尚不足以跳过联调直接启用自动生命周期推进。

1. 固化供应商 DTO 和脱敏契约样例。
2. 实现原始载荷、订阅、同步回执和能力配置。
3. 建立版本化外部码映射与未知码复核队列。
4. 覆盖重复、乱序、重放、撤销和预计晚于实际的契约测试。
5. 逐码确认权威来源、对象范围、推进条件和撤销规则。
6. 经领域负责人和安全负责人评审后开放自动推进。
