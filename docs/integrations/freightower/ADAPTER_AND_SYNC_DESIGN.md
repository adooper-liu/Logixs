# 飞驼适配与同步设计

## 边界

飞驼通过 `FreightowerPort` 接入 Infrastructure Adapter。供应商 DTO、状态码和重试细节不得进入 Domain。建议持久化对象：

- `ProviderSubscription`：订阅对象、能力、供应商 ID、状态及版本。
- `ProviderRawPayload`：不可变原始载荷、哈希、接收时间和权威来源。
- `ProviderSyncReceipt`：调用、推送、重试、补拉、对账结果。
- `ExternalEventCandidate`：解析后的供应商事件及证据等级。
- `CanonicalEvent`：通过映射、对象消歧和质量校验的规范事件。
- `ProviderCapability`：按国家、港口、进出口、单/箱条件和生效期版本化的能力配置。

## 接收链

```text
HTTP/push -> 边界校验 -> 原始载荷落库 -> 验签/去重
-> 供应商 DTO 解析 -> 事件候选 -> 对象消歧
-> 规范映射 -> 生命周期守卫 -> 领域事件/人工核查
```

- Webhook 返回成功前必须完成耐久化，解析和业务处理异步执行。
- 幂等键优先使用供应商事件 ID；缺失时使用订阅、业务对象、事件码、事件性质、发生时间和稳定载荷哈希组合。
- 允许乱序到达；按实际发生时间、预计/实际性质和接收序号重建投影。
- 同一能力避免无意双订阅；若需双源校验，必须定义主源、辅源和冲突策略。
- 更新通知型推送接收后拉全量；增量型推送仍需定期对账。没有补拉接口的能力必须标为可靠性降级。
- `stopPush`、订阅 `COMPLETE` 或 API 成功均不得关闭 Logixs 主任务。

## 状态推进

Adapter 不直接写 `FlowInstance`、`NodeTask` 或 `WorkOrder` 状态。它只发布规范事件候选和同步结果：

1. 同步动作记录 `ClientOperation` 和 `ProviderSyncReceipt`。
2. 规范事件交由 Application 用例核验租户、对象、权限、当前节点及时效。
3. 工单完成条件由工单规则决定；子任务按多工单聚合策略变更。
4. 子任务完成后产生领域事件，由主流程状态机决定是否进入下一节点。

## 失败与恢复

- 区分可重试传输错误、供应商业务拒绝、无数据、未知码、映射失败和生命周期冲突。
- 指数退避必须有最大次数、超时和死信队列；人工重放保持原载荷且生成新操作记录。
- 对账任务比较订阅状态、全量快照与本地投影，输出缺失、重复、倒序和冲突报告。
- 映射表必须版本化；重放历史数据时记录所用映射版本，禁止静默改写既有审计事实。
