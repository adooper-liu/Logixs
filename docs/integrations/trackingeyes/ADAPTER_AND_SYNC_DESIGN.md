# 云当网适配与同步设计

> 状态：**外部供应商适配设计（候选，接收/留痕/对象解析/日期事实接入已部分实现）** · 2026-09-20
> 公共同步阶段、幂等、Inbox/Outbox、重试、死信与补偿唯一引用[同步可靠性契约 V1](../../product/domain/SYNC_RELIABILITY_CONTRACT_V1.md)；本文只定义云当网供应商适配细节。

## 1. 边界

云当网通过 `TrackingEyesPort` 接入 Infrastructure Adapter。供应商 DTO、状态码、签名与限流细节不得进入 Domain：

```text
domain/          TrackingEyesEventCandidate、证据等级、映射规则（纯求值，无框架依赖）
application/     订阅、归一、对账用例编排
infrastructure/  TrackingEyesHttpClient（签名/token/限流）、映射表读取、原始载荷落库
```

与 [飞驼适配设计](../freightower/ADAPTER_AND_SYNC_DESIGN.md) 共用同一组持久化对象，**不新增供应商专属模型**：

- `ProviderSubscription`：订阅对象、能力、供应商 ID、状态及版本。
- `ProviderRawPayload`：不可变原始载荷、哈希、接收时间和权威来源。
- `ProviderSyncReceipt`：调用、推送、重试、补拉、对账结果。
- `ExternalEventCandidate`：解析后的供应商事件及证据等级。
- `CanonicalEvent`：通过映射、对象消歧和质量校验的规范事件。
- `ProviderCapability`：按港口/口岸/场站/码头/船东和生效期版本化的能力配置。

**云当网相对飞驼的额外要求**：`TrackingEyesHttpClient` 必须内置 token 缓存与刷新（2 小时有效期），且凭据不得落代码——见 [AUTH_AND_SECURITY §3](./AUTH_AND_SECURITY.md)。

## 2. 与飞驼适配器的复用关系

两家是**独立供应商，共享同一套接入机制**。这是对「加新供应商 = 加注册 + 码表 + 映射条目 + 对拍测试，核心逻辑不动」这一设计假设的检验点：

| 层                               | 是否复用    | 说明                                                                                              |
| -------------------------------- | ----------- | ------------------------------------------------------------------------------------------------- |
| Inbox/Outbox/幂等/租约/死信/重放 | ✅ 完全复用 | 与供应商无关                                                                                      |
| 规范事件信封与目录               | ✅ 完全复用 | 32 个规范事件是内部语义，不随供应商变                                                             |
| 生命周期守卫与状态机             | ✅ 完全复用 | 事件→节点资格、R1/R2/R3 不变量                                                                    |
| 来源权威策略                     | ✅ 完全复用 | 但云当网的 `sourceCd` 提供了飞驼没有的逐事件来源信号                                              |
| 事件码映射表                     | ❌ 独立     | 42 码与飞驼仅约 23 个重叠，且码集会各自演进（见 [README §5](./README.md#5-与飞驼码表的对照重要)） |
| 订阅/鉴权/限流客户端             | ❌ 独立     | 签名算法、token 模型、限流均不同                                                                  |
| 能力配置                         | ❌ 独立     | 覆盖范围完全不同                                                                                  |

若实现后发现必须改动规范事件目录或生命周期守卫，说明抽象漏了——**那应当记为架构问题并立 ADR，而不是在适配器里打补丁**。

## 3. 接收链

```text
云当网推送 -> 边界校验 -> 原始载荷落库 -> 去重/幂等
-> 供应商 DTO 解析 -> 事件候选（含 sourceCd 定级）-> 对象消歧（localKey / blNo / ctnrNo）
-> 复合键映射（provider + rawCode + context）-> 生命周期守卫 -> 领域事件/人工核查
```

当前已实现到“Evidence + 统一日期事实”第一刀：按 `tenantId + ctnrNo` 大小写不敏感查询，租户内唯一命中才保存稳定 `containerRecordId`；零命中保存 `not_found`，多命中保存 `ambiguous`，两者均进入复核且不猜测历史货柜。只有“规范事件候选 + 唯一货柜”才幂等注册 Evidence，并调用 `RecordLifecycleDateFact` 公共 Port；未知码、无时区、删除/更正意图及对象未唯一解析时只保留接入记录，不生成下游业务事实。

云当网在 Evidence 与日期事实中均保存为 `provider=trackingeyes`，接口、映射版本、供应商事件 ID 和原始接入记录引用一并留存。载荷目前只能给出 `sourceCd` 来源信号，不能识别具体船公司或码头主体，因此 `authoritySystem=unresolved`；不得把云当网或 `carrier/terminal` 信号冒充已核验权威主体。Evidence 初始为 `pending / unknown|provisional`，实际日期因此进入 `review_required`，不会直接推进生命周期。

原始接入与下游事实采用分段幂等恢复：Inbox 同消息同载荷重试复用原接入记录、Evidence 和日期事实继续处理；同消息异载荷或同 Evidence 幂等键异内容返回 `IDEMPOTENCY_CONFLICT`。Evidence 使用 `(tenantId, idempotencyKey)` 数据库唯一约束，历史 Evidence 在迁移时回填为 `legacy:<evidenceId>`。

按 [PUSH_PAYLOAD_STRUCTURE §11](./PUSH_PAYLOAD_STRUCTURE.md) 的优先级选幂等键：`ctnrStatus[].id` → `localKey + statusCd + eventTime` → `运单 id + dataUpdateTime + ctnrNo` → 载荷哈希。

- 推送返回成功前必须完成耐久化，解析与业务处理异步执行。
- 允许乱序到达；按 `eventTime` 与领域规则重建投影，不得按接收顺序覆盖。
- 云当网提供**完整的订阅/推送/下载三件套**，因此推送接收后应触发补拉与定期对账；**不存在"无补拉接口"的可靠性降级**。
- 我方主动订阅时应写入 `localKey`（客户本地关键字），从源头建立与 Logixs 对象的关联。
- 订阅 `S`/`F`、`endStatus=E/EF`、`dataStatus=B` 均**不得关闭 Logixs 主任务**或生成否定业务事实。

## 4. 状态推进

Adapter 不直接写 `FlowInstance`、`NodeTask` 或 `WorkOrder` 状态。它只发布规范事件候选和同步结果：

1. 同步动作记录 `ClientOperation` 和 `ProviderSyncReceipt`。
2. 规范事件交由 Application 用例核验租户、对象、权限、当前节点及时效。
3. 工单完成条件由工单规则决定；子任务按多工单聚合策略变更。
4. 子任务完成后产生领域事件，由主流程状态机决定是否进入下一节点。

**云当网特有的三条推进约束**：

1. **`sourceCd=4`（云当计算）与 `availableStatus` 等推断值不得单独驱动节点推进**，只能作为佐证进入核查。
2. **港区/海关类回执的权威主体是海关与码头，云当网是传输方**——按证据来源权威契约，其可单独完成的范围由运行时 `SourceAuthorityPolicy` 复合策略决定；对象解析成功不代表命中权威策略。
3. **`deleteStatus[]` 表达更正与撤回**，必须追加引用原事件的新记录，禁止原地改写历史。

## 5. 失败与恢复

- 区分可重试传输错误、token 失效、供应商业务拒绝（`code != 200`）、`type=warning` 的部分失败、无数据（`dataStatus=B`）、未知码、映射失败和生命周期冲突。
- 指数退避必须有最大次数、超时和死信队列；人工重放保持原载荷且生成新操作记录。
- 对账任务比较订阅状态、下载接口全量快照与本地投影，输出缺失、重复、倒序和冲突报告。
- 映射表必须版本化；重放历史数据时记录所用映射版本，禁止静默改写既有审计事实。
- 订阅成功的运单清单须落库，否则无法判断"某运单从未订阅"与"订阅了但无数据"的区别。

## 6. 能力配置（不得硬编码）

覆盖范围**高度不对称**，必须按对象与生效期版本化配置：

**中国港区（10 港）**：查验与 VGM 仅**增强版**提供；上海、南沙、大连、青岛只有状态无放行时间；盐田、蛇口有查验状态无时间；大铲湾无查验无 VGM；**大连需另行提供「大连口岸物流网」账号密码**；蛇口仅支持出口单且不支持万海、锦江、OVP。

**EIR（4 口岸）**：厦门、青岛、深圳（仅出口）、宁波；不支持万海；深圳仅支持 SO 查询。

**场站数据**：当前清单以青岛各堆场为主（23 个场站代码），覆盖不具全国性。

**全球码头**：以美国港口为主（洛杉矶、长滩等码头），`ieId` 暂不支持出口；**建议抵港时订阅，实际提箱日距订阅超 10 天可能取不到数据**。

**海运船东**：各船东对 ETD/ATD/ETA/ATA 的支持度不同（支持清单中逐船东标注 √/×），例如 CSTAR LINE 仅支持 ETA。订阅前须按 `carrierCd` 校验目标字段是否可得，否则会静默缺证。

**附加能力**：AIS 的 `aisAtd`/`aisAta`/`aisETA`/`aisATA`、OOCL 的 `chargeDatas`（免箱期）、京东与厦门航空的航班动态，均**需额外商务开通**。

2. 推送的重试策略、验签协议与失败告警。
3. 分页推送（船期）的暂停、续传与重复投递语义。
4. `deleteStatus[]` 的触发条件：供应商纠错 vs 业务撤销是否可区分。
5. 同一运单重复推送时 `ctnrStatus[]` 是全量还是增量——决定幂等键是否必须按事件级。
6. 三个支持代码接口的变更通知机制。
