# 云当网字段与时间语义

> 状态：**外部供应商字段语义（参考，待联调复核）** · 2026-09-18

## 1. 事实等级

云当网的动态节点自带 `sourceCd`，可以直接支撑分级，不必只靠供应商身份推断：

| 等级           | 判据                                                          | 生命周期政策                                   |
| -------------- | ------------------------------------------------------------- | ---------------------------------------------- |
| 原始权威事实   | `sourceCd=1`（船东）、`sourceCd=2`（码头）                    | 保留原文，经对象与规则核验后可形成规范事件候选 |
| 供应商转述事实 | 港区/海关/场站回执（来源未在字段中标注）                      | 可作为候选，必须核验来源、时效、幂等           |
| 供应商推断     | `sourceCd=4`（云当计算）、`availableStatus`                   | 仅供核查与预警，**不得单独驱动节点推进**       |
| 计划/预计      | `planTime`、`estimateTime`、`isEstimate=true`、船期表         | 不推进实际流程                                 |
| 同步状态       | `trackStatus`、`endStatus`、`dataStatus`                      | 只描述采集进度，不是业务事实                   |
| UI 展示        | 内嵌 iframe（集装箱轨迹、船舶轨迹、船期表等均有「内嵌方式」） | 不作为领域证据                                 |

`authority`（事实权威来源，如船东、码头、CBP）与 `provider`（数据传输方，云当网）必须分别保存。按 [证据来源权威契约 §4](../../product/domain/EVIDENCE_SOURCE_AUTHORITY_CONTRACT_V1.md)，**云当网作为 provider 不得自动继承 authority 身份**。

`availableStatus`（可提箱状态）是云当网的计算结果而非码头原始事实，属供应商推断——与飞驼知识库对「可提箱守卫」的处理一致。

## 2. 时间语义（本知识库最重要的冲突）

### 2.1 供应商只给无时区的本地时间

云当网在**几乎每一个**数据域的推送接口上都写明：

> 所有的时间字段都是字符串类型，格式为 `"yyyy-MM-dd HH:mm:ss"`，如果时间没有值则为空字符串 `""`。

**没有时区偏移，没有 UTC 标记。** 港区、场站、报关、快递、海运跟踪、及时请求等接口均如此。

### 2.2 与 Logixs 契约直接冲突

[证据来源权威契约 §5](../../product/domain/EVIDENCE_SOURCE_AUTHORITY_CONTRACT_V1.md) 要求：

> 所有时间以带时区 ISO 8601 交换、UTC 持久化。**无法确认原始时区时保存原文并进入复核，不得假定 UTC。**

因此适配器**不得**直接 `new Date("2026-09-18 14:30:00")`。在 Node.js 中该构造会按**服务器本地时区**解释，同一份载荷在不同部署环境解析出不同时刻，直接污染节点时间与超期费用计算。

正确做法：**原样留存时间字符串 + 记录推断依据 + 进入复核**，只有能确定时区时才转换为 UTC。可用的推断依据包括港口代码（`portCd`/`polCd`/`podCd`）、`timeZone` 字段（见下）与我方对船东/码头所在时区的既有知识——但推断结果必须标记为推断，不能当作原始事实。

### 2.3 同一供应商内部时区语义就不一致

| 接口组                        | 时间语义                                                                               |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| `/api/shipAIS/*`（老接口）    | 「返回的时间都是北京时间」——硬编码北京时间                                             |
| `/api/shipAIS/v2/*`（新接口） | 「若请求参数上传 `timeZone` 时区，返回值的时间为**该时区当地时间**」；不传时语义未说明 |
| 全球码头数据推送              | 有 `timeZone` 字段，「如为空则表示当地时间」                                           |
| 其余数据域                    | 只说是 `yyyy-MM-dd HH:mm:ss`，未说明时区                                               |

**`timeZone` 字段只给时区名或空值，不给偏移量**，也没有历史时区的夏令时处理说明。因此即便拿到 `timeZone`，跨夏令时的换算仍需我方自行处理并留档。

结论：**时区必须在适配器层显式建模，不能依赖供应商字段**。这是接入云当网（以及任何同类供应商）的前置工作，建议单独立 ADR。

### 2.4 计划、预计、实际三列分离

海运跟踪推送的 `oceanNodes[]` 明确分三列，必须分别落库、不得互相覆盖：

```text
planTime       计划动态发生时间
estimateTime   预计动态发生时间
actualityTime  实际动态发生时间
aisEstimateTime / aisActualityTime   AIS 推算（需额外开通）
```

箱级动态用 `isEstimate` 布尔区分预计/实际。另有 `firstETA`（开航后第一次获取到的预计抵港时间）——这是**首估基线**，用于度量 ETA 漂移，不要覆盖。

### 2.5 换船与订舱取消

`oldVesselName` / `oldVoyage` / `changeVslId`（`Y`=起运港换船）与 `shipRolled`（`BCL`=整票订舱取消）描述的是**航次变更**，不是节点推进。换船后 `vesselName`/`voyage` 会变，历史动态仍指向旧船名——映射与投影时必须按 `eventTime` 而不是按当前船名归属。

## 3. 标识符与原始值

- 提单号、箱号、订舱号、报关单号、场站/码头代码、MMSI、船名航次等一律**按字符串处理**，保留前导零与原始大小写。
- `localKey`（客户本地关键字，≤38 字符，**唯一值**）由**我方订阅时填写**，建议写入 Logixs 的对象引用，从源头减少对象消歧。
- 逐事件唯一标识按数据域不同：
  - 海运跟踪/及时请求：`ctnrStatus[].id`（雪花 id，动态关键字）
  - 港区/场站/报关/全球码头：运单级 `id`（订阅接口返回）+ `dataUpdateTime`
- `id` 在**海运跟踪推送里是字符串**（云端运单关键字），在**港区/场站推送里是整数**（运单 id）。同一个字段名语义与类型都不同，**不得用同一列存储**。
- `referenceNo`（订阅号）、`requestId`（请求号，唯一）、`batchId`（批次号）三者用途不同：前者是订阅关系，中者是本次请求，后者是批次。
- `ctnrNo` 长度上限 11 位，符合 ISO 6346 标准箱号（4 字母 + 7 数字）。

## 4. 已确认的契约冲突与存疑

1. **时区缺失**（§2）——最高优先级，影响所有时间字段。
2. **「无效字段」标记与实际使用矛盾**：海运跟踪推送把 `dschTime`（卸船时间）、`cyOpenTime`（开港）、`cyCutOffTime`（截港）、`pkgs`/`gwgt`/`vgm` 标为「无效字段」，但**及时请求推送里同样的字段仍在正常返回**。适配器不得依据"无效"标记丢弃这些字段，须按接口分别处理并记录差异。
3. **同一供应商新旧接口时区不一致**（§2.3）：`/shipAIS/*` 北京时间 vs `/shipAIS/v2/*` 当地时间。
4. **`blType` 的 `BK` 取值未在文档中说明**（`BL`=提单号、`CN`=箱号已说明）。
5. **普通 CT 与综合 CT 的能力差未逐字列出**：`PASS`/`CUIP`/`SUOT`/`TMPS`/`TMCL` 五个码只在综合接口提供，但"综合"的完整范围、计费与订阅方式未说明。
6. **全球码头数据不支持出口**（`ieId` 注明"暂不支持出口"），但字段仍存在。
7. **`/api/terminalOpTime/queryTerminalOpTime`（船舶计划）与 `/api/localCharge/queryOptime`（操作时间）文档无描述**，与各数据域自带的时间字段是补充还是冗余需联调确认。
8. **`chargeDatas[]`（含 LFD 免箱期）仅支持 OOCL 船东**——超期费用计算不得假设该字段普遍可得。
9. **美国清关主单/分单事件码不同步**，文档明确要求以最新时间为准。

## 5. 与 Logixs 既有映射的对接点

| Logixs 现有条目                                                                                    | 云当网对应                                                         |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| [EXTERNAL_EVENT_MAPPING](../../product/domain/EXTERNAL_EVENT_MAPPING.md) 的 `EIR RELS YAR -> 放箱` | `/api/eir/query`（厦门、青岛、深圳出口、宁波四口岸）               |
| `GTOT + EMPTY/LADEN` 提空箱/提柜                                                                   | 云当网无 `GTOT`，对应 `STCS`（货主提柜）、`DGOT`（卸货港码头出场） |
| `1H↔1I` 美国海关成对扣留/解除                                                                      | `statusType` 的 `HOLD`↔`RMHOLD`（`RLS` 才是放行）                  |
| 中国海关 `PAS`/`BLR`/`CLR`/`ATP` 不得归并                                                          | 云当网报关状态码中同名同义，但**码表独立维护**                     |
| 免箱期/LFD                                                                                         | `chargeDatas[].lfd`，仅 OOCL；海外码头另有 `lastFreeDay`           |

映射条目按 `(provider, rawCode, context)` 分别建档，即使码面与飞驼相同也不合并——见 [README §5](./README.md#5-与飞驼码表的对照重要)。

这些冲突必须在 Adapter 契约测试中固化已验证行为；确认前不得在领域层猜测。
