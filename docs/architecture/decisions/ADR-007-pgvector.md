# ADR-007：pgvector 承担初期向量检索并定义迁移阈值

> 状态：`accepted` · 日期：2026-09-04 · 决定人：刘志高（2026-09-04 接受）

## 背景

知识片段/相似案例检索需要向量能力。初期的规模、延迟与混合检索需求不明确；若直接引入独立向量数据库会多一套基础设施与运维。

## 决策

- 初期复用 **PostgreSQL + pgvector** 承载知识片段向量，收益于其事务、权限与运维能力（架构 §10.1）。
- 检索权限在服务端执行；删除/降权源文档时，其文本、向量与缓存同步失效（架构 §10.2）。
- **迁移到独立向量库的触发条件**（满足其一且被证实即评估迁移并新增 ADR）：
  1. 向量规模/查询延迟超过 pgvector 可承担基线（P8 实测）；
  2. 出现 pgvector 无法满足的混合检索/精确度需求；
  3. 独立扩缩容或资源隔离需求成为客观要求。
- 阶段四按检索指标决定是否迁移（架构 §17 阶段四）。

## 后果

- 正面：复用事务与运维，初期成本最低；迁移路径预先定义。
- 代价：pgvector 在超大规模或复杂混合检索上有上限。
- 连锁：影响 P4-01（扩展启用）、P4-06（对象存储保留）、P10 RAG 管线实现。

## 备选方案

| 方案 | 取舍 | 为何未选 |
| --- | --- | --- |
| 独立向量库（Milvus/Qdrant） | 独立扩与专用能力 | 无规模/延迟证据，运维成本高（过早） |
| 纯关系检索（无向量） | 简单 | 无法支撑相似案例/语义检索需求 |
| 外部托管向量服务 | 免运维 | 数据驻留/合规与成本不满足自用优先原则 |

## 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 检索质量在阈值边缘波动 | 引入 Reranker 与评测（§13.2），用指标而非主观判断决策 |
| pgvector 性能瓶颈暴露晚 | P8 容量基线 + 触发条件量化 |

## 迁移与撤销条件

迁移独立向量库须由新 ADR 触发（见上）；迁移后须保证权限过滤与服务端执行语义不变。
