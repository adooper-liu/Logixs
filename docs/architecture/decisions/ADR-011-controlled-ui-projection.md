# ADR-011：受控 UI 投影与控件化（拒绝 Odoo Studio 式绑库搭页）

> 状态：`proposed` · 2026-09-18 · 决定人：【待指定】
> 锚定：[UI_SYSTEM](../../product/UI_SYSTEM.md) §8.5–8.6、[MODULE_PLUGIN_CONVENTION](../MODULE_PLUGIN_CONVENTION.md)、[INCREMENTAL_MODULE_PLAYBOOK](../INCREMENTAL_MODULE_PLAYBOOK.md) §4、[ADR-003](./ADR-003-postgresql-prisma.md)、[ADR-010](./ADR-010-bounded-context-modules.md)、[QUERY_PROJECTION_CONTRACT_V1](../../product/domain/QUERY_PROJECTION_CONTRACT_V1.md)。

## 背景（Context）

运营侧希望借鉴 Odoo Studio：编辑态自由新建页面，拖放表单/表格/甘特/按钮等控件，表格可选数据库表并做多表联合后展示。目标是降低「加一屏」的工程摩擦。

Logix 已是模块化单体：schema 只走迁移、跨模块经 Port/契约、写路径服务端授权与证据链、UI 以代码化路由与受控展示投影为主。`UI_SYSTEM` 已规定 `DynamicFieldPanel` / `DynamicDataTable` 纪律，并明确禁止把动态字段扩成低代码页面引擎。全量 Studio 会与上述边界冲突，并引入租户泄漏与「显示即真相」风险。

## 决策（Decision）

采用 **受控 UI 投影 + 控件化**，拒绝 **Studio 式运行时绑库搭页**。

### 接受（Accepted）

1. **控件库**：表单、表格、甘特、工具栏按钮等作为可复用前端控件（壳层/领域包装）；业务页装配控件，不复制表头/字段模板。
2. **Schema 驱动展示**：列表与只读字段区继续加深 `schema + rows`（及等价 Display Schema）；列/字段显隐、顺序、渲染类型由服务端契约决定。
3. **注册数据集**：多表关联若需要，以 Application 层登记的 `datasetId → 查询用例` 提供（固定 join、分页、能力码、字段白名单）。UI 只选数据集与列子集，不写任意 JOIN。
4. **白名单动作**：按钮只触发已注册 `actionCode` / 公共写 Port；不自定义写 SQL 或绕过工单/复核策略。
5. **布局配置（可选、后置）**：可配置槽位/密度/列宽；配置须版本化，且只能引用已注册控件与数据集。短期优先仓库内定义（评审进 Git）；入库须发布门禁与 `business_admin` 能力。
6. **管理只读看板**：若业务人员要「自己搭屏」，范围限于只读管理投影 + 注册数据集，不承载现场作业与过站写路径；扩展时另评，不静默升级本 ADR。

### 拒绝（Rejected）

1. Odoo Studio / 运行时改模型或 XML View 存库当权威。
2. 浏览器或 API 暴露「选任意数据库表 / 任意多表联合」。
3. 展示 schema 等同数据库元数据，或自动把实体列暴露到页面。
4. 服务端下发 HTML、脚本、表达式、任意组件名或可执行样式。
5. 编辑态自由新建导航页并挂任意写控件，绕过模块 manifest、路由与能力码。
6. 将三状态、生命周期轨道、过站、费用确认、证据核验、死信重放等做成通用动态字段/低代码块（须专用组件与契约）。

### 与 `UI_SYSTEM` §8.5–8.6 对照

| UI_SYSTEM 纪律 | 本 ADR |
| -------------- | ------ |
| 动态字段只消费受控展示投影；不扩成低代码页面引擎 | 接受控件化与 schema 驱动；拒绝 Studio 页面引擎 |
| 未声明值不渲染；schema 错误可见失败；无 `v-html`/执行下发代码 | 同左，上升为架构拒绝项 |
| 三状态/生命周期/动作/异常/证据/费用禁止动态字段化 | 列入拒绝域，必须专用交互 |
| 展示 schema 是 API 契约，不是 DB 元数据 | 拒绝选表与任意 JOIN；改为注册数据集 |
| 禁止浏览器直连库、直接返回实体、任意列自动暴露 | 同左 |
| 前端有限可审计渲染器集合 | 控件白名单 = 渲染器/组件注册表 |
| 写/筛/排/聚/动作走对应表单表格领域组件，不靠 DynamicFieldPanel | 写路径仅白名单 action / Port |

## 后果（Consequences）

- 正面：与迁移、契约、租户断言、证据链一致；可继续用动态表格降低「加列」成本，而不开放绑库。
- 代价：业务人员不能像 Studio 一样即改即用生产页；新数据集与写动作仍需工程切片。
- 连锁：巩固 `MODULE_PLUGIN_CONVENTION` / 增量手册对 Studio 的不采纳；实现须遵守 `UI_SYSTEM` §8.5–8.6；新数据集进 contracts 或模块公开 Port，不进临时 SQL。

## 备选方案（Alternatives）

| 方案 | 取舍 | 为何未选 |
| ---- | ---- | -------- |
| 全量 Odoo Studio 式搭页绑库 | 改屏最快 | 无 ORM 同构安全网；冲突迁移/边界/审计 |
| 纯代码 UI、禁止一切 schema 驱动 | 最简单 | 已证明动态表格/字段可安全降摩擦；不必回退 |
| 第三方低代码嵌核心作业链 | 外购加速 | 写路径与状态机难嵌入；供应链与权限难对齐 |

## 风险与缓解（Risks）

| 风险 | 缓解 |
| ---- | ---- |
| 「注册数据集」退化成隐藏任意 SQL | 数据集须代码评审或发布门禁；禁止运行时拼接未审批 SQL |
| 布局配置演变成页面引擎 | 配置只能引用白名单控件/数据集；禁止配置写路径与状态规则 |
| 管理看板需求反压主链 | 看板只读；过站/工单仍走专用工作台 |

## 迁移与撤销条件（Migration & Reversal）

- 本决策为 `proposed`，负责人接受后改为 `accepted`，并更新 ADR 索引与 INDEX。
- 若未来有独立部署的「报表/门户」产品且与主链写路径物理隔离，可另立 ADR 允许更宽的布局工作室；**不得**在无新 ADR 的情况下于主链启用选表 JOIN。
- 撤销本决策须新 ADR，并先给出租户隔离、契约门禁与迁移方案。
