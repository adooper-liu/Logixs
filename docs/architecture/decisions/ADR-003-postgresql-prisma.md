# ADR-003：PostgreSQL + Prisma + 唯一迁移入口

> 状态：`accepted` · 日期：2026-09-04 · 决定人：刘志高（2026-09-04 接受）

## 背景

需要承载业务事实、AI 元数据与审计，且所有结构变更必须受控。要求强约束（非空/唯一/引用/取值域）、跨语言（TS 业务侧为主、Python AI 侧只经契约/API）的明确数据边界，以及「迁移只在一处」的可审计工作流。

## 决策

- 主数据库采用 **PostgreSQL**；向量能力由同一实例的 **pgvector** 扩展承担（见 ADR-007）。
- 业务 API（TS）使用 **Prisma** 做类型化查询与迁移工作流；所有结构变更只经 `database/migrations/` 唯一入口（生成/管理）。
- **禁止 ORM 在生产自动同步 schema**；迁移一律追加，不修改已进入共享环境的历史迁移；破坏性变更走 expand→migrate→contract。
- 数据库/代码/DTO 间显式映射；命名 `snake_case` / `camelCase` / `PascalCase` 按规则。
- Python AI 侧不直接管理业务表结构：经契约/API 读写，向量与 RAG 相关表结构归属同一迁移入口。

## 后果

- 正面：强一致与 ACID 事务；pgvector 复用 Postgres 运维；集中迁移可审计。
- 代价：单库扩展受限于实例；Prisma 在复杂查询/SQL 下需 raw 逃生门（受控）。
- 连锁：P4-04（首条迁移 + 幂等 Seed）、P4-08（空库/升级验证）、P2-06（逻辑模型）。

## 备选方案

| 方案                           | 取舍           | 为何未选                                                      |
| ------------------------------ | -------------- | ------------------------------------------------------------- |
| 独立向量库（如 Milvus/Qdrant） | 向量规模独立扩 | 初期复用事务与运维，规模/延迟/混合检索证据出现再迁（ADR-007） |
| TypeORM / Drizzle / 原生 SQL   | 社区/风格差异  | Prisma 类型化 + 集中迁移最契合现状；Drizzle 可作后续评估      |
| MongoDB 等 NoSQL               | 灵活 schema    | 业务事实/审计需强约束与事务，关系模型更合适                   |

## 风险与缓解

| 风险                               | 缓解                                                          |
| ---------------------------------- | ------------------------------------------------------------- |
| Prisma 迁移与 raw SQL 并存导致漂移 | 唯一迁移入口 + Migration 测试（空库/升级/约束）               |
| 单库成为瓶颈                       | 先索引/分区治理；出现独立扩需求时评估读写分离或拆分（须 ADR） |

## 迁移与撤销条件

替换数据库、引入独立向量库、或开放 ORM 自动同步均须新增 ADR；撤销后需完整数据迁移方案与验证。
