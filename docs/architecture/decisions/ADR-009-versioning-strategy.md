# ADR-009：契约与运行物统一版本策略

> 状态：`accepted` · 日期：2026-09-04 · 决定人：刘志高（2026-09-04 接受）

## 背景

系统横跨 TS/Python、API/Workflow/AI/Prompt/评测，任何一端改动都可能破坏另一端或使历史回放失配。需要一套覆盖「代码契约 + 运行物（Prompt/模型/Tool/Schema/评测）」的统一版本策略，并防漂移。

## 决策

- **统一版本语义**：对公共契约与可发布运行物使用语义化版本（`major.minor.patch`）；破坏性变更升 major，兼容新增升 minor。
- **版本化对象范围**：API（OpenAPI）、事件、Workflow、Activity、Tool、Prompt、模型能力、Schema、评测集均带稳定标识 + 版本；运行时按「能力版本 + Prompt 版本 + Schema 版本」绑定并留痕（架构 §7.2/§10.3）。
- **单一权威源**：共享契约只保留一处权威定义，其余端由代码生成或派生；**Contract Parity 测试**（TS ↔ Python ↔ OpenAPI ↔ 评测集）在 CI 防漂移，注册项缺失即失败（ENGINEERING_RULES §7 / P3-13）。
- **兼容策略**：破坏性 API/事件变更提供兼容期或新版本；Workflow/Activity 版本遵循确定性重放规则（历史运行回放须稳定）。
- **版本发布**：Prompt/Tool/模型/Schema 的发布经 P5-06 流程；AI 回归评测随版本跑（§13.2）。

## 后果

- 正面：跨语言与跨运行物失配可被发现；历史回放稳定；AI 结果可溯源（版本绑定）。
- 代价：版本管理面广，需纪律与工具化；小步改动也要走版本登记。
- 连锁：影响 P1-10 完结、P2-08/09（API/Workflow 契约）、P3-13（Parity）、P5-06、P7（评测门禁）。

## 备选方案

| 方案                           | 取舍   | 为何未选                                  |
| ------------------------------ | ------ | ----------------------------------------- |
| 仅在代码内集中版本，不对外承诺 | 简单   | AI/Workflow/Prompt 无版本则无法回放与评测 |
| 全对象统一单一递增版本         | 简单   | 粒度过粗，改一处全触发回归与兼容负担      |
| 无版本（靠部署时间）           | 零成本 | 无法回滚/溯源 AI 结果，违反架构验收       |

## 风险与缓解

| 风险                 | 缓解                                  |
| -------------------- | ------------------------------------- |
| 手工登记遗漏导致漂移 | Parity 测试 + 发布流程自动化（P5-06） |
| 版本对象过多难维护   | 明确“权威源 + 生成”策略，减少手工双写 |

## 迁移与撤销条件

若某类对象长期无版本消费方（无回放/无评测需求），可将其退出版本管理——须评审并记录理由；放弃全局版本纪律则需新增 ADR。
