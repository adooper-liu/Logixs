# ADR-006：业务 AI Gateway 与 LiteLLM Provider Gateway 分层

> 状态：`accepted` · 日期：2026-09-04 · 决定人：刘志高（2026-09-04 接受）

## 背景

模型供应商可能多源、可替换，且 AI 调用需统一受制于权限、预算、限流、输入裁剪、版本绑定、输出校验与审计。需要一个「供应商路由」与「业务治理」分离的双层结构，避免业务模块直接贴供应商 SDK。

## 决策

- **LiteLLM Proxy**：负责供应商协议统一、基础模型路由与供应商级统计（无业务语义）。
- **业务 AI Gateway（在业务 API 内）**：只做治理与转发，不直接面向模型供应商，承担：租户/权限校验、输入裁剪与数据驻留、预算/限流/超时/降级策略、Prompt/Tool/模型/Schema 版本绑定、结构化输出与业务规则复核、调用与成本审计。
- **能力统一由 FastAPI AI Service 实现**并经 LiteLLM Proxy 调模型（ADR-005）；页面/领域模块/Workflow 不得直接调用模型供应商（架构 §7.2）。
- 模型/供应商路由、降级与数据驻留选择**不得仅按价格或可用性切换**，须可配置、可审计。

## 后果

- 正面：供应商可替换、业务治理集中、审计完整；Prompt/工具版本可回滚。
- 代价：多一跳治理层（可接受，属本地转发）；分层职责需纪律避免绕行。
- 连锁：影响 §7.2 实现、P2-11（L0–L4 与审批）、P5-05/06、架构验收「业务模块不引用供应商 SDK」。

## 备选方案

| 方案 | 取舍 | 为何未选 |
| --- | --- | --- |
| 只用 LiteLLM 承担全部治理 | 少一层 | LiteLLM 无法承载租户权限/业务审批/输出规则等业务治理 |
| 业务代码直连各家 SDK | 直接 | 绑定供应商、绕过治理，无法统一审计与降级 |
| 自研网关替换 LiteLLM | 完全可控 | 成本高且非核心；LiteLLM 提供协议统一即可 |

## 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 治理被绕过（直连供应商） | 依赖/端口限制 + 评审 + 架构验收测试 |
| 分层增加排障复杂度 | 全链路 Trace 与 AI 观测（Langfuse/OTel） |

## 迁移与撤销条件

替换供应商网关或允许业务模块直连供应商均须新增 ADR；撤销后必须仍满足「业务模块不引用供应商 SDK」验收线。
