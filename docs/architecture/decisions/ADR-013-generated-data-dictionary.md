# ADR-013：数据库字典采用结构提取、人工语义注解与单向投影

> 状态：`accepted` · 日期：2026-10-01 · 决定人：刘志高

## 背景

当前 Prisma、迁移与数据库原生对象持续演进，手工维护全量字段文档会漂移；业务人员又需要可筛选、可批注的中文
工作簿。项目必须同时保留可复算的物理事实、可追溯的业务语义和方便评审的交付物，且不得新增一套会反向覆盖
Schema、迁移或 `doc/` 的业务真相。

## 决策

- 物理结构从 `database/schema.prisma`、有序迁移和隔离数据库的 `pg_catalog` 自动提取并交叉核对；数量只作运行结果，
  不硬编码为通过条件。
- 人工注解只保存结构不能推导的中文名、用途、来源、工作台关联、敏感等级及各自证据状态；类型、可空性、默认值和
  约束不手抄进注解。
- `doc/` 继续是业务含义和流程权威；正式契约与实现只能证明各自层级的语义。无法可靠确定时必须标记
  `needs_business_confirmation`，禁止按英文名、UI 文案或行业惯例猜测。
- 仓库 Markdown 与 Excel 由同一规范化模型单向生成。Excel 用于筛选、批注和业务确认，不作为生成器的反向输入；
  采纳的批注意见必须先回写既有业务权威或人工注解，再重新生成。
- 该机制只建设数据字典与追溯链，不修改数据库结构、迁移或业务规则。

## 后果

- 正面：物理结构可重复核验，中文语义有证据等级，业务评审仍可使用 Excel，Schema 变化可触发漂移检查。
- 代价：需要维护提取器、注解稳定键和生成测试；业务批注必须经过裁决和回写，不能直接改生成物。
- 连锁：`database-data-dictionary-v1` 负责实现；各工作台只引用相关字段子集，不复制全量字典。

## 备选方案

| 方案                  | 取舍                 | 为何未选                               |
| --------------------- | -------------------- | -------------------------------------- |
| 手工维护 Excel        | 上手快、业务易编辑   | 结构和约束会持续漂移，来源难追溯       |
| 只生成仓库 Markdown   | 技术侧简单、便于检索 | 不便业务筛选、批注和批量确认           |
| 从 Excel 反向生成注解 | 业务可直接改“权威”   | 会形成第二真相并绕过来源核验与代码评审 |

## 风险与缓解

| 风险                          | 缓解                                                          |
| ----------------------------- | ------------------------------------------------------------- |
| 注解把猜测包装成业务事实      | 每个语义分别记录证据状态和来源；未知值明确待业务确认          |
| 生成物被手工修改              | check 模式重新生成并比较；生成物标注生成命令                  |
| Schema 与迁移或目录事实不一致 | 完整迁移重放后对账 `pg_catalog`，差异登记 finding，不静默覆盖 |
| Excel 评审意见未进入权威链    | Codex 裁决后先回写业务权威或注解，再统一重新生成              |

## 迁移与撤销条件

先以独立提取器建立规范化结构模型，再接入人工注解、Markdown 和 Excel，最后串行接入根命令与 CI。若生成链长期没有
消费者，或维护成本高于人工核对收益，可停止生成 Excel；物理结构仍不得退回手抄，已确认语义及来源记录须保留并迁移。
