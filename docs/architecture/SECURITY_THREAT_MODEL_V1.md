# 安全威胁模型 V1

> 状态：**安全基线 V1** · 2026-09-17 · 所有者：安全与平台负责人
> 消费者：P5-02～P5-10 实现者、API/AI/集成模块评审者、上线审批人。
> 权威边界：身份协议与授权架构见 [ADR-008](./decisions/ADR-008-oidc-oauth.md)；动作授权语义见 [GC-008](../product/domain/ACTION_PERMISSION_CONTRACT_V1.md)；角色、能力和范围见 [IDENTITY_ACCESS_MODEL_V1](../product/domain/IDENTITY_ACCESS_MODEL_V1.md)。

## 1. 保护目标与事实状态

| 资产                         | 必须保护的性质                         | 当前事实（R）                                                       |
| ---------------------------- | -------------------------------------- | ------------------------------------------------------------------- |
| 货柜、任务、事件、费用事实   | 租户隔离、完整性、不可越权修改         | 部分用例已有租户断言；尚无正式能力授权                              |
| 导入原文件、证据与解析结果   | 机密性、完整性、来源追溯、恶意内容隔离 | 文件大小/类型有边界且原件进私有对象存储；病毒扫描和隔离解析尚未实现 |
| 用户、服务身份和授权上下文   | 不可伪造、最小权限、可撤销、可审计     | 用户使用可伪造开发头；服务使用静态头                                |
| AI Prompt、模型输出和 Tool   | 不因不可信文本扩大权限或直接写业务事实 | AI 映射仅给建议；尚无统一 Tool 授权执行层                           |
| Inbox/Outbox、补偿和死信重放 | 幂等、因果链、授权、不可篡改           | 已有幂等/租约/重放记录；正式服务身份和能力授权尚未实现              |
| Token、密钥、连接串和日志    | 保密、轮换、最少披露                   | 配置来自环境；集中密钥管理、轮换和日志泄漏门禁尚未完成              |

🗣️ 白话：系统现在有一些“门锁零件”，但用户只要自己写两个请求头就能冒充身份，所以还不能当生产权限系统使用。

## 2. 信任边界

```text
浏览器 / 外部调用方
  -> [B1 公网或终端边界] -> Web / API
  -> [B2 身份边界]       -> Keycloak（目标；当前为开发头）
  -> [B3 业务授权边界]   -> Application / Domain
  -> [B4 数据边界]       -> PostgreSQL / MinIO

不可信文件 -> [B5 解析隔离边界] -> 确定性解析 -> AI Gateway -> 模型供应商
Worker / 集成 -> [B6 服务身份边界] -> API -> Inbox / Outbox / Temporal
AI 输出 -> [B7 Tool 执行边界] -> 与人工相同的授权、审批和业务守卫
```

- B1 之后的客户端输入全部不可信，包括隐藏字段、路由状态、`allowedActions` 和租户标识。
- B2 只证明“是谁”；B3 仍须判断“能否对这个对象做这个动作”。
- B5 中的文档正文、公式、宏、链接和嵌入指令都是数据，不是系统指令。
- B6 的服务身份不得模拟用户；B7 的模型输出不得成为身份、能力或审批凭据。

## 4. 上线阻断项

以下任一成立时不得开放生产写流量：

1. API 仍接受 `X-Tenant-Id` / `X-Operator-Id` 作为可信身份。
2. 任一写端点没有认证、能力、租户和对象范围的默认拒绝策略。
3. 服务端信任浏览器传入的 actor、role、capability、tenant 或 `allowedActions`。
4. 文件未完成类型/魔数、大小、解压资源和病毒策略，或解析进程与主 API 无隔离边界。
5. AI Tool 可以绕过与人工相同的 Application 用例、审批或业务守卫。
6. 原文件、证据或 Token 可通过日志、错误响应、公开 bucket 或长期 URL 读取。
7. 跨租户、提示注入、Tool 越权和敏感信息泄漏测试未进入门禁。

## 6. 变更规则

- 新增入口、资产、第三方、Tool 或高风险动作时必须更新威胁登记，不能只补代码。
- 风险只有在控制实现并有自动化证据后才能降级；文档设计本身不降低当前风险。
- 接受严重/高风险残余必须记录责任人、期限、监控和退出条件，不能以“内部系统”为理由豁免。
- 本文不复制能力或动作清单；授权细节分别引用身份访问模型与 `GC-008`。
